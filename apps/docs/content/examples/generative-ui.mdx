## 概述

`examples/with-generative-ui`的主路由演示了**生成式 UI**：模型通过调用`present`工具，在运行时组合界面，并从应用提供的词汇表中选择组件。应用中的任何内容都不会将组件绑定到特定的工具调用。

- **默认词汇表** — 卡片、事实、行、表格和图表来自`defaultGenerativeUILibrary`，因此应用只需注册一个工具，无需编写渲染器
- **自定义组件** — 通过`defineGenerativeComponents`添加`DashboardHeader`，展示如何使用自己的 React 组件扩展词汇表；同时将`Markdown`替换为注册表项的实际渲染器
- **带样式的输出** — 词汇表样式表通过 monorepo 的 tsconfig 别名从`@assistant-ui/ui`加载，这是仓库内每个示例使用该包的方式；在自己的应用中，相同的 CSS 会通过`shadcn add generative-ui`引入
- **仪表板提示** — 建议描述数据而非布局，并让模型决定组合方式

### 同一示例应用中的路由

| 路由 | 演示内容 |
|-------|---------------------|
| `/` | `present`工具（`JSONGenerativeUI`）——模型从词汇表中组合 UI |
| `/tool-ui` | Tool UI（`Tools({ toolkit })`）——为每个已知工具绑定一个渲染器 |
| `/primitive` | 带有手写规范的静态`GenerativeUIRender`（旧版） |
| `/gui-chat` | 与`MessagePrimitive.GenerativeUI`桥接的`render_gui`工具聊天（旧版） |

查看[生成式 UI 指南](/docs/tools/generative-ui)了解完整设置，查看[Tool UI](/docs/tools/tool-ui)了解按工具配置的替代方案。

## 演示的模式

### present 工具

一个工具包条目就能暴露整个词汇表。`display: "standalone"`会在自身的界面上渲染结果，而不是将其渲染在思维链轨迹中：

```tsx title="app/present-toolkit.tsx"
"use generative";

const markdown = defaultGenerativeUILibrary.Markdown!;

const generative = new JSONGenerativeUI({
  library: {
    ...defaultGenerativeUILibrary,
    ...defineGenerativeComponents({
      Markdown: {
        properties: markdown.properties,
        streamProperties: markdown.streamProperties,
        description:
          "A markdown string, rendered with GitHub-flavored markdown.",
        render: styledGenerativeUILibrary.Markdown!.render,
      },
      DashboardHeader: {
        description:
          "A heading for a dashboard, with an optional description and reporting period.",
        properties: z.object({
          title: z.string().describe("The dashboard title."),
          description: z.string().optional(),
          period: z.string().optional(),
        }),
        render: (props) => <DashboardHeader {...props} />,
      },
    }),
  },
});

export default defineToolkit({
  present: generative.present({ display: "standalone" }),
});
```

两个演示使用彼此独立的工具包和路由。如果`/`也包含 Tool UI 条目，那么对于每个提到图表的提示，`generate_chart`都会与`present`竞争，演示最终会渲染 Recharts 小部件，而不是组合出的仪表板。

由于`present`会在浏览器中解析，提供程序会传入`sendAutomaticallyWhen`，以便 UI 渲染完成后继续运行。传输层会将此路由指向自己的端点，从而使两个演示使用彼此独立的工具集：

```tsx title="app/page.tsx"
const runtime = useChatRuntime({
  transport: new AssistantChatTransport({ api: "/api/present" }),
  sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithToolCalls,
});
```

### 后端渲染的工具（图表、位置）

在`/tool-ui`中，这些工具具有后端`execute`函数和前端工具包渲染器。AI 生成数据，后端进行确认，然后前端根据`args`渲染丰富的 UI：

```tsx
const toolkit = defineToolkit({
  generate_chart: {
    type: "backend",
    render: ({ args, status }) => {
    const { title, type, data, xKey, dataKeys } = args;
    // Render a Recharts BarChart/LineChart/PieChart based on args
    return <ChartContainer config={buildChartConfig(dataKeys)}>...</ChartContainer>;
  },
  },
});
```

### 仅前端工具（日期选择器、联系人表单）

这些工具没有后端`execute`——AI 触发工具调用，用户通过交互式 UI 完成操作。`addResult`回调会将用户输入发送回 AI：

```tsx
const toolkit = defineToolkit({
  select_date: {
    type: "human",
    render: ({ args, result, addResult }) => {
    if (result) return <div>Selected: {result.date}</div>;

    return (
      <div>
        <p>{args.prompt}</p>
        <input type="date" onChange={(e) => setValue(e.target.value)} />
        <button onClick={() => addResult({ date: value })}>Confirm</button>
      </div>
    );
  },
  },
});
```

## 核心概念

| 概念 | 使用位置 | 描述 |
|---------|---------|-------------|
| `JSONGenerativeUI` | `/` | 将组件库转换为面向模型的`present`架构 |
| `defineGenerativeComponents` | `/` | 将自己的组件添加到词汇表 |
| `sendAutomaticallyWhen` | `/` | 前端工具解析后继续运行 |
| `Tools({ toolkit })` | `/tool-ui` | 为特定工具调用注册 React 渲染器 |
| `addResult` | 日期选择器、联系人表单 | 将用户输入作为工具结果发送回 AI |
| `status.type` | 图表、位置 | AI 流式传输工具参数时显示加载状态 |
