---
title: 方法
description: 使用 useAui 访问作用域方法。
---

方法是作用域的命令式 API。它们是资源返回的函数：`increment`、`send`、`delete`，或其他任何函数。你可以通过 `useAui()` 访问它们。

## 定义方法

首先，在 `ScopeRegistry` 中注册方法签名：

```ts title="lib/store/counter-scope.ts"
import "@assistant-ui/store";

declare module "@assistant-ui/store" {
  interface ScopeRegistry {
    counter: {
      methods: {
        increment: () => void;
        decrement: () => void;
        reset: () => void;
      };
    };
  }
}
```

然后创建一个实现这些方法的资源。返回类型 `ClientOutput<"counter">` 会将资源与作用域关联起来：如果返回的方法与注册表不匹配，TypeScript 会报错：

```ts title="lib/store/counter-resource.ts"
import { resource } from "@assistant-ui/tap";
import { useState } from "react";
import type { ClientOutput } from "@assistant-ui/store";

const useCounterResource = (): ClientOutput<"counter"> => {
  const [count, setCount] = useState(0);

  return {
    increment: () => setCount((c) => c + 1),
    decrement: () => setCount((c) => c - 1),
    reset: () => setCount(0),
  };
};

const CounterResource = resource(useCounterResource);
```

你返回的每个函数都会成为作用域上的一个方法。它们没有任何特殊之处：就是可以调用 `useState` setter、触发副作用或执行其他操作的普通函数。

## useAui

在任何 `AuiProvider` 内无参数调用 `useAui()`，即可获取当前 store：

```tsx
const aui = useAui();
```

返回的客户端为当前上下文中可用的每个作用域提供一个访问器。客户端是不可变的：状态更新不会改变其标识，而结构变化（某个作用域解析为不同的实例）会生成新的客户端，并通过 React 触发消费者重新渲染。

## 作用域访问器

`aui.counter` 是作用域访问器：它会公开作用域的方法，以及 `source`/`query`/`name` 元数据。对于每个作用域绑定，其标识都保持稳定；绑定变化时，标识也会变化：

```tsx
aui.counter.increment();
```

当派生作用域切换其指向的项目时，组件会使用新的客户端和新的访问器重新渲染。在使用位置访问作用域：

```tsx
const MessageActions = () => {
  const aui = useAui();

  return (
    <button
      onClick={() => {
        // resolves at click time, always gets the current scope
        aui.message.reload();
        aui.thread.cancelRun();
      }}
    />
  );
};
```

### 不要在渲染期间读取状态

`aui.counter.getState()` 会返回一个不订阅状态的快照，因此基于它构建的渲染输出会过时。应改用 `useAuiState` 在渲染期间读取状态。

```tsx
const Counter = () => {
  const aui = useAui();

  // ❌ Don't read state during render
  const count = aui.counter.getState().count;

  // ✅ Use useAuiState for render-time reads
  const count = useAuiState((s) => s.counter.count);

  // ✅ Read in event handlers, effects, or callbacks
  const handleClick = () => aui.counter.increment();
};
```

## 检查作用域是否存在

访问 `aui.counter` 永远不会抛出异常，并且访问器始终为真值 — `if (aui.counter)` 并不能说明任何问题。当作用域未由上方任何 `AuiProvider` 提供时，访问器仍然可以正常响应 `source`（`null`）、`query` 和 `name`；但调用它或读取任何其他属性都会抛出异常。通过 `aui.optional` 读取作用域：作用域可用时，它会解析为同一个访问器；不可用时则解析为 `undefined`：

```tsx
const aui = useAui();

aui.optional.counter?.increment();
```

这与状态侧的 `s.optional` 相对应。访问器元数据仍然可用，并且无论访问器报告 `source: null`，还是作用域完全缺失于手动构建的父级链中，只要作用域不可用，`aui.optional.counter` 就是 `undefined`。

## 订阅作用域标识

<Callout type="info">
这是一种高级模式。在整个 assistant-ui 代码库中，只有两个使用场景。
</Callout>

有时你需要知道作用域本身何时发生变化，例如当派生作用域切换到不同项目时，向外部系统注册或取消注册。

使用 `useAuiState` 订阅作用域标识：

```tsx
const thread = useAuiState(() => aui.thread);

useEffect(() => {
  analytics.register(thread);
  return () => analytics.unregister(thread);
}, [thread]);
```

`aui.thread` 对于每个作用域绑定都是稳定的访问器。当派生作用域切换其指向的线程时，`useAuiState` 会检测到新的访问器并重新渲染，从而触发 effect 清理和重新注册。
