---
title: 为什么使用 Store
description: Store 要解决的问题。
---

借助 Tap 的 `useResource`，组件可以直接拥有自己的资源：

```tsx
const Counter = () => {
  const { count, increment } = useResource(CounterResource());
  return <button onClick={increment}>{count}</button>;
};
```

当创建状态的组件与显示状态的组件是同一个组件时，这种方式运行良好。但当它们相距很远时会发生什么？

## 差距

在大多数应用中，状态在组件树的上层创建，却在树的深层被使用。聊天应用会在根部创建其会话线程状态，但单条消息的渲染位置可能要深入许多层。

```
App              ← owns the thread
  └ Layout
    └ Sidebar
      └ ChatPanel
        └ MessageList
          └ Message  ← needs the thread's data
```

你可以通过 props 逐层传递，或者设置自己的 React Context。Store 会替你完成这些工作。

## Store 如何弥合差距

```tsx
// At the top — create and provide
const App = () => {
  const config = AuiConfig({ thread: ThreadResource() });
  return (
    <AuiProvider config={config}>
      <Layout />
    </AuiProvider>
  );
};

// Anywhere below — consume
const Message = () => {
  const isRunning = useAuiState((s) => s.thread.isRunning);
  return <p>{isRunning ? "Running" : "Idle"}</p>;
};
```

`AuiProvider` 根据其 `config` 创建状态，并使其在组件树中可用。`useAuiState` 从中读取状态——组件仅在选中的值发生变化时重新渲染。
