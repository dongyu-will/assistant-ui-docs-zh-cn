---
title: 状态
description: 使用 useAuiState 订阅状态变化。
---

作用域可以定义一个名为 `getState()` 的特殊方法。它本质上是一个普通方法，但在 Store 中有特殊的集成逻辑：它为 `useAuiState`、`AuiIf` 以及 `subscribe` API 提供支持。

## 定义状态

首先，在 `ScopeRegistry` 中注册 `getState` 及其返回类型：

```ts title="lib/store/counter-scope.ts"
import "@assistant-ui/store";

declare module "@assistant-ui/store" {
  interface ScopeRegistry {
    counter: {
      methods: {
        getState: () => { count: number; step: number };
        increment: () => void;
        setStep: (n: number) => void;
      };
    };
  }
}
```

`getState` 的返回类型定义了 `useAuiState((s) => s.counter.count)` 中 `s.counter` 的结构。作用域不一定要定义 `getState()`：如果它只有方法而没有可读取的状态，这也是可以的。

然后，在资源中实现 `getState()`。它应返回一个根据资源内部状态构建的记忆化对象：

```ts title="lib/store/counter-resource.ts"
import { resource } from "@assistant-ui/tap";
import { useState, useMemo } from "react";
import type { ClientOutput } from "@assistant-ui/store";

const useCounterResource = (): ClientOutput<"counter"> => {
  const [count, setCount] = useState(0);
  const [step, setStep] = useState(1);

  const state = useMemo(() => ({ count, step }), [count, step]);

  return {
    getState: () => state,
    increment: () => setCount((c) => c + step),
    setStep: (n: number) => setStep(n),
  };
};

const CounterResource = resource(useCounterResource);
```

使用 `useMemo` 创建状态对象。这样可以确保在没有任何变化时保持稳定的引用，因为 Store 使用引用相等性来检测更新。依赖数组中的 `useState` 值发生变化时，会触发资源重新渲染；此时 Store 会检查是否有新状态。

## useAuiState

`useAuiState` 用于订阅状态。你必须传入一个选择器函数，从 Store 中选择要订阅的部分。只有选中的值发生变化时，组件才会重新渲染。

```tsx
const count = useAuiState((s) => s.counter.count);
```

选择器函数接收一个状态对象，其中每个键都对应一个作用域。`s.counter` 是计数器的 `getState()` 的返回值。

<Callout type="warn">
避免选择超出所需范围的状态。选择一个较大的对象（例如整个作用域的状态）意味着该对象中的*任意*字段发生变化时，组件都会重新渲染，即使这些字段并未被使用。

```tsx
// ❌ Avoid: re-renders on any counter state change
const { count } = useAuiState((s) => s.counter);

// ✅ Prefer: re-renders only when count changes
const count = useAuiState((s) => s.counter.count);
```
</Callout>

## 从多个作用域中选择状态

使用 `useAuiState` 时最常见的陷阱，是从选择器中返回一个新对象：

```tsx
// ❌ Infinite re-render: creates a new object every time
const summary = useAuiState((s) => ({
  count: s.counter.count,
  name: s.user.name,
}));
```

`useAuiState` 会通过引用比较选择器的返回值（`Object.is`）。类似 `{ count, name }` 的对象字面量会在每次运行选择器时创建一个新引用，因此 Store 会认为值发生了变化，重新渲染组件，而重新渲染又会再次运行选择器（形成无限循环）。

解决方法很简单：针对每个值分别调用 `useAuiState`。

```tsx
const count = useAuiState((s) => s.counter.count);
const name = useAuiState((s) => s.user.name);
```

这样也更加精确：只有组件使用的特定值发生变化时，组件才会重新渲染，而不是在任意已选择的作用域发生变化时都重新渲染。

## 检查作用域是否存在

如果尚未提供 `counter` 作用域，在选择器中访问 `s.counter` 会抛出异常。若要读取可能不存在的作用域中的状态，请使用 `s.optional` ——不可用的作用域会解析为 `undefined`，而不是抛出异常：

```tsx
const count = useAuiState((s) => s.optional.counter?.count);
```

若要在选择器外根据作用域是否可用进行分支，请使用客户端对此视图的镜像：作用域可用时，`useAui().optional.counter` 是绑定的访问器；不可用时则为 `undefined`。

## AuiIf

`AuiIf` 仅在状态条件为 true 时渲染其子元素：

```tsx
<AuiIf condition={(s) => s.counter.count > 0}>
  <ResetButton />
</AuiIf>
```

它在内部使用 `useAuiState`，因此只有选中的值发生变化时才会重新求值。

## 底层原理：subscribe + getState

`useAuiState` 和 `AuiIf` 都基于 Store 提供的两个原语构建：

- `aui.subscribe(callback)`：任意作用域的状态发生变化时调用 `callback`
- `aui.counter.getState()`：返回当前的状态快照

二者共同构成标准的 `useSyncExternalStore` 模式。对于非 React 集成，或需要命令式访问时，你可以直接使用它们：

```ts
const aui = useAui();

// imperative read
const count = aui.counter.getState().count;

// manual subscription
const unsub = aui.subscribe(() => {
  console.log("new count:", aui.counter.getState().count);
});
```
