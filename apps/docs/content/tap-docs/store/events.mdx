title: 事件
description: 发出和订阅类型化事件。

状态描述当前事物的样子。事件描述刚刚发生了什么。对于响应离散操作的副作用，请使用事件，例如显示 toast、滚动到新消息或触发分析。

## 声明事件

在 `ScopeRegistry` 的作用域中添加 `events` 字段。事件名称遵循 `"scopeName.eventName"` 格式：

```ts title="lib/store/counter-scope.ts"
import "@assistant-ui/store";

declare module "@assistant-ui/store" {
  interface ScopeRegistry {
    counter: {
      methods: {
        getState: () => { count: number };
        increment: () => void;
      };
      events: {
        "counter.incremented": { newCount: number };
        "counter.reset": undefined;
      };
    };
  }
}
```

每个事件都有类型化载荷。对于不携带数据的事件，请使用 `undefined`。

## 发出事件

在资源中调用 `useAssistantEmit()` 以获取事件发出函数：

```ts title="lib/store/counter-resource.ts"
import { resource } from "@assistant-ui/tap";
import { useState, useMemo } from "react";
import { useAssistantEmit } from "@assistant-ui/store";
import type { ClientOutput } from "@assistant-ui/store";

const useCounterResource = (): ClientOutput<"counter"> => {
  const [count, setCount] = useState(0);
  const emit = useAssistantEmit();

  const state = useMemo(() => ({ count }), [count]);

  return {
    getState: () => state,
    increment: () => {
      const newCount = count + 1;
      setCount(newCount);
      emit("counter.incremented", { newCount });
    },
  };
};

const CounterResource = resource(useCounterResource);
```

事件通过微任务传递：它们会在当前状态更新完成后触发，而不是在更新过程中触发。这意味着监听器始终能看到一致的状态。

## 订阅事件

在 `AuiProvider` 内的任意组件中使用 `useAuiEvent`：

```tsx
import { useAuiEvent } from "@assistant-ui/store";

const CounterToast = () => {
  useAuiEvent("counter.incremented", ({ newCount }) => {
    toast(`Count is now ${newCount}`);
  });

  return null;
};
```

回调会接收类型化载荷。它在内部是稳定的（通过 `useEffectEvent`），因此无需对其进行记忆化。

## 事件作用域

当你将类似 `"counter.incremented"` 的字符串传递给 `useAuiEvent` 时，它会监听**当前上下文中** `counter` 作用域发出的事件。这就是作用域过滤：只有当事件来自你所在的特定作用域实例时，监听器才会触发。

当同一作用域存在多个实例时，这一点很重要。请考虑一个计数器列表，其中每个计数器都有自己的 `counter` 作用域：

```
App
  └ CounterItem (counter scope, id: "a")
  └ CounterItem (counter scope, id: "b")
  └ CounterItem (counter scope, id: "c")
```

`CounterItem "a"` 内的 `useAuiEvent("counter.incremented", ...)` 只会针对该计数器触发，不会针对“b”或“c”触发。每个监听器都限定在自己的实例中。

### 监听子级事件

如果你尝试监听组件上下文中不可用的作用域发出的事件，Store 会抛出错误。例如，如果你的组件位于 `counter` 作用域之上，`useAuiEvent("counter.incremented", ...)` 会抛出错误，因为不存在可用于过滤的 `counter` 作用域。

要监听子级作用域发出的事件，请将 `scope` 设置为你自己的作用域（即父级作用域）：

```tsx
// inside a component that has counterList but not counter
useAuiEvent(
  { scope: "counterList", event: "counter.incremented" },
  ({ newCount }) => {
    console.log("some counter changed:", newCount);
  },
);
```

这会针对 `counterList` 作用域下方任意计数器实例发出的 `counter.incremented` 事件触发。`scope` 字段会告诉 Store 应在哪一层进行过滤：该作用域实例的任何后代发出的事件都会匹配。

### 监听同级事件

无法直接监听同级作用域发出的事件。相反，请在共同的父级作用域（或 `"*"`）处进行监听，并根据事件载荷中的元数据进行过滤：

```tsx
// inside counter "a", listening for increments from any sibling
useAuiEvent(
  { scope: "counterList", event: "counter.incremented" },
  ({ counterId, newCount }) => {
    if (counterId === "b") {
      console.log("counter b incremented:", newCount);
    }
  },
);
```

请将过滤所需的元数据包含在事件载荷中；Store 不会自动提供同级作用域的身份信息。

### 通配符作用域

使用 `"*"` 作为作用域，可以监听来自任意实例的事件，不受你在树中的位置影响：

```tsx
useAuiEvent(
  { scope: "*", event: "counter.incremented" },
  ({ newCount }) => {
    console.log("any counter incremented:", newCount);
  },
);
```

### 通配符事件

使用 `"*"` 作为事件，即可监听所有事件。载荷会与事件名称一起进行包装：

```tsx
useAuiEvent("*", ({ event, payload }) => {
  console.log(event, payload);
});
```

这对于调试和日志记录很有用。

## 选择作用域模式

| 你想要…… | 选择器 |
| --- | --- |
| 监听自己作用域发出的事件 | `"scope.event"` |
| 监听下方任意子级发出的事件 | `{ scope: "yourScope", event: "child.event" }` |
| 监听同级作用域发出的事件 | `{ scope: "mutualParent", event: "sibling.event" }` + 根据载荷过滤 |
| 监听来自任意位置的事件 | `{ scope: "*", event: "scope.event" }` |
| 监听所有事件（调试） | `"*"` |
