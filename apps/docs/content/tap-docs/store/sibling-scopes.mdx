---
title: 同级作用域
description: 在同一层级相互引用的作用域。
---

子作用域向下指向——从父作用域指向子作用域。但有时，同一层级的作用域需要相互交互。一个 `tools` 作用域可能需要向 `modelContext` 作用域注册定义。一个 `composer` 作用域可能需要从 `thread` 作用域读取数据。

这些就是**同级作用域**——位于提供者树同一层级并相互引用的作用域。

## 问题

当你在 `AuiConfig` 中传入多个作用域时，它们都会作为同级作用域创建：

```tsx
AuiConfig({
  thread: ThreadResource(),
  tools: ToolsResource(),
  modelContext: ModelContextResource(),
});
```

但如果 `ToolsResource` 需要调用 `modelContext` 作用域上的方法，该怎么办？在定义时，`tools` 资源无法访问其同级作用域。

## useAssistantClientRef

`useAssistantClientRef()` 让资源可以访问正在构建的存储。它返回一个 ref，其 `.current` 属性会在所有作用域挂载后指向 `AssistantClient`：

```ts
import { resource } from "@assistant-ui/tap";
import { useAssistantClientRef } from "@assistant-ui/store";
import type { ClientOutput } from "@assistant-ui/store";
import { useEffect } from "react";

const useToolsResource = (): ClientOutput<"tools"> => {
  const clientRef = useAssistantClientRef();

  useEffect(() => {
    // access a sibling scope
    const unsub = clientRef.current!.modelContext.register({
      getModelContext: () => ({ tools: myTools }),
    });
    return () => unsub();
  }, [clientRef]);

  return {
    getState: () => ({ ... }),
  };
};

const ToolsResource = resource(useToolsResource);
```

请在 effect 中使用 `useAssistantClientRef`，不要在资源主体中使用。该 ref 会在所有同级作用域挂载后填充，因此只有在 `useEffect` 中或在稍后调用的方法中访问它才是安全的。

## attachTransformScopes

`useAssistantClientRef` 允许作用域在运行时与同级作用域通信。但如果同级作用域尚不存在呢？如果用户只提供了 `thread: ThreadResource()`，就没有 `modelContext` 可供通信。

`attachTransformScopes` 通过允许资源声明“挂载我时，确保这些同级作用域也存在”来解决这个问题。

将 transform 附加到你传递给 `resource()` 的 hook 函数上——transform 按 hook 进行关联，而不是按资源包装器进行关联：

```ts
import { attachTransformScopes } from "@assistant-ui/store";

attachTransformScopes(useToolsResource, (scopes, parent) => {
  // ensure modelContext exists as a sibling
  if (!scopes.modelContext && parent.modelContext.source === null) {
    scopes.modelContext = ModelContextResource();
  }
});
```

transform 函数接收：
- `scopes` — 当前正在构建的作用域配置（直接修改它）
- `parent` — 父级 `AssistantClient`（来自上方的 `AuiProvider`）

它会直接修改 `scopes` 对象，添加应当与其一起创建的作用域。

### 检查 parent.source

添加作用域前，请检查 `parent.scopeName.source`：
- `null` — 该作用域未由任何祖先提供，可以安全地在此处添加。
- `"root"` 或某个作用域名称 — 祖先已经提供了该作用域，不要重复添加。

```ts
attachTransformScopes(useMyResource, (scopes, parent) => {
  // only add if not already in scopes AND not provided by a parent
  if (!scopes.tools && parent.tools.source === null) {
    scopes.tools = ToolsResource();
  }
});
```

### 添加派生作用域

Transform 还可以添加 `Derived` 作用域：

```ts
attachTransformScopes(useThreadResource, (scopes) => {
  scopes.composer ??= Derived({
    source: "thread",
    query: {},
    get: (aui) => aui.thread.composer(),
  });
});
```

这样，当用户提供 `thread` 作用域时，`composer` 作用域就会自动连接为该线程的子作用域，而无需用户自行声明。

### 迭代应用

Transform 会以迭代方式应用。当某个 transform 添加新的根作用域时，Store 会检查该新作用域是否也附加了 transform，并运行它。这个过程会持续进行，直到不再添加新的作用域。

例如：
1. 用户提供 `thread: ThreadResource()`
2. `ThreadResource` 的 transform 添加 `tools: ToolsResource()` 和 `modelContext: ModelContextResource()`
3. `ToolsResource` 的 transform 运行——发现 `modelContext` 已经存在，因此不执行任何操作
4. 没有更多新的作用域 → 完成

<Callout type="warn">
每个 hook 只能附加一个 transform。在同一个 hook 上调用两次 `attachTransformScopes` 会抛出错误。要将被包装 hook 的 transform 传递给包装器，请使用 `forwardTransformScopes(target, source)`——它会与目标上已有的 transform 组合。
</Callout>

## 何时使用哪一种

| 模式 | 使用场景 |
| --- | --- |
| `useAssistantClientRef` | 作用域需要在运行时调用同级作用域上的方法（effect、事件处理器） |
| `attachTransformScopes` | 作用域需要确保同级作用域在挂载前存在 |

在实际使用中，它们通常会一起使用：`attachTransformScopes` 确保创建同级作用域，然后 `useAssistantClientRef` 在运行时访问它。
