description: 如何高效地渲染来自状态存储的项目列表。
---

## 模式

从状态存储渲染项目列表遵循以下三个步骤：

1. 使用 `useAuiState`**订阅列表长度** — 仅在添加或移除项目时重新渲染
2. 使用 `useMemo`**记忆化元素数组** — 避免在无关的重新渲染中重新创建元素
3. 在每个项目中使用 `RenderChildrenWithAccessor` — 将项目状态的读取推迟到子组件实际需要时

```tsx
import { useMemo } from "react";
import { useAuiState, RenderChildrenWithAccessor } from "@assistant-ui/store";

const TodoList = ({
  children,
}: {
  children: (value: { todo: TodoState }) => ReactNode;
}) => {
  const length = useAuiState((s) => s.todoList.todos.length);

  return useMemo(
    () =>
      Array.from({ length }, (_, index) => (
        <TodoProvider key={index} index={index}>
          <RenderChildrenWithAccessor
            getItemState={(aui) => aui.todoList.todo({ index }).getState()}
          >
            {(getItem) =>
              children({
                get todo() {
                  return getItem();
                },
              })
            }
          </RenderChildrenWithAccessor>
        </TodoProvider>
      )),
    [length, children],
  );
};
```

用法：

```tsx
<TodoList>
  {({ todo }) => <TodoCard title={todo.title} />}
</TodoList>
```

## 为什么采用这种模式？

### 基于长度的订阅

订阅 `.length` 而不是完整数组，意味着列表组件只会在添加或移除项目时重新渲染，而不会在单个项目的数据发生变化时重新渲染。这比订阅键或完整数组的开销低得多。

### RenderChildrenWithAccessor

`RenderChildrenWithAccessor` 提供惰性访问器（`getItem`），而不是主动读取项目状态。这意味着：

- **延迟读取**：如果 children 渲染函数从未访问该项目，则不会创建订阅
- **无 props 记忆化**：当 children 返回一个无 props 的组件（例如 `{() => <Todo />}`）时，输出会自动进行记忆化 — 不会因父组件更新而重新渲染

`getItem` 函数是一个 getter，会按需读取最新状态。将它封装在惰性属性（`get todo() { return getItem(); }`）中，这样只有在使用者访问该属性时才会读取状态。

## 内置原语

所有 assistant-ui 列表原语（Messages、Parts、Attachments、Suggestions、ThreadListItems 等）在内部都使用此模式。使用 children 渲染函数 API 时，会自动获得惰性访问器行为：

```tsx
<ThreadPrimitive.Messages>
  {({ message }) => {
    // `message` is a lazy getter — state is read here, not above
    if (message.role === "user") return <MyUserMessage />;
    return <MyAssistantMessage />;
  }}
</ThreadPrimitive.Messages>
```
