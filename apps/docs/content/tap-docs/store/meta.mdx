---
title: 元数据
description: 通过 source 和 query 跟踪作用域来源。
---

每个作用域访问器都有三个元数据属性：`source` 和 `query` 描述作用域的来源，`name` 是作用域自身的名称。它们是保留名称——作用域方法不能使用这些名称。

```tsx
aui.thread.source; // "root" | "parentScope" | null
aui.thread.query; // {} | { index: 0 } | null
aui.thread.name; // "thread"
```

## 根作用域

当你通过 provider 的 `AuiConfig({ ... })` 直接填充作用域时，它会获得 `source: "root"` 和一个空的 `query`：

```tsx
const config = AuiConfig({ thread: ThreadResource() });

<AuiProvider config={config}>

aui.thread.source; // "root"
aui.thread.query; // {}
```

这是默认情况——该作用域是直接提供的，而不是从其他作用域派生而来。

## 派生作用域

当通过 `Derived` 创建作用域时，其 `source` 会指向派生它的父作用域，而 `query` 则携带查找参数：

```tsx
const aui = useAui();
const config = AuiConfig({
  message: Derived({
    source: "thread",
    query: { index: 0 },
    get: (aui) => aui.thread.message({ index: 0 }),
  }),
});

<AuiProvider extends={aui} config={config}>

aui.message.source; // "thread"
aui.message.query; // { index: 0 }
```

你可以在 `ScopeRegistry` 中声明预期的元数据结构：

```ts
declare module "@assistant-ui/store" {
  interface ScopeRegistry {
    message: {
      methods: {
        getState: () => { role: string; content: string };
      };
      meta: { source: "thread"; query: { index: number } };
    };
  }
}
```

这样可以明确 `source` 和 `query` 的类型——TypeScript 会强制要求，任何提供 `message` 作用域的 `Derived` 都必须使用正确的 source 和 query 结构。

## 不可用的作用域

当当前组件上方没有任何 `AuiProvider` 提供某个作用域时，其访问器的 `source: null` 和 `query: null`。`name` 仍会响应；调用该访问器或读取任何其他属性都会抛出异常：

```tsx
aui.message.source; // null — no message scope in context
aui.message.query; // null
aui.message.name; // "message"
aui.message.getState(); // throws
```

访问器本身始终为真值，因此 `if (aui.message)` 无法提供任何信息。请通过 `optional` 视图检查可用性；对于不可用的作用域，它会解析为 `undefined`：

```tsx
if (aui.optional.message) {
  // scope is available
}
```

## 总结

| `source` | 含义 |
| --- | --- |
| `"root"` | 作用域通过 `AuiConfig({ ... })` 直接填充 |
| `"parentScope"` | 作用域通过 `Derived` 从其他作用域派生而来 |
| `null` | 作用域在当前上下文中不可用 |
