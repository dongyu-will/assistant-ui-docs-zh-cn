## resource

将 Hook 转换为资源工厂。

```ts
function resource<R, A extends readonly unknown[]>(
  hook: (...args: A) => R,
): Resource<R, A>;
```

Hook 应使用以 **`use` 开头的名称**，以便 Hooks 规则检查其
函数体。

```ts
import { resource } from "@assistant-ui/tap";
import { useState } from "react";

const useCounter = (props: { initialValue: number }) => {
  const [count, setCount] = useState(props.initialValue);
  return { count, increment: () => setCount((c) => c + 1) };
};

const Counter = resource(useCounter);
```

调用该工厂会生成一个 [`ResourceElement`](#resourceelement)。

## withKey

为资源元素或资源工厂附加一个 key。

```ts
function withKey<E extends ResourceElement<any>>(
  key: string | number,
  element: E,
  deps?: readonly unknown[],
): E;

function withKey<F extends Resource<any, any[]>>(
  key: string | number,
  resource: F,
): F;
```

带 key 的元素会在
[`useResources`](#useresources) 中保留其身份。同一列表中的 key 必须唯一。

```ts
import { withKey } from "@assistant-ui/tap";

const element = withKey("my-key", Counter({ initialValue: 0 }));
```

<Callout type="warn">
将资源工厂传递给 `withKey` 属于实验性功能，未来可能变更。
</Callout>

传递资源工厂会返回一个工厂，为其创建的每个元素添加该 key：

```ts
const KeyedCounter = withKey("my-key", Counter);
const element = KeyedCounter({ initialValue: 0 });
```

<Callout type="warn">
将 `deps` 传递给 `withKey` 属于实验性功能，未来可能变更。
</Callout>

可选的 `deps` 数组仅适用于元素。在 `useResources` 中，依赖项未变化的
元素可以复用其上一次提交的值，而无需再次渲染。状态更新和上下文变化仍会触发其渲染。

## Hooks

在资源函数体内使用 React 自带的 Hooks，这些 Hooks 从 `"react"` 导入：
`useState`、`useReducer`、`useEffect`、`useMemo`、`useCallback`、`useRef`、
`useLayoutEffect`、`useInsertionEffect`、`useEffectEvent`、
`useSyncExternalStore`、`useDebugValue`、`useContext` 和 `use`（仅限 tap 上下文 — 不支持
promise）。它们遵循 React 的 Hooks 规则，但存在一些
[差异](/tap/docs/tap/differences-from-react)。由
React Compiler 编译的 Hooks 同样有效：tap 实现了编译器的 memo-cache 原语。

其余 React Hooks 不支持在资源函数体内使用：`useId`、
`useTransition`、`useDeferredValue`、`useImperativeHandle`、`useOptimistic`、
以及 `useActionState`。在资源内部调用其中任何一个都会抛出一个 `TypeError`，其中包含
该 Hook 的名称，例如 `useId is not a function`。这只限制
资源函数体本身：承载资源的 React 组件仍然可以在并发功能（例如 `useDeferredValue`）
中包装 `useResource`
（[生命周期](/tap/docs/tap/lifecycle)）。

以下 Hooks 由 tap 导出。

## useResource

承载单个资源元素并返回其值。它既可以在 React 组件中使用，也可以在另一个资源中使用。

```ts
function useResource<V>(element: ResourceElement<V>): V;
```

```ts
const value = useResource(Counter({ initialValue: 0 }));
```

## useResources

承载资源元素的动态列表，并按相同顺序返回它们的值。每个元素都必须通过
[`withKey`](#withkey) 附加唯一的 key。它既可以在 React 组件中使用，也可以在另一个
资源中使用。

```ts
function useResources<V>(
  elements: readonly ResourceElement<V>[],
): V[];
```

```ts
const values = useResources(
  items.map((item) => withKey(item.id, Item({ text: item.text }))),
);
```

## useTapRoot

在可订阅边界后承载渲染回调。它返回稳定的根句柄，而不是渲染值，并且既可以在 React 组件中使用，也可以在另一个资源中使用。

```ts
function useTapRoot<R>(render: () => R): {
  getValue(): R;
  subscribe(listener: () => void): () => void;
};
```

请使用命名函数，以便 Hooks 规则检查回调函数体。请参阅
[树与重新渲染](/tap/docs/tap/trees-and-rerenders#separate-scheduling-with-usetaproot)。

```ts
const handle = useTapRoot(function CounterRoot() {
  return useResource(Counter({ initialValue: 0 }));
});
handle.getValue();
handle.subscribe(() => {});
```

## useTapHost

在 React 组件内承载资源渲染回调。

```ts
function useTapHost<R>(render: () => R): {
  value: R;
  effects: () => void;
};
```

资源会与组件一起渲染，并在被动 effect 中提交。
`effects` 是每次渲染的提交回调，而不是 Hook。宿主会
自动调用它。后代还可以将其传递给无依赖项的 `useEffect`，
以便在该后代的其他 effect 之前提交；第一次调用会提交
此次渲染。

```tsx
function CounterProvider({ children }: { children: ReactNode }) {
  const { value, effects } = useTapHost(function CounterHost() {
    return useResource(Counter({ initialValue: 0 }));
  });
  return (
    <CounterContext.Provider value={value}>
      <TapEffects effects={effects} />
      {children}
    </CounterContext.Provider>
  );
}

function TapEffects({ effects }: { effects: () => void }) {
  useEffect(effects);
  return null;
}
```

## createTapRoot

[在 React 外部](/tap/docs/tap/outside-react)承载渲染回调。

```ts
function createTapRoot<R>(
  render: () => R,
  options?: { mountOnSubscribe?: boolean },
): {
  getValue(): R;
  subscribe(listener: () => void): () => void;
  unmount(): void;
};
```

```ts
const root = createTapRoot(function CounterRoot() {
  return useResource(Counter({ initialValue: 0 }));
});
root.getValue();
root.subscribe(() => {});
root.unmount();
```

使用 `mountOnSubscribe: true` 时，生命周期会改为由订阅者决定：
根会在第一次 `getValue()` 或 `subscribe()` 时延迟渲染，
effect 会在第一个订阅者附加时提交；最后一个取消订阅者完成取消订阅后，根会在下一次调度器刷新时软卸载 — effect
清理函数会运行，但状态会保留，下一个订阅者会重新挂载它。
由于卸载会延迟执行，同一 tick 内先取消订阅再重新订阅（React StrictMode 的订阅反弹、`useSyncExternalStore`
变动，或订阅组件重新挂载）会在不触及 effect 的情况下被吸收。`unmount()` 在此模式下会抛出异常。

## flushTapSync

运行回调，并同步刷新该回调所调度的 tap 更新。返回
回调的返回值。

```ts
function flushTapSync<T>(callback: () => T): T;
```

这适用于由 `createTapRoot` 或 `useTapRoot` 创建的 tap 调度树。
对于直接在 React 中承载的资源，请使用来自 `react-dom` 的 `flushSync`。

```ts
flushTapSync(() => handle.getValue().increment());
```

## 上下文

使用来自 `"react"` 的 `createContext` 创建[上下文](/tap/docs/tap/context)。
使用来自 `"react"` 的 `use` 或 `useContext` 读取它。

```ts
const ThemeContext = createContext("light");
```

## useContextProvider

向回调内部渲染的每个资源提供 React 上下文值，并返回回调的值。

```ts
function useContextProvider<T, R>(
  context: React.Context<T>,
  value: T,
  render: () => R,
): R;
```

```ts
useContextProvider(ThemeContext, "dark", () => useResource(Button()));
```

## 类型

### Resource

```ts
type Resource<R, A extends readonly unknown[] = any[]> = (
  ...args: A
) => ResourceElement<R>;
```

由 `resource()` 返回的工厂。`R` 是 Hook 的返回值，`A` 是
其参数元组。对于只有一个 props 对象的 Hook，`A` 是 `[Props]`。

### ResourceElement

```ts
type ResourceElement<R> = {
  readonly hook: (...args: any[]) => R;
  readonly args: readonly unknown[];
  readonly key?: string | number;
  readonly deps?: readonly unknown[];
};
```

要承载的资源的非活动描述。`resource()` 提供 `hook` 和
`args`；[`withKey`](#withkey) 可以添加 `key` 和 `deps`。
