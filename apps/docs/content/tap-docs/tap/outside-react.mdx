description: 独立运行资源，无需 React 树。
---

资源无需依赖 React。`createTapRoot` 以命令式方式承载资源树，这也是库和测试驱动资源的方式，以及 `@assistant-ui/store` 将资源桥接到 React 的方式。

## createTapRoot

```ts
import { createTapRoot, useResource } from "@assistant-ui/tap";

const root = createTapRoot(function CounterRoot() {
  return useResource(Counter({ initialValue: 0 }));
});

// read the current value
root.getValue().count; // 0

// subscribe to changes
const unsubscribe = root.subscribe(() => {
  console.log(root.getValue().count);
});

// call methods
root.getValue().increment();

// clean up
root.unmount();
```

`createTapRoot(callback)` 将回调作为根的渲染主体运行，你可以在其中调用 `useResource` 来承载资源。它返回一个稳定的 `{ getValue, subscribe, unmount }` 对象：`getValue()` 读取资源当前的返回值，`subscribe(callback)` 在返回值变化时触发，而 `unmount()` 则卸载整棵树。

使用 `createTapRoot(callback, { mountOnSubscribe: true })` 时，生命周期由订阅者决定，而不是由调用方管理：第一个订阅者会挂载树，最后一个取消订阅者会软卸载树（状态会为下一个订阅者保留），而 `unmount()` 会抛出错误。完整契约请参阅 [API 参考](/tap/docs/tap/api-reference#createtaproot)。

## 调度与刷新

更新的交付方式取决于承载树的宿主：

| 宿主 | 调度器 | 更新通过以下方式交付 |
| --- | --- | --- |
| `useResource` | React | React 重新渲染 |
| `useTapRoot` | tap | `.subscribe()` |
| `createTapRoot` | tap | `root.subscribe()` |

tap 调度器会批处理状态变化：同一个同步代码块中的多个 setter 只会产生一次重新渲染。如果更新持续触发更多更新（例如，会设置状态的 effect），tap 最多会刷新 50 次，之后抛出最大更新深度错误。

### flushTapSync

`flushTapSync` 会同步刷新待处理的 tap 调度更新，因此新状态可以立即读取。

```ts
import { flushTapSync } from "@assistant-ui/tap";

flushTapSync(() => root.getValue().increment());
console.log(root.getValue().count); // already updated
```

这适用于由 tap 调度的树（`createTapRoot` / `useTapRoot`）。对于 `useResource` 树，请改用来自 `react-dom` 的 `flushSync`。当库需要同步结果时，这一功能非常有用，例如受控输入需要在 `onChange` 处理程序中更新其存储。

## React 互操作

当资源在 React 内部通过 `useResource` 承载时，tap 会与 React 的调度器集成：

- **并发功能**（`startTransition`、`useDeferredValue`、`<Suspense>`）可以在不发生撕裂的情况下运行。
- **`<Activity>`**：资源隐藏期间到达的更新会被跟踪，并在资源再次可见时重放。
- **严格模式**会继承自外围的 `<StrictMode>`。

无需进行特殊配置。

<Callout type="warn">
`@assistant-ui/store` 通过 `useSyncExternalStore` 将资源桥接到 React，因此这些读取会触发同步重新渲染，并退出并发调度。
这一行为未来版本可能会改变。
</Callout>
