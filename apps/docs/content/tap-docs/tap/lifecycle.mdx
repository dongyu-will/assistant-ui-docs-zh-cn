## 渲染与提交

与 React 一样，tap 将工作拆分为两个阶段：

1. **渲染**：资源函数运行，Hook 记录其数据，并生成返回值。此阶段不会产生副作用。
2. **提交**：依赖发生变化的 effect 运行。如果 effect 正在重新运行，则会先执行其之前的清理函数。资源在此阶段之后被视为已挂载。

```ts
import { resource } from "@assistant-ui/tap";
import { useState, useEffect } from "react";

const useApp = () => {
  // --- render phase ---
  const [count, setCount] = useState(0);

  useEffect(() => {
    // --- commit phase ---
    console.log(`Mounted with count: ${count}`);
    return () => console.log("Cleaned up");
  }, [count]);

  return { count };
};

const App = resource(useApp);
```

### Effect 执行顺序

在 React 中，effect 按照先子组件、后父组件的顺序运行（由内向外）。这是因为组件只能通过返回子组件来渲染它们，无法在子组件的 effect 执行后再运行 effect。

在 tap 中，**effect 按照它们在渲染过程中被调用的确切顺序运行**。由于 `useResource` 只是另一个 Hook，因此你可以将 `useEffect` 调用放在它之前或之后：

```ts
import { resource, useResource } from "@assistant-ui/tap";
import { useEffect } from "react";

const useParent = () => {
  useEffect(() => {
    console.log("1: before child");
  });

  const child = useResource(Child());

  useEffect(() => {
    console.log("3: after child");
  });

  return child;
};

const Parent = resource(useParent);

const useChild = () => {
  useEffect(() => {
    console.log("2: child");
  });
};

const Child = resource(useChild);
// Mount order: 1, 2, 3
```

这是有意为之的，它允许你在子组件之前和之后运行设置逻辑。当父资源需要响应子资源提供的数据时，这一特性非常有用。

卸载时的清理操作按照与挂载相同的顺序运行（FIFO），与 effect 最初注册的顺序一致。

## 挂载与卸载

资源在首次提交后被**挂载**。此时，effect 已经运行，资源处于活动状态。

当资源的所有者移除资源时，资源会被**卸载**，所有 effect 清理函数都会运行，资源也会被释放。以下情况会自动触发这一过程：

- 父资源通过 `useResource` 停止渲染子资源
- 使用 `useResource` 的 React 组件卸载
- 在 `createTapRoot` 根上调用 `root.unmount()`

## 并发模式

Tap 与 React 的并发模式完全互操作。通过 `useResource` 渲染的资源可以与 `startTransition`、`useDeferredValue`、`<Suspense>` 以及其他并发特性正确协作，状态更新能够一致地应用，不会出现撕裂。

<Callout type="warn">
`@assistant-ui/store` 层目前依赖 `useSyncExternalStore` 将 tap 资源桥接到 React。这意味着 store 订阅始终会触发同步重新渲染，使这些读取退出并发调度。未来版本可能会改变这一行为。
</Callout>

## Offscreen / Activity

当资源被 `<Activity mode="hidden">` 隐藏时，隐藏期间到达的状态更新会被跟踪，并在资源重新可见后重放。无需进行任何配置。

当 `createTapRoot` 根使用 `mountOnSubscribe: true`，且其订阅者数量降为零时，也遵循相同的模型：
effect 清理函数会运行，状态会被保留，下一个订阅者会重新挂载整棵树——就像 Activity 在隐藏和重新可见之间切换一样。

## 严格模式

在开发环境中，资源在挂载时会渲染两次，以便暴露渲染过程中的副作用，这与 React 的 `<StrictMode>` 相同。

- **`useResource`** 继承周围的 `<StrictMode>`。
- **`createTapRoot`** 会在开发环境中自动启用该模式。
