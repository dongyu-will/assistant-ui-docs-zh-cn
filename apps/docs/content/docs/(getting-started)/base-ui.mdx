shadcn/ui 为两个无头库 Radix UI 和 Base UI 提供所有组件。`npx shadcn init` 从 2026 年 7 月起，新项目默认使用 Base UI 样式。以 `base-` 开头的样式名称（例如 `base-nova`）会选择 Base UI 风格；其他所有样式名称都会选择 Radix。

## 组件注册表

assistant-ui 的组件注册表通过同一主机提供这两种风格。在 `components.json` 中配置样式感知 URL：

```json title="components.json"
{
  "registries": {
    "@assistant-ui": "https://r.assistant-ui.com/styles/{style}/{name}.json"
  }
}
```

shadcn CLI 会根据你的 `components.json` `style` 字段填充 `{style}`。名称以 `base-` 开头的样式会获得 Base UI 风格的组件；其他所有样式会获得 Radix 风格的组件。普通的 `https://r.assistant-ui.com/{name}.json` 形式仍可作为 Radix 回退方案使用。

## 兼容性原理

assistant-ui 的无头原语（从 `@assistant-ui/react` 导出的组件）接受两种组合约定：Radix 的 `asChild` 属性和 Base UI 的 `render` 属性。大多数组件注册表组件只组合这些原语，因此同一份实现即可在两种风格下正确渲染，注册表不需要单独的变体。

打开状态样式和面板高度动画同样不需要变体：组件库通过同时匹配两个库的数据属性的自定义变体来设置状态样式，并通过读取两个库高度变量的关键帧为可折叠组件添加动画，因此 `reasoning`、`tool-group` 和 `tool-fallback` 等组件可以使用同一份源代码服务两种风格。

涉及库特定表面、超出组合范围的组件（原始原语导入、触发器组合、Provider wiring、弹出层重新组合）则会提供专用的 Base UI 变体。目前具有此类变体的组件包括：`tooltip-icon-button`、`attachment`、`context-display`、`message-timing`、`mcp-config`、`threadlist-sidebar`、`assistant-modal`、`select`、`tabs`、`accordion`、`badge`、`model-selector` 和 `direction`。

## 行为说明

在 Base UI 样式下，助手模态框组合项目的 Base UI 弹出层，因此堆叠的层（附件预览对话框、工具提示和模态框本身）会在每次按下 Escape 键时关闭一层，并将焦点恢复到打开已关闭层的元素。点击模态框外部会使其保持打开，这与 Radix 风格的行为一致。

## 常见问题

- **现有的 Radix 项目需要更改任何内容吗？** 不需要。普通的 `https://r.assistant-ui.com/{name}.json` URL 仍会解析到 Radix 风格的组件，因此现有设置无需任何更改。
- **如果之后切换样式会发生什么？** 通过 shadcn CLI 重新添加你使用的组件。样式感知 URL 会根据新样式解析到正确的风格，无需执行其他迁移步骤。
- **`@assistant-ui/react` 在 Base UI 下的行为会有所不同吗？** 不会。无头 `@assistant-ui/react` 包在两种环境中的工作方式完全相同；只有 `components/assistant-ui` 下的注册表组件会因风格而异。
