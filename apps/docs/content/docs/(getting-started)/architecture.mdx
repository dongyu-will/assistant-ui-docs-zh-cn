### 1. 前端组件
构建于 Shadcn 组件之上的风格化且功能完善的聊天组件，其上下文状态管理由 assistant-ui 运行时提供程序提供。这些预构建的 React 组件具备智能状态管理。[查看我们的组件](/elements/thread)

### 2. 运行时
用于助手聊天的 React 状态管理上下文。运行时负责在本地状态与后端及 LLM 调用之间进行数据转换。我们提供了适用于不同框架的多种运行时解决方案，例如 Vercel AI SDK、LangGraph、LangChain、Helicone、本地运行时，以及在需要完全控制前端消息状态时使用的 ExternalStore。[查看我们支持的运行时](/docs/runtimes/pick-a-runtime)

### 3. Assistant Cloud
通过完善的线程管理和消息历史记录增强助手体验的托管服务。Assistant Cloud 会存储完整的消息历史记录，自动持久化线程，支持人在回路（human-in-the-loop）工作流，并与常见的身份验证提供商集成，让用户可以在任意时刻无缝恢复对话。[Cloud 文档](/docs/cloud)


## 每一层负责什么

在选择运行时或连接组件之前，了解每一层负责哪些职责会很有帮助。assistant-ui 明确划分了渲染、对话状态以及模型实际运行位置之间的边界。

### UI 层
原语和预构建组件负责渲染助手体验：线程、消息、输入框、消息部分、操作、附件和建议。它们通过运行时上下文读写状态，而不是直接操作后端或模型。

### 运行时层
UI 与后端之间的状态和行为边界。运行时负责管理或适配对话状态：消息、线程状态、输入框状态、运行生命周期、分支、编辑和重新生成。不同的运行时之所以存在，是因为不同后端管理这些状态的方式不同。`LocalRuntime`将状态保存在内部；`ExternalStoreRuntime`则将状态管理委托给你的存储。

### 后端 / agent 层
生成助手输出并实现应用特定的行为。根据运行时和协议的不同，后端可能会发出文本、消息部分、工具调用、元数据、agent 状态、附件或其他事件，运行时会将这些内容映射为 UI 状态。

### 集成 / 协议层
运行时适配器和协议将 assistant-ui 与不同形态的后端连接起来：AI SDK、LangGraph、LangChain、ADK、A2A、AG-UI、OpenCode 或你自己的后端。DataStream 和 AssistantTransport 协议让通用后端能够与 assistant-ui 通信，而无需为每个应用编写自定义适配器。

### 持久化层
线程和消息历史记录可以由 Assistant Cloud 存储，也可以通过线程和历史记录适配器存储在你自己的数据库中。持久化与渲染及后端生成相互独立，但运行时会与持久化层协调工作。
