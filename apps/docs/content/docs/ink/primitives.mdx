---
title: 原语
description: 使用 Ink 构建聊天 UI 的可组合终端组件。
---

原语是对 Ink 组件（`Box`、`Text`）的轻量封装，可与 assistant-ui 运行时集成。它们接受所有标准 Ink props，并添加感知运行时的行为。

原语使用命名空间导入，与 Web 包采用相同模式（例如 `ThreadPrimitive.Root`、`ComposerPrimitive.Input`）。

许多原语通过 `@assistant-ui/core/react` 与 `@assistant-ui/react` 共享核心逻辑，区别仅在于 UI 层（Ink 与 DOM）。

## Thread

```tsx
import { ThreadPrimitive } from "@assistant-ui/react-ink";
```

### Root

线程区域的容器 `Box`。

```tsx
<ThreadPrimitive.Root>
  {children}
</ThreadPrimitive.Root>
```

| Prop | Type | Description |
|------|------|-------------|
| `...rest` | `BoxProps` | 标准 Ink Box props |

### Messages

渲染消息列表并自动集成运行时。每条消息都包装在一个作用域上下文中，因此 `useAuiState((s) => s.message)` 可以在消息组件内部使用。

```tsx
<ThreadPrimitive.Messages>
  {() => <MyMessage />}
</ThreadPrimitive.Messages>
```

| Prop | Type | Description |
|------|------|-------------|
| `components` | `MessageComponents` | 包含 `Message`、`UserMessage`、`AssistantMessage`、`SystemMessage` 和编辑输入框变体的组件映射 |

### AuiIf

基于助手状态进行条件渲染。替代已弃用的 `ThreadPrimitive.Empty`、`ThreadPrimitive.If`、`MessagePrimitive.If` 和 `ComposerPrimitive.If`。

```tsx
import { AuiIf } from "@assistant-ui/react-ink";

<AuiIf condition={(s) => s.thread.isEmpty}>
  <Text dimColor>Send a message to get started</Text>
</AuiIf>

<AuiIf condition={(s) => s.thread.isRunning}>
  <Text color="yellow">Generating...</Text>
</AuiIf>
```

| Prop | Type | Description |
|------|------|-------------|
| `condition` | `(state) => boolean` | 用于确定是否渲染子元素的选择器 |

### Empty（已弃用）

  已弃用。请改用带有 `condition={(s) => s.thread.isEmpty}` 的 `AuiIf`。
</Callout>

仅在线程没有消息时渲染子元素。

```tsx
<ThreadPrimitive.Empty>
  <Text dimColor>Send a message to get started</Text>
</ThreadPrimitive.Empty>
```

### MessageByIndex

低级 provider，根据索引为特定消息设置消息上下文。由 `ThreadPrimitive.Messages` 内部使用。

```tsx

</ThreadPrimitive.MessageByIndex>
```

| Prop | Type | Description |
|------|------|-------------|
| `index` | `number` | 从零开始的消息索引 |

### Suggestions

使用提供的组件渲染线程中的所有建议。每条建议都包装在 `SuggestionByIndexProvider` 上下文中。

```tsx
<ThreadPrimitive.Suggestions>
  {() => <MySuggestion />}
</ThreadPrimitive.Suggestions>
```

| Prop | Type | Description |
|------|------|-------------|
| `children` | `() => ReactElement` | 为每条建议调用的渲染函数 |

### SuggestionByIndex

低级 provider，根据索引为特定建议设置建议上下文。由 `ThreadPrimitive.Suggestions` 内部使用。

```tsx
<ThreadPrimitive.SuggestionByIndex index={0}>
  <SuggestionPrimitive.Title />
</ThreadPrimitive.SuggestionByIndex>
```

| Prop | Type | Description |
|------|------|-------------|
| `index` | `number` | 从零开始的建议索引 |

### Suggestion

渲染建议按钮。使用 Ink `Box` + `Text`。

```tsx
<ThreadPrimitive.Suggestion
  prompt="What is the weather?"
  send
/>
```

| Prop | Type | Description |
|------|------|-------------|
| `prompt` | `string` | 建议文本 |
| `send` | `boolean` | 为 true 时自动发送消息 |
| `clearComposer` | `boolean` | 为 true（默认值）时替换输入框文本；为 false 时追加文本 |

## Loading

```tsx
import { LoadingPrimitive } from "@assistant-ui/react-ink";
```

用于活动运行的可组合加载 UI。`LoadingPrimitive.Root` 仅在线程运行期间渲染，因此很适合与终端聊天布局中的状态行搭配使用。

```tsx
<LoadingPrimitive.Root gap={1}>
  <LoadingPrimitive.Spinner variant="bar" />
  <LoadingPrimitive.Text>Analyzing codebase...</LoadingPrimitive.Text>
  <LoadingPrimitive.ElapsedTime />
</LoadingPrimitive.Root>
```

助手进行流式输出时，该组件会渲染类似 `[=== ] Analyzing codebase... (3s)` 的紧凑状态行。

### Root

感知运行时的 `Box` 容器，仅在 `s.thread.isRunning` 为 true 时渲染子元素。

| Prop | Type | Description |
|------|------|-------------|
| `children` | `ReactNode` | 状态行内容 |
| `...rest` | `BoxProps` | 标准 Ink Box props |

### Spinner

动画加载指示器。支持现有的 `ink-spinner` 路径，以及一些内置的基于文本的变体，以实现更符合终端风格的样式。

| Prop | Type | Description |
|------|------|-------------|
| `variant` | `"spinner" \| "dots" \| "pulse" \| "bar" \| "bounce"` | 加载器样式（默认值：`"spinner"`） |
| `type` | `ink-spinner` 类型 | `variant="spinner"` 时使用的 Spinner 预设 |
| `intervalMs` | `number` | 非 Spinner 变体的动画速度（默认值：`120`） |
| `...rest` | `TextProps` | 标准 Ink Text props |

### Text

以 Ink `Text` 渲染的状态标签。

| Prop | Type | Description |
|------|------|-------------|
| `children` | `ReactNode` | 消息文本（默认值：`"Thinking..."`） |
| `...rest` | `TextProps` | 标准 Ink Text props |

### ElapsedTime

当前运行的已用时间指示器。如果可用，则使用消息计时元数据；否则回退到本地计时器，因此在手动测试期间也能正常工作。

| Prop | Type | Description |
|------|------|-------------|
| `format` | `(seconds: number) => string` | 已用时间标签的自定义格式化函数 |
| `...rest` | `TextProps` | 标准 Ink Text props |

## Composer

```tsx
import { ComposerPrimitive } from "@assistant-ui/react-ink";
```

### Root

输入框区域的容器 `Box`。

```tsx
<ComposerPrimitive.Root>
  {children}
</ComposerPrimitive.Root>
```

### Input

与输入框运行时连接的终端行编辑器。值会自动管理，并支持感知光标的编辑。

```tsx
<ComposerPrimitive.Input
  submitOnEnter
  multiLine
  placeholder="Type a message..."
  autoFocus
/>
```

| Prop | Type | Description |
|------|------|-------------|
| `submitOnEnter` | `boolean` | Enter 是否发送消息（默认值：`false`） |
| `placeholder` | `string` | 为空时显示的占位文本 |
| `autoFocus` | `boolean` | 挂载时自动聚焦 |
| `multiLine` | `boolean` | 为 true 时，Enter 插入换行，除非启用了 `submitOnEnter` |
| `onSubmit` | `(text: string) => void` | 覆盖默认发送行为，并接收当前输入框文本 |

支持的键盘绑定：

| Key | Action | Context |
|-----|--------|---------|
| `Left` / `Right` | 将光标移动一个字素 | 始终 |
| `Backspace` / `Delete` | 删除光标前/后的字素 | 始终 |
| `Home` / `End` | 跳转到缓冲区或行边界 | 单行时为缓冲区，多行时为行 |
| `Up` / `Down` | 在行之间移动，并尽可能保留列位置 | 仅多行 |
| `Ctrl+A` / `Ctrl+E` | 移动到行首/行尾 | 始终 |
| `Ctrl+W` | 删除光标前的单词 | 始终 |
| `Ctrl+D` | 删除光标后的字素 | 始终 |
| `Ctrl+U` / `Ctrl+K` | 删除从光标到行首/行尾的内容；多行时，`Ctrl+K` 在行尾会连接下一行 | 始终 |
| `Ctrl+J` | 插入换行 | 仅多行；单行时会吞掉该输入，因此不会提交 |
| `Alt+B` / `Alt+F` | 向前/向后按单词移动 | 会发出 meta-key 序列的终端 |
| `Alt+D` | 删除光标后的单词 | 会发出 meta-key 序列的终端 |
| `Shift+Enter` | 插入换行 | 多行提交模式，以及能够区分该输入的终端 |

单词边界和字素移动使用 `Intl.Segmenter`，因此 emoji、重音字母、肤色修饰符、ZWJ 序列和 CJK 表意文字都会作为单个字符移动和删除。

部分绑定取决于终端能力。iTerm2、Windows Terminal 和大多数 Linux 终端会将 `Alt`-字母组合发出为带 `Esc` 前缀的序列，Ink 会将其解码为 meta-key 输入；macOS Terminal.app 需要先在偏好设置中启用“Use Option as Meta key”，`Alt+B` / `Alt+F` / `Alt+D` 才能按预期工作。`Shift+Enter` 要求终端支持 CSI-u 协议（iTerm2 3.4+、kitty、foot 及类似终端）；将其与 `Enter` 混淆的终端会回退到 `submitOnEnter` 行为。

自定义提交处理示例：

```tsx
<ComposerPrimitive.Input
  multiLine
  submitOnEnter
  onSubmit={(text) => {
    console.log("submit", text);
  }}
/>
```

### Queue

渲染所有排队的输入框项目。每个项目都包装在 `QueueItemByIndexProvider` 中，因此 `QueueItemPrimitive.*` 可以在 render prop 中读取项目状态并调用队列操作。底层使用来自 `@assistant-ui/core/react` 的共享 `ComposerPrimitiveQueue`。

```tsx
<ComposerPrimitive.Queue>
  {({ queueItem }) => (
    <Box>
      <QueueItemPrimitive.Text />
      <QueueItemPrimitive.Steer>
        <Text color="cyan">[Run Now]</Text>
      </QueueItemPrimitive.Steer>
      <QueueItemPrimitive.Remove>
        <Text color="red">[x]</Text>
      </QueueItemPrimitive.Remove>
    </Box>
  )}
</ComposerPrimitive.Queue>
```

| Prop | Type | Description |
|------|------|-------------|
| `children` | `(value: { queueItem: QueueItemState }) => ReactNode` | 为每个队列项目调用的渲染函数 |

| `...rest` | `BoxProps` | 标准 Ink Box props |

## Message

```tsx
import { MessagePartPrimitive, MessagePrimitive } from "@assistant-ui/react-ink";
```

### Root

单条消息的容器 `Box`。

```tsx
<MessagePrimitive.Root>
  {children}
</MessagePrimitive.Root>
```

### Parts

通过 `components` prop 渲染消息内容部分。工具调用和数据部分会自动渲染已注册的 toolkit 渲染器和数据 UI（通过 `useAssistantDataUI`），并在必要时回退到此处提供的组件。默认提供适用于终端的文本、推理、来源、图像、文件和数据部分渲染器。

```tsx
<MessagePrimitive.Parts>
  {({ part }) => {
    if (part.type === "text") return <Text>{part.text}</Text>;
    if (part.type === "tool-call") return <Text dimColor>[Tool: {part.toolName}]</Text>;
    return null;
  }}
</MessagePrimitive.Parts>
```

需要更丰富的终端 UI 时，可以使用应用自有组件覆盖部分渲染：

```tsx
<MessagePrimitive.Parts
  components={{
    Image: () => <Text color="cyan">image available</Text>,
    Reasoning: () => null,
    data: {
      by_name: {
        weather_card: ({ data }) => <Text>{data.city}: {data.temperature}</Text>,
      },
    },
  }}
/>
```

### Content（已弃用）

<Callout type="warn">
  已弃用。请改用 `MessagePrimitive.Parts`。详情请参阅 [v0.11 迁移指南](/docs/migrations/v0-11)。
</Callout>

使用 render props 渲染消息内容部分。工具调用和数据部分会自动渲染已注册的 toolkit 渲染器和数据 UI（通过 `useAssistantDataUI`）；如果提供了 render props，则回退到这些 render props。

```tsx
<MessagePrimitive.Content
  renderText={({ part }) => <Text>{part.text}</Text>}
  renderToolCall={({ part }) => <Text dimColor>[Tool: {part.toolName}]</Text>}
/>
```

| Prop | Type | Description |
|------|------|-------------|
| `renderText` | `(props: { part; index }) => ReactElement` | 文本部分渲染器 |
| `renderToolCall` | `(props: { part; index }) => ReactElement` | 工具调用回退渲染器 |
| `renderImage` | `(props: { part; index }) => ReactElement` | 图像部分渲染器 |
| `renderReasoning` | `(props: { part; index }) => ReactElement` | 推理部分渲染器 |
| `renderSource` | `(props: { part; index }) => ReactElement` | 来源部分渲染器 |
| `renderFile` | `(props: { part; index }) => ReactElement` | 文件部分渲染器 |
| `renderData` | `(props: { part; index }) => ReactElement` | 数据部分回退渲染器 |

## MessagePartPrimitive

用于在由 `MessagePrimitive.Parts`、`MessagePrimitive.PartByIndex` 或 `PartByIndexProvider` 提供的部分上下文中渲染当前消息部分的可组合原语。

```tsx
<MessagePrimitive.Parts
  components={{
    Text: () => (
      <>
        <MessagePartPrimitive.Text />
        <MessagePartPrimitive.InProgress>
          <Text color="yellow"> ...</Text>
        </MessagePartPrimitive.InProgress>
      </>
    ),
    File: () => <MessagePartPrimitive.File dimColor />,
  }}
/>
```

| Primitive | 默认终端行为 |
|-----------|-----------|
| `MessagePartPrimitive.Text` | 使用 Ink `<Text>` 渲染文本 |
| `MessagePartPrimitive.InProgress` | 仅在当前部分状态为 `running` 时渲染子元素 |
| `MessagePartPrimitive.Image` | 渲染 `[image: filename]` 或 `[image]`；不会发出图像数据或终端图像协议 |
| `MessagePartPrimitive.File` | 渲染 `[file: filename mimeType]` 或 `[file: mimeType]`；不会打印文件数据 |
| `MessagePartPrimitive.Source` | 渲染来源标题和/或 URL 元数据 |
| `MessagePartPrimitive.Reasoning` | 默认渲染保守的推理文本；覆盖它或返回 `null` 可抑制渲染 |
| `MessagePartPrimitive.Data` | 没有可用的已注册数据渲染器时渲染 `[data: name]` |

## Attachment

```tsx
import { AttachmentPrimitive } from "@assistant-ui/react-ink";
```

用于渲染单个附件的原语。每个原语都从当前附件上下文读取数据，该上下文由 `ComposerPrimitive.Attachments`、`ComposerPrimitive.AttachmentByIndex`、`MessagePrimitive.Attachments` 或 `MessagePrimitive.AttachmentByIndex` 提供。

### Root

附件的容器 `Box`。转发所有 `Box` props。

| Prop | Type | Description |
|------|------|-------------|
| `children` | `ReactNode` | 附件子组件 |
| `...rest` | `ComponentProps<typeof Box>` | 转发给底层 Ink `Box` |

### Name

显示 `s.attachment.name` 的 `Text` 组件。

| Prop | Type | Description |
|------|------|-------------|
| `...rest` | `ComponentProps<typeof Text>` | 转发给底层 Ink `Text` |

### Thumb

显示附件短标识的 `Text` 组件。如果名称包含文件扩展名，则渲染该扩展名（`.pdf`、`.png`、……）。否则回退到附件 `type`（例如 `image`、`document`），最后回退到 `file`。传入 `children` 可覆盖自动标签。

| Prop | Type | Description |

## TextInput

```tsx
import { TextInput } from "@assistant-ui/react-ink";
```

无需状态存储、由外部控制的单行/多行文本字段。Ink 没有提供原生文本输入，因此这是 DOM `<textarea>` 或 React Native `<TextInput>` 在终端中的等价实现——包含编辑引擎（缓冲区、感知字素的光标以及完整的 emacs/方向键映射），但不耦合任何运行时或输入框逻辑。`ComposerPrimitive.Input` 是对 `TextInput` 的轻量适配器，并将其绑定到输入框 store；当需要在线程输入框之外使用可编辑字段时（例如在确认操作前编辑某个值），请直接使用 `TextInput`。

它通过 `value`/`onChange` 受控，因此外部所有者可以随时覆盖文本（缓冲区会吸收回显，而不会导致光标抖动）。所有者还可以在 `onChange` 中转换发出的文本（转为大写、掩码或拒绝）；缓冲区会应用修正后的值，同时将光标保留在编辑位置，并将其对齐到字素边界。对于不响应编辑的替换（空闲时通过程序设置值），光标仍会置于末尾：

```tsx
const [command, setCommand] = useState(approval.action.command);

<TextInput
  value={command}
  onChange={setCommand}
  submitOnEnter
  onSubmit={(text) => runEdited(text)}
/>
```

| Prop | Type | Description |
|------|------|-------------|
| `value` | `string` | 当前文本（受控） |
| `onChange` | `(text: string) => void` | 缓冲区变化时使用下一段文本调用 |
| `onSubmit` | `(text: string) => void` | 设置了 `submitOnEnter` 时按下 Enter 调用，并传入当前显示的文本；在 `onChange` 中执行验证的所有者也应在 `onSubmit` 中再次验证 |
| `submitOnEnter` | `boolean` | Enter 是否调用 `onSubmit`（默认值：`false`） |
| `placeholder` | `string` | 为空时显示的占位文本（默认值：`""`） |
| `autoFocus` | `boolean` | 挂载时自动聚焦（默认值：`true`） |
| `multiLine` | `boolean` | 为 true 时，Enter 插入换行，除非启用了 `submitOnEnter` |
| `...rest` | `ComponentProps<typeof Box>` | 转发给底层 Ink `Box` |

键盘绑定、字素处理和终端能力注意事项与 [`ComposerPrimitive.Input`](#input) 完全相同。
