## 概览

`@assistant-ui/cloud-ai-sdk` 软件包提供了一个单独的 hook，可为任何 [AI SDK](https://sdk.vercel.ai/) 应用添加完整的消息和线程持久化功能：

- **`useCloudChat`** — 包装 `useChat`，提供自动云端持久化和内置线程管理

此 hook 适用于任何 React UI。你可以完全控制自己的组件。

<Callout type="tip">
  有关与 assistant-ui 原语和运行时的完整集成，请参阅 [AI SDK + assistant-ui](/docs/cloud/ai-sdk-assistant-ui)。
</Callout>

```tsx title="app/page.tsx"
"use client";

import { useState } from "react";
import { useCloudChat } from "@assistant-ui/cloud-ai-sdk";

export default function Chat() {
  // Zero-config: auto-initializes anonymous cloud from env var with built-in threads.
  // For custom config, pass: { cloud, threads: useThreads(...), onSyncError }
  const { messages, sendMessage, threads } = useCloudChat();

  const [input, setInput] = useState("");
  const handleSubmit = () => {
    if (!input.trim()) return;
    sendMessage({ text: input });
    setInput("");
  };

  return (
    <div>
      {/* Thread list */}
      <ul>
        {threads.threads.map((t) => (
          <li key={t.id} onClick={() => threads.selectThread(t.id)}>
            {t.title || "New conversation"}
          </li>
        ))}
        <li onClick={() => threads.selectThread(null)}>New chat</li>
      </ul>

      {/* Chat messages */}
      <div>
        {messages.map((m) => (
          <div key={m.id}>
            {m.parts.map((p) => p.type === "text" && p.text)}
          </div>
        ))}
      </div>

      {/* Composer */}
      <form onSubmit={(e) => { e.preventDefault(); handleSubmit(); }}>
        <input value={input} onChange={(e) => setInput(e.target.value)} />
        <button type="submit">Send</button>
      </form>
    </div>
  );
}
```

## API 参考

### `useCloudChat(options?)`

封装 AI SDK 的 `useChat`，提供自动云端持久化和内置线程管理。消息会在流式传输结束时持久化。首次发送消息时会自动创建线程——此钩子会自动创建线程、选中该线程、刷新线程列表，并在首次响应后生成标题。

#### 配置模式

**1. 零配置** — 设置 `NEXT_PUBLIC_ASSISTANT_BASE_URL` 环境变量，无参数调用：

```tsx
const chat = useCloudChat();
```

**2. 自定义云端实例** — 适用于已认证用户或自定义配置：

```tsx
const cloud = new AssistantCloud({ baseUrl, authToken });
const chat = useCloudChat({ cloud });
```

**3. 外部线程管理** — 当线程需要从独立组件中访问，或需要使用 `includeArchived` 等自定义线程选项时：

```tsx
// In a context provider or parent component
const myThreads = useThreads({ cloud, includeArchived: true });

// Pass to useCloudChat - it will use your thread state
const chat = useCloudChat({ threads: myThreads });
```

#### 参数

| 参数 | 类型 | 描述 |
|-----------|------|-------------|
| `options.cloud` | `AssistantCloud` | 云端实例（可选——如果未提供，则根据 `NEXT_PUBLIC_ASSISTANT_BASE_URL` 环境变量自动创建匿名实例） |
| `options.threads` | `UseThreadsResult` | 来自 `useThreads()` 的外部线程管理。在需要于独立组件中执行线程操作，或需要使用 `includeArchived` 等自定义线程选项时使用 |
| `options.onSyncError` | `(error: Error) => void` | 发生同步错误时调用的回调 |

同时接受部分 [AI SDK `useChat` 选项](https://sdk.vercel.ai/docs/reference/ai-sdk-ui/use-chat) `ChatInit` 中定义的选项）。`useChat` 上提供的某些选项（例如 `experimental_throttle` 和 `resume`）不受支持。

**返回值：** `UseCloudChatResult`

| 值 | 类型 | 描述 |
|-------|------|-------------|
| `messages` | `UIMessage[]` | 聊天消息（来自 AI SDK） |
| `status` | `string` | 聊天状态：`"ready"`、`"submitted"`、`"streaming"` 或 `"error"` |
| `sendMessage` | `(message, options?) => Promise<void>` | 发送消息（如有需要会自动创建线程） |
| `stop` | `() => void` | 停止当前流式传输 |
| `threads` | `UseThreadsResult` | 线程管理（见下文） |

以及 AI SDK 的 [`UseChatHelpers`](https://sdk.vercel.ai/docs/reference/ai-sdk-ui/use-chat). 中的所有其他属性。

**线程管理（`threads`）：**

| 值 | 类型 | 描述 |
|-------|------|-------------|
| `threads.cloud` | `AssistantCloud` | 用于线程操作的云端实例 |
| `threads.threads` | `CloudThread[]` | 按最近使用时间排序的线程；当 `useThreads({ includeArchived: true })` 提供归档线程时，也会包含这些线程 |
| `threads.threadId` | `string \| null` | 当前线程 ID（新建且尚未保存的聊天为 `null`） |
| `threads.selectThread` | `(id: string \| null) => void` | 切换线程，或传入 `null` 以开始新聊天 |
| `threads.isLoading` | `boolean` | 初始加载或刷新期间的 `true` |
| `threads.error` | `Error \| null` | 最近一次错误（如果有） |
| `threads.refresh` | `() => Promise<boolean>` | 重新获取线程列表 |
| `threads.get` | `(id: string) => Promise<CloudThread \| null>` | 根据 ID 获取单个线程 |
| `threads.create` | `(options?: \{ externalId?: string \}) => Promise<CloudThread \| null>` | 创建新线程 |
| `threads.delete` | `(id: string) => Promise<boolean>` | 删除线程 |
| `threads.rename` | `(id: string, title: string) => Promise<boolean>` | 重命名线程 |
| `threads.archive` | `(id: string) => Promise<boolean>` | 归档线程 |
| `threads.unarchive` | `(id: string) => Promise<boolean>` | 取消归档线程 |
| `threads.generateTitle` | `(threadId: string) => Promise<string \| null>` | 使用 AI 生成标题 |

### `useThreads(options)`

用于 `useCloudChat` 的线程列表管理。需要在聊天上下文之外（例如独立的侧边栏组件中）访问线程操作时，显式调用此函数，并将其传递给 `useCloudChat({ threads })`。

```tsx
const myThreads = useThreads({ cloud: myCloud });
const { messages, sendMessage } = useCloudChat({ threads: myThreads });
```

`useThreads` 每页请求 20 个线程，并沿着 Cloud 游标继续请求，直到加载所有匹配的线程。使用 `includeArchived` 时，活动线程和归档线程的页面会并发加载，并在两者都完成后提交完整列表。

**参数：**

| 参数 | 类型 | 描述 |
|-----------|------|-------------|
| `options.cloud` | `AssistantCloud` | Cloud 客户端实例 |
| `options.includeArchived` | `boolean` | 是否包含归档线程（默认值：`false`） |
| `options.enabled` | `boolean` | 是否启用线程获取（默认值：`true`） |

**返回值：** `UseThreadsResult` — 形状与 `threads` 中的 `useCloudChat()` 相同。

## 遥测

`useCloudChat` hook 会在每次助手响应后，自动将运行遥测报告发送到 Assistant Cloud。其中包括：

**自动捕获：**
- `status` — 根据响应内容确定的 `"completed"` 或 `"incomplete"`
- `tool_calls` — 包含名称、参数和结果的工具调用。MCP 工具调用会明确标记为 `tool_source: "mcp"`
- `total_steps` — 响应中的推理/工具步骤数量
- `output_text` — 完整的响应文本（最多 50K 个字符）

**需要配置路由：**
- `model_id` — 用于响应的模型
- `input_tokens` / `output_tokens` — Token 使用统计
- `reasoning_tokens` — 链式思考推理所使用的 Token（例如 GPT-5.6 Luna 或其他推理模型）
- `cached_input_tokens` — 从提供商提示词缓存中提供的输入 Token

若要捕获模型和使用量数据，请在 AI SDK 路由中配置 `messageMetadata` 回调：

```tsx title="app/api/chat/route.ts"
import { streamText } from "ai";
import { openai } from "@ai-sdk/openai";

export async function POST(req: Request) {
  const { messages } = await req.json();

  const result = streamText({
    model: openai("gpt-5.6-luna"),
    messages,
  });

  return result.toUIMessageStreamResponse({
    messageMetadata: ({ part }) => {
      if (part.type === "finish") {
        return {
          usage: part.totalUsage,
        };
      }
      if (part.type === "finish-step") {
        return {
          modelId: part.response.modelId,
        };
      }
      return undefined;
    },
  });
}
```

<Callout type="info">
  独立 hook 会在消息元数据可序列化为 JSON 时捕获这些元数据，但不会捕获 `duration_ms`、每个步骤的细分数据（`steps`）或 `"error"` 状态。这些功能需要通过 [`useChatRuntime`](/docs/cloud/ai-sdk-assistant-ui) 提供的完整运行时集成。
</Callout>

### 自定义报告

使用 `beforeReport` hook 来丰富或筛选遥测数据：

```tsx
const cloud = new AssistantCloud({
  baseUrl: process.env.NEXT_PUBLIC_ASSISTANT_BASE_URL!,
  anonymous: true,
  telemetry: {
    beforeReport: (report) => ({
      ...report,
      metadata: { environment: "production", version: "1.0.0" },
    }),
  },
});
```

从 `beforeReport` 返回 `null`，即可跳过特定运行的报告。若要完全禁用遥测，请传入 `telemetry: false`。

### 子代理模型跟踪

在多代理设置中，如果工具调用委托给不同的模型（例如主运行使用 GPT，而工具调用 Gemini），可以通过 `messageMetadata` 传递采样调用数据，以跟踪受委托模型的使用情况。

**步骤 1：在服务器上收集采样数据**

使用 `assistant-cloud` 中的 `createSamplingCollector` 和 `wrapSamplingHandler`，捕获工具执行期间发起的 LLM 调用：

```ts title="app/api/chat/route.ts"
import { streamText } from "ai";
import { openai } from "@ai-sdk/openai";
import {
  createSamplingCollector,
  wrapSamplingHandler,
} from "assistant-cloud";

export async function POST(req: Request) {
  const { messages } = await req.json();

  // Collect sub-agent sampling calls per tool call
  const samplingCalls: Record<string, SamplingCallData[]> = {};

  const result = streamText({
    model: openai("gpt-5.6-luna"),
    messages,
    tools: {
      delegate_to_gemini: tool({
        parameters: z.object({ task: z.string() }),
        execute: async ({ task }, { toolCallId }) => {
          const collector = createSamplingCollector();
          // Your sub-agent logic that calls another model
          const result = await runSubAgent(task, {
            onSamplingCall: collector.collect,
          });
          samplingCalls[toolCallId] = collector.getCalls();
          return result;
        },
      }),
    },
  });

  return result.toUIMessageStreamResponse({
    messageMetadata: ({ part }) => {
      if (part.type === "finish") {
        return {
          usage: part.totalUsage,
          samplingCalls, // attach collected sampling data
        };
      }
      if (part.type === "finish-step") {
        return { modelId: part.response.modelId };
      }
      return undefined;
    },
  });
}
```

**步骤 2：就是这样。** 遥测报告器会自动从消息元数据中读取 `samplingCalls`，并将数据附加到报告中匹配的工具调用上。Cloud 仪表板会在模型分布图表中显示每个受委托的模型，并分别展示其 Token 和成本明细。

<Callout type="info">
  对于使用采样协议的 MCP 工具，`wrapSamplingHandler` 可以直接包装 MCP 客户端的采样处理器，从而透明地捕获所有嵌套的 LLM 调用。
</Callout>

<Callout type="tip">
  **在较旧的版本中**，如果尚未从元数据中读取 `samplingCalls`，请使用 `beforeReport` 手动注入数据：

  ```ts
  telemetry: {
    beforeReport: (report) => ({
      ...report,
      tool_calls: report.tool_calls?.map((tc) => ({
        ...tc,
        sampling_calls: samplingCalls[tc.tool_call_id],
      })),
    }),
  }
  ```
</Callout>
