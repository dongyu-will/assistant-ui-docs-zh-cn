---
title: 图像生成
description: 在后端生成图像，并将其内联渲染到 assistant-ui 会话线程中。
---

图像生成不需要专用原语。在已有模型调用的位置（路由处理器或工具）生成图像，将结果存储为 `ImageMessagePart`，然后使用 `@assistant-ui/ui` `Image` 组件渲染。

<Callout type="info">
  本页涵盖非流式生成、渲染和操作。流式传输部分图像以及多图画廊不在讨论范围内。
</Callout>

## 在后端生成

从服务器路由调用你的提供商。使用 AI SDK 时，对应的是 `generateImage`；将图像以 data URI（或对象存储 URL）以及你希望保留的提供商元数据返回。

```ts
// app/api/image/route.ts
import { generateImage } from "ai";
import { openai } from "@ai-sdk/openai";

export async function POST(req: Request) {
  const { prompt } = await req.json();
  const result = await generateImage({
    model: openai.image("gpt-image-1"),
    prompt,
  });
  const revisedPrompt = (
    result.providerMetadata as
      | Record<string, Record<string, unknown>>
      | undefined
  )?.openai?.revisedPrompt;
  return Response.json({
    image: `data:${result.image.mediaType};base64,${result.image.base64}`,
    mimeType: result.image.mediaType,
    ...(typeof revisedPrompt === "string" && { revisedPrompt }),
  });
}
```

模型提供商与渲染无关；将 `openai.image(...)` 替换为任意 AI SDK 图像模型即可。

## 将其存储为 `ImageMessagePart`

`ImageMessagePart` 只需要 `image`（`data:` URI、`https://` URL 或 `blob:` URL）以及可选的 `filename`。将你希望展示的来源信息、提示词、修订后的提示词、模型 ID 等内容保存在自己的组件状态或消息元数据中；该部分本身保持精简。

```ts
const part: ImageMessagePart = {
  type: "image",
  image: result.image, // data:, https://, or blob: URL
};
```

## 使用 `Image` 组件渲染

`Image` 组件位于 `@assistant-ui/ui` 中，可为你处理各种渲染状态：

1. **运行中**（`status.type === "running"`）会渲染一个加载指示器。
2. **内容过滤**（`status.type === "incomplete"`，以及 `reason: "content-filter"`）会渲染一个不带 `<img src>` 的错误卡片。
3. **完成**状态会渲染一个可缩放的 `<img>`，并可选择性地包含 `Image.Actions`。

`Image.Actions` 提供下载和复制按钮；传入 `onRegenerate` 回调后，还会提供重新生成按钮。将其连接到上文使用的同一生成流程；防抖、速率限制和确认逻辑由你决定。

```tsx
import { Image } from "@assistant-ui/ui";

<>
  <Image {...imagePart} />
  <Image.Actions part={imagePart} onRegenerate={() => regenerate(prompt)} />
</>;
```
