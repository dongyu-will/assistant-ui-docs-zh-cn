Context API 可直接访问 assistant-ui 的状态管理系统，让你能够构建与助手运行时无缝集成的自定义组件。

## 简介

Context API 是 assistant-ui 强大的状态管理系统，让你能够构建可完全访问助手状态和能力的自定义组件。它提供：

- **响应式状态访问** - 订阅状态变化并自动重新渲染
- **操作执行** - 触发发送消息或重新加载响应等操作
- **事件监听** - 响应用户交互和系统事件
- **感知作用域的设计** - 组件会自动了解自身上下文（消息、线程等）

它是所有 assistant-ui 原语的基础。当内置组件无法满足需求时，你可以使用 Context API 创建具备相同能力的自定义组件。

Context API 由你提供给 `<AssistantRuntimeProvider>` 的运行时提供支持。该运行时充当统一存储，管理所有助手状态、处理操作，并在整个应用中分发事件。

## 核心概念

### 作用域与层级

assistant-ui 将状态组织为 **作用域**（scope）——提供相关数据和操作访问权限的逻辑边界。每个作用域对应聊天界面的特定部分，并自动提供与上下文相关的功能。

```
🗂️  ThreadList (threads) - Manages the list of conversations
    ├── 📄 ThreadListItem (threadListItem) - Individual thread in the list
    └── 💬 Thread (thread) - Active conversation with messages
        ├── 🔵 Message (message) - User or assistant message
        │   ├── 📝 Part (part) - Content within a message (text, tool calls, etc.)
        │   ├── 🧠 ChainOfThought (chainOfThought) - Reasoning steps within a message
        │   │   └── 📝 Part (part) - Individual reasoning/tool-call step
        │   ├── 📎 Attachment (attachment) - Files attached to messages
        │   └── ✏️  Composer (composer) - Edit mode for existing messages
        │       └── 📎 Attachment (attachment) - Files in edit mode
        └── ✏️  Composer (composer) - New message input
            └── 📎 Attachment (attachment) - Files being added

💡 Suggestions (suggestions) - Follow-up message suggestions
    └── 💬 Suggestion (suggestion) - Individual suggestion item
🔧 Tools (tools) - Custom UI components for tool calls
🧩 ModelContext (modelContext) - Model context and tool registration
```

**作用域的工作方式：**

- 作用域由组件的渲染位置**自动确定**
- `<ThreadPrimitive.Messages>` 内的按钮会自动获得 `message` 作用域
- `<ComposerPrimitive.Attachments>` 内的按钮会自动获得 `attachment` 作用域
- 子作用域可以访问父作用域的数据（例如，`message` 组件可以访问 `thread` 数据）

```tsx
// Inside a message component
function MessageButton() {
  // ✅ Available: message scope (current message)
  const role = useAuiState((s) => s.message.role);

  // ✅ Available: thread scope (parent)
  const isRunning = useAuiState((s) => s.thread.isRunning);
}
```

### 状态管理模型

Context API 遵循可预测的状态管理模式：

1. **状态**是不可变的，并通过作用域向下传递
2. **操作**是用于触发状态变化的方法
3. **事件**通知组件状态变化和用户交互
4. **订阅**让组件能够响应变化

## 核心 Hooks

### useAuiState

以响应式方式读取状态，并在值变化时自动重新渲染。此 Hook 的工作方式类似 Zustand 的选择器模式：你提供一个提取所需特定数据的函数，组件只会在该数据变化时重新渲染。

```tsx
import { useAuiState } from "@assistant-ui/react";

// Basic usage - extract a single property
const role = useAuiState((s) => s.message.role); // "user" | "assistant"
const isRunning = useAuiState((s) => s.thread.isRunning); // boolean

// Access nested data
const attachmentCount = useAuiState(
  (s) => s.composer.attachments.length,
);
const lastMessage = useAuiState((s) => s.thread.messages.at(-1));
```

选择器函数会接收组件所在位置的所有可用作用域，并应返回一个特定值。组件只会在该返回值变化时重新渲染。

**常见模式：**

```tsx
// Access multiple scopes
const canSend = useAuiState(
  (s) => !s.thread.isRunning && s.composer.text.length > 0,
);

// Compute derived state
const messageCount = useAuiState((s) => s.thread.messages.length);
```

**重要：**不要在选择器中创建新对象。请返回原始值或稳定引用，以避免无限重新渲染。

```tsx
// ❌ Bad - creates new object every time
const data = useAuiState((s) => ({
  role: s.message.role,
  content: s.message.content,
}));

// ✅ Good - returns stable values
const role = useAuiState((s) => s.message.role);
const content = useAuiState((s) => s.message.content);
```

### useAui

访问 API 实例，以执行命令式操作和操作。与 `useAuiState` 不同，此 Hook 不会订阅状态更新：客户端的标识只会在结构发生变化时改变（某个作用域解析到不同实例），因此非常适合事件处理器和命令式操作。

```tsx
import { useAui } from "@assistant-ui/react";

function CustomMessageActions() {
  const aui = useAui();

  // Perform actions in event handlers
  const handleSend = () => {
    aui.composer.send();
  };

  const handleReload = () => {
    aui.message.reload();
  };

  // Read state imperatively when needed
  const handleConditionalAction = () => {
    const { isRunning } = aui.thread.getState();
    const { text } = aui.composer.getState();

    if (!isRunning && text.length > 0) {
      aui.composer.send();
    }
  };

  return (
    <div>
      <button onClick={handleSend}>Send</button>
      <button onClick={handleReload}>Reload</button>
      <button onClick={handleConditionalAction}>Smart Send</button>
    </div>
  );
}
```

API 对象不会因状态更新而导致重新渲染。请将其用于：

- 在事件处理器和回调中**触发操作**
- 在不需要订阅时以命令式方式**读取当前状态**
- 以编程方式**访问嵌套作用域**
- 执行操作前**检查作用域是否可用**

**各作用域可用的操作：**

```tsx
// Thread actions
aui.thread.append(message);
aui.thread.startRun(config);
aui.thread.resumeRun(config);
aui.thread.cancelRun();
aui.thread.getState();
aui.thread.message({ index: idx });
aui.thread.message({ id: messageId });
aui.thread.composer();

// Message actions
aui.message.reload();
aui.message.speak();
aui.message.stopSpeaking();
aui.message.submitFeedback({ type: "positive" | "negative" });
aui.message.switchToBranch({ position, branchId });
aui.message.getState();
aui.message.part({ index: idx });
aui.message.part({ toolCallId });
aui.message.composer();

// Part actions
aui.part.addToolResult(result);
aui.part.resumeToolCall(result);
aui.part.getState();

// Composer actions
aui.composer.send();
aui.composer.setText(text);
aui.composer.setRole(role);
aui.composer.addAttachment(file); // File object
aui.composer.addAttachment({ name, content }); // external source
await aui.composer.clearAttachments();
await aui.composer.reset();
aui.composer.getState();

// Attachment actions
aui.attachment.remove();
aui.attachment.getState();

// ThreadList actions
aui.threads.switchToNewThread();
aui.threads.switchToThread(threadId);
aui.threads.reload();
await aui.threads.getLoadThreadsPromise();
aui.threads.getState();

// ThreadListItem actions
aui.threadListItem.switchTo();
aui.threadListItem.rename(title);
aui.threadListItem.updateCustom(custom);
aui.threadListItem.archive();
aui.threadListItem.unarchive();
aui.threadListItem.delete();
aui.threadListItem.getState();

// Suggestions actions
aui.suggestions.getState();
aui.suggestions.suggestion({ index: 0 });

// Suggestion actions
aui.suggestion.getState();

// ChainOfThought actions
aui.chainOfThought.getState();
aui.chainOfThought.setCollapsed(collapsed);
aui.chainOfThought.part({ index: 0 });

// ModelContext actions — see /docs/copilots/model-context for full usage
aui.modelContext.register(provider);
aui.modelContext.getState();

// Tools actions
aui.tools.setToolUI(toolName, render);
aui.tools.getState();
```

### useAuiEvent

订阅事件，并在卸载时自动清理。此 Hook 非常适合响应用户交互、系统事件，或与外部分析服务集成。

```tsx
import { useAuiEvent } from "@assistant-ui/react";

// Listen to current scope events (most common)
useAuiEvent("composer.send", (event) => {
  console.log("Composer sent message in thread:", event.threadId);
});

// Listen to thread events
useAuiEvent("thread.modelContextUpdate", (event) => {
  console.log("Model context updated in thread:", event.threadId);
});

// Listen to all events of a type across all scopes
useAuiEvent({ event: "composer.send", scope: "*" }, (event) => {
  console.log("Any composer sent a message:", event.threadId);
});

// Listen to ALL events (useful for debugging or analytics)
useAuiEvent("*", (event) => {
  console.log("Event occurred:", event.event, event.payload);
});

// Practical example: Track user interactions
function AnalyticsTracker() {
  useAuiEvent("composer.send", (event) => {
    analytics.track("message_sent", {
      threadId: event.threadId,
    });
  });

  return null; // This component only tracks events
}
```

**事件名称模式：**

- 事件名称遵循 `source.action` 格式，并使用 camelCase（例如 `composer.send`、`thread.runStart`）
- 使用 `"*"` 作为事件名称，可以监听所有事件
- `scope` 参数控制哪些实例会触发事件

## 使用作用域

### 可用作用域

每个作用域都提供对特定状态和操作的访问：

- **ThreadList**（`threads`）：线程的集合与管理
- **ThreadListItem**（`threadListItem`）：列表中的单个线程
- **Thread**（`thread`）：包含消息的会话
- **Message**（`message`）：单条消息（用户或助手）
- **Part**（`part`）：消息中的内容部分（文本、工具调用等）
- **ChainOfThought**（`chainOfThought`）：消息中归组的推理步骤
- **Composer**（`composer`）：用于发送或编辑消息的文本输入框
- **Attachment**（`attachment`）：附加到消息或输入框的文件或媒体
- **Suggestions**（`suggestions`）：后续消息建议的集合
- **Suggestion**（`suggestion`）：单条后续消息建议
- **Tools**（`tools`）：工具 UI 组件
- **ModelContext**（`modelContext`）：模型上下文和工具注册

### 作用域解析

Context API 会根据组件位置自动解析当前作用域：

```tsx
function MessageButton() {
  const aui = useAui();

  // Automatically uses the current message scope
  const handleReload = () => {
    aui.message.reload();
  };

  return <button onClick={handleReload}>Reload</button>;
}
```

### 检查作用域是否可用

通过可选视图读取可能不可用的作用域——它们会解析为 `undefined`，而不是抛出异常：

```tsx
const role = useAuiState((s) => s.optional.message?.role);
```

### 访问嵌套作用域

以编程方式遍历作用域层级：

```tsx
const aui = useAui();

// Access specific message by ID or index
const messageById = aui.thread.message({ id: "msg_123" });
const messageByIndex = aui.thread.message({ index: 0 });

// Access part by index or tool call ID
const partByIndex = aui.message.part({ index: 0 });
const partByToolCall = aui.message.part({ toolCallId: "call_123" });

// Access attachment by index
const attachment = aui.composer.attachment({ index: 0 }).getState();

// Access thread list item by ID, index, or the "main" selector
const threadItem = aui.threads.item({ id: "thread_123" });
const threadByIndex = aui.threads.item({ index: 0 });
const archivedThread = aui.threads.item({ index: 0, archived: true });

// Traverse to the main thread directly
const mainThread = aui.threads.thread("main");
const message = aui.threads.thread("main").message({ id: "msg_123" });
```

## 常见模式

### 条件渲染

```tsx
function RunIndicator() {
  const isRunning = useAuiState((s) => s.thread.isRunning);

  if (!isRunning) return null;
  return <div>Assistant is thinking...</div>;
}
```

### 自定义操作按钮

```tsx
function CopyButton() {
  const aui = useAui();

  const handleCopy = () => {
    navigator.clipboard.writeText(aui.message.getCopyText());
  };

  return <button onClick={handleCopy}>Copy</button>;
}
```

### 感知状态的组件

```tsx
function SmartComposer() {
  const aui = useAui();
  const isRunning = useAuiState((s) => s.thread.isRunning);
  const text = useAuiState((s) => s.composer.text);

  const canSend = !isRunning && text.length > 0;

  return (
    <div>
      <textarea
        value={text}
        onChange={(e) => aui.composer.setText(e.target.value)}
        disabled={isRunning}
      />
      <button onClick={() => aui.composer.send()} disabled={!canSend}>
        Send
      </button>
    </div>
  );
}
```

### 事件驱动的更新

```tsx
function MessageCounter() {
  const [sendCount, setSendCount] = useState(0);

  useAuiEvent("composer.send", () => {
    setSendCount((c) => c + 1);
  });

  return <div>Messages sent: {sendCount}</div>;
}
```

## 高级主题

### 解析动态性

作用域会在渲染期间解析并绑定到客户端。状态更新不会改变客户端的标识；结构变化（例如切换线程）会生成新的客户端，并通过 React 重新渲染使用它的组件：

```tsx
const aui = useAui();

// Bound to the thread current at this render
aui.thread.append({ role: "user", content: "Hello" });

// After a thread switch, the component re-renders with a new client.
// Accessors read from a previous render keep pointing at the old thread.
```

### 性能优化

**选择器优化：**

```tsx
// ❌ Expensive computation in selector (runs on every store update)
const result = useAuiState(
  (s) => s.thread.messages.filter((m) => m.role === "user").length,
);

// ✅ Memoize expensive computations
const messages = useAuiState((s) => s.thread.messages);
const userCount = useMemo(
  () => messages.filter((m) => m.role === "user").length,
  [messages],
);
```

**减少重新渲染：**

```tsx
// ❌ Subscribes to entire thread state
const thread = useAuiState((s) => s.thread);

// ✅ Subscribe only to needed values
const isRunning = useAuiState((s) => s.thread.isRunning);
```

## API 参考

### Hooks

| Hook                          | 用途                    | 返回值        |
| ----------------------------- | -------------------------- | -------------- |
| `useAuiState(selector)`       | 订阅状态变化 | 选中的值 |
| `useAui()`                    | 获取 API 实例           | API 对象     |
| `useAuiEvent(event, handler)` | 订阅事件        | void           |

### 作用域状态

| 作用域          | 关键状态属性                                                                             | 描述                                        |
| -------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| ThreadList     | `mainThreadId`、`newThreadId`、`threadIds`、`archivedThreadIds`、`isLoading`、`threadItems`（`readonly ThreadListItemState[]`） | 管理所有可用的会话线程 |
| ThreadListItem | `id`、`title`、`status`、`remoteId`、`externalId`、`custom?: Record<string, unknown>`           | 单个线程的元数据和状态；`custom` 携带由远程运行时设置的每个线程的任意元数据 |
| Thread         | `isRunning`（可以由运行时显式设置，而不是从最后一条消息的状态推导）、`isLoading`、`isDisabled`、`isEmpty`、`messages`、`capabilities`、`suggestions` | 活跃会话状态和消息历史 |
| Message        | `role`、`content`、`status`、`attachments`、`parts`、`parentId`、`branchNumber`、`branchCount`、`isLast`、`index` | 单条消息的内容和元数据 |
| Part           | `type`、`status`、`text`、`toolCallId`、`toolName`                                              | 消息中的内容部分（文本、工具调用）   |
| ChainOfThought | `parts`、`collapsed`、`status`                                                                   | 消息中归组的推理步骤           |
| Composer       | `text`、`role`、`attachments`、`isEmpty`、`canCancel`、`type`、`isEditing`                      | 新消息或已编辑消息的文本输入状态           |
| Attachment     | `id`、`type`、`name`、`contentType`、`status`                                                   | 文件附件的元数据和内容              |
| Suggestions    | `suggestions`                                                                                    | 后续消息建议的集合        |
| Suggestion     | `title`、`label`、`prompt`                                                                       | 包含标题、标签和提示词的单条建议 |
| ModelContext   | *（为空——请使用 `register()` / `getToolCallParams()` 方法；参见 [模型上下文](/docs/copilots/model-context)）* | 系统指令、工具和上下文提供程序 |

| 作用域          | 操作                                                                                                           | 使用场景                                  |
| -------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| ThreadList     | `switchToNewThread()`、`switchToThread(id)`、`reload()`、`getLoadThreadsPromise()`、`item(selector)`、`thread("main")`、`getState()` | 线程导航、创建和同步 |
| ThreadListItem | `switchTo()`、`rename(title)`、`updateCustom(custom)`、`archive()`、`unarchive()`、`delete()`、`getState()`      | 线程管理操作               |
| Thread         | `append(message)`、`startRun(config)`、`resumeRun(config)`、`cancelRun()`、`reset()`、`export()`、`import(repository)`、`message(selector)`、`composer()`、`getState()` | 消息处理和会话控制 |
| Message        | `reload()`、`speak()`、`stopSpeaking()`、`submitFeedback(feedback)`、`switchToBranch(options)`、`getCopyText()`、`part(selector)`、`attachment(selector)`、`composer()`、`setIsCopied(value)`、`setIsHovering(value)`、`getState()` | 消息交互和重新生成 |
| Part           | `addToolResult(result)`、`resumeToolCall(result)`、`getState()`                                                   | 工具调用结果处理                  |
| ChainOfThought | `setCollapsed(collapsed)`、`part({ index })`、`getState()`                                                        | 展开/折叠推理步骤            |
| Composer       | `send()`、`setText(text)`、`setRole(role)`、`addAttachment(file \| attachment)`、`clearAttachments()`（异步）、`reset()`（异步）、`getState()` | 文本输入和消息编辑 |
| Attachment     | `remove()`、`getState()`                                                                                          | 文件管理                            |
| Suggestions    | `suggestion({ index })`、`getState()`                                                                             | 访问后续建议               |
| Suggestion     | `getState()`                                                                                                      | 读取单条建议数据            |
| ModelContext   | `register(provider)`、`getState()`                                                                                | 注册提供程序；详情请参见 [模型上下文](/docs/copilots/model-context) |

### 事件与状态观察

使用 `useAuiState` 渲染某项的当前值；使用 `useAuiEvent` 响应某件事发生的时刻。两者都受支持：许多事件标志着一个也可以通过状态观察到的转换，而订阅事件是针对该转换执行副作用的预期方式。

经验法则：

1. 要渲染某个值？→ 使用 `useAuiState`。
2. 你是调用方并希望立即获得反馈？→ 捕获拒绝结果 / 读取返回值。
3. 要在某件事发生时执行副作用？→ 使用 `useAuiEvent`。

#### 可用事件

| 事件                         | 触发时机                                                                |
| ----------------------------- | ---------------------------------------------------------------------------- |
| `threads.selectionChanged`    | 主线程选择发生变化。负载包含 `threadId`（新选中的线程）和 `previousThreadId`。初始挂载时选中的线程不会触发此事件。 |
| `thread.runStart` / `runEnd`  | 线程上的运行开始/结束（也可通过 `isRunning` 翻转观察到）   |
| `thread.initialize`           | 线程从新建状态转换为已初始化状态，在添加第一条消息之前 |
| `thread.modelContextUpdate`   | 模型上下文提供程序通知发生变化。模型上下文存在于提供程序中，而不在线程状态中，因此此事件没有可从状态推导出的等价形式。 |
| `composer.send`               | 用户发送了输入框内容；对于编辑输入框的发送，`messageId` 会被设置 |
| `composer.attachmentAdd`      | 有附件添加到输入框                                      |
| `composer.attachmentAddError` | 某个 `addAttachment()` 调用失败。负载中的 `reason` 用于区分 `no-adapter` / `not-accepted` / `adapter-error`。事件还会提供便于人类阅读的 `message`（以及通过底层 `runtime.unstable_on("attachmentAddError")` API 提供底层的 `Error` 实例；`useAuiEvent` 负载会省略该实例，因为原始 `Error` 对象无法序列化到存储中）。 |

#### 已弃用的事件

| 已弃用的事件              | 替代方案                                                                  |
| ----------------------------- | ---------------------------------------------------------------------------- |
| `threadListItem.switchedTo`   | `threads.selectionChanged` — 其 `threadId` 是新选中的线程     |
| `threadListItem.switchedAway` | `threads.selectionChanged` — 其 `previousThreadId` 是切换离开的线程 |

## 故障排除

### 常见错误

**“Cannot access [scope] outside of [scope] context”**

```tsx
// ❌ This will throw if not inside a message component
const role = useAuiState((s) => s.message.role);

// ✅ Read through the optional view — unavailable scopes resolve to undefined
const role = useAuiState((s) => s.optional.message?.role ?? "none");
```

**“Maximum update depth exceeded” / 无限重新渲染**

```tsx
// ❌ Creating new objects in selectors causes infinite re-renders
const data = useAuiState((s) => ({
  role: s.message.role,
  content: s.message.content, // New object every time!
}));

// ✅ Return primitive values or use separate selectors
const role = useAuiState((s) => s.message.role);
const content = useAuiState((s) => s.message.content);
```

**“Scope resolution failed” / 作用域引用过期**

```tsx
// ❌ Storing scope references can lead to stale data
const aui = useAui();
const thread = aui.thread; // This reference might become stale

useEffect(() => {
  // This might reference the wrong thread if user switched
  thread.cancelRun();
}, [thread]);

// ✅ Resolve scopes fresh each time
const aui = useAui();

useEffect(() => {
  // Always gets the current thread
  aui.thread.cancelRun();
}, [aui]);
```
