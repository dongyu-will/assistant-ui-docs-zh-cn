如果你订阅了 ChatGPT Plus 或 Pro，可以在本地运行 assistant-ui 应用并使用该订阅，而无需使用 API 密钥按 token 付费。OpenAI 的 Codex CLI 通过 OAuth 完成身份验证，并将令牌缓存到你的计算机上；使用这些令牌发出的请求会访问 `chatgpt.com` 处的 Responses API 端点，并计入你的订阅方案。Codex 本身以及越来越多的本地代理也使用相同的机制。

这种配置适用于在你自己的计算机上运行的个人应用。对于任何已部署或共享的应用，请使用 API 密钥。

## 使用 Codex 登录

使用 Codex CLI 完成一次身份验证。登录流程会在浏览器中运行 OAuth，并将访问令牌和刷新令牌写入 `~/.codex/auth.json`：

```sh
npx @openai/codex login
```

下面的所有内容都会读取该文件；不涉及环境变量或 API 密钥。

## AI SDK 路由

社区 AI SDK 提供商 [`openai-oauth-provider`](https://github.com/EvanZhouDev/openai-oauth) 会自动读取 `~/.codex/auth.json`，并在需要时刷新令牌，同时支持流式传输、工具调用和推理轨迹。

```sh
npm install openai-oauth-provider
```

在聊天路由中，将 `@ai-sdk/openai` 替换为 OAuth 提供商。从默认的 assistant-ui 模板路由开始，只需更改模型；`frontendTools` 和 UI 消息流响应的工作方式保持不变：

```ts title="/app/api/chat/route.ts" {10}
import { createOpenAIOAuth } from "openai-oauth-provider";
import { frontendTools } from "@assistant-ui/ai-sdk";
import {
  type JSONSchema7,
  streamText,
  convertToModelMessages,
  type UIMessage,
} from "ai";

const openai = createOpenAIOAuth();

export async function POST(req: Request) {
  const {
    messages,
    system,
    tools,
  }: {
    messages: UIMessage[];
    system?: string;
    tools?: Record<string, { description?: string; parameters: JSONSchema7 }>;
  } = await req.json();

  const result = streamText({
    model: openai("gpt-5.3-codex"),
    messages: await convertToModelMessages(messages),
    system,
    tools: {
      ...frontendTools(tools ?? {}),
    },
  });

  return result.toUIMessageStreamResponse({
    sendReasoning: true,
  });
}
```

提供商会从你的 ChatGPT 账户中发现订阅方案包含哪些模型（例如 `gpt-5.4` 和 `gpt-5.3-codex`）。

## Eve 代理

Eve 的 `defineAgent` 接受由提供商创建的 AI SDK `LanguageModel`，因此可以将同一个提供商直接用于 Eve 代理配置：

```ts title="agent/agent.ts"
import { defineAgent } from "eve";
import { createOpenAIOAuth } from "openai-oauth-provider";

export default defineAgent({
  model: createOpenAIOAuth()("gpt-5.3-codex"),
});
```

## OpenAI 兼容代理

对于使用 OpenAI base URL 而不是 AI SDK 模型的技术栈，同一项目还发布了姊妹包 `openai-oauth`，其 CLI 可以运行本地代理：

```sh
npx openai-oauth
# OpenAI-compatible endpoint ready at http://127.0.0.1:10531/v1
```

将任何 OpenAI 兼容客户端指向该 URL。这里不涉及真实的 API 密钥，但大多数客户端在构造时都要求传入一个密钥，因此请传入占位符：

```ts
import { OpenAI } from "openai";

const openai = new OpenAI({
  baseURL: "http://127.0.0.1:10531/v1",
  apiKey: "unused",
});
```

代理默认绑定到 `127.0.0.1`；请保持默认设置，因为任何能够访问该端点的调用方都会从你的订阅中扣费。

<Callout type="warn">
  你的 OAuth 令牌存储在 `~/.codex/auth.json` 中，因此只有在该文件存在的环境中才能工作。已部署的实例会让每位访问者产生的费用都计入你的订阅。`openai-oauth-provider` 是非官方的社区软件包，可用模型取决于你的 ChatGPT 订阅方案；OpenAI 认可这种身份验证流程用于 Codex 工具，因此请将其视为个人用途。
</Callout>
