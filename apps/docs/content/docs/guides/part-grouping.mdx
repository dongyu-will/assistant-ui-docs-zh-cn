## 基本用法

对于相邻分组，请使用 `MessagePrimitive.GroupedParts`。对于常见的按 `part.type` 分组场景，将 `groupPartByType` 传入，以将每种部分类型映射到组键路径。共享组键的相邻部分会合并，并通过组分支进行渲染。

```tsx title="/components/assistant-ui/elements/thread.aui.tsx"
import { MessagePrimitive, groupPartByType } from "@assistant-ui/react";

const AssistantMessage: FC = () => {
  return (
    <MessagePrimitive.Root className="...">
      <div className="...">
        <MessagePrimitive.GroupedParts
          groupBy={groupPartByType({
            "tool-call": ["group-tool"],
          })}
        >
          {({ part, children }) => {
            switch (part.type) {
              case "group-tool":
                return <div className="group">{children}</div>;
              case "tool-call":
                return part.toolUI ?? null;
              default:
                return null;
            }
          }}
        </MessagePrimitive.GroupedParts>
      </div>
      <AssistantActionBar />
      <BranchPicker className="..." />
    </MessagePrimitive.Root>
  );
};
```

只有在辅助函数无法满足表达需求时，才使用内联 `groupBy={(part) => …}` ——例如需要根据 `part.toolName`、`part.parentId` 或部分元数据进行分支处理。

## 相邻分组的工作方式

`groupBy` 接收每个部分，并返回 `null`（表示未分组的叶部分）或类似 `["group-chainOfThought", "group-tool"]` 的组键路径。组键必须以 `"group-"` 开头，以便渲染函数区分合成组和真实的部分类型。

渲染函数通过 `{ part, children }` 同时接收组节点和叶部分。只有组分支应渲染 `children`；叶分支应渲染自身 UI，或返回 `null`。

<Callout type="warn">
  `MessagePrimitive.Unstable_PartsGrouped` 仍可用于少见的非相邻聚类场景，即一个组需要收集消息中不同位置的部分。对于正常的连续推理/工具分组，请使用 `GroupedParts`。
</Callout>

## 使用场景与示例

### 按父级 ID 分组

将共享相同父级关系的相邻内容分组：

```tsx
import { useState, type PropsWithChildren } from "react";
import { ChevronDownIcon, ChevronUpIcon } from "lucide-react";
import { MessagePrimitive } from "@assistant-ui/react";

function ParentGroup({
  id,
  count,
  children,
}: PropsWithChildren<{ id: string; count: number }>) {
  const [collapsed, setCollapsed] = useState(false);

  return (
    <div className="my-2 overflow-hidden rounded-lg border">
      <button
        type="button"
        onClick={() => setCollapsed((value) => !value)}
        className="hover:bg-muted/50 flex w-full items-center justify-between p-3"
      >
        <span>
          Group {id} ({count} items)
        </span>
        {collapsed ? <ChevronDownIcon /> : <ChevronUpIcon />}
      </button>
      {!collapsed && <div className="border-t p-3">{children}</div>}
    </div>
  );
}

<MessagePrimitive.GroupedParts
  groupBy={(part) => {
    if (!part.parentId) return [];
    return [`group-parent-${part.parentId}`];
  }}
>
  {({ part, children }) => {
    if (part.type.startsWith("group-parent-")) {
      const id = part.type.replace("group-parent-", "");
      return (
        <ParentGroup id={id} count={part.indices.length}>
          {children}
        </ParentGroup>
      );
    }

    if (part.type === "text") return <MarkdownText />;
    if (part.type === "tool-call") return part.toolUI ?? <ToolFallback {...part} />;
    return null;
  }}
</MessagePrimitive.GroupedParts>
```

### 按工具名称分组

按工具名称组织相邻的工具调用：

```tsx
<MessagePrimitive.GroupedParts
  groupBy={(part) => {

    }

    if (part.type === "text") return <MarkdownText />;
    if (part.type === "tool-call") return part.toolUI ?? <ToolFallback {...part} />;
    return null;
  }}
</MessagePrimitive.GroupedParts>
```

### 将连续的文本部分分组

将多个文本部分合并为连贯的内容块：

```tsx
<MessagePrimitive.GroupedParts
  groupBy={groupPartByType({
    text: ["group-text-block"],
  })}
>
  {({ part, children }) => {
    switch (part.type) {
      case "group-text-block":
        return (
          <div className="prose prose-sm my-2 rounded-lg bg-gray-50 p-4">
            {children}
          </div>
        );
      case "text":
        return <MarkdownText />;
      case "tool-call":
        return part.toolUI ?? <ToolFallback {...part} />;
      default:
        return null;
    }
  }}
</MessagePrimitive.GroupedParts>
```

### 按内容类型分组

分离不同类型的内容，以便采用不同的视觉样式：

```tsx
<MessagePrimitive.GroupedParts
  groupBy={groupPartByType({
    text: ["group-content-text"],
    "tool-call": ["group-content-tools"],
    reasoning: ["group-content-reasoning"],
  })}
>
  {({ part, children }) => {
    switch (part.type) {
      case "group-content-text":
        return <div className="space-y-2">{children}</div>;
      case "group-content-tools":
        return <div className="my-2 rounded-lg border p-3">{children}</div>;
      case "group-content-reasoning":
        return <div className="my-2 text-muted-foreground">{children}</div>;
      case "text":
        return <MarkdownText />;
      case "reasoning":
        return <Reasoning {...part} />;
      case "tool-call":
        return part.toolUI ?? <ToolFallback {...part} />;
      default:
        return null;
    }
  }}
</MessagePrimitive.GroupedParts>
```

### 将独立的工具 UI 排除在追踪记录之外

工具 UI 可分为三类：提示用户（人在回路）、告知用户（生成式 UI），以及记录模型正在执行的操作（常规工具调用）。前两类应单独呈现，而最后一类应折叠到可展开的思维链组中。

为工具标记 `display: "standalone"`，即可将其 UI 排除在分组追踪记录之外。`human` 工具和 MCP 应用会自动独立显示；其他工具默认使用 `"inline"`，需要显式选择加入：

```tsx
const toolkit = defineToolkit({
  ask_user: { type: "human", render: AskUI }, // standalone (forced)
  search_web: { type: "frontend", render: SearchUI }, // inline trace (default)
  checkout: {
    type: "frontend",
    render: CheckoutUI,
    display: "standalone", // opt in
  },
});
```

`groupPartByType` 上的合成 `"standalone-tool-call"` 键会匹配所有这些工具。`MessagePrimitive.GroupedParts` 会将实时工具 UI 注册表作为第二个 `context` 参数传递给 `groupBy`，辅助函数会读取该注册表，以解析由注册表驱动的分支 ——MCP 应用调用可仅根据部分本身检测，因此无需传入任何额外内容：

```tsx
<MessagePrimitive.GroupedParts
  groupBy={groupPartByType({
    reasoning: ["group-chainOfThought", "group-reasoning"],
    "tool-call": ["group-chainOfThought", "group-tool"],
    "standalone-tool-call": [], // ungrouped — rendered on its own
  })}
>
  {({ part, children }) => {
    switch (part.type) {
      case "group-chainOfThought":
        return <div className="chain-of-thought">{children}</div>;
      case "tool-call":
        return part.toolUI ?? <ToolFallback {...part} />;
      // ...
      default:
        return null;
    }
  }}
</MessagePrimitive.GroupedParts>;
```

### 将工具调用渲染为平铺行

上一节会将 `"tool-call"` 折叠到思维链中，只将独立的工具 UI 提取出来。若要在组中保持推理折叠，同时让每个工具调用都作为消息流中的独立行进行渲染，请将两个工具键都映射到 `[]`：

```tsx
<MessagePrimitive.GroupedParts
  groupBy={groupPartByType({
    reasoning: ["group-thought", "group-reasoning"],
    "tool-call": [],
    "standalone-tool-call": [],
  })}
>
  {({ part, children }) => {
    switch (part.type) {
      case "group-thought":
      case "group-reasoning":
        return <ReasoningBlock>{children}</ReasoningBlock>;
      case "reasoning":
        return <Reasoning {...part} />;
      case "tool-call":
        return part.toolUI ?? <ToolFallback {...part} />;
      case "text":
        return <MarkdownText />;
      case "indicator":
        return <LoadingDots />;
      default:
        return null;
    }
  }}
</MessagePrimitive.GroupedParts>
```

相邻的 `reasoning` 部分仍会合并为一个 `group-thought`，而每个工具调用则会成为与文本处于同一层级的叶部分 ——`"standalone-tool-call"` 条目也会映射到 `[]`，因此人在回路和生成式 UI 工具会与常规调用一样保持平铺，而不会落入 `"tool-call"`。工具调用叶部分会在重新渲染时保留稳定的身份键，因此消息流式传输时行不会重新挂载。

<Callout type="warn">
  这会在**消息流中**平铺渲染工具调用 ——每个叶部分都按照部分出现的顺序位于相应位置。它不会固定、传送、浮动，也不会以其他方式将工具 UI 移出消息流并放入侧边栏或固定区域。若要将内容放置在消息流之外，仍需在 `GroupedParts` 外部自行管理布局。
</Callout>

### 按自定义元数据分组

可以使用部分中的任意自定义元数据进行分组：

```tsx
const priorityStyles = {
  high: "border-red-500 bg-red-50",
  normal: "border-gray-300 bg-white",
  low: "border-gray-200 bg-gray-50",
};

<MessagePrimitive.GroupedParts
  groupBy={(part) => {
    const priority = part.metadata?.priority;
    if (!priority) return [];
    return [`group-priority-${priority}`];
  }}
>
  {({ part, children }) => {
    if (part.type.startsWith("group-priority-")) {
      const priority = part.type.replace("group-priority-", "");
      return (
        <div
          className={`my-2 rounded-lg border-2 p-4 ${priorityStyles[priority] || ""}`}
        >
          <div className="mb-2 text-xs font-semibold uppercase text-gray-600">
            {priority} Priority
          </div>
          {children}
        </div>
      );
    }

    if (part.type === "text") return <MarkdownText />;
    if (part.type === "tool-call") return part.toolUI ?? <ToolFallback {...part} />;
    return null;
  }}
</MessagePrimitive.GroupedParts>
```

### groupPartByType 辅助函数

`groupPartByType` 根据 `part.type → group-key path` 映射构建 `groupBy`。映射中未包含的部分类型将保持未分组状态。返回的函数带有内部记忆指纹，因此即使发生无关的重新渲染，树也能保持不变。

```typescript
import { groupPartByType } from "@assistant-ui/react";

groupPartByType({
  reasoning: ["group-thought", "group-reasoning"],
  "tool-call": ["group-thought", "group-tool"],
});
```

### GroupPart 类型

```typescript
type GroupPart<TKey extends `group-${string}` = `group-${string}`> = {
  readonly type: TKey;
  readonly status: MessagePartStatus | ToolCallMessagePartStatus;
  readonly indices: readonly number[];
};
```

## 最佳实践

1. **保持分组局部化**：`GroupedParts` 会将相邻的连续部分分组。如果同一个键稍后再次出现，它会在该位置成为一个新组。
2. **处理未分组的部分**：始终为消息可以渲染的部分类型包含叶分支。
3. **仅对组渲染 `children`**：叶部分会接收到哨兵值 `children`，如果误将其渲染，就会抛出错误。
4. **使用 `group-` 前缀**：合成组键必须以 `group-` 开头，以避免与真实的部分类型冲突。

## 常见模式

### 嵌套分组

通过返回多个键创建层级化的相邻组：

```tsx
<MessagePrimitive.GroupedParts
  groupBy={(part) => {
    if (part.type === "reasoning")
      return ["group-chainOfThought", "group-reasoning"];
    if (part.type === "tool-call")
      return ["group-chainOfThought", `group-tool-${part.toolName}`];
    return [];
  }}
>
  {({ part, children }) => {
    if (part.type === "group-chainOfThought") return <div>{children}</div>;
    if (part.type === "group-reasoning") return <ReasoningRoot>{children}</ReasoningRoot>;
    if (part.type.startsWith("group-tool-")) return <div>{children}</div>;
    if (part.type === "reasoning") return <Reasoning {...part} />;
    if (part.type === "tool-call") return part.toolUI ?? <ToolFallback {...part} />;
    if (part.type === "text") return <MarkdownText />;
    return null;
  }}
</MessagePrimitive.GroupedParts>
```

### 动态组渲染

根据组节点的状态或索引调整组的外观：

```tsx
<MessagePrimitive.GroupedParts
  groupBy={groupPartByType({
    "tool-call": ["group-tools"],
  })}
>
  {({ part, children }) => {
    if (part.type === "group-tools") {
      const isRunning = part.status.type === "running";

      return (
        <div
          className={`my-2 rounded-lg border p-4 ${
            isRunning ? "animate-pulse border-blue-500" : ""
          }`}
        >
          <div className="mb-2 text-sm text-muted-foreground">
            {part.indices.length} tool calls
          </div>
          {children}
        </div>
      );
    }

    if (part.type === "tool-call") return part.toolUI ?? <ToolFallback {...part} />;
    if (part.type === "text") return <MarkdownText />;
    return null;
  }}
</MessagePrimitive.GroupedParts>
```

## 非相邻分组（不稳定）

仅当需要将非相邻部分收集到同一个渲染组中时，才使用 `MessagePrimitive.Unstable_PartsGrouped`，例如：即使相同父级 ID 的部分之间存在其他部分，也要收集所有这些部分。此 API 不稳定，不应当用于常规的连续推理或工具调用分组。

```tsx
<MessagePrimitive.Unstable_PartsGrouped
  groupingFunction={(parts) => {
    const groups = new Map<string, number[]>();

    parts.forEach((part, index) => {
      const key = part.parentId ?? `__ungrouped_${index}`;
      const indices = groups.get(key) ?? [];
      indices.push(index);
      groups.set(key, indices);
    });

    return Array.from(groups.entries()).map(([key, indices]) => ({
      groupKey: key.startsWith("__ungrouped_") ? undefined : key,
      indices,
    }));
  }}
  components={{
    Text: MarkdownText,
    tools: { Fallback: ToolFallback },
    Group: ({ groupKey, children }) => {
      if (!groupKey) return <>{children}</>;
      return <div className="rounded-lg border p-3">{children}</div>;
    },
  }}
/>
```

### MessagePartGroup 类型

```typescript
type MessagePartGroup = {
  groupKey: string | undefined; // The group identifier (undefined for ungrouped parts)
  indices: number[]; // Array of part indices belonging to this group
};
```

### 组组件属性

`Group` 组件接收：

- `groupKey`：组标识符（未分组部分则为 `undefined`）
- `indices`：该组中各部分的索引数组
- `children`：渲染后的消息部分组件
