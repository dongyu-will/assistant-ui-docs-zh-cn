`ComposerPrimitive.Input` 仍然是大多数应用推荐使用的输入框。它负责自动调整大小、键盘快捷键、IME 处理、粘贴为附件、焦点行为以及触发器弹出框的键盘集成。

当你已经拥有输入界面时，请使用 `unstable_useComposerInput`，例如自定义编辑器、`contentEditable` 界面，或某个文本区域包装器，且其行为无法通过 `ComposerPrimitive.Input` 的 props、`asChild` 或 `render` API 表达。

<Callout type="warn">
  此 API 标记为不稳定，可能在不另行通知的情况下发生变化。它只是连接
  输入框文本和发送状态的轻量桥接，而不是 `ComposerPrimitive.Input` 的替代实现。
</Callout>

## 用法

在输入框中渲染自定义输入，并将文本变化同步到 assistant-ui 输入框状态：

```tsx
"use client";

import {
  ComposerPrimitive,
  unstable_useComposerInput,
  unstable_useTriggerPopoverAriaProps,
} from "@assistant-ui/react";

function HeadlessComposer() {
  const composer = unstable_useComposerInput();
  const popoverAria = unstable_useTriggerPopoverAriaProps();

  return (
    <ComposerPrimitive.Root>
      <textarea
        aria-label="Message"
        value={composer.value}
        disabled={composer.isDisabled}
        onChange={(event) => {
          composer.setText(event.currentTarget.value);
        }}
        onKeyDown={(event) => {
          if (event.nativeEvent.isComposing) return;

          if (event.key === "Enter" && !event.shiftKey) {
            event.preventDefault();

            if (composer.canSend) {
              composer.send();
            }
          }
        }}
        {...popoverAria}
      />
      <ComposerPrimitive.Send />
    </ComposerPrimitive.Root>
  );
}
```

`composer.send()` 暴露了与 `ComposerPrimitive.Send` 使用的相同发送操作，包括 `composer.send({ steer: true })` 等发送选项。除非 `composer.canSend` 为 `true`，否则它不会执行任何操作；在自定义键盘处理器中检查 `canSend`，以明确处理事件。

## Hook 返回值

| 字段 | 描述 |
| --- | --- |
| `value` | 当前输入框文本。当输入框未处于编辑状态时，返回 `""`。 |
| `setText(text)` | 在输入框处于编辑状态时，将文本写入输入框。 |
| `send(options?)` | 当 `canSend` 为 `true` 时发送当前输入框消息；否则不会执行任何操作。 |
| `isDisabled` | 将 hook 的 `disabled` 选项与 assistant-ui 的禁用来源结合起来，例如线程禁用状态和活动听写输入锁定。 |
| `canSend` | 匹配 `ComposerPrimitive.Send` 的门控逻辑，并额外遵循 `isDisabled`。 |

当编辑器还有额外的只读状态时，传入 `disabled`：

```tsx
const composer = unstable_useComposerInput({
  disabled: editorReadOnly,
});
```

## 仍需由你负责的部分

此 hook 不会重新实现 `ComposerPrimitive.Input` 的行为。你的输入框或编辑器仍需负责：

- Enter/换行快捷键、steer 快捷键、Escape/取消行为以及其他键盘行为。
- IME 和组合输入处理。
- 光标和选择范围跟踪。
- 自动调整大小和焦点管理。
- 粘贴/拖放附件行为。
- `contentEditable` 的富文本状态、序列化和 DOM 同步，或编辑器库集成。

对于带样式的文本区域，优先使用 `ComposerPrimitive.Input`。当编辑器拥有自己的模型或 DOM 生命周期，而 assistant-ui 只需提供输入框状态和发送门控时，再使用无头 hook。

## 触发器弹出框

`unstable_useTriggerPopoverAriaProps` 返回当前打开的触发器弹出框的 combobox ARIA 属性：

```tsx
const popoverAria = unstable_useTriggerPopoverAriaProps();

<textarea {...popoverAria} />;
```

最后展开这些 props，使其在弹出框打开时能够同步 `ComposerPrimitive.Input`。

此辅助方法只会向辅助技术描述已打开的弹出框。它不会将自定义编辑器接入 mention 或斜杠命令的键盘处理、光标跟踪或条目插入。若要使用完整的内置触发器弹出框体验，请使用 `ComposerPrimitive.Input`；对于功能更丰富的编辑器，请将触发器 UI 与编辑器自身的选择范围和键盘模型集成。
