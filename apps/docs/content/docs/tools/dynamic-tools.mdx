大多数工具都是静态的：它们的执行器在构建时便已固定。但有些工具需要读取或写入**组件状态**——向用户也可以编辑的列表中添加内容、修改画布、预填表单。此类工具的执行器必须闭包捕获 React setter，而这无法放在构建拆分的 `"use generative"` 文件中。

具体模式是：使用 `execute: stubTool()` 在工具包中声明面向模型的**契约**，并在拥有该状态的组件中通过 `useAuiToolOverrides` 在运行时提供**实际执行器**。

<Callout type="warn">
  `useAuiToolOverrides` 目前处于实验阶段，其 API 可能会发生变化。
</Callout>

## 1. 使用 `stubTool()` 声明契约

在你的 `"use generative"` 文件中，为工具提供描述、参数和渲染器，并将执行器标记为存根。编译器会将 schema 发送到后端并移除存根——模型可以调用该工具，但在组件提供实际实现之前不会执行任何操作。将 schema 保存在单独的非指令模块中，还可以让组件导入参数类型：

```tsx title="app/task-board-toolkit.tsx"
"use generative";

import { defineToolkit, stubTool } from "@assistant-ui/react";
import { manageTasksParameters } from "./state";

export default defineToolkit({
  manage_tasks: {
    description:
      'Manage tasks on the board. Actions: "add" (requires title), ' +
      '"toggle" (requires id), "remove" (requires id), "clear".',
    parameters: manageTasksParameters,
    execute: stubTool(),
    renderText: {
      running: ({ args }) => `Updating tasks: ${args.action}`,
      complete: "Tasks updated",
    },
  },
});
```

## 2. 使用 `useAuiToolOverrides` 提供执行器

拥有该状态的组件注册工具包，然后渲染一个返回 null 的小型子组件，由它提供闭包捕获其 `setState` 的执行器：

```tsx title="app/TaskBoard.tsx"
import {
  AuiConfig,
  AuiProvider,
  Tools,
  useAui,
  useAuiToolOverrides,
} from "@assistant-ui/react";
import { useState, type Dispatch, type SetStateAction } from "react";
import type { Task } from "./state";
import toolkit from "./task-board-toolkit";

function TaskBoard() {
  const [tasks, setTasks] = useState<Task[]>([]);
  const aui = useAui();
  const config = AuiConfig({ tools: Tools({ toolkit }) });
  return (
    <AuiProvider extends={aui} config={config}>
      <TaskBoardToolOverrides setTasks={setTasks} />
      <TaskList tasks={tasks} />
    </AuiProvider>
  );
}

function TaskBoardToolOverrides({
  setTasks,
}: {
  setTasks: Dispatch<SetStateAction<Task[]>>;
}) {
  useAuiToolOverrides({
    manage_tasks: {
      execute: async ({ action, id, title }) => {
        switch (action) {
          case "add":
            setTasks((prev) => [
              ...prev,
              { id: crypto.randomUUID(), title: title ?? "Untitled", done: false },
            ]);
            return { success: true };
          case "toggle":
            setTasks((prev) =>
              prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t)),
            );
            return { success: true };
          case "clear":
            setTasks([]);
            return { success: true };
          default:
            return { success: false, error: "Unknown action" };
        }
      },
    },
  });
  return null;
}
```

覆盖配置**仅**提供 `execute`；描述、参数和 `renderText` 仍保留在工具包文件中。覆盖配置的注册优先级高于工具包默认值，因此对于相应的工具名称，它会优先生效——返回有用的载荷（例如新项目的 `id`），模型便会在下一轮中获取该载荷。

<Callout type="info">
  挂载后保持覆盖配置的键稳定，并确保同一时间只有一个已挂载的 provider
  定义给定的工具名称。返回 null 的 overrides 组件会在 setter 发生变化时重新绑定执行器，
  而不会重新挂载 provider。
</Callout>

## 何时使用它，而不是 Interactables

如果你主要希望模型通过自动为你生成的部分更新工具来更新一部分组件状态，那么 [Interactables](/docs/tools/interactables) 开箱即用地支持这一点——无需 `stubTool`。当你希望完全控制工具的名称、schema、执行器逻辑和返回值时，请使用动态工具。两者可以组合使用：[with-interactables 示例](https://github.com/assistant-ui/assistant-ui/tree/main/examples/with-interactables) 同时展示了二者的用法。
