## 概览

assistant-ui 中的工具 UI 允许你创建在调用 AI 工具时显示的自定义界面。这些生成式 UI 组件可以通过以下方式提升用户体验：

- **可视化工具执行过程**，显示加载状态和进度指示器
- **显示结果**，使用丰富且格式化的布局
- **支持用户交互**，提供表单和控件
- **提供错误反馈**，包含有帮助的恢复选项

本指南将演示如何使用 **Vercel AI SDK** 构建工具 UI。

如果你希望让模型从一组 UI 词汇中组合界面，而不是为每个工具绑定一个组件，请参阅[生成式 UI](/docs/tools/generative-ui)。

## 创建工具 UI

工具 UI 注册在 toolkit 条目上。同一个条目可以定义由浏览器执行的前端工具、通过 `addResult` 完成的人机工具，或仅用于渲染的后端工具，其 schema 和执行逻辑位于服务器上。

### 1. 客户端定义的工具

如果你要在客户端创建工具，请使用 `Tools({ toolkit })` 将其注册到 toolkit 中。

```tsx title="app/toolkit.tsx"
"use generative";

import { defineToolkit } from "@assistant-ui/react";
import { z } from "zod";

export default defineToolkit({
  getWeather: {
    description: "Get current weather for a location",
    parameters: z.object({
      location: z.string(),
      unit: z.enum(["celsius", "fahrenheit"]),
    }),
    execute: async ({ location, unit }) => {
      "use client";
      return fetchWeatherAPI(location, unit);
    },
    render: ({ args, result, status }) => {
      if (status.type === "running") {
        return <div>Checking weather in {args.location}...</div>;
      }

      return (
        <div className="weather-card">
          <h3>{args.location}</h3>
          <p>
            {result.temperature}°{args.unit === "celsius" ? "C" : "F"}
          </p>
          <p>{result.description}</p>
        </div>
      );
    },
  },
});
```

```tsx title="app/MyRuntimeProvider.tsx"
import { AssistantRuntimeProvider, AuiConfig, Tools } from "@assistant-ui/react";
import { useChatRuntime } from "@assistant-ui/ai-sdk";
import toolkit from "./toolkit";

function MyRuntimeProvider({ children }: { children: React.ReactNode }) {
  const runtime = useChatRuntime();
  const config = AuiConfig({ tools: Tools({ toolkit }) });
  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

默认情况下，`useChatRuntime()` 以 `/api/chat` 为目标。如需指向其他端点或自定义请求，请参阅[自定义传输层](/docs/runtimes/ai-sdk/v7#custom-transport)。

<Callout type="tip">
  你可以使用 `frontendTools` 工具函数，将前端 toolkit 条目传递给后端。
</Callout>

如需进一步了解工具的创建方式，请参阅[工具指南](/docs/tools/defining-tools)。

### 2. 为现有工具仅添加 UI

如果你的工具定义在其他位置（例如后端 API、MCP server 或 LangGraph 中），请仅使用 `render` 注册一个后端 toolkit 条目：

```tsx
const toolkit = defineToolkit({
  getWeather: {
    type: "backend",
    render: ({ args, result, status }) => {
      // UI rendering logic only
    },
  },
});
```

```tsx title="/app/api/chat/route.ts"
export async function POST(req: Request) {
```

## 工具 UI 模式

### 组件模式

创建独立的工具 UI 组件：

```tsx
import type { ToolCallMessagePartComponent } from "@assistant-ui/react";

export const WebSearchToolUI: ToolCallMessagePartComponent<
  { query: string },
  { results: SearchResult[] }
> = ({ args, status, result }) => {
  return (
    <div className="search-container">
      <div className="mb-3 flex items-center gap-2">
        <SearchIcon />
        <span>Search results for: "{args.query}"</span>
      </div>

      {status.type === "running" && <LoadingSpinner />}

      {result && (
        <div className="space-y-2">
          {result.results.map((item, index) => (
            <div key={index} className="rounded border p-3">
              <a href={item.url} className="font-medium text-blue-600">
                {item.title}
              </a>
              <p className="text-sm text-gray-600">{item.snippet}</p>
            </div>
          ))}
        </div>
      )}
    </div>
  );
};
```

将其注册到 toolkit 中：

```tsx
const toolkit = defineToolkit({
```

### 动态 Toolkit 模式

当渲染器需要组件状态时，可以在单独的文件中使用 toolkit hook：

```tsx title="analyze-data-toolkit.tsx"
"use client";

import { defineToolkit, useInlineRender } from "@assistant-ui/react";
import { useMemo } from "react";

export function useAnalyzeDataToolkit(theme: "light" | "dark") {
  const renderAnalyzeData = useInlineRender(({ result, status }) => {
    return (
      <DataVisualization
        data={result}
        theme={theme}
        loading={status.type === "running"}
      />
    );
  });

  return useMemo(
    () =>
      defineToolkit({
        analyzeData: {
          type: "backend",
          render: renderAnalyzeData,
        },
      }),
    [renderAnalyzeData],
  );
}
```

```tsx title="DynamicToolUI.tsx"
import { AuiConfig, AuiProvider, Tools, useAui } from "@assistant-ui/react";
import { useState } from "react";
import { useAnalyzeDataToolkit } from "./analyze-data-toolkit";

function DynamicToolUI({ children }: { children: React.ReactNode }) {
```

## 交互式工具 UI

### 收集用户输入

创建在执行过程中收集用户输入的工具：

<Callout type="tip">
  **小贴士：**调用 `addResult(...)` 恰好一次，以完成工具调用。调用后，助手会使用你提供的数据继续对话。
</Callout>

```tsx
const toolkit = defineToolkit({
  selectDate: {
    type: "human",
    description: "Ask the user to select a date.",
    parameters: z.object({ prompt: z.string() }),
    render: ({ args, result, addResult }) => {
      if (result) {
        return (
          <div className="rounded bg-green-50 p-3">
            ✅ Selected date: {new Date(result.date).toLocaleDateString()}
          </div>
        );
      }

      return (
        <div className="rounded border p-4">
          <p className="mb-3">{args.prompt}</p>
          <DatePicker
            onChange={(date) => {
              addResult({ date: date.toISOString() });
            }}
          />
        </div>
      );
    },
  },
});
```

### 多步骤交互

使用人在回路（human in the loop）模式，为多步骤用户交互构建复杂工作流：

```tsx title="app/approval-toolkit.tsx"
"use generative";

import { defineToolkit } from "@assistant-ui/react";
import { z } from "zod";

export default defineToolkit({
  requestApproval: {
    description: "Request user approval for an action",
    parameters: z.object({
      action: z.string(),
      details: z.any(),
    }),
    execute: async ({ action, details }, { human }) => {
      "use client";
      // Request approval from user
      const response = await human({ action, details });

      return {
        approved: response.approved,
        reason: response.reason,
      };
    },
    render: ({ args, result, interrupt, resume }) => {
      const [reason, setReason] = useState("");

      // Show result after approval/rejection
      if (result) {
        return (
          <div className={result.approved ? "text-green-600" : "text-red-600"}>
            {result.approved ? "✅ Approved" : `❌ Rejected: ${result.reason}`}
          </div>
        );
      }

      // Show approval UI when waiting for user input
      if (interrupt) {
        return (
          <div className="rounded border-2 border-yellow-400 p-4">
            <h4 className="font-bold">Approval Required</h4>
            <p className="my-2">{interrupt.payload.action}</p>
            <pre className="rounded bg-gray-100 p-2 text-sm">
              {JSON.stringify(interrupt.payload.details, null, 2)}
            </pre>

            <div className="mt-4 flex gap-2">
              <button
                onClick={() => resume({ approved: true })}
                className="rounded bg-green-500 px-4 py-2 text-white"
              >
                Approve
              </button>
              <button
                onClick={() => resume({ approved: false, reason })}
                className="rounded bg-red-500 px-4 py-2 text-white"
              >
                Reject
              </button>
              <input
                type="text"
                placeholder="Rejection reason..."
                value={reason}
                onChange={(e) => setReason(e.target.value)}
                className="flex-1 rounded border px-2"
              />
            </div>
          </div>
        );
      }

      return <div>Processing...</div>;
    },
  },
});
```

<Callout type="tip">
  对于需要暂停工具执行并等待用户输入的工作流，请使用工具人类输入（`human()` / `resume()`）。对于“人机工具”，即 AI 请求工具调用但整个执行过程通过用户交互完成的场景，请使用 `addResult()`。
</Callout>

### 服务端审批门控

某些运行时（尤其是 AI SDK v7 中受 `toolApproval` 门控的工具）会在服务器上暂停，并发出审批请求；客户端必须确认该请求后，工具才会运行。assistant-ui 会在工具部分中通过 `approval` 暴露此状态，并在渲染器上提供 `respondToApproval({ approved, reason? })`：

```tsx
import { useState } from "react";
import type { ToolApprovalResponse } from "@assistant-ui/react";

const toolkit = defineToolkit({
  deploy: {
    type: "backend",
    render: ({ args, approval, respondToApproval, result }) => {
      const [error, setError] = useState<string | null>(null);

      if (approval?.approved === undefined) {
        // `try`/`await` rather than `.catch`: a rejected response and a
        // rejected precondition (an unknown option, an answer the request does
        // not take) reach the caller by different routes.
        const answer = async (response: ToolApprovalResponse) => {
          setError(null);
          try {
            await respondToApproval(response);
          } catch (failure) {
            setError(failure instanceof Error ? failure.message : String(failure));
          }
        };

        return (
          <div>
            <p>Approve deploy to {args.target}?</p>
            <button onClick={() => void answer({ approved: true })}>Approve</button>
            <button onClick={() => void answer({ approved: false, reason: "user denied" })}>
              Deny
            </button>
            {error && <p role="alert">{error}</p>}
          </div>
        );
      }

      if (approval?.approved === false) {
        return <p>Denied{approval.reason ? `: ${approval.reason}` : ""}</p>;
      }

      if (result === undefined) return <p>Approved, running…</p>;
      return <p>Deployed</p>;
    },
  },
});
```

`approval.approved` 是一个包含三种状态的信号：

- `undefined`：门控已打开，渲染器应向用户发起询问。只有在此状态下，`respondToApproval` 才是合法操作。
- `true`：已记录允许决定。服务器正在生成结果（或已经生成结果，可通过 `result` 获取）。
- `false`：已记录拒绝决定。运行时会记录错误结果（`isError`），并暴露 `approval.reason`。

当运行时根据服务端策略而非用户授予决定时，`approval.isAutomatic` 为 `true`；此时应渲染“自动批准”徽章，而不是显示按钮。

`respondToApproval` 返回一个 promise：运行时接受响应后，该 promise 将解析；如果响应无法记录（例如门控已过期，或提供方拒绝给定的答案），则会拒绝。请在禁用控件前等待该 promise，这样被拒绝的响应会使请求仍可重试，而不会消耗掉请求。

审批门控要求运行时实现相应功能：AI SDK v7 运行时会为受 `toolApproval` 门控的工具发出审批门控，`LocalRuntime` 支持由你的 `ChatModelAdapter` 发出的门控；请参阅 [LocalRuntime 审批门控](/docs/runtimes/custom/local-runtime#approval-gates)。对于由用户自行提供结果的工具，请改用 `unstable_humanToolNames` 和 `addResult`；请参阅[人在回路工具](/docs/runtimes/custom/local-runtime#human-in-the-loop-tools)。

关于通信层设置（`needsApproval`、`sendAutomaticallyWhen`），请参阅 [AI SDK v7 服务端工具审批](/docs/runtimes/ai-sdk/v7#server-side-tool-approval)。

### 审批选项

除了简单的允许 / 拒绝选项外，宿主还可以为一次审批附加决策选项列表，例如“仅允许一次”“在本次会话中允许”和“始终允许”。每个选项都包含机器可读的 `kind`（`"allow-once"`、`"allow-always"`、`"reject-once"`、`"reject-always"`）；会话与全局等作用域语义属于选项的 `id` 和 `label`，只有宿主会解释这些语义：

```ts
const approval = {
  id: "a1",
  options: [
    { id: "once", kind: "allow-once" },
    { id: "session", kind: "allow-always", label: "Allow for this session" },
    {
      id: "always",
      kind: "allow-always",
      label: "Always allow",
      grants: ["git *"],
      confirm: true,
    },
    { id: "deny", kind: "reject-once" },
  ],
};
```

渲染器会返回选中的选项，而不是布尔值；选项的 kind 会解析出对应的决定：

```tsx
respondToApproval({ optionId: "session" });
```

运行时会接收 `{ approvalId, approved, optionId, text?, reason? }`，因此，持久化“始终允许”决定的宿主可以使用 `optionId` 作为其存储键。持久化完全由宿主负责：assistant-ui 不会存储决定，也不会自动回答未来的审批。`grants` 列出选项将持久化的模式（在用户确认前显示给用户），`confirm` 则表示该选项需要经过确认步骤。带有自定义 `_` 前缀 kind 的选项必须通过显式的 `approved` 值进行回答，也可以同时提供 `optionId`，以便仍然记录所选选项。默认的 `ToolFallback` 栏会将这些选项与已知 kind 并列渲染，并在选中某个选项时发送 `{ optionId, approved: true }`，因为选择已声明的选项属于回答，而不是拒绝；当决策请求未声明 reject-kind 选项时，它也会继续提供 Deny 控件。

### 审批问题

审批请求可以询问权限以外的其他内容。`approval.prompt` 携带问题，`approval.display` 指定展示方式：`"decision"`（默认值）用于是 / 否门控，`"select"` 用于答案是 `approval.options` 之一的场景，`"text"` 用于用户输入答案的场景。`approval.allowFreeform` 支持在选项之外附带文本答案。

```ts
const approval = {
  id: "a1",
  prompt: "Which environment should I deploy to?",
  display: "select",
  allowFreeform: true,
  options: [
    { id: "staging", kind: "_staging", label: "Staging" },
    { id: "production", kind: "_production", label: "Production" },
  ],
};
```

渲染器会直接使用答案本身回答自由格式请求：

```tsx
respondToApproval({ text: "staging" });
```

运行时会将其记录为 `{ approvalId, approved: true, text }`，因为回答问题并不等同于拒绝问题。如果请求既未声明 `display: "text"`，也未声明 `allowFreeform`，则 `text` 响应会抛出异常，从而确保宿主不会收到无处记录的答案。

单独的答案只能解决问题。对于决策，审批本身就是授权，因此在此场景下单独使用 `text` 会抛出异常；答案必须与显式决策（`{ approved, text }`）或所选选项一同提供，否则输入的文本备注将会授权该调用。因此，在决策中使用 `allowFreeform` 时，它会为决策添加注释，而不是替代决策；这也是默认的 `ToolFallback` 会在 Allow 和 Deny 旁显示文本字段、且不提供单独提交按钮的原因。问题没有实际意义上的拒绝操作，因此默认的 `ToolFallback` 会为问题渲染文本字段，并省略它在决策中添加的 Deny 控件。

并非所有运行时都会发出这些字段。Eve runtime 会将其输入请求映射到这些字段。AI SDK v7 runtime 的门控从设计上就是布尔值，而 AG-UI runtime 只接受其响应 schema 能够通过决策回答的门控，因此二者都会继续发送普通决策，并且仅在门控提供时携带 `prompt`。

以无决策结束的审批（例如运行被取消或请求已过期）会由宿主记录为 `approval.resolution: "cancelled" | "expired"`，这会关闭门控，但不会记录拒绝。

默认的 `ToolFallback` 组件会自动渲染所提供的选项，包括确认步骤。

## 高级功能

### 工具状态处理

`status` prop 提供详细的执行状态：

```tsx
render: ({ status, args }) => {
  switch (status.type) {
    case "running":
      return <LoadingState />;

    case "requires-action":
      return <UserInputRequired reason={status.reason} />;

    case "incomplete":
      if (status.reason === "cancelled") {
        return <div>Operation cancelled</div>;
      }
      if (status.reason === "error") {
        return <ErrorDisplay error={status.error} />;
      }
      return <div>Failed: {status.reason}</div>;

    case "complete":
      return <SuccessDisplay />;
  }
};
```

### 延迟渲染

<Callout type="info">
本节适用于模型通过工具调用**驱动**组件的场景（参数会逐步到达，而你希望等待最终形状）。如果组件由后端或编排器推送，请优先使用带有 `makeAssistantDataUI` 的[数据部分生成式 UI](#data-part-generative-ui)。数据部分会作为终止事件到达，因此渲染器只会使用最终数据触发一次，无需延迟渲染。
</Callout>

有时你需要捕获工具调用的流式参数，但只在调用完成后渲染最终 UI。当部分参数会渲染出具有误导性或令人不适的中间状态（例如图表不断闪过填充了一半的数据）、组件挂载成本较高（例如复杂可视化、嵌入式 iframe、第三方小部件），或模型控制组件是否显示时，这种方式非常有用。

#### 在流式传输结束时内联显示

在工具 UI 的 `render` 中返回 `null`，直到 `status.type === "complete"`。模型发出参数时，流式参数仍会到达 `args`，但在调用完成前可以忽略这些参数：

```tsx
const toolkit = defineToolkit({
  renderChart: {
    type: "backend",
    render: ({ args, status }) => {
      if (status.type !== "complete") return null;
      return <Chart title={args.title} data={args.series} />;
    },
  },
});
```

流式传输结束后，图表只会使用最终参数挂载一次。流式传输期间不会重新渲染。

相同的 `render` 结构也适用于 [`Tools()`](/docs/tools/defining-tools) toolkit 的 `render` 字段，以及 `MessagePrimitive.Parts` 的内联 `tools.by_name` 覆盖配置。

#### 位于消息正文下方

如果组件应位于消息部分*之外*（例如附加在头像区块下方、而不是与文本内联），请通过[`AuiIf`](/docs/api-reference/primitives/assistant-if)在消息级别进行门控，并读取 `s.message.status`：

```tsx
import { MessagePrimitive, AuiIf, useAuiState } from "@assistant-ui/react";

function PostMessageCard() {
  const parts = useAuiState((s) => s.message.parts);
  const chartCall = parts.find(
    (p) => p.type === "tool-call" && p.toolName === "renderChart",
  );
  if (!chartCall) return null;
  return <Chart {...chartCall.args} />;
}

<MessagePrimitive.Root>
  <MessagePrimitive.Parts />

  <AuiIf
    condition={(s) =>
      s.message.role === "assistant" &&
      s.message.status?.type === "complete"
    }
  >
    <PostMessageCard />
  </AuiIf>
</MessagePrimitive.Root>;
```

每当助手状态发生变化时，`AuiIf` 谓词都会触发；只有两个检查都通过时，子元素才会挂载。随后，`PostMessageCard` 会从 `s.message.parts` 读取捕获的工具调用部分，并根据其参数进行渲染。

关于相反的模式（在数据流式传输时显示部分数据），请参阅下方的[字段级流式状态](#field-level-streaming-state)和[部分结果与流式传输](#partial-results--streaming)。

### 字段级流式状态

使用 `useToolArgsStatus` 响应每个字段的流式状态。该 hook 返回一个 `propStatus` 映射，其中 args 对象的每个顶级键都会随着部分 JSON 的到达，从 `"streaming"` 解析为 `"complete"`。请在工具调用消息部分的上下文中调用它：

```tsx
import { useToolArgsStatus } from "@assistant-ui/react";

const toolkit = defineToolkit({
  submitForm: {
    type: "backend",
    render: ({ args }) => {
      const { propStatus } = useToolArgsStatus<{
        email: string;
        phone: string;
      }>();

      return (
        <form className="space-y-4">
          <div>
            <input
              type="email"
              value={args.email ?? ""}
              className={propStatus.email === "streaming" ? "loading" : ""}
              disabled
            />
          </div>

          <div>
            <input
              type="tel"
              value={args.phone ?? ""}
              className={propStatus.phone === "streaming" ? "loading" : ""}
              disabled
            />
          </div>
        </form>
      );
    },
  },
});
```

### 部分结果与流式传输

在结果流式传输时显示结果：

```tsx
const toolkit = defineToolkit({
  analyzeData: {
    type: "backend",
    render: ({ result, status }) => {
      const progress = result?.progress || 0;
      const insights = result?.insights || [];

      return (
        <div className="analysis-container">
          {status.type === "running" && (
            <div className="mb-4">

                <span>Analyzing...</span>
                <span>{progress}%</span>
              </div>
              <div className="w-full rounded bg-gray-200">
                <div
                  className="h-2 rounded bg-blue-500"
                  style={{ width: `${progress}%` }}
                />
              </div>
            </div>
          )}

          <div className="space-y-2">
            {insights.map((insight, i) => (
              <div key={i} className="rounded bg-gray-50 p-2">

              </div>
            ))}
          </div>
        </div>
      );
    },
  },
});
```

## 执行上下文

生成式 UI 组件可以通过 props 访问执行上下文：

```tsx
type ToolCallMessagePartProps<TArgs, TResult> = {
  // Tool arguments
  args: TArgs;
  argsText: string; // JSON stringified args

  // Execution status
  status: ToolCallMessagePartStatus;
  isError?: boolean;

  // Tool result (may be partial during streaming)
  result?: TResult;

  // Tool metadata
  toolName: string;
  toolCallId: string;

  // Interactive callbacks
  addResult: (result: TResult | ToolResponse<TResult>) => void;
  resume: (payload: unknown) => void;

  // Interrupt state
  interrupt?: { type: "human"; payload: unknown }; // Payload from context.human()

  // Optional artifact data
  artifact?: unknown;
};
```

### 人类输入处理

工具在执行过程中调用 `human()` 时，有效负载会以 `interrupt.payload` 的形式在渲染函数中可用：

```tsx
const toolkit = defineToolkit({
  confirmAction: {
    type: "backend",
    render: ({ args, result, interrupt, resume }) => {
      // Tool is waiting for user input
      if (interrupt) {
        return (
          <div className="confirmation-dialog">
            <p>Confirm: {interrupt.payload.message}</p>
            <button onClick={() => resume(true)}>Yes</button>
            <button onClick={() => resume(false)}>No</button>
          </div>
        );
      }

      // Tool completed
      if (result) {
        return <div>Action {result.confirmed ? "confirmed" : "cancelled"}</div>;
      }

      return <div>Processing...</div>;
    },
  },
});
```

如需进一步了解工具人类输入，请参阅[工具指南](/docs/tools/defining-tools#human-tools)。

使用 `useInlineRender` 防止不必要的重新渲染：

```tsx title="heavy-computation-toolkit.tsx"
"use client";

import { defineToolkit, useInlineRender } from "@assistant-ui/react";
import { useMemo } from "react";

export function useHeavyComputationToolkit() {
  const renderHeavyComputation = useInlineRender(({ result }) => {

      defineToolkit({

  );
}
```

```tsx title="HeavyComputationToolProvider.tsx"
import { AuiConfig, AuiProvider, Tools, useAui } from "@assistant-ui/react";
import type { ReactNode } from "react";
import { useHeavyComputationToolkit } from "./heavy-computation-toolkit";

function HeavyComputationToolProvider({ children }: { children: ReactNode }) {
  const toolkit = useHeavyComputationToolkit();
  const aui = useAui();
  const config = AuiConfig({ tools: Tools({ toolkit }) });

  return (
    <AuiProvider extends={aui} config={config}>
      {children}
    </AuiProvider>
  );
}
```

## 数据部分生成式 UI

除了工具调用渲染之外，assistant-ui 还支持另一种基于 `DataMessagePart` 的生成式 UI 机制。后端（或 LangGraph graph）不会将 UI 附加到工具调用上，而是发出命名的数据事件，并将其作为 `{ type: "data", name, data }` 部分追加到父级助手消息中。

**如何选择：**

- **工具 UI**：由**模型**通过调用工具决定渲染什么，工具参数会成为组件数据。通过 [`Tools()`](/docs/tools/defining-tools) toolkit 的 `render` 字段注册渲染器。参数会逐步进行流式传输，因此可以通过 `status` / `useToolArgsStatus` 观察部分状态；对于只能在最终数据到达后挂载的组件，可能需要使用[延迟渲染](#deferred-rendering)。
- **数据 UI**（`makeAssistantDataUI`）：由**后端或编排器**决定渲染什么，并将命名的数据事件推送到助手消息中。数据部分会作为终止事件到达，不包含流式部分，因此渲染器自然只会使用最终数据触发一次。

如果你希望组件仅在消息完成后显示，并且能够控制后端，那么数据 UI 通常是更直接的选择；如果必须由模型本身决定是否显示组件，请使用工具 UI 的延迟渲染模式。

使用 `makeAssistantDataUI` 为命名的数据部分注册渲染器：

```tsx
import { makeAssistantDataUI } from "@assistant-ui/react";

type ChartProps = { series: number[]; title: string };

export const ChartUI = makeAssistantDataUI<ChartProps>({
  name: "chart",
  render: ({ data }) => (
    <div>
      <h3>{data.title}</h3>
      <Chart series={data.series} />
    </div>
  ),
});
```

在 `AssistantRuntimeProvider` 树中挂载 `<ChartUI />` 一次；它本身不会渲染任何内容，只负责注册渲染器。

关于 LangGraph 特有的模式（通过 `push_ui_message` / `typedUi` 从 Python/TypeScript graph 节点发出 UI、使用 `LoadExternalComponent` 动态加载，以及 `useLangGraphUIMessages` 逃生舱），请参阅 [LangGraph 生成式 UI](/docs/runtimes/langgraph/generative-ui)。

内部提供了用于匹配不到的数据部分的回退渲染器，但 `setFallbackDataUI` 目前还不是公开 API。
