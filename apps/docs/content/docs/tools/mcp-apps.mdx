[MCP Apps](https://apps.extensions.modelcontextprotocol.io/) 允许 Model Context Protocol 服务器随工具一同提供 UI 资源——一个自包含的 HTML 小组件，在调用工具时由聊天宿主内联渲染。assistant-ui 提供原生渲染器，通过 [`SafeContentFrame`](/safe-content-frame) 将小组件挂载到沙盒 iframe 中，并运行 JSON-RPC postMessage 桥接，使小组件能够调用工具、发送消息、请求显示模式以及读取宿主上下文。

## 概览

当 MCP 服务器为工具附加 `_meta.ui.resourceUri`（即 [`text/html;profile=mcp-app`](https://apps.extensions.modelcontextprotocol.io/api/index.html) MIME) 时，AI SDK 会通过消息流转发该元数据。assistant-ui 的渲染器会从 `ToolCallMessagePart` 的 `mcp` 字段中读取它，通过你的后端路由获取资源并挂载。

渲染器只处理以 `ui://` 开头的 URI（符合 MCP Apps 规范）。`resourceUri` 使用其他 scheme 的工具会被视为非 MCP Apps 工具，并交由你常规的工具 UI 处理。

小组件通过 JSON-RPC 桥接进行通信：

- **小组件 → 宿主请求**：`ui/initialize`、`tools/call`、`resources/read`、`resources/list`、`openLink`、`sendMessage`、`requestDisplayMode`、`updateModelContext`
- **宿主 → 小组件通知**：工具输入流式传输、工具结果、宿主上下文变化
- **小组件 → 宿主通知**：已初始化、尺寸变化、日志、错误、请求拆除

是否具备某项能力取决于挂载时你提供了哪些处理器。未知方法返回 JSON-RPC `-32601`；参数错误返回 `-32602`。

## 快速开始

渲染器会与你公开的后端路由通信——MCP 客户端位于服务端，因此凭证和传输层不会暴露在浏览器中。路由接收 `{ method, params }` POST 请求，并将其分发给 MCP 客户端。

### 安装 MCP 客户端

安装路由处理器使用的 AI SDK MCP 客户端包：

<InstallCommand npm={["@ai-sdk/mcp"]} />

### 客户端

将 `McpAppRenderer({...})` 组合到你的 `Tools` 资源中。提供指向路由的 `host.url`。任何携带 `mcp.app` 元数据的工具调用部分都会自动渲染 MCP App 小组件。

```tsx
import {
  AuiConfig,
  AuiProvider,
  Tools,
  McpAppRenderer,
  McpAppsRemoteHost,
  useAui,
} from "@assistant-ui/react";

function MyAssistant({ children }) {
  const aui = useAui();
  const config = AuiConfig({
    tools: Tools({
      toolkit: myToolkit,
      mcpApp: McpAppRenderer({
        host: McpAppsRemoteHost({ url: "/api/mcp-apps" }),
        hostInfo: { name: "my-app", version: "1.0.0" },
        hostContext: { theme: "light" },
      }),
    }),
  });
  return (
    <AuiProvider extends={aui} config={config}>
      {children}
    </AuiProvider>
  );
}
```

`McpAppsRemoteHost` 是默认的宿主策略——它会将 `{ method, params }` POST 到你的路由。你也可以编写自定义资源，返回相同的 `McpAppsHost` 结构（`{ loadResource, callTool, readResource, listResources }`），从而接入其他策略（例如客户端 MCP 客户端）。

对 `headers` 或自定义 `fetch` 函数的修改，会应用于后续宿主请求，而无需重新加载小组件。当账户或工作区身份发生变化时，请显式为宿主资源设置 key，以便重新加载其 UI 资源。

安装资源辅助工具：

```bash
pnpm add @assistant-ui/tap
```

```tsx
import { withKey } from "@assistant-ui/tap";

const mcpApp = McpAppRenderer({
  host: withKey(
    workspaceId,
    McpAppsRemoteHost({
      url: "/api/mcp-apps",
      headers: () => getWorkspaceHeaders(workspaceId),
    }),
  ),
});
```

`openLink` 会自动连接到 `window.open(url, "_blank", "noopener,noreferrer")`。`sendMessage` 会自动连接为当前线程追加用户消息。它接受 MCP Apps 的 `{ role, content }` 参数，并按顺序追加每个 `text` 块，以及传统的 `string`、`{ prompt }`、`{ text }` 和 `{ message }` 形式。宿主会在 `ui/initialize` 期间公布 `message: { text: {} }`，因此非文本块会被丢弃；不包含文本的请求会解析为 `{ isError: true }`。

当小组件需要宿主侧 UI 或生命周期回调时，传入 `handlers`。这些能力会在挂载期间公布，因此请在小组件初始化前提供处理器：

```tsx
McpAppRenderer({
  host: McpAppsRemoteHost({ url: "/api/mcp-apps" }),
  handlers: {
    requestDisplayMode: ({ mode }) => applyHostDisplayMode(mode),
    updateModelContext: applyHostModelContext,
    openLink: ({ url }) => window.open(url, "_blank", "noopener,noreferrer"),
  },
});
```

`requestDisplayMode` 应更新宿主界面，并返回实际接受的模式。仅回显 `{ mode }` 而不实际应用它，会让小组件认为修改成功，但宿主仍保持 `inline`。

调用方处理器会覆盖默认的 `openLink` 和 `sendMessage` 行为，并可以提供 `requestDisplayMode`、`updateModelContext` 以及 `onInitialized`、`onSizeChange` 等生命周期钩子。`callTool`、`readResource` 和 `listResources` 仍绑定到已配置的 `host`；如需修改这些数据平面操作，请使用自定义宿主。

### 每个应用的选项

一个渲染器会服务线程中的所有 MCP App，因此 `hostContext`、`handlers` 及其他显示选项都是线程范围的默认值。当某个应用需要独立的值时，传入 `forPart`。它会针对每次 MCP App 工具调用运行，并且返回的每个选项都会仅替换该应用的线程级选项。

`handlers` 是例外：它按 key 合并。因此，仅返回 `requestDisplayMode` 的解析器会为该应用保留线程范围的 `onError` 和 `onInitialized`。其中的 key 是与小组件协商的能力，而不是数据；如果为了添加一个处理器而替换整个对象，该应用的其他能力就会被撤回，且没有任何观察者能够感知这一变化。请指定要覆盖的 key。

```tsx
const [modes, setModes] = useState<Record<string, McpAppDisplayMode>>({});

McpAppRenderer({
  host: McpAppsRemoteHost({ url: "/api/mcp-apps" }),
  hostInfo: { name: "my-app", version: "1.0.0" },
  hostContext: { theme },
  forPart: (part) => ({
    hostContext: {
      theme,
      displayMode: modes[part.toolCallId] ?? "inline",
      availableDisplayModes: ["inline", "fullscreen", "pip"],
    },
    handlers: {
      requestDisplayMode: ({ mode }) => {
        setModes((current) => ({ ...current, [part.toolCallId]: mode }));
        return { mode };
      },
    },
  }),
});
```

解析器会闭包捕获该部分，因此 `requestDisplayMode` 知道是哪个应用发起了请求，授予的模式也只会通过 `notifications/host_context/changed` 传递给该应用。返回值可以在每次渲染时重新构建；如果宿主上下文的结构未发生变化，就不会传递给小组件。

`forPart` 会在某个部分首次渲染前解析，因此每个部分从一开始就会使用对应的值。之后对某个选项的修改能否传递，取决于该选项。`hostContext` 会在每次变化时再次发送。处理器通过实时引用调用，但框架挂载时会捕获已存在的处理器 key，因此每次渲染时都应为同一部分返回相同的 key。`hostInfo` 以及 `sandbox` 中的框架设置（`className` 和 `style` 除外）也只会在挂载时读取一次，因此在生命周期中途修改它们不会生效，除非应用的资源 URI 发生变化并重新构建框架。

### 路由处理器

路由接受带有 `{ method, params }` JSON 请求体的 `POST` 请求。根据方法名进行分发，并将结果作为 JSON 返回。以下是 Next.js App Router 示例：

```ts
// app/api/mcp-apps/route.ts
import { createMCPClient } from "@ai-sdk/mcp";

const serverUrls = new Map([
  ["search", process.env.SEARCH_MCP_SERVER_URL!],
  ["calendar", process.env.CALENDAR_MCP_SERVER_URL!],
]);
const fallbackServerUrl = process.env.MCP_SERVER_URL!;
const clientPromises = new Map<string, ReturnType<typeof createMCPClient>>();

const getClient = (serverId?: string) => {
  const url = serverId ? serverUrls.get(serverId) : fallbackServerUrl;
  if (!url) throw new Error(`Unknown MCP server: ${serverId}`);
  let clientPromise = clientPromises.get(url);
  if (!clientPromise) {
    clientPromise = createMCPClient({
      transport: { type: "sse", url },
    }).catch((error) => {
      clientPromises.delete(url);
      throw error;
    });
    clientPromises.set(url, clientPromise);
  }
  return clientPromise;
};

export async function POST(req: Request) {
  const { method, params } = await req.json();
  const client = await getClient(params?.serverId);

  switch (method) {
    case "mcp-apps/read-resource": {
      const { contents } = await client.readResource({ uri: params.uri });
      const c = contents.find((x: { uri: string }) => x.uri === params.uri);
      return Response.json({
        uri: params.uri,
        mimeType: "text/html;profile=mcp-app",
        html: c?.text ?? "",
      });
    }
    case "tools/call": {
      const tools = await client.tools();
      const tool = tools[params.name];
      if (!tool?.execute) {
        return Response.json({ error: "Tool not callable" }, { status: 400 });
      }
      return Response.json(
        await tool.execute(params.arguments ?? {}, {
          toolCallId: `mcp-apps-bridge-${crypto.randomUUID()}`,
          messages: [],
        }),
      );
    }
    case "resources/read":
      return Response.json(await client.readResource({ uri: params.uri }));
    case "resources/list": {
      const { serverId: _, ...listParams } = params ?? {};
      return Response.json(await client.listResources(listParams));
    }
    default:
      return Response.json({ error: "Unsupported method" }, { status: 400 });
  }
}
```

渲染器会 POST 四个方法名：`mcp-apps/read-resource`、`tools/call`、`resources/read`、`resources/list`。请在服务端拒绝其他请求，并在路由中自行应用身份验证和速率限制。

### 多个 MCP 服务器

当工具部分携带 `mcp.app.serverId` 时，渲染器会将其作为 `params.serverId` 转发给宿主操作，以便路由选择拥有该资源或工具的 MCP 客户端。代理栈会在部分元数据中发出这一可路由身份。对于 `@ag-ui/mcp-apps-middleware`，assistant-ui 使用其配置的 `serverId`；当 `serverId` 缺失或为空时，则回退到 `serverHash`。请将路由映射的 key 与你的设置实际发出的身份保持一致：可以在每个中间件服务器上配置显式的 `serverId`，也可以使用发出的哈希作为映射 key。省略 `serverId` 会保留单服务器行为，路由示例中的回退客户端展示了这一点。

按名称注册的 `setToolUI` 始终优先于 MCP 回退，因此你仍然可以自定义特定工具。

## AI SDK 集成

`@assistant-ui/ai-sdk` 会将 AI SDK 工具 UI 部分中的 `callProviderMetadata.mcp.app` 转发到 `ToolCallMessagePart.mcp.app`。使用 AI SDK 5.x 和支持 MCP Apps 的 MCP 服务器时，无需对部分结构进行额外接线。

丰富的 UI 来自 MCP 服务器的元数据，而不是模型，因此无论由哪个提供商驱动对话，流程都相同。运行 Claude 只是 `streamText` 中不同的 `model:`（通过 `@ai-sdk/anthropic` 使用 `anthropic("claude-sonnet-4-6")`）；MCP 服务器、`splitMcpAppTools` 和渲染器都无需改变。MCP Apps 是 MCP 生态中的开放标准（Claude 是其宿主之一），因此标准 MCP Apps 服务器开箱即用。下面的桥接仅适用于使用 OpenAI `openai/outputTemplate` 约定的服务器，与运行哪个模型无关。

在聊天路由中，使用 `splitMcpAppTools()`（来自 `@ai-sdk/mcp`），将仅供应用使用的工具排除在模型视图之外：

```ts
import { splitMcpAppTools } from "@ai-sdk/mcp";

const tools = await client.listTools();
const { modelVisible } = splitMcpAppTools(tools);

const result = streamText({
  model: openai("gpt-5.6-luna"),
  tools: modelVisible.tools,
  // ...
});
```

### OpenAI Apps SDK 服务器

[OpenAI Apps SDK](https://developers.openai.com/apps-sdk) 服务器使用另一种约定携带相同的 `ui://` 模板：工具定义上的指针是 `_meta["openai/outputTemplate"]`（而不是 `_meta.ui.resourceUri`），资源通过 `text/html+skybridge` 提供，而不是 `text/html;profile=mcp-app`。`@ai-sdk/mcp` 无法识别 `openai/outputTemplate`，因此不会填充 `callProviderMetadata.mcp.app`，渲染器也会保持空闲。

无需修改渲染器，只需将该指针暴露出来。assistant-ui 会从工具结果中读取规范的 `result._meta.ui.resourceUri`（同时仍接受已弃用的扁平字段 `result._meta["ui/resourceUri"]`），因此最简单的桥接方式是按工具名称将模板复制到结果中。根据工具列表构建一次映射，然后在每个工具的 `execute` 中写入：

```ts
import type { Tool } from "ai";

// reuse the listTools() result from the AI SDK integration step above; no second round-trip
const templateByTool = new Map(
  tools.tools
    .filter((t) => typeof t._meta?.["openai/outputTemplate"] === "string")
    .map((t) => [t.name, t._meta["openai/outputTemplate"] as string]),
);

const withTemplateUri = (tool: Tool, name: string): Tool => {
  const uri = templateByTool.get(name);
  const exec = tool.execute;
  if (!uri || !exec) return tool;
  return {
    ...tool,
    execute: async (args, options) => {
      const result = (await exec(args, options)) as { _meta?: Record<string, unknown> };
      return {
        ...result,
        _meta: {
          ...result._meta,
          ui: { ...(result._meta?.["ui"] as Record<string, unknown>), resourceUri: uri },
        },
      };
    },
  } satisfies Tool;
};
```

将 AI SDK 工具对象传给 `streamText` 之前先进行包装：

```ts
const aiTools = await client.tools();
const wrappedTools = Object.fromEntries(
  Object.entries(aiTools).map(([name, t]) => [name, withTemplateUri(t, name)]),
);
// pass wrappedTools to streamText
```

你的 `mcp-apps/read-resource` 处理器会读取 `ui://` 资源，方式与上面的路由示例相同。将响应的 `mimeType` 设置为 `McpAppResource` 所需的 `text/html;profile=mcp-app` 字面量，并将服务器的 HTML 保存在 `html` 中；不要转发原始的 `text/html+skybridge` 值，因为该类型会拒绝它。

更长期、更简洁的修复方式是在上游解决：如果 `@ai-sdk/mcp` 的 `getMCPAppToolMeta` 也读取 `openai/outputTemplate`，那么 `callProviderMetadata.mcp.app` 就会自动填充，无需此桥接。

## AG-UI 集成

使用 `@assistant-ui/react-ag-ui` 时，后端通过 `ACTIVITY_SNAPSHOT` 将 MCP App 与工具调用关联起来。在多个服务器之间路由时，请包含工具调用 ID、应用的 `ui://` 资源 URI 以及 MCP 服务器身份：

```json
{
  "type": "ACTIVITY_SNAPSHOT",
  "activityType": "mcp-apps",
  "content": {
    "toolCallId": "call-1",
    "resourceUri": "ui://maps/result.html",
    "serverId": "maps",
    "result": {
      "content": [{ "type": "text", "text": "Map ready" }],
      "structuredContent": { "center": [37.77, -122.42] },
      "_meta": { "initialView": "street" },
      "isError": false
    }
  }
}
```

`serverId` 是可选的。如果缺失，运行时会接受 `serverHash` 作为回退。较旧的中间件可能省略 `toolCallId`，此时快照会应用于最近解析的工具调用；新的集成应包含它，以便明确关联并发的工具调用。请在工具调用的 `TOOL_CALL_START` 之后发出快照。快照中指定了从历史记录恢复的工具调用时，它会直接应用于对应消息，因此在 `MESSAGES_SNAPSHOT` 后重新发出该活动即可重新水合其小组件；对于运行时从未见过的工具调用 ID，快照会被静默忽略。

发送常规的 `TOOL_CALL_RESULT`，并附带简洁、对模型可见的摘要：

```json
{
  "type": "TOOL_CALL_RESULT",
  "toolCallId": "call-1",
  "content": "Map ready"
}
```

快照的 `result` 会成为小组件可见的 `part.result`；而 `TOOL_CALL_RESULT.content` 字符串会作为 `part.modelContent` 保留给模型，即文本内容部分数组（`[{ "type": "text", "text": "Map ready" }]`）。

或者，AG-UI 服务器也可以直接在 `TOOL_CALL_RESULT` 上放置 MCP 宿主字段：

```json
{
  "type": "TOOL_CALL_RESULT",
  "toolCallId": "call-1",
  "content": "Map ready",
  "structuredContent": { "center": [37.77, -122.42] },
  "_meta": { "initialView": "street" },
  "isError": false
}
```

在这种形式下，运行时会根据 `content`、`structuredContent`、`_meta` 和 `isError` 组装出符合 `CallToolResult` 结构的 `part.result`。`structuredContent` 或 `_meta` 至少必须存在一个；如果两者都不存在，则不会启用增强路径，结果会回退为普通的 `content` 字符串。`_meta` 也可以携带应用指针本身（规范字段 `ui.resourceUri` 或已弃用的扁平字段 `"ui/resourceUri"`），此时无需 `ACTIVITY_SNAPSHOT` 即可激活小组件。快照仍然是传递服务器身份（`serverId`）的唯一载体；如果两者都提供 `resourceUri`，则以快照为准。

可见性划分遵循 MCP Apps 契约：`content` 对模型可见；`structuredContent` 和 `_meta` 仅对宿主和小组件可用。当 assistant-ui 将历史记录序列化到后续 AG-UI 请求中时，会发送保存的模型可见文本，绝不会包含 `structuredContent` 或 `_meta`。

## 桥接协议

该桥接通过 `window.postMessage` 实现 MCP UI JSON-RPC 协议，并同时根据 `event.source === frame.iframe.contentWindow` 和 `event.origin === frame.origin` 进行过滤——跨源域 `SafeContentFrame` 会为每次渲染生成。来自其他源或窗口的消息会被静默丢弃。

### 小组件 → 宿主请求

| 方法 | 说明 |
|---|---|
| `ui/initialize` | 返回 `{ protocolVersion, host, hostContext, capabilities }`。始终支持。 |
| `tools/call` | 使用方法 `tools/call` 路由到 `host.url`。可选的 `handlers.allowedTools` 允许列表。`arguments` 结构无效 → `-32602`。 |
| `resources/read` | 使用方法 `resources/read` 路由到 `host.url`。 |
| `resources/list` | 使用方法 `resources/list` 路由到 `host.url`。 |
| `openLink` | 需要 `handlers.openLink`。对于非 `http(s)` URL，使用 `-32602` 拒绝。 |
| `sendMessage` | 需要 `handlers.sendMessage`。 |
| `requestDisplayMode` | 需要 `handlers.requestDisplayMode`。模式：`inline`、`fullscreen`、`pip`。 |
| `updateModelContext` | 需要 `handlers.updateModelContext`。 |

未提供处理器时，桥接会返回 JSON-RPC `-32601`（找不到方法）；在 `ui/initialize` 响应中，`capabilities` 也会以同样方式报告。

### 宿主 → 小组件通知

- `notifications/tools/call/input` — `part.args`（流式工具输入）发生变化时发送
- `notifications/tools/call/result` — 工具结果到达时发送（包括错误封装）
- `notifications/host_context/changed` — `hostContext` 发生变化时发送（例如用户切换主题）

### 小组件 → 宿主通知

`notifications/initialized`、`notifications/size_changed`、`notifications/log`、`notifications/error`、`notifications/request_teardown` — 分别通过 `handlers.onInitialized`、`onSizeChange`、`onLog`、`onError`、`onRequestTeardown` 接入。

如果小组件始终不发送 `notifications/initialized`（例如已损坏或不符合规范），宿主会在 5 秒安全超时后刷新排队中的通知，避免 iframe 看起来像是卡住了。

## 沙盒

iframe 使用 [`SafeContentFrame`](/safe-content-frame) 构建，它会从经过内容哈希的跨源中提供每个小组件，因此宿主页面无法通过 `same-origin` 引用访问它。默认的 sandbox 标志为 `allow-same-origin allow-scripts`。可以通过 `McpAppRendererOptions` 上的 `sandbox` 字段进行调整：

```tsx
McpAppRenderer({
  // ...
  sandbox: {
    sandbox: ["allow-forms", "allow-popups"],
    enableBrowserCaching: true,
    className: "my-mcp-app",
  },
});
```

## 安全说明

- 小组件在沙盒 iframe 中跨源运行。桥接会同时根据源窗口和源进行过滤。
- 宿主路由是你的身份验证边界——请在那里应用会话检查、速率限制和按工具设置的允许列表。渲染器会信任路由返回的所有内容。
- `openLink` 会在桥接层拒绝非 `http(s)` URL，但你的 `openLink` 处理器仍应将 URL 视为不可信输入（例如始终使用 `noopener,noreferrer`）。
- 请在多次渲染之间保持自定义 `host` 和 `handlers` 引用稳定（例如使用模块作用域常量或 `useMemo`）；不稳定的自定义宿主身份会使小组件保持在 `loadingFallback`，并在父组件每次重新渲染时重新获取资源。
