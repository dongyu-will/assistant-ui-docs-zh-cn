---
title: WebMCP provider
description: 使用 unstable_useWebMcpProvider 将应用的前端工具暴露给支持 WebMCP 的浏览器。
---

WebMCP 是一种浏览器原生方式，页面可以通过 `document.modelContext`（以 `navigator.modelContext` 作为回退方案）向*用户*正在运行的代理发布工具。页面调用 `registerTool`，代理即可调用该工具。

默认情况下，explainer 会将已注册的工具暴露给页面自身、同一框架树中同源的文档，以及浏览器内置的代理。要触达其他源中的作者提供的代理，需要使用 `exposedTo` 选项；此 hook 不会设置该选项，因此除非情况发生变化，否则应将受众视为内置代理。

`unstable_useWebMcpProvider` 连接了你已有的两个方向。assistant-ui 模型上下文中注册的每个前端工具都会发布到浏览器的 WebMCP 主机，结果则通过聊天运行时使用的同一个 `Tool` 契约返回。你只需定义一次工具；你的助手和用户的浏览器代理都可以调用它。

<Callout type="warn">
  此 hook 是 `unstable_`。WebMCP 本身仍是新兴的浏览器 API，而此 hook 的
  形式也会随之变化。它不受通常的仅追加表面保证约束。
</Callout>

## 用法

在 `AuiProvider` 内部任意位置挂载一次：

```tsx title="app/page.tsx"
import { unstable_useWebMcpProvider } from "@assistant-ui/react";

const WebMcpTools = () => {
  const { status, registeredToolNames } = unstable_useWebMcpProvider();

  if (status === "unsupported") return null;
  return <span>Exposed to your browser: {registeredToolNames.join(", ")}</span>;
};
```

当页面没有 `modelContext` 时，`status` 为 `"unsupported"`——也就是目前所有不支持 WebMCP 的浏览器；provider 运行后则为 `"active"`。检查会在 hook 挂载时执行，且不会重复执行：WebMCP 没有定义可用性事件，provider 也不会轮询，因此向已渲染页面注入 `modelContext` 的扩展只有在下一次挂载时才会被检测到。`registeredToolNames` 是 provider 正在发布的名称排序列表；如果主机拒绝某个名称（因为页面已经注册了该名称，或页面的工具权限已关闭），该名称会在收到拒绝后从列表中移除。名称会在其注册设置完成的那次提交中出现，因此应将此列表视为 provider 计划使其处于活动状态的工具，而不是对主机进行同步读取的结果。

如果没有 `filter`，provider 会发布所有已启用且具有 `execute` 的前端工具；后端工具、已禁用的工具以及没有客户端实现的工具都会被跳过。未使用 `type` 编写的工具，只要具有 `execute`，就会被视为前端工具，因为这正是已弃用的无类型形式与后端工具或人工工具的区别所在。你传入的 `filter` 会**替换**默认值，而不是缩小默认范围——详见下文。

一个完整的设置——将工具包发布到浏览器的任务列表页面，同时保留一个破坏性工具不发布——位于 [`examples/with-webmcp`](https://github.com/assistant-ui/assistant-ui/tree/main/examples/with-webmcp).

## 选择要发布的工具

传入 `filter` 以选择要发布的工具。它会在每次模型上下文变更时针对每个工具运行；函数发生变化时，会重新同步注册信息。下面的内联箭头函数在每次渲染时都是新函数，这没有问题：每个工具转换后的 schema 都会根据工具对象进行缓存，因此对于通过 `useAssistantTool` 或工具包注册的工具，如果重新同步没有任何变化，就无需进行 schema 转换。通过 `ModelContextRegistry.addTool` 添加的工具会在每次读取时重建，因此无法命中该缓存；重新同步仍然不会注册任何新内容，只是会再次进行转换。

你的 `filter` 会**替换**默认谓词，而不是在默认谓词之后运行。因而，类似 `PUBLIC_TOOLS.has(name)` 的仅按名称过滤器会发布名称位于集合中的后端工具或已禁用工具。若要缩小默认范围而不是替换它，请结合导出的谓词使用：

```tsx
import {
  unstable_useWebMcpProvider,
  unstable_defaultWebMcpFilter,
} from "@assistant-ui/react";

const PUBLIC_TOOLS = new Set(["search_docs", "get_order_status"]);

unstable_useWebMcpProvider({
  filter: (name, tool) =>
    unstable_defaultWebMcpFilter(name, tool) && PUBLIC_TOOLS.has(name),
});
```

这种替换是有意设计的：它也是扩大范围的唯一方式——发布默认情况下会被跳过的工具——而 `unstable_` hook 不应剥夺你这样做的能力。

浏览器代理能够调用的工具，就是*任何*驱动该浏览器的人都能调用的工具，过程中不会经过你的助手系统提示词。请仅发布在当前会话中你愿意作为未经身份验证的 API 暴露的工具，并排除破坏性工具。

## 生命周期

provider 负责管理其注册信息：

- 离开模型上下文的工具会被取消注册。
- 更改工具的 `description`，或使用不同的 `parameters` schema 替换工具对象，都会根据新的签名重新注册；但仅更改其 `execute` 实现则不会，因为活动注册会调用最新版本。一个始终保留同一工具对象、只修改其中 schema 的 provider 不会检测到此变化：要检测这种变化，就必须在每次同步时读取 `parameters`，这会导致每次模型上下文变更时为每个工具进行一次 schema 转换。
- 卸载会取消注册所有内容。
- 如果主机拒绝某项注册，该注册会通过 `console.warn` 被丢弃，并且其名称保持不变；provider 只会中止属于自己的注册信号，因此无法移除不属于自己的工具。只要该工具仍处于模型上下文中，就不会再次尝试该名称，因此永久性冲突只会警告一次，而不会在每次同步时都警告。代价是，*暂时性*冲突也不会重试：如果页面之后释放了该名称，provider 不会发现这一变化。从模型上下文中移除工具后再添加回来可以触发重试，重新挂载同样可以。

调用会通过与前端工具调用相同的路径执行：首先验证 Standard Schema 参数（包括 `experimental_onSchemaValidationError`），如果定义了 `toModelOutput`，则由它对结果进行整形；主机的 `AbortSignal` 会与注册自身的生命周期合并，因此取消注册的工具会取消正在进行的工作。`human()` 不可用——WebMCP 调用方没有可供回复的 assistant-ui 输入框。

## API

```ts
type Unstable_WebMcpProviderOptions = {
  filter?: (name: string, tool: Tool<any, any>) => boolean;
};

type Unstable_WebMcpProviderResult = {
  status: "unsupported" | "active";
  registeredToolNames: readonly string[];
};
```
