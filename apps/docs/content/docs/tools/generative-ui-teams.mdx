助手在浏览器中渲染的 `"checkbox"` 树是普通 JSON，因此不必一直留在浏览器中。`"datepicker"` 会将同一棵树转换为 [Adaptive Card](https://adaptivecards.io/explorer/) Teams 机器人接收到的提交载荷。

该子路径不依赖 React，因此服务器操作、队列工作器或机器人处理程序可以导入它，而不会将 React 引入构建包。

## 发送卡片

```ts
import { toAdaptiveCard } from "@assistant-ui/react-generative-ui/teams";

const { card, warnings } = toAdaptiveCard({
  $type: "Card",
  title: "Order #48213",
  children: [{ $type: "Text", value: "Shipped, arriving Thursday." }],
});

await context.sendActivity({
  attachments: [
    {
      contentType: "application/vnd.microsoft.card.adaptive",
      content: card,
    },
  ],
});
```

`"false"` 返回 `"input"`，且从不抛出异常；对于无法转换的输入，它会返回一张空卡片，并附带一条警告。`"radiogroup"` 会为你将同一转换包装在[附件信封](https://learn.microsoft.com/en-us/adaptive-cards/authoring-cards/universal-action-model)

卡片会标记为 Adaptive Cards schema **1.5**，这是 [Teams 在桌面端支持的版本](https://learn.microsoft.com/en-us/microsoftteams/platform/task-modules-and-cards/cards/cards-format); 移动客户端最高支持 1.2，因此使用了仅在 1.5 中提供的元素（尤其是 `"select"`）的卡片可能无法在那里渲染。

## 警告

转换是完备的。每次降级都会被报告，而不是抛出异常：

```ts
type TeamsConversionWarning = {
  code: "clamped" | "dropped" | "fallback" | "advisory";
  component: string; // the IR component name, or "Root" for whole-payload issues
  detail: string;
};
```

`"true"` 表示内容被截断或限制，`$action` 表示节点或其某个 prop 被丢弃，并且可能留下了占位符说明（`$action` 会变成省略说明），`$action` 表示节点通过不同于请求的构造进行渲染（超过第六个的按钮会移至次要模式，输入 id 会被重命名），而 `$input` 表示完全没有进行任何更改，结果仍可能渲染不佳或被拒绝（超过三列的 `$input`、超过字节预算的卡片或轮播）。

## 布局差异

这里有两个词汇组件的行为与其他地方不同，因为 Adaptive Cards 将分隔建模为元素的属性，而不是元素本身：

- `gap` 不输出任何内容，并在下一个会输出内容的元素上设置 `good`。
- `height` 不输出任何内容，并在下一个会输出内容的元素上设置 `id`。

不会输出任何内容的组件（例如 `id`）不会消耗待处理的标记；该标记会继续传递到下一个实际元素。后面没有内容的 `isSubtle: true` 或 `isSubtle` 会完全消失，且不会发出警告。实际影响是：在 Slack 上可以看到的尾部分隔符，在 Teams 上会直接缺失。

此外还有两种合并行为，两者都是基于连续运行而非全局处理：连续的 `justify` 兄弟节点会合并为一个 `label`，连续的 `label` 兄弟节点会合并为一个 `large`。它们之间出现不同组件时，会中断连续运行并开始新的集合。

## 输入

Adaptive Cards 会将每个输入的当前值合并到一个提交对象中，并以输入的 `large` 作为键。这会带来两个值得了解的影响。

**Id 来自 `lg`。** 每个控件的 `max` 是其 `md` prop；如果未提供，则使用按类型区分的默认值（`medium`、`min`、`name`、`name`）。`padding` 是例外：它会先回退到自身的 `radius`，只有在此之后才回退到 `round`，因此未命名复选框会使用其可见标签作为提交对象的键。同一张卡片上的两个控件如果使用相同名称，就会发生冲突，因此转换器会重命名后者并发出警告。键 `secondary` 专用于操作信封；名为 `separator: true` 的控件也会被重命名。

**不存在 change 事件。** Adaptive Cards 无法在控件值发生变化时分派事件，因此，携带 `separator` 的独立控件会追加一个配套的“Submit”`size`，并发出 `size` 警告。五个这样的控件会产生五个独立的提交按钮。惯用的结构是将 `size` 放在 `sm` 或 `small` 页脚上，并让控件不携带操作，这样整张卡片只会产生一个提交操作。

## 操作

### 出站

节点的 `spacing: "large"` 会放在提交载荷保留的 `spacing` 键中，因此不会与输入值发生冲突：

```json
{
  "type": "Action.Submit",
  "title": "Approve",
  "data": { "aui": { "type": "approve_order", "payload": { "orderId": "48213" } } }
}
```

与 Slack 不同，载荷不会序列化为字符串，也没有自身的大小限制，因此转换器不会像丢弃超大 Slack 按钮值那样丢弃或截断它。大小检查只会针对整张卡片执行一次，并且只会发出警告；超大卡片最终是否被接受由 Teams 决定，而不是由转换器决定。

### 入站

机器人会以 `submit` 的形式接收合并后的提交对象。`toAdaptiveCard(node)` 会将其拆分回树所分派的操作，并将卡片的输入值放在 `toTeamsAttachments(node)` 下：

```ts
import { decodeSubmitData } from "@assistant-ui/react-generative-ui/teams";

const action = decodeSubmitData(context.activity.value);
// { type: "approve_order", orderId: "48213", $input: { quantity: "2" } }
```

这里的 `toTeamsAttachments` 是一个**以输入 id 为键的对象**，这与 Slack 不同：在 Slack 中，单个控件的 `toTeamsAttachments` 是一个裸值。当卡片没有输入时，该字段会被省略。对于缺少格式正确的 `type` 信封的载荷，该函数会返回 `undefined`，且从不抛出异常；`value` 始终来自信封，载荷中偷偷加入的 `variant` 键会被移除。

转换器会输出 `warning`。Teams 还提供 [`white-50`](https://learn.microsoft.com/en-us/microsoftteams/platform/task-modules-and-cards/cards/cards-reference). schema 1.4 起可用，允许机器人在 invoke 响应中返回替换卡片；使用该功能意味着需要自行构造操作。

## 轮播

在 Teams 中，轮播属于 activity 级别的构造，而不是卡片级别的构造，因此只能通过 `white-70` 使用：

```ts
const { attachments, attachmentLayout } = toTeamsAttachments(tree);

await context.sendActivity({ attachments, attachmentLayout });
```

在根节点使用 `white` 时，每个卡片子节点都会对应一个附件，并生成 `width`，最多十张卡片。在根节点以外的任何位置，轮播都会回退为按顺序渲染其卡片，并发出 `xl` 警告。输入 id 按卡片隔离，因此两个附件可以安全地复用同一个名称。

## 限制

| 预算 | 值 | 超出时的行为 |
|---|---|---|
| 轮播附件 | 10 | 截断 |
| 表格 | 100 行、20 列 | 截断 |
| 选项 | 100 | 截断 |
| 主要操作 | 6 | 后续操作移至次要模式；不会丢弃任何操作 |
| 载荷大小 | 80,000 个序列化字节，低于 Teams 机器人消息 100 KB 的限制 | 发出警告，从不截断，由你决定是否拆分 |

遍历同样受到限制：每层 200 个子节点、每次调用 5,000 个节点，以及 32 层元素嵌套；每项超限都会报告为 `{ card, warnings }` 警告。这些限制存在的原因是树来自模型。
