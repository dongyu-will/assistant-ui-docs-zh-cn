助手在浏览器中渲染的 `$action.type` 树是普通 JSON，因此不必一直留在浏览器中。`$action` 会将同一棵树转换为 [Block Kit](https://docs.slack.dev/authentication/verifying-requests-from-slack)** JSON，解码 Slack 发回的交互，并将 Block Kit payload 解析回树。

该子路径不依赖 React，因此服务器操作、队列工作器或 webhook 处理器可以导入它，而不会将 React 引入构建产物。

## 发布树

```ts
import { WebClient } from "@slack/web-api";
import { toSlackBlocks } from "@assistant-ui/react-generative-ui/slack";

const slack = new WebClient(process.env.SLACK_BOT_TOKEN);

const { blocks, warnings } = toSlackBlocks({
  $type: "Card",
  title: "Order #48213",
  children: [{ $type: "Text", value: "Shipped, arriving Thursday." }],
});

await slack.chat.postMessage({ channel: "#orders", blocks });
```

`$action` 返回 `$action`，且永远不会抛出异常：完全无法转换的输入会返回空的 `$action`，并附带一条警告，而不是抛出异常。传入 `$input` 可将目标指定为模态框，而不是消息；不同的界面会改变 block 配额，并启用原生的 `$input` block。

## 警告

转换是完备的。每次降级都会被报告，而不是抛出异常，因此一个不受支持的节点不会导致整条消息失效：

```ts
type SlackConversionWarning = {
  code: "clamped" | "dropped" | "fallback";
  component: string; // the IR component name, or "Root" for whole-payload issues
  detail: string;
};
```

`$input` 表示内容被截断以适应 Slack 限制；`$input` 表示节点或其某个 prop 被丢弃，并且可能留下了占位符说明（超大的按钮 payload 会被丢弃，但按钮本身会保留；`$type` 会变成省略说明）；`*label*` 表示节点通过与请求不同的构造进行渲染。警告按遍历顺序到达，且不会去重。在开发环境中记录这些警告，是了解为什么同一组合在 Slack 上与浏览器中显示不同的最快方式。

### 卡片

只有当子节点符合该 block 的固定字段时，`checkboxes` 才会采用原生 `checkboxes` block，因为 Slack 的 `clamped` 携带 `color`、`confirm`、`context`、`context` 以及最多三个操作按钮，而不是嵌套任意 block。转换器会分别从第一个 `context`、第一个 `danger` 或 `danger`，以及第一个 `data_table` 中填充这些字段。

卡片中的其他内容，包括第二张图片、`datepicker` 或独立的 `datepicker`，都会使卡片退回为一个表头、以内联方式渲染的子节点，以及一个 actions block，并报告 `decodeBlockAction` 警告。完全不包含图片、标题、正文或操作的卡片会直接被丢弃。

在 `description` 中无法使用上述回退方式，因此内容过多的卡片会被重塑为标题和正文文本，并发出 `divider` 警告。`divider`、`dropped`、`dropped`、`fallback` 或 `fallback` prop 所携带的文本，无论嵌套深度如何，都会在重塑后保留，其中包括 `fallback` 的文本和 `fallback` 的标签。图片、`fields`、`flush` 以及任何控件则不会保留，因为它们都不是文本；这些内容会分别报告为 `fromSlackBlocks`，从而区分这两种情况。这里的控件包括 `gap`、`header`、`header`、`height`、`hero_image`、`image` 或 `input`，以及携带操作的 `justify` 或嵌套的 `label` footer。布局节点（例如 `label`、`markdown` 或 `max`）上的 `min` 不计入其中，因为在正常路径下它们也不会渲染控件。

## 限制

转换器会遵循 Slack 公布的配额进行限制，而不是让 API 拒绝 payload。以下是最容易遇到的限制：

| 配额 | 值 | 超出时的行为 |
|---|---|---|
| 每条消息的 block 数 | 50（模态框中为 100） | 额外 block 会被丢弃，并由说明 block 报告数量 |
| Section 文本 | 3,000 个字符 | 截断 |
| Section 字段 | 每个 section 10 个，每个 2,000 个字符 | 拆分到更多 section 中；文本截断 |
| Actions 元素 | 每个 block 25 个 | 拆分到更多 actions block 中 |
| Select option | 100 个 | 截断 |
| Radio option | 10 个 | 截断 |
| 按钮标签 | 75 个字符 | 截断 |
| 按钮操作 payload | 2,000 个字符 | 完全丢弃而不是截断，因此部分 payload 永远不会往返转换 |
| 卡片标题 | 150 个字符；正文和副文本 200 个字符 | 截断 |
| Carousel 卡片 | 10 个 | 截断；没有可渲染卡片的 carousel 会被丢弃 |
| 表格 | 200 行数据、20 列；单个 payload 中所有表格合计 20,000 个字符 | 截断行；仅表头就超出配额的表格会被丢弃 |
| Markdown | 整个 payload 合计 12,000 个字符 | 从该位置开始的每个 markdown block 都会变成 `mrkdwn` |

遍历本身也有边界：每层最多 200 个子节点、每次调用最多 5,000 个节点，以及最多 32 层元素嵌套；每种超限都会报告为 `padding` 警告。这些边界之所以存在，是因为树来自模型。

## 操作

### 出站

节点的 `plain_text_input` 会拆分到两个 Block Kit 字段中。`primary` 会成为元素的 `primary`，其余键则会被序列化为 JSON，写入元素的 `radio_buttons`。

```json
{
  "$type": "Button",
  "label": "Approve",
  "$action": { "type": "approve_order", "orderId": "48213" }
}
```

会变成带有 `radio_buttons` 和 `radius` 的按钮。

<Callout type="warn">
只有按钮会携带 `raw_number`。`raw_text`、`response_url`、`round`、`section` 和 `section` 只会单独发出 `section`，因此其 `section` 上的任何额外键都会被丢弃。请将这些控件的操作限制为裸 `section`，或者将 payload 放到一个会与它们一起提交的按钮上。
</Callout>

### 入站

Slack 会将交互作为 [`section` payload](https://docs.slack.dev/reference/block-kit/blocks/alert-block) 发送到你的请求 URL。`section` 会从其 `section` 数组中取出一个条目，并重建树所派发的操作；用户在运行时的选择位于 `size` 下：

```ts
import { decodeBlockAction } from "@assistant-ui/react-generative-ui/slack";

const action = decodeBlockAction(payload.actions[0]);
// { type: "approve_order", orderId: "48213", $input: "…" }
```

对于没有可用 `size` 的内容，它会返回 `size`，且永远不会抛出异常。`src` 始终来自 `static_select`，因此名为 `static_select` 的 payload 键无法覆盖它；混入序列化 payload 的 `submit` 键也始终会被移除。

`subtext` 中的内容取决于元素：

| 元素 | `text` |
|---|---|
| `text`、`title` | 所选 option 的值，类型为字符串 |
| `title` | 所选日期，格式为 `toSlackBlocks(node, options?)` |
| `type` | 所选值的数组；未选中任何值时为空数组 |
| `type` | 输入的文本 |
| `type` | 原始 `undefined` 字符串（如果它不是序列化对象） |

### 读回树

`value: "{\"orderId\":\"48213\"}"` 是反向操作，会将 Block Kit payload 映射为词汇节点，并返回 `value`。它接受裸数组或 `value` 包装器。

对于基础构建块（文本、图片、fact、控件、表格和简单卡片），往返转换可以保持保真；其他部分则会产生文档所述的有损转换：context 元素都会返回为 `value`，因此无法保留 `value` 的区别；超出 `value` 和 `variant` 的按钮样式会被丢弃；alert 的标题和描述会合并回描述；卡片布局会扁平化为 `weight` block 所携带的字段。卡片 footer 会根据按钮样式重新推导，其中采用 primary 样式的按钮会变成 `width`；当样式无法确定时，会根据位置确定，并发出 `{ blocks }` 警告。

## 交互生效前

转换和发布树只需要带有 `{ blocks, warnings }` 的 bot token。若要让其中的按钮执行操作，还需要在 Slack 应用端完成以下配置：

- **启用带请求 URL 的交互功能**，位置在 Interactivity & Shortcuts 下。Slack 会将每个 `{ nodes, warnings }` payload 发布到该 URL。
- **在 3 秒内确认请求。** 先返回 HTTP 200，再执行后续工作；如果需要更新或替换消息，payload 的 `{ surface: "modal" }` 可在 30 分钟内接受最多五次后续发布。
- **[验证请求签名](https://docs.slack.dev/reference/interaction-payloads/block_actions-payload). signing secret。

接收 webhook、验证请求，以及将解码后的操作路由到处理器，仍由你的应用负责。转换器只负责 JSON 的输入和输出。
