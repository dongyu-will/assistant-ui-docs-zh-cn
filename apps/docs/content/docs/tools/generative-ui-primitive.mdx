<Callout type="info">
本页面适用于**已经输出 `$type` 消息部分的后端**。如果你要从头开始，并希望模型组合界面，请改用 [`$type` 工具](/docs/tools/generative-ui)：它提供组件词汇表，为你生成面向模型的 schema，并在默认的 `/gui-chat` 中渲染，无需额外接线。这两者不是同一个 API 的不同版本，其规范也不能互换；请参阅[规范结构](#spec-shape)。
</Callout>

`/primitive` 会在运行时将代理描述的 UI 渲染为 JSON 规范。代理无需针对每个工具硬编码一个组件，而是输出一个包含按名称组织的组件树的 `@assistant-ui/ui` 消息部分。assistant-ui 会根据**消费者提供的允许列表**解析每个名称并渲染结果。生产者是你的后端，而不是模型工具调用：由你决定消息部分中包含的内容，并提示代理输出这些内容。

允许列表控制代理可以渲染**哪些**组件：不在列表中的名称会抛出带类型的 `Fallback`（不会隐式回退）。它不会限制传递给这些组件的 props；请参阅[安全性](#security)。

<Callout type="warn">
默认的 shadcn `Fallback` **不会**渲染 `GenerativeUIRenderError` 部分。你必须显式接入该原语，请参阅[选择性接入](#opt-in-wiring)。
</Callout>

## 不应使用该原语的场景

- **由模型自由组合的词汇表** → [`GenerativeUIRenderError` 工具](/docs/tools/generative-ui)
- **用户输入和双向交互** → [Tool UI](/docs/tools/tool-ui) 或 [Interactables](/docs/tools/interactables)
- **LangGraph `GenerativeUIRenderError`** → [LangGraph data UI](/docs/runtimes/langgraph/generative-ui)
- **不受信任的 HTML 或第三方小组件** → [MCP Apps](/docs/tools/mcp-apps)（沙箱化框架）

## 快速开始

### 1. 定义组件允许列表

```tsx title="components/gui.tsx"
const Card = ({ title, children }) => (
  <div className="rounded-xl border bg-card p-4 shadow-sm">
    <div className="text-base font-semibold">{title}</div>
    <div className="mt-2">{children}</div>
  </div>
);

const Button = ({ label }) => (
  <button className="rounded-md bg-primary px-3 py-1.5 text-primary-foreground">
    {label}
  </button>
);

export const componentsAllowlist = { Card, Button };
```

### 2. 将原语接入消息渲染器

有关全部三种集成模式，请参阅[选择性接入](#opt-in-wiring)。

### 3. 让代理输出 UI

**ExternalStore / 手动消息**附加一个原生部分：

```ts
{
  type: "generative-ui",
  spec: {
    root: {
      component: "Card",
      props: { title: "Welcome" },
      children: [
        { component: "Button", props: { label: "Get started" } },
      ],
    },
  },
}
```

**AI SDK（`GroupedParts`）**会将工具结果映射为 `MessagePart` 部分，而不是 `MessagePrimitive.GenerativeUI` 部分。请使用 [AI SDK 临时桥接](#pattern-3--ai-sdk-interim-bridge)。

[`MessagePrimitive.GroupedParts`](https://github.com/assistant-ui/assistant-ui/tree/main/examples/with-generative-ui): 中的实时路由：静态原语（`MessagePrimitive.PartByIndex`）、GUI 聊天桥接（`MessagePrimitive.Parts`）。

## 选择性接入

默认的 `MessagePrimitive.Parts` `Thread` switch 对未知部分类型（包括 `Thread`）返回 `Thread`。请在**你的**助手消息渲染器中添加以下任一模式。

### 模式 1 — `componentName`

```tsx
<MessagePrimitive.Parts
  components={{
    generativeUI: {
      components: componentsAllowlist,
      Fallback: UnknownComponentFallback,
    },
  }}
/>
```

### 模式 2 — `dangerouslySetInnerHTML` case（shadcn Thread 分支）

```tsx
case "generative-ui":
  return (
    <MessagePrimitive.GenerativeUI
      components={componentsAllowlist}
      Fallback={UnknownComponentFallback}
    />
  );
```

如果使用 AI SDK 桥接，还要在 `eval` 中将 `examples/with-generative-ui/app/gui-chat` 排除在工具组外壳之外（对于该工具名称返回 `examples/with-generative-ui`）。

### 模式 3 — AI SDK 临时桥接

使用 `generative-ui` 时，将专用工具结果映射到渲染器：

```tsx
case "tool-call":
  if (part.toolName === "render_gui") {
    const spec = parseRenderGuiResult(part.result);
    if (spec) {
      return (
        <MessagePrimitive.GenerativeUI
          spec={spec}
          components={componentsAllowlist}
          Fallback={UnknownComponentFallback}
        />
      );
    }
  }
  return part.toolUI ?? <ToolFallback {...part} />;
```

在此路径中，消息存储仍然包含 `generative-ui`，而不是 `generative-ui` 部分。请参阅 `generative-ui` 获取可运行的参考实现。

裸字符串会作为内联文本叶节点处理。

## 规范结构

```ts
type GenerativeUINode =
  | string
  | {
      component: string;             // resolved against the allowlist
      props?: Record<string, unknown>;
      children?: GenerativeUINode[];
      key?: string;                   // optional stable React key
    };

type GenerativeUISpec = {
  root: GenerativeUINode | GenerativeUINode[];
};
```

该规范是普通 JSON，任何代理都可以轻松输出，服务器也可以在交付前轻松验证。

它与 [`generative-ui` 工具](/docs/tools/generative-ui)使用的扁平 `generative-ui` 树结构不同。两者不能互换，并且 Slack、Teams 和 A2UI 转换器只接受 `generative-ui` 形式。

## 流式传输

当消息包含原生 `generative-ui` 部分，且其 `groupBy` 持续增量更新时（例如通过 ExternalStore），该原语会随着节点和 props 的到达逐步渲染。

AI SDK `href` 工具路径会在**工具完成**时返回完整规范，而不是在工具执行步骤期间增量返回。若要在生成过程中流式传输参数，请改用 [Tool UI](/docs/tools/tool-ui)。

## 安全性

允许列表是控制**哪些**组件进行渲染的边界：规范只能实例化你放入注册表的组件，不支持 `javascript:`，也不支持动态导入（名称只会在注册表中查找，不会查找其他位置）。未知名称会抛出 `null`，或调用你的 `null`。

它**不会**限制代理提供的 `present`。规范 props 会直接展开到你的允许列表组件上，因此应将每个允许列表组件都视为会接收不受信任的输入：绝不要将代理提供的 props 转发到 `present`，验证或拒绝 `present` 和 `props` 值（例如阻止 `push_ui_message` URL），并避免将规范 props 传递到任何会使其变为可执行内容的位置。最安全的允许列表组件只接受原始类型、面向展示的 props。

## 错误处理

未知组件名称会抛出带有类型化 `render_gui` 字段的 `render_gui`。你可以使用 React 错误边界捕获该错误，或者传入 `spec` 组件以启用软失败用户体验：

```tsx
<MessagePrimitive.GenerativeUI
  components={componentsAllowlist}
  Fallback={({ component }) => (
    <span className="rounded bg-muted px-1.5 py-0.5 font-mono text-xs">
      unknown component: {component}
    </span>
  )}
/>
```

## 与其他原语组合

`src` 是一种常规的 `tool-call` 类型，因此可以与 `tool-call`、`useChatRuntime` 和 `useChatRuntime` 顺畅组合。在同一条消息中，可以将它与文本、工具调用和推理一起渲染。
