可交互组件允许智能体和用户读取及编辑工具 UI 和组件。它们可以是会话线程内的工具 UI，例如邮件编辑器；也可以是应用范围的组件，例如工件、任务看板或设置面板。

## 概览

### 可交互组件的类型

- **应用级：** 使用 `unstable_useInteractable` 自行挂载的组件，可放置在应用中的任意位置（侧边栏、面板等）。模型会自动获得一个 `update_{name}` 工具，用于读取和编辑该组件，其状态还可以跨线程持久化。
- **线程级：** 模型可以在线程中调用的工具 UI。你可以在 `defineToolkit` 中使用 `unstable_interactableTool` 定义它，调用时会以内联方式渲染。

### 功能

- **共享且可编辑的状态：** 用户（通过 React）和模型（通过自动生成的 `update_{name}` 工具）都会写入同一状态，并且双方都能看到对方的编辑。
- **流式传输和部分更新：** 更新会以流式方式传输到可交互组件，模型只需更新想要更改的字段。
- **版本控制和历史记录：** 每次用户编辑和模型的 `update_*` 都会记录为一个版本，你可以显示、列出和 `restore()` 这些版本（[版本](#versions)）。
- **持久化：** 状态的生命周期会超出工具调用和当前轮次，并且可以在重新加载后保留（线程级状态通过线程历史记录持久化；应用级状态通过持久化适配器持久化）。
- **自动生成的更新工具：** 系统会根据可交互组件的状态 schema 生成一个 `update_{name}` 工具，供模型更新和编辑该组件。

### 使用场景

- 助手可以编辑和交互的设置面板或仪表板
- 协作任务列表、便利贴、文档编辑器
- 让构件支持编辑和版本控制
- 其他任何场景，**任何 React 组件都可以成为可交互组件！**

const taskBoardSchema = z.object({

function TaskBoard() {

          <input
            type="checkbox"
            checked={task.done}
            onChange={() =>
              setState((prev) => ({
                tasks: prev.tasks.map((t) =>

              }))
            }
          />
          {task.title}
        </li>

## 状态快照

当状态自模型上次看到后发生变化时，发出的用户消息可以将可交互组件的状态作为快照携带给模型。仅部分字段发生变化时，会创建部分快照，其中仅包含发生变化字段的浅层差异和 id。

默认的完整快照格式：

```ts
`[Current state of "note" (id: "n1"): {"title":"Q3 launch","body":"Ship the beta by Friday."}]`;
```

默认的部分快照格式：

```ts
`[State of "note" (id: "n1") changed — updated fields: {"title":"Q4 launch"}; fields not listed are unchanged]`;
```

### 自定义格式

格式化器接收一个快照 `entry`，并返回模型看到的行：

- `name` 和 `id` 用于标识实例。请保留可见的 `id`，以便模型知道该状态所属的对象。
- `state` 是快照负载。
- 当 `state` 携带自模型上次已知状态以来仅发生变化字段的浅层差异时，`partial` 为 `true`。请处理这种情况。

编写自定义格式化器：

```ts
import { type Unstable_InteractableSnapshotEntry } from "@assistant-ui/react";

const formatSnapshot = (entry: Unstable_InteractableSnapshotEntry) =>
  entry.partial
    ? `State of "${entry.name}" (id: "${entry.id}") has been updated, the following fields have changed: ${JSON.stringify(entry.state)}`
    : `Current state of "${entry.name}" (id: "${entry.id}"): ${JSON.stringify(entry.state)}`;
```

<Callout type="info">
  自定义格式时，请记住：
  - 处理 `partial: true` 条目，其中其 `state` 携带仅发生变化字段的浅层差异。
  - 保留每个实例的 `id` 可见，以便模型知道该状态所属的对象。
</Callout>

然后将其连接到后端：

- **AI SDK：**将其作为第二个参数 `unstable_injectInteractableContext(messages, formatSnapshot)` 传入。
- **其他后端：**在辅助函数中使用它替代 `unstable_formatInteractableSnapshot`（请参阅[步骤 3](#surface-state-to-the-model-in-your-route)中的“其他后端”标签页）。

```ts title="app/api/chat/route.ts"
messages: await convertToModelMessages(
  unstable_injectInteractableContext(messages, formatSnapshot),
),
```

## 构件

一个构件由两个指向同一个可交互项的部分组成：

- 线程工具（`unstable_interactableTool`），模型通过它在消息中内联创建构件（按钮或消息中的小型预览）；以及
- 通过 `unstable_useInteractable` 挂载的面板，用于以完整尺寸打开同一个实例。

两者使用相同的 `id`，因此它们是同一个可交互项，而不是两个：模型在对话中创建它，面板只是同一状态的更大视图。由于创建调用保存在会话线程中，构件是**线程范围内的**：它会随线程历史记录持久存在（不需要[持久化适配器](#persistence)），并且每条消息的触发器都可以打开该消息对应的版本（参见[版本](#versions)）。

```
  in the thread (model-created)            your layout (mounted once)
──────────────────────────────          ──────────────────────────────
unstable_interactableTool("document")    ArtifactPanel()
  render: a button / inline preview        unstable_useInteractable("document", { id })
    onClick → openArtifact(id) ────┐         → live, editable, full height
                                   │                    │
                                   └─────  same id  ────┘
                                     one thread-scoped instance
```

```tsx
const toolkit = defineToolkit({
  document: unstable_interactableTool({
    description: "A document the user can open and edit.",
    stateSchema: documentSchema,
    render: ({ state, version, id }) => (
      <ArtifactButton
        title={(version?.state ?? state).title}
        onClick={() => openArtifact(id)} // your own state: which artifact is open
      />
    ),
  }),
});

function ArtifactPanel({ id }: { id: string }) {
  const [state, { setState }] = unstable_useInteractable("document", {
    id,
    description: "A document the user can open and edit.",
    stateSchema: documentSchema,
    initialState: emptyDocument, // fallback only; existing state comes from the thread
  });
  const versions = unstable_useInteractableVersions<Document>(id, "document");

  return (
    <aside>
      <VersionMenu>
        {versions.map((v, i) => (
          <DropdownItem key={i} onSelect={v.restore}>
            v{i + 1}: {v.origin === "user-edit" ? "you" : "assistant"}
          </DropdownItem>
        ))}
      </VersionMenu>
      <Editor value={state} onChange={setState} />
    </aside>
  );
}
```

你不需要为每个构件单独挂载任何内容：模型会自行渲染内联部分，而 `openArtifact(id)` 是你自己的状态设置器，用于指定面板当前显示的构件。在消息部分之外，该 hook 始终返回实时状态（`version` 为 `undefined`），因此面板可以直接编辑。面板和内联工具 UI 注册相同的 `id`，因此它们共享同一个实例；注册采用引用计数，只有最后一个实例卸载后，该实例才会保持不再活跃。

<Callout type="warn">
  只要该实例应该保持可用，就应在屏幕上保留一个构件挂载（隐藏也可以）。如果面板已关闭，并且所有内联按钮都因虚拟化线程滚动到视口外，该实例及其 `update_{name}` 工具就会注销，工具列表也会发生变化。状态本身是安全的，因为它依托线程历史记录保存。
</Callout>

## 配套工具

生成的 `update_{name}` 工具涵盖状态中的所有内容：编辑字段，以及在列表中添加、更新、移除或清除项目。只有当状态无法表达某些操作时，才应使用单独的前端工具，例如发送、导出或保存等副作用。

以用户和助手共同编辑的邮件输入框为例。`update_email` 会让双方保持草稿同步，但实际**发送**邮件是一种无法通过任何状态编辑完成的副作用。这正是配套工具的用途：`send_email` 会作用于当前草稿并将其发送出去。

具体接入方式取决于执行器会触及什么内容。

**闭包捕获 React 状态**（此处为实时草稿）：在 `"use generative"` 工具包中使用 `stubTool()` 声明契约，并在拥有该状态的组件中通过 `useAuiToolOverrides` 提供执行器。请参阅[动态工具](/docs/tools/dynamic-tools)。

```tsx title="app/email-toolkit.tsx"
"use generative";

import { defineToolkit, stubTool } from "@assistant-ui/react";
import { z } from "zod";

export default defineToolkit({
  send_email: {
    description:
      "Send the email currently shown in the composer. Call this only once the draft is ready.",
    parameters: z.object({}),
    execute: stubTool(),
    renderText: { running: "Sending...", complete: "Email sent" },
  },
});
```

```tsx title="app/EmailComposer.tsx"
import {
  unstable_useInteractable,
  useAuiToolOverrides,
} from "@assistant-ui/react";

function EmailComposer() {
  const [draft, { setState }] = unstable_useInteractable("email", {
    description: "An email draft the user and assistant can read and edit.",
    stateSchema: emailSchema,
    initialState: { to: "", subject: "", body: "" },
  });

  return (
    <>
      <SendEmailTool draft={draft} />
      {/* inputs bound to draft + setState */}
    </>
  );
}

// A null-returning child supplies the executor, closing over the live draft.
function SendEmailTool({ draft }: { draft: Email }) {
  useAuiToolOverrides({
    send_email: {
      execute: async () => {
        await fetch("/api/send-email", {
          method: "POST",
          body: JSON.stringify(draft),
        });
        return { success: true };
      },
    },
  });
  return null;
}
```

这种拆分正是关键所在：`update_email` 编辑草稿，`send_email` 执行草稿本身无法描述的操作。执行器会读取实时的 `draft`，因此发送的始终是当前屏幕上显示的内容。

**自包含**（不需要 React，只依赖自身参数和浏览器 API）：直接在工具包中放置一个真正的 `execute`，其中包含内部的 `"use client"`。构建 URL 并将其写入剪贴板的 `copy_share_link({ id })` 就很适合这种情况。请参阅[定义工具](/docs/tools/defining-tools#frontend-tools)。

## 自定义更新渲染

`render` 渲染创建调用；`updateRender` 渲染每个 `update_{name}` 调用。`unstable_interactableTool` 会为两者复用同一个 `render`，因此编辑效果看起来与创建相同。提供你自己的 `updateRender`，即可用不同方式渲染编辑。

<Callout type="info">
  如果你想根据此消息的版本进行不同渲染，或让旧消息与最新消息显示不同，
  则不需要 `updateRender`。渲染时已经会接收
  `version`；请参阅[版本](#versions)。
</Callout>

### 让编辑与创建的渲染方式不同

线程工具会将创建和编辑的渲染绑定在一起。改用 `unstable_useInteractable` 即可将两者拆分；下面的示例在创建调用中显示完整记事本，而在每次编辑时显示一行摘要：

```tsx
// Hoisted so its identity is stable; an inline updateRender re-registers the
// tool UI on every render.
const EditSummaryRender: ToolCallMessagePartComponent = ({ args }) => (
  <EditSummary changed={args} />
);

const NotepadToolUI: ToolCallMessagePartComponent<NotepadArgs> = ({
  toolCallId,
  args,
  result,
}) => {
  if (!result) return <NotepadDraft args={args} />;
  return <Notepad id={toolCallId} initial={args} />;
};

function Notepad({ id, initial }: { id: string; initial: NotepadArgs }) {
  const [state, { setState }] = unstable_useInteractable("notepad", {
    id,
    description: "A notepad the user can read and edit.",
    stateSchema: notepadSchema,
    initialState: initial,
    updateRender: EditSummaryRender,
  });
  return <NotepadEditor value={state} onChange={setState} />;
}

// NotepadToolUI is the create call's render; updateRender handles the edits.
const toolkit = defineToolkit({
  notepad: {
    type: "frontend",
    description: "A notepad the user can read and edit.",
    parameters: notepadSchema,
    display: "standalone",
    execute: async () => ({ success: true as const }),
    render: NotepadToolUI,
  },
});
```

将创建调用的 `toolCallId` 作为 `id` 传入：这一约定会将两种渲染绑定到同一个实例，并在重新加载后根据线程历史恢复其状态。

### 在应用作用域界面上标记编辑

应用作用域的可交互界面位于你的布局中（例如侧边栏或面板），因此在线程中没有内联显示。传入 `updateRender` 后，每个 `update_{name}` 调用都会获得一个内联标记，用于说明模型刚刚执行的操作，同时实时组件会在原位置持续更新。

```tsx
const EditMarkerRender: ToolCallMessagePartComponent = ({ args }) => (
  <EditMarker changed={args} />
);

function DocumentPanel() {
  const [state, { setState }] = unstable_useInteractable("document", {
    description: "A document the user can read and edit.",
    stateSchema: documentSchema,
    initialState: emptyDocument,
    updateRender: EditMarkerRender,
  });
  return <Editor value={state} onChange={setState} />;
}
```

## 版本

线程是一个只追加日志，因此一个实例会累积多个**版本**：每次用户编辑、每次 `update_*` 调用，以及（仅限线程级）创建调用。对于线程级可交互对象，这些版本会根据线程记录计算，因此重新加载后历史记录仍然存在，无需额外持久化。有两种方式可以访问这些版本。

**此消息的版本。** 在一个线程级 `render` 中，`state` / `setState` 是**当前**实例（所有消息共享同一个实例），而 `version` 是**此消息的**快照：`{ state, isLatest, restore }`。`version.state` 是该可交互对象在对话进行到此处时的状态；`restore()` 会将当前状态恢复为该状态。

只需使用这三个字段，而历史记录的行为由两个相互独立的选择决定：

- **可编辑还是只读？** 渲染当前的 `state` / `setState`，让任何消息都可以编辑共享实例；或者使用只读的 `version.state` 将其冻结。
- **是否可恢复？** 提供 `version.restore()`，将旧版本恢复为当前版本；或者不提供它。

| 你的需求             | 渲染                                  |
| -------------------- | --------------------------------------- |
| 冻结历史记录         | 在旧版本上使用只读的 `version.state`        |
| 可实时编辑           | 在所有位置使用 `state` / `setState`         |
| 只读 + 回滚          | 只读的 `version.state` 加上 `restore` |

```tsx
// Read-only history with rollback:
// old messages are frozen but can roll their version back to live
render: ({ state, setState, version }) =>
  version && !version.isLatest ? (
    <Notepad value={version.state} readOnly onRestore={version.restore} />
  ) : (
    <Notepad value={state} onChange={setState} />
  );
```

```tsx
// Live-editable:
// every message edits the shared instance; restore reverts to this point
render: ({ state, setState, version }) => (
  <Notepad value={state} onChange={setState} onRestore={version?.restore} />
);
```

**一次获取所有版本。** `unstable_useInteractableVersions(id, name)` 会按从旧到新的顺序返回所有版本，每个版本都包含完整的 `state` 和一个 `restore()`。可以使用它构建历史记录下拉菜单；它同时适用于应用级和线程级可交互对象：

```tsx
function VersionDropdown({ id, name }: { id: string; name: string }) {
  const versions = unstable_useInteractableVersions(id, name);
  if (versions.length < 2) return null;

  return (
    <select onChange={(e) => versions[+e.target.value]!.restore()}>
      {versions.map((v, i) => (
        <option key={i} value={i}>
          v{i + 1}: {v.origin === "user-edit" ? "you" : "assistant"}
        </option>
      ))}
    </select>
  );
}
```

**线程级：**

```tsx
const Notepad = ({
  id,
  state,
  setState,
}: Unstable_InteractableToolRenderProps<NotepadArgs>) => (
  <div>
    <VersionDropdown id={id} name="notepad" />
    {/* ...editor... */}
  </div>
);
```

**应用级：**

```tsx
const [state, { id }] = unstable_useInteractable("taskBoard", config);
return <VersionDropdown id={id} name="taskBoard" />;
```

应用级项目的历史记录涵盖当前对话，而不是其跨线程的完整生命周期。

## 持久化

默认情况下，应用范围内的可交互状态保存在内存中，刷新页面后会丢失。你可以通过向 `unstable_Interactables` 传入适配器来添加持久化：

```tsx
import {
  AuiConfig,
  AuiProvider,
  useAui,
  unstable_Interactables,
} from "@assistant-ui/react";

// Module-level (or memoized) so the adapter identity is stable across renders.
const persistenceAdapter = {
  load: () => {
    const saved = localStorage.getItem("interactables");
    return saved ? JSON.parse(saved) : undefined;
  },
  save: (state) => {
    localStorage.setItem("interactables", JSON.stringify(state));
  },
};

function MyRuntimeProvider({ children }) {
  const aui = useAui();
  const config = AuiConfig({
    unstable_interactables: unstable_Interactables({
      persistence: persistenceAdapter,
    }),
  });
  return (
    <AuiProvider extends={aui} config={config}>
      {children}
    </AuiProvider>
  );
}
```

适配器附加后会调用 `load`，且该调用可以是异步的。加载的状态会在可交互项注册时为其提供初始值；如果在缓慢的 `load` 仍在进行时进行了本地编辑，则本地编辑会优先于加载的值。线程范围内的可交互项不会受到适配器影响；它们通过线程历史记录进行持久化。

对于动态设置（依赖身份验证的适配器），请改为直接命令式调用 `aui.unstable_interactables.setPersistenceAdapter(adapter)`。替换或移除适配器时，会先通过即将停用的适配器刷新排队中的更改，然后再附加新的持久化上下文。

### 同步状态

设置持久化适配器后，可交互项钩子会公开同步元数据：

```tsx
const [state, { setState, isPending, error, flush }] =
  unstable_useInteractableState<TState>(id);

// isPending: true while a save is in-flight
// error: the error from the last failed save, if any
// flush(): force an immediate save (useful before navigation)
```

状态更改会在保存前自动进行防抖（500 毫秒）。所属组件卸载时，任何待处理的保存操作都会立即刷新。

### 导出 / 导入

对于自定义持久化策略，请直接使用 `exportState` 和 `importState`：

```tsx
const snapshot = aui.interactables.exportState();
// => { "note-1": { name: "note", state: { title: "Hello" } }, ... }

aui.interactables.importState(snapshot);
// Imported state is picked up when components next register
```

### Schema 演进

<Callout type="warn">
  如果在状态持久化后更改 Zod schema，加载的快照可能会与新结构静默不匹配。适配器会执行浅合并，因此额外字段会被保留，缺失字段会继续使用初始值，但运行时不会检测类型不匹配。为避免静默数据损坏，每当进行破坏性更改时，请为 schema key 添加版本号（例如 `"taskBoard_v2"`），或使用 schema hash 进行命名空间隔离。或者，也可以在 `load` 或 `importState` 调用中添加迁移步骤。
</Callout>

## 流式更新

模型生成 `update_{name}` 工具调用时，相同的部分合并会逐 token 运行，因此可交互界面会实时填充：模型正在写入的字段会逐字符更新，而只有该调用涉及的字段和数组项会发生变化。它未提及的所有内容都会保持原样。

这种稳定性是实实在在的，而不只是视觉上的效果。当某个数组项以流式方式传入时，模型未编辑的其他项在整个流式传输期间都会保持完全相同的对象身份，因此其中的记忆化行永远不会重新渲染：

```tsx
import { memo } from "react";

const TaskRow = memo(function TaskRow({ task }: { task: Task }) {
  return <li>{task.title}</li>;
});

function TaskBoard() {
  const [state] = unstable_useInteractable("taskBoard", config);

  return (
    <ul>
      {state.tasks.map((task) => (
        <TaskRow key={task.id} task={task} />
      ))}
    </ul>
  );
}
```

当 `update_taskBoard` 以流式方式编辑某个任务时，该行会随着字段到达而重新渲染，而其他所有 `TaskRow` 都保持不变，没有闪烁，也不会产生额外工作。你可以直接获得一个实时更新的列表；只有在想要在流式传输期间显示额外内容时，才需要使用部分状态。

有一种情况值得处理：在全新创建操作刚开始时，模型可能还没有生成任何项。使用线程的 `isRunning` 区分“仍在流式传输，但尚未生成任何内容”和“模型返回了空结果”，并且只在这段间隙中显示骨架屏：

```tsx
import { useAuiState } from "@assistant-ui/react";

const isRunning = useAuiState((s) => s.thread.isRunning);
const isLoading = isRunning && state.tasks.length === 0;
```

在限定于线程的 `render` 中，`streaming: true` 携带相同的实时状态：在创建调用 `state` 中，它是部分草稿（字段可能缺失）；在 `update_{name}` 调用中，它是随着编辑以流式方式传入而不断填充的实时状态。渲染一个预览；创建操作流式传输期间所做的编辑会被丢弃。

## 多个实例

一个 `name` 可以同时拥有多个活动实例。它们共享同一个 `update_{name}` 工具：模型通过工具的 `id` 参数定位实例，而该参数来自对话中的状态快照。实例挂载和卸载时，工具的名称、架构和描述都不会改变，因此模型的工具列表（以及提供商的提示缓存）可以保持稳定。架构将 `id` 标记为必填，因此模型应在每次调用时发送它；不过，当恰好存在一个实例时，运行时仍会解析不带 id 的调用。使用未知 `id` 的调用会返回一个列出有效 id 的错误，以便模型进行恢复。

实例的创建方式取决于作用域。

### 线程级：无需额外操作即可获得实例

线程级 interactable 每次模型调用其工具时，都会获得一个全新的实例。实例 `id` 就是创建该实例的调用的 `toolCallId`，因此两次调用会创建两个实例，你无需编写额外代码：同一个 `render` 和同一个 `update_{name}` 工具会为它们提供服务。这就是模型如何在一次对话中创建多个 artifact 或记事本，并通过各自的 `toolCallId` 对它们进行定位。

### 应用级：每次挂载对应一个实例

对于应用级 interactable，你可以通过在多个位置挂载 `unstable_useInteractable` 来决定实例数量，每次挂载对应一个实例。为每次挂载指定不同的 `id`：

```tsx
import { unstable_useInteractable } from "@assistant-ui/react";
import { z } from "zod";

const noteSchema = z.object({
  title: z.string(),
  content: z.string(),
  color: z.enum(["yellow", "blue", "green", "pink"]),
});

const noteInitialState = {
  title: "New Note",
  content: "",
  color: "yellow" as const,
};

function NoteCard({ noteId }: { noteId: string }) {
  const [state] = unstable_useInteractable("note", {
    id: noteId,
    description: "A sticky note",
    stateSchema: noteSchema,
    initialState: noteInitialState,
  });

  return <div>{state.title}</div>;
}

function App() {
  return (
    <>
      <NoteCard noteId="note-1" />
      <NoteCard noteId="note-2" />
      {/* one update_note tool: update_note({ id: "note-2", color: "blue" }) */}
    </>
  );
}
```

当需要访问特定实例时，传入显式的 `id`：例如，通过 `unstable_useInteractableState(id)` 从其他组件读取或写入该实例，在 [artifact](#artifacts) 面板与其内联触发器之间共享实例，或在重新加载后仍将[持久化](#persistence)状态附加到该实例。省略 `id` 也可以正常工作，此时每次挂载都会获得一个自动生成的 id；但这些 id 是按位置分配的，当动态列表添加或删除项目时会发生变化，因此以旧 id 为键的持久化状态将无法重新关联。只有当组件是唯一的读取者，且其状态不会持久化时，才可以省略 `id`。

<Callout type="info">
  `id` 中的顶层字段在你的 `stateSchema` 中是保留字段：更新工具会使用
  它进行实例定位，因此模型无法写入名为
  `id` 的状态字段。请将其嵌套，或改用其他名称（例如 `noteId`）。
</Callout>

`update_note` 会编辑已经挂载的记事：包括其 `title`、`content`、`color` 以及架构中的其他字段。它无法挂载新的 `NoteCard` 或卸载现有实例；哪些组件存在，属于应用状态的一部分。如果希望模型添加和删除记事，可以将它们建模为一个包含数组的单一 interactable（包含一个 `notes` 字段），然后由 `update_notes` 直接添加、更新、删除和清空其中的条目，就像 [快速入门](#quick-start) 中的任务板一样。只有当每条记事确实都是独立组件时，才应使用分别挂载的实例；挂载和卸载这些实例属于应用层工作，你可以将其作为[伴随工具](#companion-tools)暴露出来。

## 部分更新

自动生成的工具使用一种部分 schema，其中所有字段都是可选的。助手只会发送它想要更改的字段；省略的字段会保留当前值。

```tsx
// If the state is { title: "My Note", content: "Hello", color: "yellow" }
// The AI can call: update_note({ color: "blue" })
// Result: { title: "My Note", content: "Hello", color: "blue" }
```

这对于大型状态对象尤其有用，因为重新生成整个状态的成本高且容易出错。

对于项目携带 `id` 的数组字段，助手不会发送替换数组，而是发送操作（`add`、`update`、`remove`、`clear`），框架会将这些操作应用于当前列表。新增项目的 `id` 由框架提供；现有项目则通过你为其提供的 `id` 进行定位。

<Callout type="info">
  合并是浅层的（只有一层深度）。如果助手发送嵌套对象，
  它会替换整个字段，而不是将其深度合并到该字段中。
</Callout>

## 工作原理

1. **注册**：可交互对象会使用其名称、描述、架构和初始状态加入 `interactables` 作用域。
2. **生成工具**：每个名称对应一个 `update_{name}` 工具，其中包含部分架构（每个字段都是可选的）以及一个必需的 `id`。实例挂载和卸载时，工具列表保持稳定，因此 provider 的提示缓存可以保持预热。
3. **快照**：每条发送的用户消息都会在 `metadata.custom` 中携带当前状态，但模型已经知道该状态时除外。用户编辑会记录一个快照；模型自己的 `update_*` 调用以及消息内实例的创建参数不会记录快照。当变更适合进行浅合并时，只会记录发生变化的字段（`partial: true`）。你的路由会将快照转换为模型可见的文本（参见[状态快照](#state-snapshots)）。
4. **流式传输**：模型生成工具参数时，状态会逐字段更新，因此 UI 会实时填充内容。
5. **合并**：只应用模型发送的字段，其余字段保持不变。由 `id` 作为键的数组字段会执行操作（添加/更新/移除/清空），而不是替换整个数组；框架会为新增项目生成 id。
6. **双向同步**：模型的 `update_*` 会更新状态并触发重新渲染；用户的 `setState` 会作为新的快照随下一条消息发送。

## 卸载行为

调用过 `unstable_useInteractable` 的组件卸载时，可交互项会被注销，但其状态会保留在 `unstable_Interactables` 作用域中。当组件以相同的名称和 id 再次挂载时，该作用域会恢复保留的状态，而不是将其重置为 `initialState`。这意味着临时卸载（例如 React Strict Mode 的二次挂载或切换标签页）不会丢失状态。

从多个位置注册的实例（其创建工具调用、`update_*` 调用、一个 artifact 面板）会一直保持注册状态，直到最后一个位置卸载。因此，在虚拟化线程中将某个实例滚动移出视口时，如果它仍在其他位置可见，就不会导致该实例被销毁。

## 从旧版 API 迁移

如果你使用过早期版本的 interactables API：

- `useAssistantInteractable` 和 `useInteractableState` 已合并为单个 [`unstable_useInteractable`](#unstable_useinteractable) 钩子，用于注册并返回状态。`unstable_useInteractableState` 仍可用于次要读取者。
- 每个实例的工具（`update_note_note-1`）已移除。每个名称现在对应一个稳定的 `update_{name}` 工具，并要求提供 `id` 参数。
- 顶层的 `selected` prop 和 `setSelected` 方法已移除。请将选择表示为普通状态；参见[选择](#selection)。

## 完整示例

查看完整的 [with-interactables 示例](https://github.com/assistant-ui/assistant-ui/tree/main/examples/with-interactables)

- **任务看板**：一个可交互元素，其 `tasks` 数组可由 AI 使用 `update_taskBoard` 进行编辑（添加/更新/移除/清空）
- **便签**：一个 `notes` 可交互元素，包含一个 `selectedId` 字段，AI 可通过 `update_notes` 添加、编辑、移除和选择便签
- **localStorage 持久化**：通过 `load`/`save` 持久化适配器，使状态在刷新页面后仍然保留
- **同步指示器**：保存请求进行中显示旋转图标（`isPending`）
