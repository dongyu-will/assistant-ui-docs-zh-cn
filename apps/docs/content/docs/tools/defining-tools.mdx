工具可以让模型执行操作：获取数据、调用 API、查询数据库、驱动 UI 或运行工作流。在 assistant-ui 中，你可以在一个**工具包**（toolkit）中声明工具——这是一个带名称的映射，其中每个键都是模型看到的工具名称，每个值则描述工具的 schema、运行位置以及工具调用的渲染方式。

本页面介绍如何**编写**工具。要将工具调用渲染为自定义组件，请参阅 [Tool UI](/docs/tools/tool-ui)。要将工具接入服务器，请参阅[后端工具](/docs/tools/backend)。

## 使用 `"use generative"` 定义工具

使用 `"use generative"` + `defineToolkit` 创建工具包。编译器会将 schema、执行器和渲染器放在同一个文件中，并自动将它们拆分到客户端/服务器边界两侧。

<Callout type="info">
  当工具在其他位置执行时，你仍然可以使用生成式工具包模式：

  - 对于 MCP 服务器，展开 `defineMcpToolkit({ ... })`；
  - 对于由其他后端或运行时定义的非 MCP 工具，编写
    `execute: externalTool()` 并提供渲染器。
</Callout>

在 `"use generative"` 文件中，每个工具都必须声明 `execute`，你无需手动编写
`type`——编译器会自动推断。对于仅用于渲染的外部工具，
`externalTool()` 是一个逃生口：它可以满足编译器要求，同时不会在服务器上生成 schema 或可执行代码。

## 快速开始（`"use generative"`）

`"use generative"` 文件是一个单独的模块，其中同时包含工具的 schema、执行器和渲染器。构建插件会将其拆分为服务器构建（schema + 后端执行器）和客户端构建（schema + 渲染器 + 浏览器执行器），因此后端 `execute` 不会进入浏览器，`render` 也不会进入服务器。

<Steps>
<Step>

### 添加构建插件

没有编译器时，该指令不会执行任何操作。使用 `withAui` 包装你的 Next.js 配置：

```ts title="next.config.ts"
import { withAui } from "@assistant-ui/next";

export default withAui({
  /* ...your Next config... */
});
```

对于 Vite / TanStack Start，请改为添加 `aui()` 插件：

```ts title="vite.config.ts"
import { aui } from "@assistant-ui/vite";

export default defineConfig({
  plugins: [aui()],
});
```

对于 Expo，请使用 `withAui` 包装你的 Metro 配置：

```js title="metro.config.js"
const { getDefaultConfig } = require("expo/metro-config");
const { withAui } = require("@assistant-ui/metro");

module.exports = withAui(getDefaultConfig(__dirname));
```

对于裸 React Native 应用，请从 `@react-native/metro-config` 导入 `getDefaultConfig`，而不是导入 `expo/metro-config`。

</Step>
<Step>

### 编写工具包

文件的第一行是 `"use generative"`，默认导出为 `defineToolkit({ ... })`。每个工具都是一个内联对象字面量，包含 `parameters` schema、`execute`，以及 `render`（或 `renderText`）：

```tsx title="app/toolkit.tsx"
"use generative";

import { defineToolkit } from "@assistant-ui/react";
import { z } from "zod";

export default defineToolkit({
  get_weather: {
    description: "Get current weather for a location.",
    parameters: z.object({
      location: z.string().describe("City name or zip code"),
      unit: z.enum(["celsius", "fahrenheit"]).default("celsius"),
    }),
    execute: async ({ location, unit }) => {
      "use client";
      return fetchWeatherAPI(location, unit);
    },
    render: ({ args, result }) => {
      if (!result) return <div>Fetching weather for {args.location}…</div>;
      return (
        <div className="weather-card">
          <h3>{args.location}</h3>
          <p>
            {result.temperature}° {args.unit}
          </p>
          <p>{result.conditions}</p>
        </div>
      );
    },
  },
});
```

`execute` 内部的 `"use client"` 表示这是一个**前端**工具——其执行器会在浏览器中运行。（省略它即可让工具在服务器上运行；请参阅[工具类型](#tool-kinds)。）

</Step>
<Step>

### 注册工具包

在运行时 provider 中导入工具包，并通过 `Tools` 将其传递给 `config`：

```tsx title="app/MyRuntimeProvider.tsx"
"use client";

import { AssistantRuntimeProvider, AuiConfig, Tools } from "@assistant-ui/react";
import { useChatRuntime } from "@assistant-ui/ai-sdk";
import toolkit from "./toolkit";

export function MyRuntimeProvider({ children }: { children: React.ReactNode }) {
  const runtime = useChatRuntime();
  const config = AuiConfig({ tools: Tools({ toolkit }) });
  return (
    <AssistantRuntimeProvider
      runtime={runtime}
      config={config}
    >
      {children}
    </AssistantRuntimeProvider>
  );
}
```

`useChatRuntime()` 默认指向 `/api/chat`。如需指向其他端点或自定义请求，请参阅[自定义传输](/docs/runtimes/ai-sdk/v7#custom-transport)。

</Step>
<Step>

### 在服务器上向模型公开工具包

在路由处理器中，同一个导入会解析为**服务器构建**。将它包装在 `AISDKToolkit` 中，使模型配置拥有每个工具的 schema：

```ts title="app/api/chat/route.ts"
import { AISDKToolkit } from "@assistant-ui/ai-sdk";
import { streamText, convertToModelMessages } from "ai";
import { openai } from "@ai-sdk/openai";
import toolkit from "../../toolkit";

const aiToolkit = new AISDKToolkit({ toolkit });

export async function POST(req: Request) {
  const { messages, tools } = await req.json();

  const result = streamText({
    model: openai("gpt-5.6-luna"),
    messages: await convertToModelMessages(messages),
    tools: await aiToolkit.tools({ frontend: tools }),
  });

  return result.toUIMessageStreamResponse();
}
```

完整的服务器设置请参阅[后端工具](/docs/tools/backend)。

</Step>
</Steps>

## 编译器如何拆分生成式文件

你只需编写一个文件；插件会根据构建目标为其创建不同副本。schema（`description` + `parameters`）会保留在**两个**构建中，因此模型契约保持一致，并以后端上的 schema 为权威版本。客户端会将其前端/人工 schema 标记为后端已知，从而跳过重复上传。

工具的**类型会根据其 `execute` 推断**，并写回为 `type` 字段——在 `"use generative"` 文件中，你无需编写 `type`：

| 你编写的 `execute` | 推断出的类型 | 服务器构建保留 | 客户端构建保留 |
| --- | --- | --- | --- |
| 普通 `async () => …` | **后端** | schema + `execute`（受 `server-only` 保护） | schema + `render` |
| `async () => { "use client"; … }` | **前端** | 仅 schema | schema + `execute` + `render`/`renderText` |
| `humanTool()` | **人工** | 仅 schema | schema + `render` |
| `stubTool()` | **前端**（运行时提供执行器） | 仅 schema | schema + `render`/`renderText` |
| `providerTool({ … })` | **provider** | schema + provider 配置 | schema + provider 配置 |
| `externalTool()` | **后端**（在其他位置定义） | 省略 | `type: "backend"` + `render`/`renderText` |

编译器还会在构建时强制执行以下规则：

- 每个工具都必须声明 `execute`；
- **前端**工具必须声明 `render` 或 `renderText`；
- **人工**工具必须声明 `render`。

### 不运行自己的后端

客户端构建会跳过前端/人工 schema 的上传，因为它假设你的后端已经导入同一文件的服务器构建，并且已经知道这些 schema。当不存在你自己的服务器时——例如使用云托管运行时——这一假设就会失效，模型也永远不会了解这些工具。使用 `backendless` 选项进行编译，使客户端保留所有可上传的 schema，包括 `JSONGenerativeUI` 组件库的 `present`/`prompt_user` schema：

```ts title="next.config.ts"
export default withAui({ ...yourConfig, aui: { backendless: true } });
```

```ts title="vite.config.ts"
plugins: [aui({ backendless: true })];
```

```js title="metro.config.js"
module.exports = withAui({
  ...getDefaultConfig(__dirname),
  aui: { backendless: true },
});
```

## 工具类型

### 后端工具

在服务器上运行。编写普通的 `execute`（不包含 `"use client"`）；编译器会将其移到服务器构建中，并置于 `import "server-only"` 之后，同时只在客户端保留 schema 和 `render`。后端工具仍然可以携带 `render`，以便将其调用显示为跟踪信息：

```tsx
geocode_location: {
  description: "Geocode a location name into latitude/longitude.",
  parameters: z.object({ query: z.string() }),
  execute: async ({ query }) => geocodeLocation(query),
  render: GeocodeToolUI,
},
```

<Callout type="tip">
  以这种方式编写的后端工具**具有** `execute`。如果要为执行完全位于其他位置的工具（例如 MCP 服务器或其他后端路由）附加渲染器——此时没有可供编写的真实执行器——请使用 `externalTool()` 或 `defineMcpToolkit()`。
</Callout>

### 前端工具

在浏览器中运行。使用带有前置 `"use client"` 的真实 `execute`：

```tsx
copy_to_clipboard: {
  description: "Copy text to the user's clipboard.",
  parameters: z.object({ text: z.string() }),
  execute: async ({ text }) => {
    "use client";
    await navigator.clipboard.writeText(text);
    return { copied: true };
  },
  renderText: {
    running: "Copying text…",
    complete: "Copied text to clipboard",
  },
},
```

### 人工工具

暂停运行，直到用户通过渲染后的 UI 提供结果。编写 `execute: humanTool()`，以及一个只调用 `addResult` 一次的 `render`：

```tsx
select_date: {
  description: "Ask the user to select a date.",
  parameters: z.object({ prompt: z.string() }),
  execute: humanTool(),
  render: ({ args, result, addResult }) => {
    if (result) return <p>Selected {result.date}</p>;
    return (
      <DatePicker
        prompt={args.prompt}
        onChange={(date) => addResult({ date })}
      />
    );
  },
},
```

`humanTool` 从 `@assistant-ui/react` 导入。完整模式请参阅 [Tool UI → 人在回路](/docs/tools/tool-ui#user-input-collection)。

### Provider 工具

由模型 provider 执行（例如 OpenAI 网络搜索）。编写 `execute: providerTool({ … })`；编译器会将该配置提升到工具条目上：

```tsx
web_search: {
  execute: providerTool({
    providerId: "openai.web_search_preview",
    args: { searchContextSize: "low" },
  }),
},
```

### 外部定义的工具

当非 MCP 工具已经由其他系统定义并执行（例如独立的后端路由或 LangGraph 节点），但你希望 assistant-ui 渲染其工具调用时，请使用 `externalTool()`。从 `@assistant-ui/react` 导入 `externalTool`：

```tsx
web_search: {
  parameters: z.object({ query: z.string() }),
  execute: externalTool(),
  render: ({ args, result }) => (
    <SearchResults query={args.query} results={result?.results ?? []} />
  ),
},
```

编译器会从服务器构建中省略此条目，因此模型仍会从外部系统获取工具定义。客户端构建只保留 `type: "backend"`，以及用于匹配工具调用消息部分的渲染器（或 `renderText`）。

### 工具存根（在其他位置提供执行器）

有时工具的执行器无法放在拆分构建的 `"use generative"` 文件中，通常是因为它需要捕获 React 状态（例如 `useState` setter 或 ref）。使用 `execute: stubTool()` 声明面向模型的契约，然后在拥有该状态的组件中，使用 `useAuiToolOverrides` 在运行时提供真实执行器：

```tsx title="app/toolkit.tsx"
"use generative";

import { defineToolkit, stubTool } from "@assistant-ui/react";
import { manageTasksParameters } from "./state";

export default defineToolkit({
  manage_tasks: {
    description: "Add, toggle, or clear tasks on the board.",
    parameters: manageTasksParameters,
    execute: stubTool(),
    renderText: { running: "Updating tasks…", complete: "Tasks updated" },
  },
});
```

```tsx title="app/TaskBoard.tsx"
import { useAuiToolOverrides } from "@assistant-ui/react";

function TaskBoardToolOverrides({ setTasks }) {
  useAuiToolOverrides({
    manage_tasks: {
      execute: async ({ action, title }) => {
        // close over setTasks here, then return a payload for the model
      },
    },
  });
  return null;
}
```

`stubTool()` 没有运行时实现：它表示执行器将在之后提供，同时编译器仍会将 schema 发布到后端，以便模型可以调用该工具。此覆盖项的注册优先级高于工具包默认值，因此对于该名称，`execute` 会生效。如需在运行时关闭工具，请参阅[禁用工具](#disabling-a-tool)。完整流程请参阅[动态工具](/docs/tools/dynamic-tools)。

<Callout type="warn">
  `useAuiToolOverrides` 目前处于实验阶段，其 API 可能会发生变化。
</Callout>

## 渲染工具调用

`render` 会接收调用实时的 `args`、`result` 和 `status`，并返回一个 React 节点。如果不使用组件，而是要显示单行状态，请使用 `renderText`，并传入 `running` 和/或 `complete` 值（每个值可以是字符串或 `({ args, result }) => …` 函数）：

```tsx
renderText: {
  running: ({ args }) => `Searching for ${args.query}…`,
  complete: "Search complete",
},
```

如果没有提供渲染器，请添加 [`ToolFallback`](/elements/tool-fallback) 组件来渲染默认工具卡片。完整的渲染 API——包括状态、流式参数、延迟渲染和审批——请参阅 [Tool UI](/docs/tools/tool-ui)。

## 仅用于渲染的工具（用于外部执行的工具）

对于非 MCP 工具，优先使用带有 `externalTool()` 的 `"use generative"`；对于 MCP 服务器，则使用 `defineMcpToolkit()`。如果文件无法通过生成式编译器处理，请声明一个 `"use client"` 工具包对象，显式指定 `type: "backend"`，并且只提供 `render`：

```tsx title="app/tool-ui.tsx"
"use client";

import { defineToolkit } from "@assistant-ui/react";

export const toolkit = defineToolkit({
  web_search: {
    type: "backend",
    render: ({ args, result }) => (
      <SearchResults query={args.query} results={result?.results ?? []} />
    ),
  },
});
```

注册方式与生成式工具包完全相同：在组件主体中提升 `const config = AuiConfig({ tools: Tools({ toolkit }) })`，并传入 `config={config}`。键必须与后端或 MCP 服务器发布的工具名称一致。仅用于渲染的条目不会上传 schema，也不会运行浏览器代码——它们只会为匹配的工具调用消息部分附加 UI。

<Callout type="warn">
  这种 `{ type: "backend", render }` 形状**仅适用于普通工具包**。在
  `"use generative"` 文件中，请改用 `execute: externalTool()`；生成式
  工具必须声明 `execute`，并且不能在其中编写 `type`。
</Callout>

## 组织工具包

### 将 schema 保存在单独的模块中

从普通的 `.ts` 文件导入 Zod schema（以及 `z.infer` 参数类型），可以将它们排除在编译边界之外，并让路由处理器和组件共享相同的类型：

```ts title="app/tools/schemas.ts"
import { z } from "zod";

export const getWeatherParameters = z.object({ location: z.string() });
export type GetWeatherArgs = z.infer<typeof getWeatherParameters>;
```

### 跨文件拆分并合并工具

拆分出的每个文件都是独立的 `"use generative"` 模块，并默认导出一个 `defineToolkit(...)`：

```tsx title="app/tools/weather.tsx"
"use generative";

import { defineToolkit } from "@assistant-ui/react";

export default defineToolkit({
  get_weather: {
    /* description, parameters, execute, render */
  },
});
```

将这些默认导入展开到父工具包中，即可合并它们：

```tsx title="app/toolkit.tsx"
"use generative";

import { defineToolkit } from "@assistant-ui/react";
import weatherTools from "./tools/weather";
import databaseTools from "./tools/database";

export default defineToolkit({
  ...weatherTools,
  ...databaseTools,
});
```

编译器会自行将每个文件拆分到客户端/服务器边界两侧，然后检查展开导入是否解析为 `"use generative"` 模块，确认无误后才允许使用。因此，后端 `execute` 不会泄漏到客户端。由此有以下两条规则：

- **展开默认导入**（`import weatherTools from "./tools/weather"`）。相对路径和类似 `@/tools/weather` 的 `tsconfig` 路径别名都可以解析。只有默认导出会跨越生成式模块边界，因此命名导入（或任何不透明的非生成式导入）都会被拒绝。
- 也可以展开在同一文件中声明的本地 `defineToolkit(...)` 或 `defineMcpToolkit(...)` 绑定。

编译器会检查内联条目和编译器可见展开项中的静态工具名称。如果两个片段定义了相同的工具名称，构建会发出警告，指出 JavaScript 对象展开会保留后出现的工具定义。

如果编译器报告 `tool "weather" cannot be makeTool()`，说明该条目来自不透明的工厂调用。请将其重写为内联工具对象，或改为展开编译器可见的 `defineToolkit(...)` / `defineMcpToolkit(...)` 片段。

### 添加 MCP 服务器工具

`defineMcpToolkit` 会公开 MCP 服务器提供的工具。对于仅包含 MCP 工具的工具包，直接导出它：

```tsx title="app/mcp-toolkit.tsx"
"use generative";

import { defineMcpToolkit } from "@assistant-ui/react";

export default defineMcpToolkit({
  docs: { type: "http", url: "https://mcp.example.com/mcp" },
});
```

要将 MCP 工具与自有工具一起公开，请将其展开到 `defineToolkit` 中：

```tsx
"use generative";

import { defineToolkit, defineMcpToolkit } from "@assistant-ui/react";

export default defineToolkit({
  ...defineMcpToolkit({
    docs: { type: "http", url: "https://mcp.example.com/mcp" },
  }),
  // ...your own tools
});
```

当两个 MCP 服务器公开了相同的工具名称时，请在条目上使用 `{ server, prefix }`，这样模型就能看到不同的名称，例如 `docs_search` 和 `github_search`。

完整的服务器端和用户管理 MCP 流程请参阅 [MCP](/docs/tools/mcp)。

## 高级用法

### 多模态工具结果

默认情况下，工具的 `execute` 结果会以 JSON blob 的形式发送给模型。当有用的输出是文件或图像时，请添加 `toModelOutput`，将结果投影到模型可见的多模态内容中——你的 `render` 仍然会接收类型丰富的 `result`：

```tsx
read_pdf: {
  description: "Fetch a PDF from a URL and return it.",
  parameters: z.object({ url: z.string().url() }),
  execute: async ({ url }) => {
    const buf = new Uint8Array(await (await fetch(url)).arrayBuffer());
    return { mediaType: "application/pdf", base64: toBase64(buf) };
  },
  toModelOutput: ({ output }) => [
    { type: "text", text: "PDF contents:" },
    { type: "file", data: output.base64, mediaType: output.mediaType },
  ],
},
```

`ToolModelContentPart` 是 `{ type: "text"; text }` 和 `{ type: "file"; data; mediaType; filename? }` 的联合类型。使用 AI SDK 运行时时，还要将工具注册表传递给 `convertToModelMessages`，这样 `toModelOutput` 才会在往返传输的结果上触发——请参阅[后端工具](/docs/tools/backend#multi-modal-results)。

### 每个工具的 Provider 选项

每个工具都接受 `providerOptions` 字段。assistant-ui 会将其原样序列化到工具条目下；AI SDK 路由会转发它；provider SDK 会读取其关注的键。通过这种方式，你可以启用 provider 特有的行为（例如 Anthropic 的渐进式工具披露），而无需编写了解 provider 的代码：

```tsx
search_docs: {
  description: "Search the documentation index.",
  parameters: z.object({ query: z.string() }),
  providerOptions: { anthropic: { deferLoading: true } },
  execute: async ({ query }) => {
    "use client";
    return searchIndex(query);
  },
  renderText: { running: "Searching…", complete: "Done" },
},
```

外层键是 provider 名称；内层对象则是相应 provider 的 AI SDK 包在 `tool.providerOptions[provider]` 下所期望的内容。

### 取消

`execute` 会接收一个上下文对象，其中的 `abortSignal` 会在用户停止运行时触发。将其传递给任何异步 I/O，使工作立即停止：

```tsx
execute: async ({ query }, { abortSignal }) => {
  "use client";
  const res = await fetch(`/api/search?q=${query}`, { signal: abortSignal });
  return res.json();
},
```

该上下文还包含 `toolCallId` 和一个 `human()` 函数，可用于在执行过程中请求输入。

### 流式参数

工具运行期间，其参数会以不完整的 JSON 形式到达。在渲染器中使用 [`useToolArgsStatus`](/docs/tools/tool-ui#field-level-streaming-state)，即可在每个字段流式传入时做出响应。

### 禁用工具

设置 `disabled: true`，即可让客户端知道某个工具，但在当前作用域中对模型隐藏该工具。

如需在不编辑工具包的情况下于运行时切换工具状态，请通过 `useAuiToolOverrides` 注册相同的标志：

```tsx
import { useAuiToolOverrides } from "@assistant-ui/react";

function GuestModeTools() {
  useAuiToolOverrides({
    delete_account: { disabled: true },
  });
  return null;
}
```

该覆盖项的注册优先级高于工具包默认值，因此该工具会从发送给模型的工具集合中移除。仅在工具应被隐藏期间挂载覆盖项（例如对未登录用户隐藏工具）；卸载覆盖项后，会恢复工具包默认值。

## 从组件 API 迁移

`makeAssistantTool`、`useAssistantTool`、`makeAssistantToolUI` 和 `useAssistantToolUI` 已弃用。有关机械式迁移，请参阅[将工具迁移到工具包](/docs/migrations/toolkit-tools)。
