### fromSlackBlocks

将 Slack Block Kit JSON 转换回生成式 UI IR 树，执行与
[toSlackBlocks](/docs/api-reference/generative-ui/slack#toslackblocks) 相反的转换。接受 blocks 数组或 `{ blocks }` 包装器；
格式错误的输入会解析为空节点列表并附带警告，无法识别的区块或操作元素会被跳过，并附带
"dropped" 警告。

转换过程中读取的每个数组（blocks、fields、options、elements、cards、
rows、cells）都会在遍历前限制在其对应位置的上限以内，因此恶意数组（稀疏数组，或通过代理伪造
`length` 的数组）会被限制，并附带 "clamped" 警告，而不会阻塞事件循环。永不抛出异常。

Slack 的数据结构相比 IR 包含的信息更少，因此部分信息无法恢复：上下文区块的元素始终会解码为
`Caption`（原始的 `Badge` 与 `Caption` 区分在往返转换中不会保留）；
只有对于 `primary`/`danger` Slack 样式，按钮的 `buttonStyle` 才能恢复；
原生警告区块的 `title` 和 `description` 会合并为单个 `description` 字符串；
卡片布局会折叠为其 `title`、扁平的 `children` 列表（依次为图片、文本和说明），
以及 `confirm`/`cancel` 页脚按钮。

区块字段的标签和值会以第一个 `*`+换行分隔符进行拆分，因此如果标签或值本身包含
该完全一致的分隔符，就无法明确地拆分还原。

Slack 以 `raw_text` 携带的数据表单元格始终会解码为字符串，即使其文本是布尔值的字符串化形式，
因为 Slack 数据结构无法区分布尔值和普通文本。
