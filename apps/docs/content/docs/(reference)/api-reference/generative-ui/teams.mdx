### decodeSubmitData

解码 Teams bot 在 Action.Submit 上接收的合并 `activity.value` 对象，反转 buildSubmitAction 将恢复操作嵌套于其中的 `aui` 封装。Adaptive Cards 会将同一卡片中其他输入的值，根据其 `id` 合并到同一个提交对象中，因此除 `aui` 之外的所有顶层键都会收集到 `$input` 中（没有其他键时省略）。
`aui` 为封装保留：`toAdaptiveCard` 会在编码前将 id 可能发生冲突的输入重命名为从其派生的未使用 id，因此同一卡片输入的值绝不会落入此键。`$input` 和 `type` 在解码时保留：如果封装载荷中包含 `$input` 键，则会将其丢弃，以确保该位置始终只反映同一卡片输入的值；同时，封装自身的 `type` 会覆盖载荷中同名的键。收集到的每个键（位于 `payload` 或 `$input` 中）都会作为返回对象自身的数据属性保留，即使是 `__proto__` 或 `constructor` 键也是如此，因为对象始终通过展开和 `Object.fromEntries` 构建，而不是通过键赋值构建。封装键只会作为自身属性读取，因此原型继承的 `aui`、`type` 或 `payload` 值永远不会触发分发。对于缺失或格式错误的 `aui` 封装，返回 `undefined`；不会抛出异常。

### TeamsConversionWarning

Teams 转换过程中报告的非致命说明。

`clamped` 表示为适应限制而移除了内容，`dropped` 表示丢弃了节点或其某个属性，并可能留下占位符说明，`fallback` 表示以不同于请求的形式输出了节点。`advisory` 表示完全未做任何更改，并指出 Teams 仍可能无法良好呈现或拒绝某些内容，例如超过字节预算的载荷，或超出建议列数的 `Row`。

### toAdaptiveCard

将生成式 UI 树转换为 Microsoft Teams Adaptive Card，并生成非致命转换警告。尺寸、字重和颜色会映射到 Adaptive Card 的语义枚举，而不是原始值。如果 Input/Select/RadioGroup/Checkbox/DatePicker 的 id 将使用保留的 RESERVED_INPUT_ID，则会将其重命名并发出警告（参见 `decodeSubmitData`）。此函数不会抛出异常：未知的 `$type` 会被跳过并附带“dropped”警告；格式错误的输入则会解析为空卡片，并附带“dropped”警告，而不会抛出异常。

### toTeamsAttachments

将生成式 UI 树转换为 Teams bot framework 消息附件。根级别的 `Carousel` 会根据每个 `Card` 子节点生成一个附件（数量限制为 CAROUSEL_ATTACHMENT_CAP），并包含 `attachmentLayout: "carousel"`；其他内容则通过 [toAdaptiveCard](/docs/api-reference/generative-ui/teams#toadaptivecard) 的引擎转换为单个附件。不会抛出异常。
