### ActionHandler

解析单个 `$action.type`。即发即忘操作返回 `void` 或解析为该值的
promise；人在回路操作返回一个值，运行时使用该值恢复运行（参见 IR 文档中的
开放问题 #2——恢复值留作 `unknown`，并针对每个操作分别记录）。返回值会作为
`unknown` 传回 `dispatch` 的调用方。

```ts
type ActionHandler = (
  ctx: ActionDispatchContext,
) => unknown | Promise<unknown>;
```

### ActionRegistry

由宿主提供的从 `$action.type` 到 [ActionHandler](/docs/api-reference/generative-ui/actions#actionhandler) 的映射。这是渲染后的生成式 UI
唯一的分发目标：每个交互式组件都会通过注入的 `$dispatch`，将其
`$action` 触发到此处（提交 Button 则改为使用其祖先表单的分发）。负载的
`$input` 有两种形式：对于独立控件的分发，它是单个值（`Select`、
`Input`、`DatePicker`、`Checkbox`、`RadioGroup`）；对于
`Form`，或设置了 `asForm` 的 `Card`，它是一个以字段
`name` 为键的对象。使用 [createActionRegistry](/docs/api-reference/generative-ui/actions#createactionregistry) 创建它，并将其传递给
`JSONGenerativeUI`。

### emptyActionRegistry

未提供任何处理器时使用的空操作注册表。分发会解析为
`undefined`，并在开发环境中针对未知类型记录警告，因此模型发出的、没有处理器的
操作会降级为“什么也不做”，而不是抛出异常。

```ts
const emptyActionRegistry: ActionRegistry;
```
