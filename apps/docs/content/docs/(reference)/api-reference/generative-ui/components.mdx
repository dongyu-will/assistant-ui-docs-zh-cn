## API 参考

### defaultGenerativeUILibrary

工厂提供的封闭式生成式 UI 词汇表：模型可以渲染的一组固定内置组件。每个组件都包含一个 zod `properties` 架构，以及一个无样式的结构化 `render`（使用语义化 HTML，并通过 `data-aui` 属性标识组件，同时提供 `data-aui-<prop>` 钩子，供宿主进行样式设置）。用户可以将其传入 `new JSONGenerativeUI({ library: defaultGenerativeUILibrary })` 以启用，并使用自己的 `defineGenerativeComponents` 覆盖或扩展其中的条目。

```ts
const defaultGenerativeUILibrary: GenerativeUILibrary;
```

### defineGenerativeComponents

用于编写 `"use generative"` 生成式 UI 组件库的辅助工具，即模型可以渲染的组件集合。每个组件都将其 `properties` 架构（每次构建都会保留，用于驱动工具参数）与其 `render` 放在一起（仅在客户端保留）。将结果传递给 [JSONGenerativeUI](/docs/api-reference/generative-ui/json-generative-ui#jsongenerativeui)：

```tsx
"use generative";
const generative = new JSONGenerativeUI({
  library: defineGenerativeComponents({
    Card: {
      description: "A card.",
      properties: z.object({ title: z.string() }),
      render: (props) => <Card {...props} />,
    },
  }),
});
```

与 [defineToolkit](/docs/api-reference/tools/toolkits#definetoolkit) 不同，它**没有运行时实现**。`"use generative"` 编译器会在每次构建时展开 `defineGenerativeComponents(...)` 调用，并将每个 `render`（及其仅客户端导入）从服务器构建中移除。在运行时触达它，意味着该模块未被编译（缺少该指令，或在 `"use generative"` 文件之外使用），因此它会抛出异常，而不是将客户端 `render` 代码发送到服务器。

### GenerativeUIComponent

模型可以渲染的组件，以及其 props 的架构。

组件可以通过 `streamProperties` 选择启用 props 流式传输：随着 props 到达，组件会持续渲染，因此 `render` 会在 `$status` 为 `"streaming"` 时看到 `Partial<P>`，并在其 `P` 完成后看到完整的 `"done"`。默认情况下，组件不启用该功能，只有在 props 完整后才会渲染一次。

`render` 是 `props` 的函数，而不是 React 组件。可以直接使用钩子（每个节点都挂载在自己的 fiber 上），但同一个节点必须在多次渲染之间保持其 `type`，才能确保钩子标识保持稳定。

### GenerativeUILibrary

由使用者提供的组件允许列表，规定模型可以渲染哪些组件。键是生成式 UI 树中引用的 `type` 值（例如 `"Card"`、`"Button"`）；值则描述每个组件。

该注册表是安全边界——任何不在其中的 `type` 都会被拒绝。

```ts
type GenerativeUILibrary = Record<string, GenerativeUIComponent>;
```
