## API 参考

### buildPresentParameters

根据 [GenerativeUILibrary](/docs/api-reference/generative-ui/components#generativeuilibrary) 构建 `present` 工具的 JSON schema。

模型会生成一个节点 `{ $type, $key?,...props }`，其中 `$type` 选择
组件，可选的 `$key` 为可能重新排序的列表项固定稳定的标识，
其余字段则是该组件的 props。该 schema 是一个扁平对象：`$type`
是组件名称的枚举，所有组件的 props 会合并到一个可选字段集合中，而
`children` 则通过 `$defs` 递归，使树可以嵌套。

这种设计有意采用扁平结构，而不是按每个 `$type` 划分的判别联合。
工具 / 函数调用 schema（包括 OpenAI 等产品的 schema）要求顶层参数为普通对象，
并会拒绝顶层的 `oneOf`/`anyOf`/`enum`。因此，根部无法
按 `$type` 细化 props；相反，模型会通过 `$type` 的
description（其中列出了每个组件）以及每个 prop 自身的 description 获得引导。
渲染器在这里不会执行任何验证——未知的 `$type` 或多余的 prop 会在
渲染时处理——因此，较宽松的 schema 只会少给模型一个提示，并不会牺牲安全性。

### generativeUIToJSX

将生成式 UI 节点序列化为用于展示的类 JSX 字符串：也就是模型生成树的
“查看源代码”。线上的形式 `{ $type: "Weather", id: "x" }` 会变为 `<Weather id="x" />`，
嵌套的 `children` 会渲染在标签之间：`<Card title="Hi"><Text>hello</Text></Card>`。
模型提供的 `$key` 会变成 JSX 的 `key` 属性。

默认情况下，这是忠实的文本渲染，而不是解析器：文本子节点会原样输出（不会进行
HTML/JSX 转义），因此结果适合展示，而不适合再次解析。对于不可渲染的节点
（尚无 `$type`、`null`、布尔值），返回
`""`。

传入 `{ escape: true }` 可使输出安全地粘贴回 JSX：任何包含
`<`、`>`、`&`、
`{` 或 `}` 的字符串子节点，都会输出为
JSON 字符串化表达式（`{JSON.stringify(child)}`），而不是原样输出；不包含这些字符的
字符串子节点仍会原样渲染。

传入 `{ pretty: true }` 可使用两个空格的缩进格式化打印嵌套元素树，而纯文本
子节点仍会保持在同一行。

### renderGenerativeUI

根据 [GenerativeUILibrary](/docs/api-reference/generative-ui/components#generativeuilibrary) 渲染生成式 UI 树。

模型会将每个节点生成为扁平对象 `{ $type,...props }`。我们首先将这种线上形式
规范化为规范的 NormalizedUINode（将 `children` 提升为保留的顶层
键），然后进行渲染：每个 `type` 都会在库中查找，并将其
`props` 传递给组件的 `render(props, context)`，同时递归渲染
`children`，使组件可以嵌套。
