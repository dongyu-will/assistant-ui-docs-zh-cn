`Toolkit` 是面向模型的工具定义命名映射。`Tools` 资源会将工具包安装到助手子树中：将每个工具注册到模型上下文，并将每个 `render` 组件注册到工具调用渲染器作用域。

当你希望工具的可用性跟随运行时或 provider 树时，请使用这些 API。旧版组件作用域注册 API 已弃用；请参阅[将工具迁移到工具包](/docs/migrations/toolkit-tools)。

## API 参考

### tool

定义模型工具，包括其参数 schema、执行行为以及可选的模型输出转换。

此辅助函数让可复用的工具定义保持类型检查，并便于
export for a [Toolkit](/docs/api-reference/tools/toolkits#toolkit) registered with [Tools](/docs/api-reference/tools/toolkits#tools).
使用。当 `parameters` 是 Standard Schema（例如 Zod v4）时，其输入类型
会推断用于 `execute`、`streamCall` 以及模型输出回调。普通的
JSON Schema 对象不携带 TypeScript 输入类型，因此在需要为 JSON Schema 精确指定参数时，
请提供泛型参数或为回调添加类型注解。

```ts
import { z } from "zod";

const getWeather = tool({
  type: "frontend",
  description: "Get the weather for a city.",
  parameters: z.object({ city: z.string() }),
  execute: async ({ city }) => `Sunny in ${city}`,
});
```

### ToolDefinition

React 工具注册表接受的工具定义。

在核心工具契约的基础上扩展工具调用显示选项。Human tools
依赖 `render` 从用户处收集输入。Frontend tools 在浏览器中执行，并且需要
`render` 或 `renderText` 来显示其进度和结果。Backend tools 在服务器端执行，
可以省略渲染器。

### Toolkit

向助手模型公开的命名工具集合。

键是模型接收并在工具调用中使用的工具名称。

```tsx
const toolkit = defineToolkit({
  get_weather: {
    type: "frontend",
    description: "Get the weather for a city.",
    parameters: weatherSchema,
    execute: async ({ city }: { city: string }) => fetchWeather(city),
    render: WeatherToolUI,
  },
});
```

```ts
type Toolkit = Record<string, ToolDefinition<any, any>>;
```

### defineToolkit

工具包编写辅助函数。接受宽松的 ToolkitDefinition
（生成式 `backend` 工具可以携带其服务器 `execute`），并将结果类型化为规范的
[Toolkit](/docs/api-reference/tools/toolkits#toolkit)。

在 `"use generative"` 文件中，编译器会在每次构建时移除包装器，以便跨客户端/服务器边界拆分
schema、渲染器和执行器。在生成式编译之外，它会原样返回工具包，也可用于普通的 frontend/backend/human 工具包对象。

### externalTool

将生成式工具包条目标记为由外部执行的 backend 工具。

当其他系统（例如 backend 路由或 LangGraph 节点）已经定义并执行该工具，但 assistant-ui
应渲染其工具调用时，请使用此函数。use-generative 编译器会从服务器构建中省略 `execute: externalTool()`
条目，并在客户端构建中保留 `type: "backend"` 渲染器。

```ts
function externalTool(): never;
```

### humanTool

将工具标记为 **human-in-the-loop（人在回路）**：代理暂停，由 UI（`render`）
提供结果，而不是由代码提供。将其用作工具的 `execute`：

```tsx
confirm: { execute: humanTool(), render: (props) => <Confirm {...props} /> }
```

与 [defineToolkit](/docs/api-reference/tools/toolkits#definetoolkit) 不同，它**没有运行时实现**：`"use generative"`
编译器（例如 `@assistant-ui/next` 或 `@assistant-ui/vite`）会检测 `execute: humanTool()`，
将其移除，并为工具添加 `type: "human"` 标记。
如果在运行时到达这里，说明模块未被编译（在 `"use generative"` 文件之外使用），因此会抛出异常。

```ts
function humanTool(): never;
```

### providerTool

将工具标记为由 provider 执行。use-generative 编译器会将
`execute: providerTool(...)` 转换为 `type: "provider"` 工具条目。

### stubTool

将生成式工具包条目标记为 frontend 工具，其执行器将由 `useAuiToolOverrides(...)` 提供。

`stubTool()` 没有运行时实现。必须在 `"use generative"` 工具包文件中使用它，
以便编译器将其移除。

```ts
function stubTool(): never;
```
