### unstable_useInteractable

<Callout type="tip">
<strong>实验性。</strong> 不稳定 / 实验性（实际上并未移除）。
</Callout>

向 AI 助手注册一个 interactable，并返回其实时状态，
例如 `useState`，模型也可以读取和更新该状态。

每个显示 interactable 的位置调用一次。其他组件可以通过将其
`id` 传递给 `unstable_useInteractableState`，读取和写入同一实例。

对于渲染在工具调用消息部分中的工具创建 interactable，
`version` 包含该实例在此消息中的版本——即
会话进行到该位置时的状态、它是否是最新的工具驱动版本，以及一个指向它的
`restore()`。较早消息是渲染冻结的历史记录，还是保持可实时编辑，
由组件自行决定。在 `update_{name}` 部分中，实例的
`id` 会从调用中推断，因此同一组件既可用于
创建调用，也可用于更新调用。

### unstable_useInteractableState

<Callout type="tip">
<strong>实验性。</strong> 不稳定 / 实验性（实际上并未移除）。
</Callout>

按 ID 读取和写入在其他位置注册的 interactable 的状态。

在次级读取者（子组件、兄弟组件）中使用此 hook；拥有该 interactable
的组件通过 `unstable_useInteractable` 注册，该 hook 会直接返回状态。
在拥有的 interactable 注册之前，返回 `undefined`。

### unstable_interactableTool

<Callout type="tip">
<strong>实验性。</strong> 不稳定 / 实验性（实际上并未移除）。
</Callout>

定义一个根据参数创建线程作用域 interactable 的工具，
以便分配给工具包条目——条目键就是 interactable 名称：

```tsx
notepad: unstable_interactableTool({
  description: "A notepad the user can read and edit.",
  stateSchema: notepadSchema,
  render: (props) => <Notepad {...props} />,
}),
```

`render` 会在创建调用以及——自动安装后——每次
`update_{name}` 调用中显示，并处理流式预览、实例 ID 连接和注册。
它会接收实时的 `state`/`setState`，以及此
消息的 `version`；较早消息是渲染冻结的历史记录，还是保持
可实时编辑，由渲染函数自行决定。

```ts
const unstable_interactableTool: <TSchema extends Unstable_InteractableStateSchema>(config: Unstable_InteractableToolConfig<TSchema>) => ToolDefinition<Record<string, unknown>, { success: true; }>;
```

### unstable_getInteractableVersions

<Callout type="tip">
<strong>实验性。</strong> 不稳定 / 实验性（实际上并未移除）。
</Callout>

线程中记录的 interactable `id` 的每个版本，按时间从旧到新排列，
按时间顺序合并：

- `toolCallId` 等于 `id` 的工具调用使用其参数
  （`origin: "create"`）建立基线——这是工具创建 interactable 的
  `id: toolCallId`约定；
- 标记在用户消息上的快照是一个 `"user-edit"` 版本（完整快照会替换状态；
  部分快照会进行浅合并）；
- 每个已接受的 `update_*` 调用都会将一个
  `"update"` 版本进行浅合并。

最后一个条目就是模型所知道的状态。没有可供合并的基线时，会跳过部分快照和更新调用。
