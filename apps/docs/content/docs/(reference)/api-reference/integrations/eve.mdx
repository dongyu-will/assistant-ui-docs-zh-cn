### toEveInputResponse

将 assistant-ui 工具批准响应转换为 Eve 输入响应。

当 `inputRequest` 已知时，每个返回的响应都会携带请求声明的选项或自由格式答案。优先匹配字面选项，然后是响应布尔决策所命名的 `"approve"` / `"cancel"` 选项，最后是在请求接受自由格式答案（`display: "text"`、`allowFreeform`、没有任何选项，但绝不会是 `display: "confirmation"`）且响应不是拒绝时，使用响应的 `text`（对于早于一等答案字段的调用方，则使用其 `reason`）。
单参数调用或不带请求的 part 仍会像以往一样转发调用方的 `optionId`，包括请求从未声明的 id。

如果已知请求无法将响应记录为其所要求的答案，则会抛出异常而不是提交响应，因为 eve 会在收到针对请求的任何响应时立即解析该请求，而空响应会被记录为没有内容的答案。不发送响应会使请求保持待处理状态，因此调用方可以重试，或者用户可以像回答普通消息一样回答它。

如果没有可用于映射的请求——单参数调用，或不携带 `toolMetadata.eve.inputRequest` 的 part——响应会像以往一样映射到每个 eve 批准都声明的字面 `"approve"` / `"cancel"` 选项。猜测显示模式正是此映射器不再执行的操作；未知请求并不代表对某种显示模式的猜测。

```ts
const toEveInputResponse: (response: RespondToToolApprovalOptions, inputRequest?: EveMessageInputRequest) => InputResponse;
```

### useEveAgentRuntime

将 Eve 的 `useEveAgent` 钩子连接到 assistant-ui 的运行时契约。

该运行时会渲染 Eve 消息，将新的用户消息转发到 Eve 会话，支持取消，并将 Eve 输入请求映射到 assistant-ui 工具批准 UI。

### useEveError

从运行时附加数据中读取 Eve 会话的最后一个错误。

const useEveError: () => Error | undefined;

### useEveEvents

从运行时附加数据中读取权威的 Eve 服务器事件流。
在 Eve 运行时之外默认为空数组。

```ts
const useEveEvents: () => EveRuntimeExtras["events"];
```

### useEveReset

返回一个用于重置 Eve 会话的函数：中止正在进行的回合，重新创建所拥有的会话，并清除事件和投影数据。待处理的暂存消息和工具执行状态都会被丢弃。在 Eve 运行时之外渲染是安全的；但在此环境中调用返回的函数会抛出异常。

```ts
const useEveReset: () => () => void;
```

### useEveSession

从运行时附加数据中读取当前的 Eve 会话游标。持久化该游标，即可稍后通过 `initialSession` 恢复会话。当尚不存在会话或处于 Eve 运行时之外时，`undefined`。

```ts
const useEveSession: () => EveRuntimeExtras["session"] | undefined;
```
