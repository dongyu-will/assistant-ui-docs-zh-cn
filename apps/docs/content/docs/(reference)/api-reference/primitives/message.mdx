### groupPartByType

根据 `part.type → group-key path` 查找表构建 `groupBy`。
类型不在映射表中的部分将保持未分组状态。返回的函数带有稳定的
GROUPBY_MEMO_KEY 指纹，因此
`<MessagePrimitive.GroupedParts>` 可以在多次渲染之间缓存其树结构。

合成的 `"standalone-tool-call"` 键用于匹配应在思维链分组之外
渲染的工具调用。MCP-app 调用仅根据部分本身进行检测；由注册表驱动的情况（人工工具、生成式 UI
工具、`display: "standalone"` 选择加入）则根据
`<MessagePrimitive.GroupedParts>` 传递给
`groupBy` 函数的 GroupByContext 进行解析——无需向辅助函数传入任何额外参数。

```tsx
<MessagePrimitive.GroupedParts
  groupBy={groupPartByType({
    reasoning: ["group-thought", "group-reasoning"],
    "tool-call": ["group-thought", "group-tool"],
    "standalone-tool-call": [],
  })}
>
  {({ part, children }) => { ... }}
</MessagePrimitive.GroupedParts>
```

```ts
const groupPartByType: <TKey extends `group-${string}`>(map: Partial<Readonly<Record<GroupPartType, readonly TKey[]>>>) => ((part: PartState, context?: GroupByContext) => readonly TKey[]);
```
