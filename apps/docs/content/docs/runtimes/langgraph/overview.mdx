`@assistant-ui/react-langgraph` 直接与 [`@langchain/langgraph-sdk`](https://docs.langchain.com/oss/javascript/langgraph-sdk) 集成，将完整的 LangGraph Cloud 功能集引入 assistant-ui：流式传输、子图事件、UI 消息、消息元数据、中断和端到端取消。

<Callout type="info">
**正在从 LangServe 迁移？** LangChain 已在上游弃用 `RemoteRunnable`，并将链和助手执行统一到 LangGraph 下。将你的链重建为 LangGraph 图（LangChain 的 [LangServe → LangGraph 迁移指南](https://github.com/langchain-ai/langserve/blob/main/MIGRATION.md) 介绍了结构变化），通过 LangGraph Cloud 部署或自行托管 LangGraph Studio，然后在前端使用此运行时。该运行时开箱即支持流式传输、中断、生成式 UI、消息元数据和端到端取消。
</Callout>

## 何时使用

在以下情况下选择 LangGraph 运行时：

- 你已经拥有（或希望拥有）LangGraph Cloud 服务器，可通过 [LangGraph Studio](https://docs.langchain.com/langsmith/quick-start-studio) 在本地运行，或通过 [LangSmith](https://www.langchain.com/langsmith). 托管
- 你的图状态包含一个 `messages` 键，其值为类似 LangChain 的消息。
- 你需要生成式 UI（`ui_message`）、每条消息的元数据、子图事件或基于检查点的消息编辑。

<Callout type="info">
如果你已经在使用 `@langchain/react` 的 `useStream` hook，那么替代方案 [`@assistant-ui/react-langchain`](/docs/runtimes/langchain) 适配器可能更适合。它将流式传输的处理委托给上游 hook；功能范围有所不同，请参阅 [LangChain useStream](/docs/runtimes/langchain) 中的对比表。
</Callout>

## 架构

`@assistant-ui/react-langgraph` 构建在 `ExternalStoreRuntime` 之上（参见[架构](/docs/runtimes/concepts/architecture)）。图状态是真实数据源；运行时从 `state.values.messages` 渲染消息，并将用户输入提交回图。

共享适配器（附件、语音、反馈、历史记录）的工作方式与[适配器](/docs/runtimes/concepts/adapters)中所述相同。

## 要求

- 一个 LangGraph Cloud API 服务器。
- React 18 或 19。
- 图状态必须包含一个 `messages` 键，其值为类似 LangChain 的消息。
