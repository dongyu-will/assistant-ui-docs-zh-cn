description: 中断持久化和基于检查点的消息编辑。
---

中断持久化和消息编辑都依赖 LangGraph 的服务端检查点。完成其中一项的接入后，另一项基本无需额外工作。

## 中断持久化

LangGraph 支持中断执行流程，以请求用户输入或处理特定交互。在不同线程之间切换时，这些中断可以被持久化和恢复：

1. 确保线程状态类型包含 `interrupts` 字段。
2. 从 `load` 函数中连同消息一起返回中断。
3. 在切换线程时，运行时会自动恢复中断状态。

```ts
const runtime = useLangGraphRuntime({
  stream: async (messages, { initialize, ...config }) => {
    /* ... */
  },
  load: async (externalId) => {
    const state = await getThreadState(externalId);
    return {
      messages: state.values.messages,
      interrupts: state.tasks[0]?.interrupts,
    };
  },
});
```

这对于需要用户审批流程、多步骤表单或其他跨越多次线程切换的交互元素的应用尤其有用。

## 消息编辑与重新生成

LangGraph 使用服务端检查点进行状态管理。要支持消息编辑（分支）和重新生成，请提供 `getCheckpointId` 回调，用于解析适合服务端创建分支的检查点。

```ts
const runtime = useLangGraphRuntime({
  stream: async (messages, { initialize, ...config }) => {
    const { externalId } = await initialize();
    if (!externalId) throw new Error("Thread not found");
    return sendMessage({ threadId: externalId, messages, config });
  },
  create: async () => {
    const { thread_id } = await createThread();
    return { externalId: thread_id };
  },
  load: async (externalId) => {
    const state = await getThreadState(externalId);
    return {
      messages: state.values.messages,
      interrupts: state.tasks[0]?.interrupts,
    };
  },
  getCheckpointId: async (threadId, parentMessages) => {
    const client = createClient();
    const history = await client.threads.getHistory(threadId);
    for (const state of history) {
      const stateMessages = state.values.messages;
      if (!stateMessages || stateMessages.length !== parentMessages.length) {
        continue;
      }
      const hasStableIds =
        parentMessages.every((m) => typeof m.id === "string") &&
        stateMessages.every((m) => typeof m.id === "string");
      if (!hasStableIds) continue;

      const isMatch = parentMessages.every(
        (m, i) => m.id === stateMessages[i]?.id,
      );
      if (isMatch) {
        return state.checkpoint.checkpoint_id ?? null;
      }
    }
    return null;
  },
});
```

提供 `getCheckpointId` 后：

- 用户消息上会显示**编辑按钮**，允许用户从该位置编辑并重新发送。
- 助手消息上会显示**重新生成按钮**，允许用户重新生成响应。

解析后的 `checkpointId` 会通过 `config.checkpointId` 传递给你的 `stream` 回调。你的 `sendMessage` 辅助函数应将其映射到 LangGraph SDK 的 `checkpoint_id` 参数（有关该辅助函数，请参阅[快速入门](/docs/runtimes/langgraph/quickstart)）。

<Callout type="info">
如果没有 `getCheckpointId`，则不会显示编辑和重新生成按钮。这是有意为之；如果不从正确的服务端检查点创建分支，而仅截断客户端消息，就会产生错误的状态。
</Callout>
