每个 assistant-ui runtime 都从单个内存线程开始。根据你使用的 runtime 以及希望线程存储的位置，可以通过三种机制之一添加多线程支持。

## 单线程（默认）

不配置线程时，runtime 会渲染一个线程，并在页面重新加载时重置。适合原型、演示和无状态交互。

如果你只需要会话持久化（单线程，重新加载后仍然保留），请提供一个[历史记录适配器](/docs/runtimes/concepts/adapters#history-adapter)，而不是切换到多线程。

## 多线程方案

共有三种选项。请根据你希望由谁负责管理来选择。

| 方案 | Runtime | 线程元数据的管理方 | 最适合 |
| --- | --- | --- | --- |
| AssistantCloud | LocalRuntime 及基于它构建的适配器 | assistant-cloud | 希望由服务托管；认证、同步和持久化均由服务处理 |
| RemoteThreadListRuntime | LocalRuntime 及基于它构建的适配器 | 你的数据库 | 已有自己的后端并希望完全控制 |
| ExternalStoreThreadListAdapter | 仅 ExternalStoreRuntime | 你的状态存储 | 使用 redux、zustand 等管理状态 |

## AssistantCloud

`AssistantCloud` 是托管式多线程服务。将实例传递给 `useLocalRuntime`（或任何基于它构建的适配器）后，线程、持久化、同步和标题都会由服务代为处理。

```tsx
import { useLocalRuntime } from "@assistant-ui/react";
import { AssistantCloud } from "assistant-cloud";

const cloud = new AssistantCloud({
  baseUrl: process.env.NEXT_PUBLIC_ASSISTANT_BASE_URL,
  anonymous: true,
});

const runtime = useLocalRuntime(modelAdapter, { cloud });
```

框架适配器直接接收 `cloud`。`AISDKThreads({ cloud })` 是 `AuiConfig` 宿主的 store 条目列表。它只挂载可见线程，因此切换线程会取消正在进行的运行，且该次交互不会被持久化。

```tsx
const runtime = useChatRuntime({ cloud });
const threads = AISDKThreads({ cloud });
const runtime = useLangGraphRuntime({ cloud /* stream, load, ... */ });
const runtime = useAdkRuntime({ cloud, stream });
```

请参阅[云端文档](/docs/cloud)，了解设置、认证和自托管选项。

## RemoteThreadListRuntime（自定义数据库）

`useRemoteThreadListRuntime` 允许你使用任意数据库作为线程列表的后端，同时保持每个线程的 runtime 简单。你需要提供一个 `RemoteThreadListAdapter`，用于说明如何列出、创建、重命名、归档和删除线程。请确保该适配器引用在多次渲染之间保持稳定（放在模块作用域，或使用 `useMemo`）。替换适配器会重新加载列表，并丢弃不在替换页面中的缓存线程。

它适用于任何基于 `LocalRuntime` 的 runtime，包括基于它构建的框架适配器（`ai-sdk`、`react-google-adk`、`react-a2a`、`useDataStreamRuntime`）。

```tsx title="app/MyProvider.tsx"
"use client";

import {
  AssistantRuntimeProvider,
  useLocalRuntime,
  useRemoteThreadListRuntime,
  type RemoteThreadListAdapter,
} from "@assistant-ui/react";
import { createAssistantStream } from "assistant-stream";
import { modelAdapter } from "./model-adapter";

const adapter: RemoteThreadListAdapter = {
  async list() {
    const threads = await fetch("/api/threads").then((r) => r.json());
    return {
      threads: threads.map((t: any) => ({
        status: t.archived ? "archived" : "regular",
        remoteId: t.id,
        title: t.title,
      })),
    };
  },
  async initialize(localId) {
    const t = await fetch("/api/threads", {
      method: "POST",
      body: JSON.stringify({ localId }),
    }).then((r) => r.json());
    return { remoteId: t.id };
  },
  async rename(remoteId, title) {
    await fetch(`/api/threads/${remoteId}`, {
      method: "PATCH",
      body: JSON.stringify({ title }),
    });
  },
  async archive(remoteId) {
    await fetch(`/api/threads/${remoteId}/archive`, { method: "POST" });
  },
  async unarchive(remoteId) {
    await fetch(`/api/threads/${remoteId}/unarchive`, { method: "POST" });
  },
  async delete(remoteId) {
    await fetch(`/api/threads/${remoteId}`, { method: "DELETE" });
  },
  async fetch(remoteId) {
    const t = await fetch(`/api/threads/${remoteId}`).then((r) => r.json());
    return {
      status: t.archived ? "archived" : "regular",
      remoteId: t.id,
      title: t.title,
    };
  },
  async generateTitle(remoteId, messages) {
    return createAssistantStream(async (controller) => {
      const { title } = await fetch(`/api/threads/${remoteId}/title`, {
        method: "POST",
        body: JSON.stringify({ messages }),
      }).then((r) => r.json());
      controller.appendText(title);
    });
  },
};

export function MyProvider({ children }: { children: React.ReactNode }) {
  const runtime = useRemoteThreadListRuntime({
    runtimeHook: () => useLocalRuntime(modelAdapter),
    adapter,
  });
  return (
    <AssistantRuntimeProvider runtime={runtime}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

### 持久化消息

`RemoteThreadListAdapter` 只管理线程元数据。每个线程的历史记录和附件是独立的扩展点，提供两种使用方式：

- `unstable_useAdapters` 是一个 hook。`RemoteThreadList` store 条目会在客户端树中调用它，因此任何 `createAssistantClient` 宿主都能获得与 React hook 宿主相同的适配器。`useRemoteThreadListRuntime` 也会在省略 `unstable_Provider` 时调用它。
- `unstable_Provider` 是一个 React 组件。存在 `useRemoteThreadListRuntime` 时会渲染它。store 条目会忽略它。

在 store 条目中，使用 `withKey` 包装线程工厂，使线程在切换时重新挂载。历史记录适配器会在每次挂载时加载一次。不带 key 的工厂会一直复用同一个实例，因此下一个线程的消息永远不会出现。

```tsx
import { withKey } from "@assistant-ui/tap";
import { RemoteThreadList } from "@assistant-ui/react";

threads: RemoteThreadList({
  adapter,
  thread: (id) => withKey(id, MyThread({ threadId: id })),
}),
```

在两种方式之间共享同一个 hook：

```tsx
import {
  RuntimeAdapterProvider,
  useAui,
  type RemoteThreadListAdapter,
  type ThreadHistoryAdapter,
} from "@assistant-ui/react";
import { useMemo } from "react";

function useThreadListAdapters() {
  const aui = useAui();
  const history = useMemo<ThreadHistoryAdapter>(
    () => ({
      async load() {
        const { remoteId } = aui.threadListItem.getState();
        if (!remoteId) return { messages: [] };
        const rows = await fetch(
          `/api/threads/${remoteId}/messages`,
        ).then((r) => r.json());
        return { messages: rows.map(toThreadMessage) };
      },
      async append({ message, parentId }) {
        const { remoteId } = await aui.threadListItem.initialize();
        await fetch(`/api/threads/${remoteId}/messages`, {
          method: "POST",
          body: JSON.stringify({ message, parentId }),
        });
      },
    }),
    [aui],
  );
  return useMemo(() => ({ history }), [history]);
}

const adapterWithHistory: RemoteThreadListAdapter = {
  // ...metadata methods above...
  unstable_useAdapters: useThreadListAdapters,
  unstable_Provider({ children }) {
    const adapters = useThreadListAdapters();
    return (
      <RuntimeAdapterProvider adapters={adapters}>
        {children}
      </RuntimeAdapterProvider>
    );
  },
};
```

<Callout type="warn">
`unstable_Provider` 必须在首次提交时同步渲染 `children`。不要将 `children` 放在加载状态、Suspense 或 `useEffect` 之后。若需要在线程可用前加载数据，请在始终渲染的子组件中执行（例如通过历史记录适配器），而不是通过不渲染 `children` 来实现。
</Callout>

### 避免首条消息竞争

`append` 可能会在线程记录存在于后端之前被调用。写入前请始终等待 `aui.threadListItem.initialize()`：

```ts
async append({ message, parentId }) {
  const { remoteId } = await aui.threadListItem.initialize();
  await saveMessage(remoteId, parentId, message);
}
```

`initialize()` 可以安全地多次调用。它始终会解析为当前线程对应的同一个 `remoteId`。

同样的规则也适用于自定义外部状态存储的 dispatch。在线程记录存在之前，runtime 不会持有 `onNew` 或 `onEdit`（否则用户消息会在整个往返过程中无法显示在屏幕上），因此，处理器如果要访问以远程身份为键的后端，必须自行等待 `initialize()`：

```ts
onNew: async (message) => {
  const { remoteId } = await aui.threadListItem.initialize();
  await sendToBackend(remoteId, message);
},
```

### 异步认证后重新加载

如果你的适配器依赖于异步解析的用户（oidc、`next-auth`、`better-auth`），初始的 `list()` 可能会在用户可用之前运行。认证完成后调用 `aui.threads.reload()`：

```tsx
function ReloadOnAuth() {
  const aui = useAui();
  const { isLoading, user } = useAuth();
  useEffect(() => {
    if (!isLoading && user) aui.threads.reload();
  }, [isLoading, user?.id]);
  return null;
}
```

`reload()` 会丢弃已被后续调用取代的进行中响应，因此可以在每次认证状态切换时安全调用。在 `RemoteThreadList` store 条目中，重新创建适配器对象在调用 `reload()` 之前不会产生任何作用。对同一个实例调用 `reload()` 会刷新列表并保留当前打开的线程。对不同的适配器实例调用 `reload()` 会重置选中状态和缓存记录，然后加载替换后的状态存储。

### 重新获取当前打开的线程

对同一个适配器实例调用 `reload()` 会重新执行 `list()`，但只会刷新线程列表元数据，不会触碰用户当前正在查看的线程消息。当打开线程的服务器状态在带外发生变化，且没有任何内容通过流到达时（例如由其他进程引发的人机协作中断、流停滞，或通过轮询发现状态变化），请调用 `aui.threads.reloadMainThread()`：

```tsx
function RefetchOnInterrupt({ status }: { status: string }) {
  const aui = useAui();
  useEffect(() => {
    if (status !== "interrupted") return;
    aui.threads.reloadMainThread().catch(reportError);
  }, [status]);
  return null;
}
```

promise 的含义取决于具体方案。在重新挂载方案中，它会在替换后的 runtime 挂载后立即解析，这发生在该 runtime 的 `load()` 开始之前，因此等待它并不意味着线程已是最新状态，加载失败也不会传递给调用方。在原地更新方案中，它会随重新获取操作一起完成，并在失败时拒绝，这也是上面示例仍然处理拒绝的原因。

尚未发送过的线程会保持不变，因为它不包含远程状态。

正在进行的运行会发生什么取决于具体方案。重新挂载方案会丢弃负责渲染该运行的 runtime；运行本身是否停止取决于该 hook 的卸载清理逻辑，核心无法强制执行。在原地更新方案中，由声明该能力的 runtime 自行决定，因为核心不会替它停止运行。无论哪种方式，都应由事件触发，而不是使用短计时器：由上面这样的状态变化驱动，或者在 `useAuiState((s) => s.thread.isRunning)` 为 true 时跳过调用。

重新获取的方式取决于 runtime，共有三种。当 runtime 声明该能力时，会复用线程 runtime：编辑器草稿会保留，现有消息会在加载最新状态期间继续渲染，返回的 promise 会随重新获取操作完成，并在失败时拒绝。不具备该能力的远程线程列表会改为重新挂载 runtime hook，从而重新执行 `load()`，代价是丢弃尚未发送的编辑器输入；它会在新 runtime 挂载后解析。单线程和内存线程列表没有可供重新挂载的 hook：如果其 tap `ExternalThread` 获得了 `onRefetchThread`，则采用原地更新方案；如果没有，则直接解析且不执行任何操作。

`useAuiState((s) => s.thread.capabilities.refetchThread)` 会报告你将获得哪种行为，以及是否会原地更新。它不是决定是否提供刷新功能的信号：在调用仍会执行工作的重新挂载方案中，它为 false；在调用不会执行任何操作的情况下，它同样为 false。

LangGraph 和 Google ADK 适配器都会在 runtime hook 接收到 `load` 函数时注册原地重新获取能力；没有该函数时则退回重新挂载方案。Eve 适配器会在已安装的 `eve` 暴露 `resume()`（0.44.1 及更高版本）时注册该能力，且没有可传入的选项；在旧版本中，它会像其他适配器一样退回，在单线程和内存线程列表中通常表现为调用解析但不执行任何操作。运行期间发生重新获取时，三者的完成方式也不同：LangGraph 和 Google ADK 会立即发起加载，因此 promise 会在获取延迟后完成，并由各自的实现决定到达时竞态运行会保留快照中的哪些内容；Eve 则会将重放排在正在进行的轮次之后，因此 promise 只有在该轮次暂停后才会完成。其他远程适配器会采用重新挂载方案，除非它们自行提供该能力。

对于外部状态存储 runtime，使用 `onRefetchThread` 声明该能力。它与 `onReload` 无关（后者会重新生成一条 assistant 消息）；tap `ExternalThread` 接受相同的 prop：

```ts
useExternalStoreRuntime({
  messages,
  onNew,
  onRefetchThread: async () => {
    setMessages(await fetchMessages(threadId));
  },
});
```

### 对线程列表分页

如果后端返回线程分页数据，请从 `nextCursor` 返回一个 `list()`，并在 UI 中使用 `aui.threads.hasMore` 和 `aui.threads.loadMore()`。runtime 会在每次 `params.after` 时，通过 `list()` 将线程 `loadMore()` 传回；初始调用不会传递 `params`，因此应将缺少 `after` 视为“第一页”。`reload()` 会重置游标，使下一次加载再次从第 1 页开始。

```ts title="threadListAdapter.ts (excerpt)"
async list({ after } = {}) {
  const url = new URL("/api/threads", location.origin);
  if (after) url.searchParams.set("after", after);
  const response = await fetch(url);
  const { threads, next_cursor } = await response.json();
  return {
    threads: threads.map((thread) => ({
      remoteId: thread.id,
      status: thread.is_archived ? "archived" : "regular",
      title: thread.title ?? undefined,
    })),
    nextCursor: next_cursor ?? undefined,
  };
},
```

对于按钮驱动的 UI，将 `<ThreadListPrimitive.LoadMore>` 放在列表底部。runtime 正在加载或没有可用的 `nextCursor` 时，它会处于禁用状态。如果希望改为通过滚动触发，请在应用层将同一个原语包装在 `IntersectionObserver` 中；assistant-ui 按设计将基于可见性的加载交由用户代码处理。

```tsx title="ThreadList.tsx"
import {
  ThreadListPrimitive,
  ThreadListItemPrimitive,
} from "@assistant-ui/react";

export function ThreadList() {
  return (
    <ThreadListPrimitive.Root>
      <ThreadListPrimitive.Items>
        {() => (
          <ThreadListItemPrimitive.Root>
            <ThreadListItemPrimitive.Trigger>
              <ThreadListItemPrimitive.Title />
            </ThreadListItemPrimitive.Trigger>
          </ThreadListItemPrimitive.Root>
        )}
      </ThreadListPrimitive.Items>
      <ThreadListPrimitive.LoadMore>Load more</ThreadListPrimitive.LoadMore>
    </ThreadListPrimitive.Root>
  );
}
```

在 `loadMore()` 之上构建自定义 UI 时，需要了解以下几个不变量：

- **空字符串游标会被视为“没有更多页面”。** `nextCursor: ""` 会被视为与 `nextCursor: undefined` 相同，因此后端因页码偏移错误而返回空游标时，也不会无限循环。
- **并发的 `loadMore()` 调用会去重。** runtime 会为每个页面保留一个进行中的 promise，因此同时从哨兵和按钮调用 `loadMore()` 时，只会发出一个网络请求。
- **页面错误会被吞掉。** 如果 `list({ after })` 被拒绝，游标会被保留，下一次 `loadMore()` 会使用相同的 `after` 值重试。无论如何，返回给调用方的 promise 都会解析。如果需要向用户显示反馈，请自行处理适配器错误。

### 自定义元数据

`RemoteThreadMetadata` 包含一个可选的 `custom?: Record<string, unknown>` 插槽，用于存放后端专用字段（时间戳、所有者 ID、工作区 ID、标签、模型名称）。你从 `list()` 和 `fetch()` 返回的任何内容，都会传递到线程列表项状态中，并可通过 `useAuiState` 从任何 UI 原语访问。

```ts
type MyThreadMetadata = RemoteThreadMetadata & {
  readonly custom: {
    readonly createdAt: string;
    readonly ownerId: string;
  };
};
```

```tsx
import { useAuiState } from "@assistant-ui/react";

function ThreadListItemMeta() {
  const custom = useAuiState(
    (s) => s.threadListItem.custom as MyThreadMetadata["custom"] | undefined,
  );
  return (
    <span>
      {custom?.ownerId} · {custom?.createdAt}
    </span>
  );
}
```

`custom` 会在 `rename`、`archive`、`unarchive` 和 `generateTitle` 之间保留。要从 UI 中替换它，请实现 `RemoteThreadListAdapter.updateCustom` 并调用 `aui.threadListItem.updateCustom(custom)`。cloud 适配器会通过 `cloud.threads.update(threadId, { metadata })` 持久化该数据。如果你的适配器通过独立的应用路径修改线程元数据，请从 `fetch()` 返回更新后的值，或调用 `aui.threads.reload()` 重新执行 `list()`。

## ExternalStoreThreadListAdapter

仅适用于 `ExternalStoreRuntime` 用户。将多线程支持接入外部状态存储。

```tsx
const threadListAdapter: ExternalStoreThreadListAdapter = {
  threadId: currentThreadId,
  threads: threadList.filter((t) => t.status === "regular"),
  archivedThreads: threadList.filter((t) => t.status === "archived"),
  onSwitchToNewThread: () => {
    /* create + switch */
  },
  onSwitchToThread: (id) => setCurrentThreadId(id),
  onRename: (id, title) => {
    /* update */
  },
  onArchive: (id) => {
    /* archive */
  },
  onUnarchive: (id) => {
    /* unarchive */
  },
  onDelete: (id) => {
    /* delete */
  },
};

const runtime = useExternalStoreRuntime({
  messages: threads.get(currentThreadId) ?? [],
  setMessages: (messages) =>
    setThreads((m) => new Map(m).set(currentThreadId, messages)),
  onNew,
  adapters: { threadList: threadListAdapter },
});
```

与 `RemoteThreadListAdapter` 不同，此适配器是同步且内联的。你需要在自己的状态存储中维护线程元数据和消息；runtime 只会渲染你提供的内容。

<Callout type="warn">
runtime 的 `currentThreadId` 必须与你的状态存储中选中的线程保持同步。线程 ID 不匹配会导致消息显示在线程中，或完全消失。请在 context 中集中管理线程 ID 状态，不要放在组件本地状态中。
</Callout>

## 如何选择

请依次回答以下三个问题：

1. **希望由服务托管吗？** 使用 `AssistantCloud`。无需编写数据库代码。
2. **有自己的后端吗？** 如果使用 `RemoteThreadListRuntime`（或任何基于它构建的适配器），请使用 `LocalRuntime`。由你实现适配器并负责数据。
3. **使用 `ExternalStoreRuntime` 吗？** 使用 `ExternalStoreThreadListAdapter`。线程与消息一起存储在你的状态存储中。
