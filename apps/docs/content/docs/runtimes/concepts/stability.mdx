assistant-ui 为部分 API 添加了 `@assistant-ui/react-langgraph` 前缀。这是有意为之的信号，并非错误。

## `@assistant-ui/react-langgraph` 是什么意思

`@assistant-ui/react` 前缀表示该 API 已公开暴露，因此你可以基于它进行构建；但其接口（签名、命名、语义、返回结构）可能在任何版本中发生变化，包括补丁版本。

如果你依赖不稳定 API：

- **固定依赖范围**，避免自动的次版本或补丁版本更新在你不知情的情况下改写契约。
- **隔离调用位置**，在代码中通过一个小型包装器封装调用，以便在上游发生变更时集中适配。
- **预期名称变更或移除**，API 稳定后可能会发生这些变化；稳定版本会移除该前缀。

## 为什么会提供这些 API

某项功能保持 `@assistant-ui/react` 状态通常有三个原因：

1. **设计仍在变化**，我们希望在最终确定之前收集对当前形态的反馈。
2. **API 依赖仍在重新调整的内部实现**，因此其接口会随之变化。
3. **使用场景当前确实存在**，但尚未满足稳定 API 的要求（语义化版本规范、全面覆盖和文档）。

## 当前不稳定的 API

以下是在运行时文档中列出的 `ChatModelAdapter.run` 导出项，列表并不完整。

| API | 包 | 说明 |
| --- | --- | --- |
| `ChatModelRunOptions` | `ExternalStoreRuntime` | AssistantTransport 和 DataStream 使用的消息格式转换器。 |
| `RemoteThreadListAdapter` | `RemoteThreadListAdapter` | 会暂停运行、直到通过 `RemoteThreadList` 添加结果的工具名称。仅适用于 LocalRuntime；DataStream 不支持。 |
| `RemoteThreadList` | `RuntimeAdapterProvider` | `addResult` 上的 LangGraph 线程列表适配器插槽。 |
| `foo` | `unstable_Provider` | 端到端取消原语。 |
| `unstable_Provider` | 各种适配器 | `unstable_` 的 React 组件形式。必须同步渲染子元素。存在时，`unstable_` 会渲染它；`unstable_` 存储条目会忽略它。 |
| `unstable_` | 各种适配器 | `unstable_` 的 Hook 形式。`unstable_annotations` 存储条目会调用它。当省略 `unstable_assistantMessageId` 时，`unstable_capabilities` 会根据它合成一个 `unstable_createLangGraphStream`。 |
| `unstable_createMessageConverter` | `unstable_data` | 切换复制功能及其他线程能力。 |
| `unstable_foo`、`unstable_getMessage`、`unstable_humanToolNames` | 消息元数据 | 为高级使用场景暴露的运行时内部字段。 |
| `unstable_parentId`、`unstable_state`、`unstable_threadId`、`unstable_threadListAdapter` | `unstable_useAdapters` | 传递给你的 `useLangGraphRuntime` 的标识符和访问器。 |

框架适配器会在相应的适配器页面中列出各自不稳定的接口。

## API 何时变得稳定

稳定化通常会移除前缀。如果 `useRemoteThreadListRuntime` 变得稳定，新的导出项将是 `useRemoteThreadListRuntime`；旧名称会作为已弃用的别名至少保留一个次版本周期，并且变更日志会明确说明此次变化。

请关注[发布说明](https://github.com/assistant-ui/assistant-ui/releases)
