---
title: 适配器
description: 用于附件、语音、反馈、历史记录和建议的可复用扩展点。
---

适配器是 assistant-ui 为运行时添加文件上传或消息持久化等能力的方式，同时不会将运行时耦合到特定后端。你只需实现一个小型接口，将其插入运行时的 `adapters` 选项中，相应的 UI 界面（回形针按钮、音频按钮、历史记录重新加载）就会自动启用。

本页中的每个适配器，在支持它的各个运行时中都以相同方式工作。通过该运行时的 `adapters` 选项提供它：

```ts
const runtime = useLocalRuntime(modelAdapter, {
  adapters: { attachments, history, speech, feedback, suggestion },
});
```

框架适配器的形式相同：

```ts
const runtime = useChatRuntime({ adapters: { attachments, history } });
```

## 附件适配器 [#attachment-adapter]

用于处理文件和图片上传。启用后，输入框会渲染一个回形针按钮。

```ts
type AttachmentAdapter = {
  accept: string;
  add: (input: {
    file: File;
  }) => Promise<PendingAttachment> | AsyncGenerator<PendingAttachment, void>;
  send: (
    attachment: PendingAttachment,
    options?: { signal?: AbortSignal },
  ) => Promise<CompleteAttachment>;
  remove: (attachment: Attachment) => Promise<void>;
};
```

三个生命周期方法：

- `add` 在用户选择文件时运行。上传文件，并返回一个状态为 `requires-action` 的待发送附件，使输入框在发送前保存该文件；也可以通过异步生成器依次产出该附件的状态。每次产出都必须使用同一个 `id`；使用其他 `id` 的结果会被忽略。
- `send` 在用户提交消息时运行。完成上传，附加 `content` 负载，并将状态标记为 `complete`。
- `remove` 在用户发送前移除附件时运行。

最小上传并发送示例：

```ts
const attachmentAdapter: AttachmentAdapter = {
  accept: "image/*,application/pdf",
  async add({ file }) {
    const form = new FormData();
    form.append("file", file);
    const { id, url } = await fetch("/api/upload", {
      method: "POST",
      body: form,
    }).then((r) => r.json());
    return {
      id,
      type: file.type.startsWith("image/") ? "image" : "document",
      name: file.name,
      contentType: file.type,
      file,
      url,
      status: { type: "requires-action", reason: "composer-send" },
    };
  },
  async send(attachment) {
    return {
      ...attachment,
      status: { type: "complete" },
      content: [
        attachment.type === "image"
          ? { type: "image", image: attachment.url! }
          : { type: "text", text: `[${attachment.name}](${attachment.url})` },
      ],
    };
  },
  async remove() {
    // Delete the uploaded file here if your backend keeps one.
  },
};
```

对于多种文件类型，使用 `CompositeAttachmentAdapter`：

```ts
import {
  CompositeAttachmentAdapter,
  SimpleImageAttachmentAdapter,
  SimpleTextAttachmentAdapter,
} from "@assistant-ui/react";

const attachmentAdapter = new CompositeAttachmentAdapter([
  new SimpleImageAttachmentAdapter(),
  new SimpleTextAttachmentAdapter(),
]);
```

## 语音适配器 [#speech-adapter]

将助手消息转换为语音。启用后，消息气泡会渲染一个音频按钮。

```ts
type SpeechSynthesisAdapter = {
  speak: (text: string) => Utterance;
};
```

`speak` 返回一个 `Utterance`，其中包含 `cancel()`、`status` 字段和 `subscribe(callback)`。使用浏览器原生能力的示例：

```ts
const speechAdapter: SpeechSynthesisAdapter = {
  speak(text) {
    const utterance = new SpeechSynthesisUtterance(text);
    const subscribers = new Set<() => void>();
    const result: SpeechSynthesisAdapter.Utterance = {
      status: { type: "running" },
      cancel: () => {
        speechSynthesis.cancel();
        result.status = { type: "ended", reason: "cancelled" };
        subscribers.forEach((cb) => cb());
      },
      subscribe(cb) {
        subscribers.add(cb);
        return () => subscribers.delete(cb);
      },
    };
    utterance.addEventListener("end", () => {
      result.status = { type: "ended", reason: "finished" };
      subscribers.forEach((cb) => cb());
    });
    speechSynthesis.speak(utterance);
    return result;
  },
};
```

## 听写适配器 [#dictation-adapter]

为输入框提供语音转文字输入。启用后，输入框会渲染一个麦克风按钮。

```ts
type DictationAdapter = {
  listen: () => DictationAdapter.Session;
  disableInputDuringDictation?: boolean;
};
```

`listen` 返回一个会话，其中包含 `stop()`、`cancel()`、`status` 字段，以及 `onSpeechStart`、`onSpeech` 和 `onSpeechEnd` 订阅。

## 反馈适配器 [#feedback-adapter]

对助手消息点赞或点踩。启用后，消息气泡会渲染反馈按钮。

```ts
type FeedbackAdapter = {
  submit: (feedback: {
    type: "positive" | "negative";
    message: ThreadMessage;
    comment?: string;
  }) => void;
};
```

当调用方把意见传给 `submitFeedback({ type, comment })` 时，就会设置 `comment`，例如 FeedbackDialog 这样的表单会在点踩后提交意见。运行时会去掉首尾空白，并省略空意见。

```ts
const feedbackAdapter: FeedbackAdapter = {
  async submit({ type, message, comment }) {
    await fetch("/api/feedback", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ messageId: message.id, rating: type, comment }),
    });
  },
};
```

## 历史记录适配器 [#history-adapter]

按线程持久化消息。由 `LocalRuntime`、`useDataStreamRuntime` 以及接受 `adapters.history` 的框架适配器（`ai-sdk`、`react-a2a`、`react-ag-ui`）使用。

`ExternalStoreRuntime` 不直接使用历史记录适配器，因为消息数组已经由你维护。请改为通过你的存储进行持久化。`react-langgraph` 和 `react-google-adk` 通过其 `load` 回调读取服务器端线程状态，`react-langchain` 则通过 `useStream` 读取。

```ts
type ThreadHistoryAdapter = {
  scopeId?: string;
  load: () => Promise<{
    headId?: string | null;
    messages: { parentId: string | null; message: ThreadMessage }[];
  }>;
  append: (item: {
    parentId: string | null;
    message: ThreadMessage;
  }) => Promise<void>;
  update?: (item: {
    parentId: string | null;
    message: ThreadMessage;
  }) => Promise<void>;
  delete?: (
    items: { parentId: string | null; message: ThreadMessage }[],
  ) => Promise<void>;
  resume?: (
    options: ChatModelRunOptions,
  ) => AsyncGenerator<ChatModelRunResult, void, unknown>;
  withFormat?: <TMessage, TStorageFormat extends Record<string, unknown>>(
    formatAdapter: MessageFormatAdapter<TMessage, TStorageFormat>,
  ) => GenericThreadHistoryAdapter<TMessage>;
};
```

`load` 在线程打开时运行。`append` 在每条消息完成后运行；如果某条消息的运行尚未结束，后续轮次就已开始，也会提前运行。`update` 会原地改写已存储的消息，使运行时能够保存等待工具审批而暂停的运行，以及消息结束后才到达的工具结果；如果不提供它，暂停的运行会在结束或后续轮次开始时存储一次，此次追加之后运行新增的内容将不会被保存。

当 `LocalRuntime` 可以切换账号、工作区或其他底层存储时，
将 `scopeId` 设为该存储作用域的稳定标识符。为同一作用域重建适配器时，
保持该标识符不变；加载其他作用域前，
先更改它。切换作用域会停止属于原作用域的工作，清除其
内存中的历史记录和输入框草稿，丢弃所有尚未返回的结果，并加载
当前适配器。未提供 `scopeId` 的适配器会被视为共享同一个
作用域。

`scopeId` 目前仅适用于 `LocalRuntime`。AI SDK、AG-UI、A2A 及其他
使用外部历史记录的运行时，在每次挂载时只加载一次历史记录，因此存储作用域变化时，
需要重新挂载这些运行时。

如果本地运行时写入历史记录失败，线程会发出 `historyWriteError`，其中包含尝试执行的 `operation`（`append`、`update` 或 `delete`）、受影响的 `messageIds`、可读的 `message` 和原始 `error`。存储会转发 `thread.historyWriteError`，并携带 `threadId`、`operation`、`messageIds` 和 `message`。监听器只有在绑定到受影响的线程时才能收到失败事件，因此切换离开某个线程后，该线程发生的写入失败不会传递给任何监听器；无论如何，运行时都会通过 `console.error` 记录每一次写入失败。返回给调用方的写入 Promise 仍会拒绝。external store 的历史记录副本在写入失败时仍只给出警告，不会发出此事件。

<Callout type="info">
`ai-sdk` 要求提供 `withFormat`，以便消息能够以 AI SDK `UIMessage` 对象的形式往返转换。没有 `withFormat` 的适配器在 AI SDK 路径中会在运行时抛出错误。完整用法请参阅 [AI SDK 历史记录文档](/docs/runtimes/ai-sdk/v7)。
</Callout>

## 建议适配器 [#suggestion-adapter]

在每条助手消息之后提出后续提示。启用后，建议选项会显示在最新的助手消息下方。

```ts
type SuggestionAdapter = {
  generate: (input: {
    messages: readonly ThreadMessage[];
    signal?: AbortSignal;
  }) =>
    | Promise<readonly ThreadSuggestion[]>
    | AsyncGenerator<readonly ThreadSuggestion[], void>;
};
```

```ts
const suggestionAdapter: SuggestionAdapter = {
  async *generate({ messages }) {
    const last = messages.at(-1);
    if (!last) return;
    const response = await fetch("/api/suggestions", {
      method: "POST",
      body: JSON.stringify(last),
    });
    yield (await response.json()).suggestions;
  },
};
```

## 组合适配器 [#composing-adapters]

根据需要提供任意数量的适配器。UI 界面会根据已填充的插槽启用相应功能。

```ts
const runtime = useLocalRuntime(modelAdapter, {
  adapters: {
    attachments: myAttachmentAdapter,
    history: myHistoryAdapter,
    speech: mySpeechAdapter,
    feedback: myFeedbackAdapter,
  },
});
```
