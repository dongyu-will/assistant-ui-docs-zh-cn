import { LangGraphIcon } from "@/components/icons/langgraph";

`@assistant-ui/react-langchain` 封装了来自 `useStream` 的 [`@langchain/react`](https://reference.langchain.com/javascript/langchain-react/use-stream) assistant-ui 运行时暴露出来。它面向与 [`@assistant-ui/react-langgraph`](/docs/runtimes/langgraph/overview)（LangGraph Cloud）相同的后端，但处于更高层级，将流式传输流程委托给上游 hook。

## 适用场景

在以下情况下，优先选择 `react-langchain` 而不是 `react-langgraph`：

- 你通过 `npx create-assistant-ui -t langchain` 搭建项目（官方模板使用了它）。
- 你的应用已经依赖 `@langchain/react`，并且在其他地方使用 `useStream`。
- 你希望通过 `useLangChainState<T>(key)` 响应式地读取自定义状态键（`todos`、`files` 和计划）。
- 你更喜欢保持与上游行为一致的轻量封装。

在以下情况下，则选择 `react-langgraph`：

- 你需要完全自定义的后端流（自己的异步生成器），而不是 `useStream` 的传输层；或者你正在维护现有的 `react-langgraph` 应用。

这两个适配器都是一等支持的，目前功能已基本对等（完整对比请参见下方的[对比表](#comparison-with-react-langgraph)）；`react-langchain` 是更新且更轻量的封装，并固定使用上游的 `useStream`。

## 架构

`@assistant-ui/react-langchain` 构建于 `ExternalStoreRuntime` 之上（参见[架构](/docs/runtimes/concepts/architecture)）。图状态是事实来源；运行时从 `state.values.messages` 渲染消息，并将用户输入提交回图。

共享适配器（附件、语音、反馈）的工作方式与[适配器](/docs/runtimes/concepts/adapters)中所述相同。内置云端线程持久化功能。

`thread.isLoading` 反映 `useStream` 的 `isThreadLoading`（初始历史记录注水），这与 `isRunning`（运行正在进行中）相互独立。

## 要求

- 一个 LangGraph Cloud API 服务器（本地通过 [LangGraph Studio](https://docs.langchain.com/langsmith/quick-start-studio) [LangSmith](https://www.langchain.com/langsmith)).
- 图状态必须包含一个 `messages` 键，其值为类似 LangChain 的消息，或者传入自定义的 `messagesKey`。

## `useStreamRuntime` 选项

`useStreamRuntime` 接受上游 `useStream` 支持的所有选项，此外还支持以下 assistant-ui 特有字段：

| 选项 | 类型 | 描述 |
| --- | --- | --- |
| `cloud` | `AssistantCloud` | 可选。通过 assistant-cloud 持久化会话线程。 |
| `adapters` | `{ attachments?, speech?, feedback? }` | 可选。附件、语音和反馈适配器。 |
| `messagesKey` | `string` | 保存消息的状态键。默认为 `"messages"`。 |
| `uiStateKey` | `string` | 保存生成式 `UIMessage` 的状态键。默认为 `"ui"`。 |

### 转发每次运行的配置

发送消息时，其 `runConfig.custom`（例如选定的模式或模型）会作为 `config.configurable` 转发到底层的 `useStream().submit` 调用中。自动恢复工具结果以及中断辅助函数（`useLangChainRespond`、`useLangChainRespondAll` 和 `useLangChainSubmit(null, { command })`）会复用同一份已记录的 `configurable`，除非调用方传入 `config`。启动新运行的原始 `useLangChainSubmit` / `useLangChainSend` 调用不会继承该配置。该记录的作用域为会话，重新加载后不会保留。在图中可通过 `config["configurable"]` 读取；在 LangGraph v1 中，也可以通过 Runtime `context` 访问相同的值，而 `config.configurable` 就是该值的别名。这样，无需额外连接配置，即可将每次运行的应用配置传递到图中。

## 读取自定义状态键

LangGraph agent 通常会公开消息之外的结构化状态（计划、待办事项、临时文件、生成式 UI 工件）。使用 `useLangChainState` 直接读取这些状态。它会镜像上游的 `useStream().values[key]`，并在流式传输发出新状态时更新。

}

## 中断

LangGraph 中断会暂停图并等待客户端输入。`useLangChainInterruptState` 暴露当前中断；`useLangChainRespond` 使用响应载荷恢复中断，而 `useLangChainSubmit` 则使用原始状态更新恢复图。

`useLangChainRespond` 是更简洁的恢复路径；它通过 `useStream().respond` 传递响应载荷，并处理 interrupt 命名空间，因此你无需构造 `Command`。

<PlatformTabs>
<Tab value="React">

```tsx
import {
  useLangChainInterruptState,
  useLangChainRespond,
} from "@assistant-ui/react-langchain";

function InterruptPrompt() {
  const interrupt = useLangChainInterruptState();
  const respond = useLangChainRespond();
  if (!interrupt) return null;
  return (
    <div>
      <pre>{JSON.stringify(interrupt.value, null, 2)}</pre>
      <button onClick={() => respond({ approved: true })}>Approve</button>
    </div>
  );
}
```

当同时存在多个待处理的中断时（例如并行审批），请使用 `useLangChainRespondAll()` 在一次运行中恢复所有中断。连续调用 `useLangChainRespond` 无法实现这一点，因为第一次恢复会启动一次运行，并使其余中断被搁置。

```tsx
import {
  useLangChainInterrupts,
  useLangChainRespondAll,
} from "@assistant-ui/react-langchain";

const interrupts = useLangChainInterrupts();
const respondAll = useLangChainRespondAll();
// resume every pending interrupt with the same payload:
await respondAll(
  Object.fromEntries(
    interrupts.flatMap((i) => (i.id ? [[i.id, { approved: true }]] : [])),
  ),
);
```

你也可以通过 `useLangChainSubmit` 使用原始 `Command` 恢复：

## 子代理和子图发现

对于多智能体图，`useStream` 会将当前运行中已发现的子代理和子图记录为轻量级发现映射。`useLangChainSubagents` 和 `useLangChainSubgraphs` 会公开这些映射——以命名空间为键，每个值都是一个 `SubagentDiscoverySnapshot` / `SubgraphDiscoverySnapshot`。两者均默认为稳定的空映射，因此你可以直接进行迭代，无需额外的保护判断。

这些映射取代了 `react-langgraph` 的子图 `eventHandlers`：v1 将发现结果作为映射公开，你可以响应式地读取这些映射，而不是使用逐事件回调。

```tsx
import {
  useLangChainSubagents,
  useLangChainSubgraphs,
} from "@assistant-ui/react-langchain";

function Discovered() {
  const subagents = useLangChainSubagents();
  const subgraphs = useLangChainSubgraphs();
  return (
    <ul>
      {[...subagents.keys()].map((ns) => (
        <li key={ns}>subagent: {ns}</li>
      ))}
      {[...subgraphs.keys()].map((ns) => (
        <li key={ns}>subgraph: {ns}</li>
      ))}
    </ul>
  );
}
```

## 子代理和子图视图

上面的发现映射结合 v1 的作用域选择器 hooks，可用于渲染子代理或子图自身的消息和工具调用。`useLangChainStream` 暴露底层的 `useStream` 句柄；将其传递给 `@langchain/react` 中的 `useMessages(stream, target)` / `useToolCalls(stream, target)`，并以 `useLangChainSubagents` / `useLangChainSubgraphs` 中的 `SubagentDiscoverySnapshot` / `SubgraphDiscoverySnapshot` 作为目标。`useLangChainStream` 会在运行时提供程序之外返回 `undefined`。

```tsx
import {
  useLangChainStream,
  useLangChainSubagents,
} from "@assistant-ui/react-langchain";
import { useMessages, useToolCalls } from "@langchain/react";

function SubagentCard({ stream, subagent }) {
  const messages = useMessages(stream, subagent);
  const toolCalls = useToolCalls(stream, subagent);
  return (
    <div>
      <strong>{subagent.namespace.join("/")}</strong>
      <pre>{messages.map((m) => m.content).join("\n")}</pre>
      <ul>
        {toolCalls.map((tc) => (
          <li key={tc.id}>{tc.name}</li>
        ))}
      </ul>
    </div>
  );
}

function Subagents() {
  const stream = useLangChainStream();
  const subagents = useLangChainSubagents();
  if (!stream) return null;
  return [...subagents.values()].map((s) => (
    <SubagentCard key={s.namespace.join("/")} stream={stream} subagent={s} />
  ));
}
```

## 每条消息的元数据

`useMessageMetadata`（来自 `@langchain/react`）会读取指定消息 ID 的每条消息元数据（例如 `parentCheckpointId`）。将其与 `useLangChainStream` 配合使用，后者会在运行时提供程序之外返回 `undefined`；调用选择器前请先守护流，因为 `useMessageMetadata` 在流未定义时会抛出异常。

```tsx
import { useLangChainStream } from "@assistant-ui/react-langchain";
import { useMessageMetadata } from "@langchain/react";

function MessageInfoView({
  stream,
  messageId,
}: {
  stream: NonNullable<ReturnType<typeof useLangChainStream>>;
  messageId: string;
}) {
  const { parentCheckpointId } = useMessageMetadata(stream, messageId) ?? {};
  // …render per-message metadata…
}

function MessageInfo({ messageId }: { messageId: string }) {
  const stream = useLangChainStream();
  if (!stream) return null;
  return <MessageInfoView stream={stream} messageId={messageId} />;
}
```

## 媒体

v1 媒体 hooks 会呈现由助手流式传输的多模态媒体。将 `useLangChainStream` 句柄传递给它们——使用与上方视图和元数据部分相同的模式。

```tsx
import { useLangChainStream } from "@assistant-ui/react-langchain";
import { useImages, useAudio } from "@langchain/react";

function MediaView({
  stream,
}: {
  stream: NonNullable<ReturnType<typeof useLangChainStream>>;
}) {
  const images = useImages(stream);
  // useAudio / useVideo / useFiles likewise
  return <>{/* …render media… */}</>;
}

function Media() {
  const stream = useLangChainStream();
  if (!stream) return null;
  return <MediaView stream={stream} />;
}
```

## 生成式 UI

图可以在其状态中累积 UI 组件，并将每个组件关联到生成它的助手消息。运行时会从 `stream.values[uiStateKey]`（默认为 `"ui"`）读取这些组件，并针对每个父 ID 与助手消息匹配的 `UIMessage`，在该消息上发出一个 `data` 部分。父 ID 从 `metadata.message_id`（Python SDK）或 `metadata.id`（JS SDK）中读取。如果图将这些组件存储在其他位置，请传入 `uiStateKey`。

使用 `makeAssistantDataUI` 注册组件，以 `UIMessage` 的 `name` 作为键，并在运行时提供程序中挂载返回的元素一次：

```tsx
import {
  AssistantRuntimeProvider,
  makeAssistantDataUI,
} from "@assistant-ui/react";
import { Thread } from "@/components/assistant-ui/elements/thread.aui";
import { useStreamRuntime } from "@assistant-ui/react-langchain";

const ChartUI = makeAssistantDataUI({
  name: "chart",
  render: ({ data }) => <Chart points={data.points} />,
});

function App() {
  const runtime = useStreamRuntime({
    assistantId: "agent",
    apiUrl: "http://localhost:2024",
  });

  return (
    <AssistantRuntimeProvider runtime={runtime}>
      <ChartUI />
      <Thread />
    </AssistantRuntimeProvider>
  );
}
```

这会无缝覆盖两条路径。**状态快照**路径会渲染图已提交到其状态中的 UI。**实时**路径则会在 UI 进入状态之前（或不进入状态时），通过 `custom` 通道由 `push_ui_message` / `remove_ui_message` 流式传输 UI，因此组件会随着图发出它们而显示。运行时会累积实时事件，并将其与状态快照合并；一旦 UI 进入状态，状态快照将作为权威来源。两条路径都会使用相同的 `makeAssistantDataUI` 渲染器。

实时路径要求图的 `streamMode` 包含 `"custom"`，以便 UI 事件能够传递到客户端。

## 错误

`useLangChainError` 会公开上游 `useStream().error` 最近一次运行或水合错误。它没有类型（`unknown`），因此请在使用位置先对其进行类型收窄，然后再渲染。

```tsx
import { useLangChainError } from "@assistant-ui/react-langchain";

function ErrorBanner() {
  const error = useLangChainError();
  if (!error) return null;
  return <div role="alert">{error instanceof Error ? error.message : String(error)}</div>;
}
```

## 消息转换

`convertLangChainBaseMessage` 将 LangChain `BaseMessage` 转换为 assistant-ui 消息。在构建自定义 `ExternalStoreAdapter`，并需要在 `useStreamRuntime` 外部使用 LangChain 消息时使用它。

```ts
import { convertLangChainBaseMessage } from "@assistant-ui/react-langchain";
```

## 云端持久化

传入一个 `AssistantCloud` 实例，即可在多个会话之间持久化线程。运行时会自动连接线程列表管理，并从云端恢复状态。

```tsx
// see "AssistantCloud" in /docs/runtimes/concepts/threads for cloud setup
const runtime = useStreamRuntime({
  cloud,
  assistantId: "agent",
  apiUrl: "http://localhost:2024",
});
```

## 自定义 `messagesKey`

如果你的图将消息存储在非默认键下，请传入 `messagesKey`，以便运行时将工具结果和人工回合提交到正确的状态槽位：

```tsx
const runtime = useStreamRuntime({
  assistantId: "agent",
  apiUrl: "http://localhost:2024",
  messagesKey: "chat_messages",
});
```

## 与 `react-langgraph` 的比较

这两个包都将 assistant-ui 连接到 LangGraph 后端。它们是面向不同上游库的独立适配器；其中一个并不是另一个的后继版本。官方 `create-assistant-ui` 模板（`-t langchain`）附带 `react-langchain`。目前两者的功能已基本持平；如果需要完全自定义的后端流，或已有 `react-langgraph` 应用，则仍应选择 `react-langgraph`。

| 方面 | `react-langgraph` | `react-langchain` |
| --- | --- | --- |
| 封装对象 | `@langchain/langgraph-sdk`（原始 SDK） | `@langchain/react`（`useStream` hook） |
| 开始时间 | 2024 年 9 月起 | 2026 年 4 月起 |
| 版本 | `0.13.x` | `0.0.x` |
| 源代码行数 | 约 7,500 行 | 约 600 行 |
| 构建基础 | `useExternalStoreRuntime` | `useExternalStoreRuntime` |
| `create-assistant-ui` 模板 | 无模板 | `-t langchain` |

### 功能覆盖范围

| 功能 | `react-langgraph` | `react-langchain` |
| --- | --- | --- |
| 流式传输消息 | 是（`useLangGraphRuntime`） | 是（`useStreamRuntime`） |
| 中断状态 | 是 | 是 |
| 线程历史加载状态（`thread.isLoading`） | 是 | 是 |
| 发送原始状态更新 / 恢复命令 | 是 | 是（`useLangChainSubmit`；负载恢复使用 `useLangChainRespond`） |
| 转发每次运行的 `runConfig` | 是（整个对象 → `config`） | 是（`custom` → `config.configurable`） |
| 读取任意自定义状态键 | 否 | 是（`useLangChainState<T>(key)`） |
| 根级工具调用投影 | 通过消息部分 | 是（`useLangChainToolCalls`） |
| 消息中的文件内容部分 | 是 | 是 |
| 重新生成（检查点分叉） | 是（`getCheckpointId`） | 是（自动解析） |
| 编辑消息（检查点分叉） | 是 | 是（自动解析） |
| 每条消息的元数据（`messages-tuple`） | 是 | 是（通过 `useLangChainStream` 使用 `useMessageMetadata`） |
| 多模态媒体（音频 / 图像 / 视频 / 文件） | 通过部分 | 是（通过 `useLangChainStream` 使用 v1 媒体 hook） |
| 生成式 UI（状态快照） | 是 | 是（`uiStateKey`） |
| 生成式 UI（实时 `push_ui_message`） | 是 | 是（`streamMode: ["custom"]`） |
| 子图 / 命名空间流事件 | 是（通过 `eventHandlers`） | 由 `useLangChainSubagents` / `useLangChainSubgraphs` + 视图取代 |
| 子助手发现 | 通过 `eventHandlers` | 是（`useLangChainSubagents`） |
| 子图发现 | 通过 `eventHandlers` | 是（`useLangChainSubgraphs`） |
| 子助手 / 子图消息视图 | 通过 `eventHandlers` | 是（通过 `useLangChainStream` + v1 selector hook） |
| 端到端取消原语 | 是（`unstable_createLangGraphStream`） | 不适用——通过 `useStream().stop()` 取消（默认启用“取消”按钮） |
| 消息累加器工具 | 是（`LangGraphMessageAccumulator`） | 不适用——由 `useStream` 负责累加 |
| 流式传输计时（每条消息） | 是 | 是 |
| 云端线程持久化 | 是 | 是 |

每条消息的流式传输计时会自动附加到 `message.metadata.timing`（无需设置），与 `react-langgraph` 保持一致。它会捕获首个 token 的耗时、总流式传输时间、分块数量和每秒 token 数；这些数据根据运行进行期间的消息增长计算得出。

`react-langchain` 是较新且更轻量的封装。它将工作委托给上游的 `useStream`，而不是重新实现流处理逻辑，因此代码规模更小。

重新生成无需配置即可工作。点击“重新生成”后，系统会解析要从中分叉的服务器检查点（每条消息在流式传输进入时记录的检查点；对于较旧的轮次，则回退到匹配 `stream.client.threads.getHistory(threadId)` ID），然后使用 `submit(null, { forkFrom })` 再次运行。它适用于启用了检查点的后端（例如 LangGraph Cloud），并且能够优雅降级；当无法解析出检查点时，重新生成操作不会执行。相反，`react-langgraph` 要求用户提供 `getCheckpointId` 回调。编辑消息时会从同一个检查点分叉，并提交编辑后的助手内容，而不是重新运行之前的轮次；编辑第一条消息时，会从线程的初始检查点分叉，以重新启动线程。

### Hook 名称映射

| `react-langgraph` | `react-langchain` | 备注 |
| --- | --- | --- |
| `useLangGraphRuntime` | `useStreamRuntime` | 选项扩展自上游的 `UseStreamOptions`；无需编写 `stream` / `create` / `load`。 |
| `useLangGraphInterruptState` | `useLangChainInterruptState` | 返回结构相同。 |
| `useLangGraphSendCommand` | `useLangChainRespond` | 首选的恢复方式；通过 `stream.respond` 携带负载。对于原始 `Command`，请使用 `useLangChainSubmit(null, { command })`。 |
| `useLangGraphSend` | _（使用 `runtime.thread.append`）_ | 没有直接等价项；通过运行时发送轮次。 |
| `useLangGraphMessageMetadata` | _（使用 `useMessageMetadata(useLangChainStream(), id)`）_ | 通过上游 selector hook 获取每条消息的元数据。 |
| `useLangGraphUIMessages` | _（UI 将其渲染为数据部分；使用 `makeAssistantDataUI` 注册）_ | 请参阅[生成式 UI](#generative-ui)。 |
| _（无）_ | `useLangChainState<T>(key)` | 新增——响应式读取任意自定义状态键。 |
| _（无）_ | `useLangChainToolCalls` | 新增——由 `useStream` 组装根级工具调用。 |
| _（无）_ | `useLangChainError()` | 新增——响应式读取最近一次运行 / 水合错误。 |
| _（无）_ | `useLangChainRespondAll` | 在一个检查点恢复多个中断（`stream.respondAll`）。 |
| _（无）_ | `useLangChainInterrupts` | 新增——检查点处待处理的每个中断，每个中断都包含 `id` 和 `value`。 |
| _（通过 `eventHandlers`）_ | `useLangChainSubagents` | 新增——发现当前运行中的子助手；取代子图事件处理器。 |
| _（通过 `eventHandlers`）_ | `useLangChainSubgraphs` | 新增——发现当前运行中的子图；取代子图事件处理器。 |
| _（无）_ | `useLangChainStream` | 新增——提供原始的 `useStream` 句柄，用于 v1 的作用域 `useMessages` / `useToolCalls` selector hook。 |
