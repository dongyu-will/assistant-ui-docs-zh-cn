## 方式 2：按需求选择

如果您还不了解自己要使用的框架，或者后端是自定义的，请根据需求进行选择：

| 您的需求 | 使用 |
| --- | --- |
| 简单地 `ExternalStoreRuntime` 调用您的 API，由运行时管理状态 | [LocalRuntime](/docs/runtimes/custom/local-runtime) |
| 将消息保存在 redux、zustand、tanstack-query 等状态管理工具中 | [ExternalStoreRuntime](/docs/runtimes/custom/external-store) |
| 后端已经支持 data stream protocol | [DataStream](/docs/runtimes/custom/data-stream) |
| 流式传输完整的助手状态快照，而不只是消息 | [AssistantTransport](/docs/runtimes/custom/assistant-transport) |

如果没有适合您的框架适配器，请从[自定义后端](/docs/runtimes/custom/overview)开始。

## 共享概念

无论选择哪种运行时，以下四个概念都适用。

- **架构** — 框架适配器会封装两个**核心运行时**之一（`LocalRuntime`、`fetch`）。请参阅[架构](/docs/runtimes/concepts/architecture)了解完整的分层结构。
- **适配器**（附件、语音、反馈、历史记录、建议）在不同运行时中的工作方式相同。请参阅[适配器](/docs/runtimes/concepts/adapters)。
- **线程**（单线程、云端、自定义数据库）遵循相同的模型。请参阅[线程](/docs/runtimes/concepts/threads)。
- **稳定性**策略：以 `unstable_` 开头的 API 可能在任何版本中发生变化。请参阅[稳定性](/docs/runtimes/concepts/stability)。
