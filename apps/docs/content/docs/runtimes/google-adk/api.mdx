## createAdkStream

创建一个通过 SSE 连接到 ADK 端点的 `AdkStreamCallback`。支持两种模式。

**代理模式** — POST 到你自己的 API 路由：

```ts
import { createAdkStream } from "@assistant-ui/react-google-adk";

const stream = createAdkStream({ api: "/api/chat" });
```

**直连模式** — 直接连接到 ADK 服务器：

```ts
const stream = createAdkStream({
  api: "http://localhost:8000",
  appName: "my-app",
  userId: "user-1",
});
```

| 选项 | 类型 | 描述 |
| --- | --- | --- |
| `api` | `string` | 要 POST 到的 URL（代理路由或 ADK 服务器基础 URL）。 |
| `appName` | `string?` | ADK 应用名称（设置后启用直连模式）。 |
| `userId` | `string?` | ADK 用户 ID（与 `appName` 一起使用时必需）。 |
| `headers` | `Record<string, string>` 或 `() => ...` | 静态或动态请求标头。 |

## 直连 ADK 服务器

直接连接 ADK 服务器时（不使用代理 API 路由），使用 `createAdkSessionAdapter`，通过 ADK 会话支持线程列表：

```tsx
import {
  useAdkRuntime,
  createAdkStream,
  createAdkSessionAdapter,
} from "@assistant-ui/react-google-adk";

const ADK_URL = "http://localhost:8000";

const { adapter, load, artifacts } = createAdkSessionAdapter({
  apiUrl: ADK_URL,
  appName: "my-app",
  userId: "user-1",
});

const runtime = useAdkRuntime({
  stream: createAdkStream({
    api: ADK_URL,
    appName: "my-app",
    userId: "user-1",
  }),
  sessionAdapter: adapter,
  load,
});
```

会话适配器会将 ADK 会话映射到 assistant-ui 线程：

- **`adapter`** 是一个 `RemoteThreadListAdapter`，使用 ADK 的会话 REST API 执行线程的增删改查。
- **`load`** 通过 `AdkEventAccumulator` 从会话事件中重建消息。
- **`artifacts`** 是用于获取、列出和删除会话构件的函数（参见 [钩子 → 构件](/docs/runtimes/google-adk/hooks#artifacts)）。

| 选项 | 类型 | 描述 |
| --- | --- | --- |
| `apiUrl` | `string` | ADK 服务器基础 URL。 |
| `appName` | `string` | ADK 应用名称。 |
| `userId` | `string` | ADK 用户 ID。 |
| `headers` | `Record<string, string>` 或 `() => ...` | 静态或动态请求标头。 |

## 服务器辅助函数

服务器辅助函数位于 `/server` 子路径下：

```ts
import {
  createAdkApiRoute,
  adkEventStream,
  parseAdkRequest,
  toAdkContent,
} from "@assistant-ui/react-google-adk/server";
```

### createAdkApiRoute

将请求解析和 SSE 流式传输结合起来的单行 API 路由处理器：

```ts
export const POST = createAdkApiRoute({
  runner,
  userId: "default-user",
  sessionId: (req) =>
    new URL(req.url).searchParams.get("sessionId") ?? "default",
});
```

`userId` 和 `sessionId` 都接受静态字符串或函数 `(req: Request) => string`，用于动态解析。

### adkEventStream

将来自 ADK `Runner.runAsync()` 的 `AsyncGenerator<Event>` 转换为 SSE `Response`。发送初始 `:ok` 注释，以便连接通过代理保持活动状态。

```ts
const events = runner.runAsync({ userId, sessionId, newMessage });
return adkEventStream(events);
```

### parseAdkRequest 和 toAdkContent

用于自定义 API 路由的底层辅助函数。`parseAdkRequest` 解析传入请求；`toAdkContent` 将其转换为 ADK 的 `Content` 格式。支持用户消息、工具结果、`stateDelta`、`checkpointId` 和多模态内容：

```ts
const parsed = await parseAdkRequest(req);
// parsed.type is "message" or "tool-result"
// parsed.config contains runConfig, checkpointId
// parsed.stateDelta contains session state changes

const newMessage = toAdkContent(parsed);
const events = runner.runAsync({
  userId,
  sessionId,
  newMessage,
  stateDelta: parsed.stateDelta,
});
return adkEventStream(events);
```

## 线程管理

有三种选项，具体取决于你希望负责哪一部分。有关通用模型，请参阅 [线程](/docs/runtimes/concepts/threads)。

### ADK 会话适配器

使用 `createAdkSessionAdapter` 通过 ADK 的会话 API 持久化线程；参见上面的[直连 ADK 服务器](#direct-adk-server-connection)。

### 自定义线程管理

```ts
const runtime = useAdkRuntime({
  stream: createAdkStream({ api: "/api/chat" }),
  create: async () => {
    const sessionId = await createSession();
    return { externalId: sessionId };
  },
  load: async (externalId) => {
    const history = await loadSession(externalId);
    return { messages: history };
  },
  delete: async (externalId) => {
    await deleteSession(externalId);
  },
});
```

### 云端持久化

如需通过 assistant-cloud 持久化线程历史记录，请传入一个 `cloud` 实例：

```ts
const runtime = useAdkRuntime({
  cloud, // see "AssistantCloud" in /docs/runtimes/concepts/threads
  stream: createAdkStream({ api: "/api/chat" }),
});
```

## 消息编辑和重新生成

提供 `getCheckpointId` 回调，以启用编辑和重新生成按钮：

```ts
const runtime = useAdkRuntime({
  stream: createAdkStream({ api: "/api/chat" }),
  getCheckpointId: async (threadId, parentMessages) => {
    // Resolve checkpoint ID for server-side forking
    return checkpointId;
  },
});
```

提供 `getCheckpointId` 后：

- **编辑按钮**会显示在用户消息上。
- **重新生成按钮**会显示在助手消息上。

解析后的 `checkpointId` 会通过 `config.checkpointId` 传递给你的 `stream` 回调。

<Callout type="info">
如果没有 `getCheckpointId`，编辑和重新生成按钮不会显示。这是有意为之；如果不从正确的服务器端检查点分叉，就在客户端截断消息会产生错误状态。
</Callout>

## 事件处理器

监听流式传输事件：

```ts
const runtime = useAdkRuntime({
  stream: createAdkStream({ api: "/api/chat" }),
  eventHandlers: {
    onError: (error) => {
      console.error("Stream error:", error);
    },
    onAgentTransfer: (toAgent) => {
      console.log("Agent transferred to:", toAgent);
    },
    onCustomEvent: (key, value) => {
      // Fired for each entry in event.customMetadata
      console.log("Custom metadata:", key, value);
    },
  },
});
```

## RunConfig 和 stateDelta

传入 `AdkRunConfig` 以控制代理行为，并传入 `stateDelta`，以便与消息一同修改会话状态：

```ts
import { useAdkSend } from "@assistant-ui/react-google-adk";

const send = useAdkSend();

send(messages, {
  runConfig: {
    streamingMode: "sse",
    maxLlmCalls: 10,
    pauseOnToolCalls: true,
  },
  stateDelta: { taskId: "abc", mode: "verbose" },
});
```

`stateDelta` 映射到 `/run_sse` 上 ADK 的 `stateDelta` 参数。
