`@assistant-ui/eve` 将 assistant-ui 与 [Eve](https://eve.dev/), Vercel 面向持久 agent 的 filesystem-first 框架）集成。它封装了 Eve 的 `useEveAgent` hook，并将其作为 assistant-ui 的 `ExternalStoreRuntime` 暴露出来，因此由 Eve 管理会话流，而 assistant-ui 负责渲染消息、推理、动态工具调用和审批请求。

## 适用场景

在以下情况下选择 Eve 运行时：

- 希望将 agent 实现放在 `agent/` 下，并由 `eve/next` 提供服务。
- 希望使用 Eve 会话、续接令牌、NDJSON 流式传输和本地开发工具。
- 希望 assistant-ui 渲染 Eve 消息和人在回路的工具审批，而无需编写自定义运行时适配器。

## 架构

Next.js 应用使用 `withEve()` 挂载 Eve，并使用 `withAui()` 挂载 assistant-ui 的注册表转换：

```ts title="next.config.ts"
import { withAui } from "@assistant-ui/next";
import type { NextConfig } from "next";
import { withEve } from "eve/next";

const nextConfig: NextConfig = {};

export default withEve(withAui(nextConfig));
```

在客户端，`useEveAgentRuntime()` 调用 Eve 的 React hook，并将 Eve 消息部分转换为 assistant-ui 线程消息：

```tsx title="app/page.tsx"
"use client";

import { Thread } from "@/components/assistant-ui/elements/thread.aui";
import { useEveAgentRuntime } from "@assistant-ui/eve";
import { AssistantRuntimeProvider } from "@assistant-ui/react";

export default function Home() {
  const runtime = useEveAgentRuntime();

  return (
    <AssistantRuntimeProvider runtime={runtime}>
      <Thread />
    </AssistantRuntimeProvider>
  );
}
```

每轮 `runConfig` 的 `custom` bag 会作为 `clientContext` 转发给 Eve，因此 `runConfig: { custom: { page: "/pricing" } }` 会以 `clientContext: { page: "/pricing" }` 的形式到达。空 bag 或缺失的 bag 会被省略，并且每个值都必须可序列化为 JSON。

Eve 会将该对象转换为模型上下文消息，因此 assistant-ui 的 `custom` envelope 会被解包：否则该 envelope 会在提示词中放入一个字面量的 `custom` 键。它表示页面或客户端上下文，而不是运行配置，不能用于选择模型或更改本轮执行方式。请勿在其中放入密钥、凭据和个人数据，因为模型会将其作为消息文本读取。

## 连接器授权

当 Eve 因连接器授权而暂停时，运行时会发出一个名为 `authorization` 的助手数据部分。其数据包含 `state`、`name`，以及可用的显示字段，例如 `displayName`、`description`、`url`、`userCode`、`instructions` 和 `expiresAt`。已完成的部分还可能包含 `outcome` 和 `reason`。只有当连接器提供了 `http(s)` 地址时才会存在 `url`；适配器会丢弃其他 scheme，以便渲染器可以直接链接到该地址。

Eve 模板将此渲染器作为 `components/eve-authorization.tsx` 提供，并将其挂载在 `<Thread />` 旁边。要将其添加到现有应用中，请为该部分注册数据 UI，并使用导出的 `EveAuthorizationData` 为其指定类型：

```tsx title="authorization-ui.tsx"
import type { EveAuthorizationData } from "@assistant-ui/eve";
import { makeAssistantDataUI } from "@assistant-ui/react";

export const AuthorizationUI = makeAssistantDataUI<EveAuthorizationData>({
  name: "authorization",
  render: ({ data }) => (
    <div>
      {data.state === "required" ? (
        <>
          <p>{data.instructions ?? `Sign in to ${data.displayName ?? data.name}`}</p>
          {data.userCode && <code>{data.userCode}</code>}
          {data.url && <a href={data.url}>Continue to sign in</a>}
        </>
      ) : (
        <p>{data.outcome ?? "Authorization completed"}</p>
      )}
    </div>
  ),
});
```

将 `<AuthorizationUI />` 挂载到 `AssistantRuntimeProvider` 树中。标准线程会有意不渲染不匹配的数据部分。

## 要求

- Node.js 24 或更高版本。
- React 18 或 19。
- 使用 `eve/next` 挂载的 Eve 应用。
- 为 `agent/agent.ts` 中配置的模型准备模型凭据。

Eve 的默认 gateway 模型 ID 会通过 [Vercel AI Gateway](https://vercel.com/docs/ai-gateway). 进行路由。使用 `AI_GATEWAY_API_KEY` 或 Vercel OIDC，或者配置直接的 provider `LanguageModel`。在本地开发时，直接使用 `LanguageModel` 也可以在 ChatGPT Plus 或 Pro 方案下运行，无需任何 API key；请参阅 [ChatGPT 订阅](/docs/guides/chatgpt-subscription)。

## 身份验证说明

Eve 内置的 `eve` channel 在开发期间接受 localhost，也接受受信任的 Vercel OIDC 调用方。在生产环境中，它不会自动允许浏览器用户访问。部署公共应用前，请添加 `agent/channels/eve.ts`，并将该 channel 接入应用的身份验证系统。
