有三种方式可以运行由 Eve 驱动的 assistant-ui 应用。模板最快，`eve add`可将 assistant-ui 添加到已有的 Eve 应用中，而手动路径适用于将其集成到现有的 Next.js 项目中。

## 使用模板

<PlatformTabs>
<Tab value="React">

```sh
npx create-assistant-ui@latest -t eve my-app
cd my-app
```

设置模型凭据：

```sh title=".env.local"
AI_GATEWAY_API_KEY=your-api-key
```

```sh
npm run dev
```

打开 http://localhost:3000 并发送一条消息。模板包含：

- `agent/agent.ts`，用于 Eve 运行时配置。
- `agent/instructions.md`，用于始终启用的系统提示词。
- `next.config.ts`，包含 `withEve(withAui(nextConfig))`。
- `app/page.tsx`，包含 `useEveAgentRuntime()`。

</Tab>
<Tab value="React Native">

目前还没有 React Native Eve 模板。

</Tab>

## 使用 Eve CLI

对于已有的 Eve 应用，注册一次 assistant-ui registry，然后从中安装聊天页面：

```sh
eve registry add @assistant-ui=https://r.assistant-ui.com/{name}.json
eve add @assistant-ui/eve-chat --overwrite
```

`eve registry add`会在你的 `package.json` 中记录命名空间。随后，`eve add`会安装 `@assistant-ui/react` 和 `@assistant-ui/eve`，写入 `app/page.tsx`，并将线程组件及其导入的所有内容写入 `components/assistant-ui` 和 `components/ui`。它要求 Eve 应用包含 Next.js Web Chat 脚手架，因为已安装的文件会通过 `@/*` 别名导入 `@/lib/utils`，而该别名由 `eve init --channel-web-nextjs` 设置。

`--overwrite`是全局选项，而不是针对单个文件的选项。它允许该条目替换脚手架自带的 `app/page.tsx`，同时也会替换项目中已有的任何 `components/assistant-ui` 或 `components/ui` 文件，包括 `avatar`、`button`、`collapsible`、`dialog` 和 `tooltip`。因此，请在干净的工作树上安装，并在保留更改前查看差异。普通的 `eve add` 则会跳过所有已存在的文件，从而保持 `app/page.tsx` 不变。安装前可使用 `eve registry view @assistant-ui/eve-chat` 检查条目，也可以使用 `eve registry list --registry @assistant-ui` 浏览 registry 中的其他内容。

该命名空间对应 Radix 风格，与 Eve 的 Next.js 脚手架中的 shadcn 组件相匹配。对于 Base UI 项目，请改为指向 `https://r.assistant-ui.com/base/{name}.json`。

Eve CLI 写入 registry 文件时不会编辑 CSS，因此请自行将推理和工具组件动画所需的样式添加到 `app/globals.css`：

```css title="app/globals.css"
@import "tw-shimmer";

@custom-variant data-open (&:where([data-state="open"], [data-open]:not([data-open="false"])));
@custom-variant data-closed (&:where([data-state="closed"], [data-closed]:not([data-closed="false"])));

@theme inline {
  @keyframes collapsible-down {
    from {
      height: 0;
    }
    to {
      height: var(
        --radix-collapsible-content-height,
        var(--collapsible-panel-height, auto)
      );
    }
  }
  @keyframes collapsible-up {
    from {
      height: var(
        --radix-collapsible-content-height,
        var(--collapsible-panel-height, auto)
      );
    }
    to {
      height: 0;
    }
  }
}
```

## 在现有应用中手动设置

<Steps>
<Step>

### 安装依赖

<InstallCommand npm={["@assistant-ui/react", "@assistant-ui/eve", "eve"]} />

</Step>
<Step>

### 在 Next.js 中挂载 Eve

```ts title="next.config.ts"
import { withAui } from "@assistant-ui/next";
import type { NextConfig } from "next";
import { withEve } from "eve/next";

const nextConfig: NextConfig = {};

export default withEve(withAui(nextConfig));
```

</Step>
<Step>

### 添加 Eve 助手


```ts title="agent/agent.ts"
import { defineAgent } from "eve";

export default defineAgent({
  model: "anthropic/claude-sonnet-4.6",
});
```

```md title="agent/instructions.md"
You are a concise assistant. Use tools when they are available.
```

</Step>
<Step>

### 创建运行时


```tsx title="app/page.tsx"
"use client";

import { Thread } from "@/components/assistant-ui/elements/thread.aui";
import { useEveAgentRuntime } from "@assistant-ui/eve";
import { AssistantRuntimeProvider } from "@assistant-ui/react";

export default function Home() {
  const runtime = useEveAgentRuntime();

  return (
    <AssistantRuntimeProvider runtime={runtime}>
      <Thread />
    </AssistantRuntimeProvider>
  );
}
```

</Step>
</Steps>

## 生产环境身份验证

默认的 Eve 通道便于本地开发。对于生产环境中的浏览器用户，请定义 `agent/channels/eve.ts`，并将默认身份验证策略替换为应用自己的身份验证策略。

```ts title="agent/channels/eve.ts"
import { localDev, vercelOidc } from "eve/channels/auth";
import { eveChannel } from "eve/channels/eve";

export default eveChannel({
  auth: [localDev(), vercelOidc()],
});
```

该示例保留了开发环境默认设置。正式上线前，请替换为 Clerk、Auth.js、OIDC 或 JWT 验证。
