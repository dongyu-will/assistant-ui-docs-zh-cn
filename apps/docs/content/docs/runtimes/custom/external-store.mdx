title: ExternalStoreRuntime
description: 使用你自己的 redux、zustand 或状态管理器。
---

`ExternalStoreRuntime` 将现有的状态管理与 assistant-ui 连接起来。你提供消息和回调；运行时会渲染你提供的内容。UI 功能会根据存在的回调启用。

## 适用场景

在以下情况下选择 `ExternalStoreRuntime`：

- 你已经将消息保存在 redux、zustand、tanstack-query 或其他存储中，并希望继续保存在那里。
- 你希望完全控制消息状态、持久化和同步。
- 你使用自定义消息格式，并需要自动转换为 assistant-ui 的格式。

如果你没有现成的存储，请改用 [`LocalRuntime`](/docs/runtimes/custom/local-runtime)；它的使用成本更低。

### 创建运行时提供程序

```tsx title="app/MyRuntimeProvider.tsx"
"use client";

import { useState, ReactNode } from "react";
import {
  useExternalStoreRuntime,
  ThreadMessageLike,
  AppendMessage,
  AssistantRuntimeProvider,
} from "@assistant-ui/react";

type MyMessage = { role: "user" | "assistant"; content: string };

const convertMessage = (message: MyMessage): ThreadMessageLike => ({
  role: message.role,
  content: [{ type: "text", text: message.content }],
});

const backendApi = async (input: string): Promise<MyMessage> => {
  return { role: "assistant", content: "Hello, world!" };
};

export function MyRuntimeProvider({
  children,
}: Readonly<{ children: ReactNode }>) {
  const [isRunning, setIsRunning] = useState(false);
  const [messages, setMessages] = useState<MyMessage[]>([]);

  const onNew = async (message: AppendMessage) => {
    if (message.content[0]?.type !== "text") {
      throw new Error("Only text messages are supported");
    }
    const input = message.content[0].text;
    setMessages((prev) => [...prev, { role: "user", content: input }]);

    setIsRunning(true);
    const assistant = await backendApi(input);
    setMessages((prev) => [...prev, assistant]);
    setIsRunning(false);
  };

  const runtime = useExternalStoreRuntime({
    isRunning,
    messages,
    convertMessage,
    onNew,
  });

  return (
    <AssistantRuntimeProvider runtime={runtime}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

## 消息转换

有两种方式。

### 内联 `convertMessage`

```tsx
const convertMessage = (message: MyMessage): ThreadMessageLike => ({
  role: message.role,
  content: [{ type: "text", text: message.text }],
  id: message.id,
  createdAt: new Date(message.timestamp),
});

const runtime = useExternalStoreRuntime({
  messages: myMessages,
  convertMessage,
  onNew,
});
```

### `useExternalMessageConverter`（使用合并策略）

用于性能优化，或需要合并相邻助手消息的场景：

```tsx
import { useExternalMessageConverter } from "@assistant-ui/react";

const convertedMessages = useExternalMessageConverter({
  callback: (message: MyMessage): ThreadMessageLike => ({
    role: message.role,
    content: [{ type: "text", text: message.text }],
    id: message.id,
  }),
  messages,
  isRunning: false,
  joinStrategy: "concat-content", // merges adjacent assistant messages
});

const runtime = useExternalStoreRuntime({
  messages: convertedMessages,
  onNew,
});
```

`joinStrategy` 控制相邻助手消息的合并方式：`concat-content`（默认）会将它们合并为一条；`none` 会将它们分开。

## 处理器矩阵

每个处理器都会启用一项特定的 UI 功能。

| 处理器 | 启用功能 |
| --- | --- |
| `onNew` | 发送新的用户消息（必需） |
| `setMessages` | 切换分支 |
| `onEdit` | 消息编辑按钮 |
| `onReload` | 重新生成按钮 |
| `onCancel` | 生成期间的取消按钮 |
| `onRefetchThread` | `threads.reloadMainThread()` 原地重新获取打开的线程 |
| `onAddToolResult` | 客户端工具结果传递 |
| `queue` | 对运行期间发送的消息进行排队 |

## 流式响应

通过原地修改助手消息进行流式传输：

```tsx
const onNew = async (message: AppendMessage) => {
  const userMsg: ThreadMessageLike = {
    role: "user",
    content: message.content,
    id: generateId(),
  };
  setMessages((prev) => [...prev, userMsg]);

  setIsRunning(true);
  const assistantId = generateId();
  setMessages((prev) => [
    ...prev,
    { role: "assistant", content: [{ type: "text", text: "" }], id: assistantId },
  ]);

  const stream = await api.streamChat(message);
  for await (const chunk of stream) {
    setMessages((prev) =>
      prev.map((m) =>
        m.id === assistantId
          ? {
              ...m,
              content: [
                { type: "text", text: (m.content[0] as any).text + chunk },
              ],
            }
          : m,
      ),
    );
  }
  setIsRunning(false);
};
```

## 编辑消息

```tsx
const onEdit = async (message: AppendMessage) => {
  const index = messages.findIndex((m) => m.id === message.parentId) + 1;
  const newMessages = [...messages.slice(0, index)];
  newMessages.push({
    role: "user",
    content: message.content,
    id: message.id ?? generateId(),
  });
  setMessages(newMessages);

  setIsRunning(true);
  const response = await api.chat(message);
  newMessages.push({ role: "assistant", content: response.content, id: generateId() });
  setMessages(newMessages);
  setIsRunning(false);
};
```

## 分支

线性 `messages` 数组假设每条消息的父消息都是前一条消息。要实现分支（例如多次重新生成），请使用 `ExportedMessageRepository.fromBranchableArray()`，并通过 `thread.import()` 导入：

```tsx
import {
  ExportedMessageRepository,
  useExternalStoreRuntime,
} from "@assistant-ui/react";

const backendMessages = [
  { id: "user-1", role: "user", content: "Hello", parentId: null },
  { id: "asst-1", role: "assistant", content: "Hi!", parentId: "user-1" },
  { id: "asst-2", role: "assistant", content: "Hey!", parentId: "user-1" }, // branch
];

const repo = ExportedMessageRepository.fromBranchableArray(
  backendMessages.map((m) => ({
    message: { id: m.id, role: m.role, content: m.content },
    parentId: m.parentId,
  })),
  { headId: "asst-1" },
);

runtime.thread.import(repo);
```

每条消息都必须显式包含 `id` 和 `parentId`；具有相同 `parentId` 的消息会创建分支。父消息必须在数组中出现在子消息之前。

### 导出快照

`thread.import()` 有一个对应项 `thread.export()`，可将当前线程（包括完整的分支树）捕获为可序列化的 `ExportedMessageRepository`。使用它可以持久化对话，并在之后重新导入：

```tsx
// capture the current thread as a serializable snapshot
const repo = runtime.thread.export();
await saveToBackend(JSON.stringify(repo));

// later, restore it into a runtime
runtime.thread.import(repo);
```

导出的结构可以直接通过 `thread.import()` 往返处理，因此同一个值既是你的持久化格式，也是重新加载时使用的值。

### 持久化分支选择

如果你将完整的分支树存储在 assistant-ui 外部，也要持久化选中的分支头，并将其作为 `messageRepository.headId` 传回。`setMessages` 仍会执行分支切换；`unstable_onBranchChange` 是一个额外信号，会在显式的 `switchToBranch` 操作（例如点击 BranchPicker）后触发。

```tsx
const runtime = useExternalStoreRuntime({
  messageRepository: {
    messages: storedMessages,
    headId: selectedHeadId,
  },
  setMessages: (messages) => {
    setVisibleMessages(messages);
  },
  unstable_onBranchChange: ({ headId, visibleMessageIds }) => {
    saveSelectedBranch({
      headId,
      visibleMessageIds,
    });
  },
  onNew,
});
```

`headId` 是可见分支的规范持久化头。乐观消息或临时消息的 id 不会在其中暴露。`visibleMessageIds` 是当前按顺序可见的路径，其中可能包含乐观叶节点，而 `headId` 指向其持久化祖先。

该回调仅会在显式分支切换时触发；连续切换如果最终解析到同一个规范头，则会去重。在适配器重新同步、`messageRepository` 重置、追加、编辑/重新生成、仅内容更新或线程运行期间，都不会触发。

<Callout type="warn">
  `unstable_onBranchChange` 正在积极开发中，可能会在不另行通知的情况下发生变化。它是对 `setMessages` 的补充；本身不会启用分支切换。
</Callout>

## 工具调用

通过更新匹配的工具调用条目来处理工具结果：

```tsx
const onAddToolResult = (options: AddToolResultOptions) => {
  setMessages((prev) =>
    prev.map((message) =>
      message.id === options.messageId
        ? {
            ...message,
            content: message.content.map((part) =>
              part.type === "tool-call" &&
              part.toolCallId === options.toolCallId
                ? { ...part, result: options.result }
                : part,
            ),
          }
        : message,
    ),
  );
};

const runtime = useExternalStoreRuntime({
  messages,
  onNew,
  onAddToolResult,
});
```

运行时会根据 `toolCallId` 自动将工具结果与其工具调用进行匹配，并将相关消息分组后显示。

## 运行期间对消息排队

默认情况下，线程运行期间会禁用发送操作。提供一个 `queue` 适配器，即可缓存运行期间发送的消息，并在运行结束后处理。待处理消息会暴露在 `composer.queue` 上，并通过 [`ComposerPrimitive.Queue`](/docs/api-reference/primitives/composer) 渲染。

`createMessageQueue` 辅助函数负责双通道排序和运行中保护：先排出 `steerItems`，再排出 `items`；每个通道内部则按顺序排出项目。提供一个用于运行消息的驱动程序，将其 `adapter` 传递给运行时，并在运行开始时（`notifyBusy()`，这样并发发送会进入缓存）和结束时（`notifyIdle()`）通知队列。

手写适配器必须实现相同的契约：`items` 和 `steerItems` 暴露各个通道（每个项目都包含必需的 `parts` 内容投影），`enqueue`/`steer` 向通道添加项目，`move(queueItemId, placement)` 使用快速失败锚点重新定位项目——未知 id 或锚点会直接抛出异常，而不会被强制转换。可以通过 `composer.queueItem({ id })`（或索引）定位单个项目。

```tsx
import { useEffect, useRef, useState } from "react";
import { createMessageQueue, useExternalStoreRuntime } from "@assistant-ui/react";

const [queue] = useState(() => createMessageQueue({ run: onNew }));

const runtime = useExternalStoreRuntime({
  messages,
  isRunning,
  onNew,
  queue: queue.adapter,
});

const wasRunning = useRef(isRunning);
useEffect(() => {
  if (!wasRunning.current && isRunning) queue.notifyBusy();
  if (wasRunning.current && !isRunning) queue.notifyIdle();
  wasRunning.current = isRunning;
}, [isRunning, queue]);
```

使用 `createMessageQueue` 适配器时，取消操作会自动暂停队列：运行时会在执行你的 `onCancel` 之前通知队列，因此被取消运行的结束处理会保留待处理项目，而不会调度下一个项目；下一次发送时会恢复排出。如果希望取消操作丢弃这些项目，则改为在 `onCancel` 中调用 `queue.clear()`。手写适配器没有这样的通道，因此它需要像管理其他逻辑一样自行管理取消策略。编辑和重新加载仍由宿主负责：在你的 `onEdit` 和 `onReload` 处理器中调用 `queue.clear()`，避免旧项目被排出到新分支。

```tsx
const runtime = useExternalStoreRuntime({
  // ...
  onCancel: async () => {
    // the runtime already paused the queue; clear() here to drop the items
    await cancelRun();
  },
  onEdit: async (message) => {
    queue.clear();
    // ...
  },
  onReload: async (parentId) => {
    queue.clear();
    // ...
  },
});
```

### Redux

```tsx title="app/chatSlice.ts"
import { createSlice, PayloadAction } from "@reduxjs/toolkit";
import { ThreadMessageLike } from "@assistant-ui/react";

const chatSlice = createSlice({
  name: "chat",
  initialState: { messages: [] as ThreadMessageLike[], isRunning: false },
  reducers: {
    setMessages: (state, action: PayloadAction<ThreadMessageLike[]>) => {
      state.messages = action.payload;
    },
    addMessage: (state, action: PayloadAction<ThreadMessageLike>) => {
      state.messages.push(action.payload);
    },
    setIsRunning: (state, action: PayloadAction<boolean>) => {
      state.isRunning = action.payload;
    },
  },
});

export const { setMessages, addMessage, setIsRunning } = chatSlice.actions;
```

```tsx title="app/ReduxRuntimeProvider.tsx"
import { useSelector, useDispatch } from "react-redux";
import { useExternalStoreRuntime, AssistantRuntimeProvider } from "@assistant-ui/react";

export function ReduxRuntimeProvider({ children }) {
  const messages = useSelector((s: RootState) => s.chat.messages);
  const isRunning = useSelector((s: RootState) => s.chat.isRunning);
  const dispatch = useDispatch();

  const runtime = useExternalStoreRuntime({
    messages,
    isRunning,
    setMessages: (messages) => dispatch(setMessages(messages)),
    onNew: async (message) => {
      dispatch(
        addMessage({
          role: "user",
          content: message.content,
          id: `msg-${Date.now()}`,
          createdAt: new Date(),
        }),
      );
      dispatch(setIsRunning(true));
      const response = await api.chat(message);
      dispatch(
        addMessage({
          role: "assistant",
          content: response.content,
          id: `msg-${Date.now()}`,
          createdAt: new Date(),
        }),
      );
      dispatch(setIsRunning(false));
    },
  });

  return (
    <AssistantRuntimeProvider runtime={runtime}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

### Zustand

import { immer } from "zustand/middleware/immer";
import { ThreadMessageLike } from "@assistant-ui/react";

interface ChatState {

### TanStack Query

```tsx
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query";
import { useExternalStoreRuntime } from "@assistant-ui/react";

const messageKeys = {
  all: ["messages"] as const,
  thread: (threadId: string) => [...messageKeys.all, threadId] as const,
};

export function TanStackQueryRuntimeProvider({ children }) {
  const queryClient = useQueryClient();
  const threadId = "main";

  const { data: messages = [] } = useQuery({
    queryKey: messageKeys.thread(threadId),
    queryFn: () => fetchMessages(threadId),
  });

  const sendMessage = useMutation({
    mutationFn: api.chat,
    onMutate: async (message: AppendMessage) => {
      await queryClient.cancelQueries({
        queryKey: messageKeys.thread(threadId),
      });
      const previous = queryClient.getQueryData<ThreadMessageLike[]>(
        messageKeys.thread(threadId),
      );
      queryClient.setQueryData<ThreadMessageLike[]>(
        messageKeys.thread(threadId),
        (old = []) => [
          ...old,
          {
            role: "user",
            content: message.content,
            id: `temp-${Date.now()}`,
            createdAt: new Date(),
          },
        ],
      );
      return { previous };
    },
    onError: (_err, _msg, context) => {
      if (context?.previous) {
        queryClient.setQueryData(messageKeys.thread(threadId), context.previous);
      }
    },
    onSettled: () =>
      queryClient.invalidateQueries({ queryKey: messageKeys.thread(threadId) }),
  });

  const runtime = useExternalStoreRuntime({
    messages,
    isRunning: sendMessage.isPending,
    onNew: async (message) => {
      await sendMessage.mutateAsync(message);
    },
    setMessages: (newMessages) => {
      queryClient.setQueryData(messageKeys.thread(threadId), newMessages);
    },
  });

  return (
    <AssistantRuntimeProvider runtime={runtime}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

## 使用外部消息

### `getExternalStoreMessages`

从任意 assistant-ui 状态中获取原始消息格式：

```tsx
import { getExternalStoreMessages, useAuiState } from "@assistant-ui/react";

function MyComponent() {
  const originalMessages = useAuiState((s) => getExternalStoreMessages(s.message));
  // originalMessages is MyMessage[] (your original type)
}
```

<Callout type="warn">
对于单条 UI 消息，`getExternalStoreMessages` 可能会返回多条消息；assistant-ui 会合并相邻的助手消息和工具消息以供显示。
</Callout>

### `bindExternalStoreMessage`

将原始消息附加到你手动构造的 `ThreadMessage` 上（在内置转换器之外）：

```tsx
import {
  bindExternalStoreMessage,
  getExternalStoreMessages,
} from "@assistant-ui/react";

bindExternalStoreMessage(threadMessage, originalMessage);
const original = getExternalStoreMessages(threadMessage);
```

如果目标已经绑定了消息，`bindExternalStoreMessage` 不执行任何操作。它会直接原地修改目标。

<Callout type="warn">
此 API 处于实验阶段，可能会在不另行通知的情况下发生变化。
</Callout>

## 最佳实践

1. **使用不可变更新。** 始终创建新数组：
   ```tsx
   setMessages([...messages, newMessage]); // 不要使用 messages.push(newMessage)
   ```
2. **保持处理器引用稳定。** 使用 `useCallback` 对 `onNew`、`onEdit` 等进行记忆化，避免重新创建运行时。
3. **在 zustand 中使用 `useShallow`**，避免不必要的重新渲染。

## 常见问题

**缺少编辑/重新生成/取消按钮。** 每项功能都需要对应的处理器：

```tsx
useExternalStoreRuntime({
  messages,
  onNew, // required
  setMessages, // branch switching
  onEdit, // edit
  onReload, // regenerate
  onCancel, // cancel
});
```

**状态没有更新。** 请检查：是否用数组变更代替了创建新数组、是否缺少 `setMessages`、异步处理是否损坏，或 `convertMessage` 输出是否无效。

**消息进入了错误的线程。** 运行时的 `currentThreadId` 与存储中选中的线程必须保持同步。应在 context 中集中管理线程 id，不要放在组件本地状态中。请参阅[线程](/docs/runtimes/concepts/threads#externalstorethreadlistadapter)。
