`AssistantTransport` 是一种构建在 `ExternalStoreRuntime` 之上的状态流式传输协议（参见[架构](/docs/runtimes/concepts/architecture)）。后端不会流式传输消息片段，而是传输完整代理状态的快照，由运行时将其转换为 UI 消息。

它的实用性体现在以下三点：

- **状态流式传输** — 高效更新代理状态（任意 JSON 对象）。
- **UI 集成** — 代理的原生状态会转换为 assistant-ui 消息。
- **命令处理** — 用户操作（消息、工具结果、自定义命令）会传回代理。

## 适用场景

在以下情况下选择 `AssistantTransport`：

- 后端尚未具备流式传输协议，而你希望添加一个。
- 代理具有值得直接呈现在 UI 中的内部状态。
- 你正在构建自定义代理框架，或使用尚未提供流式传输协议的框架（例如开源 LangGraph）。
- 你需要超越简单消息轮次的双向命令。

如果只需要消息流式传输，[DataStream](/docs/runtimes/custom/data-stream) 更简单。

前端接收状态快照，并将其转换为 React 组件。UI 是构建在代理状态之上的无状态视图。

代理服务器接收来自前端的命令。当用户与 UI 交互（发送消息、点击按钮）时，前端会将命令加入队列并发送。`AssistantTransport` 定义了 `add-message` 和 `add-tool-result`；你也可以定义更多命令。

要实现这一功能，需要构建两部分：

1. **后端端点**，用于接收命令并返回状态快照流。
2. **前端状态转换器**，用于将状态快照映射为 assistant-ui 的数据格式。

## 构建后端端点

端点接收包含以下负载的 POST 请求：

```ts
{
  state: T,                                     // previous state the frontend has
  commands: AssistantTransportCommand[],
  system?: string,
  tools?: Record<string, ToolJSONSchema>,       // tool definitions keyed by name
  threadId: string | null,                      // null for new threads
  parentId?: string | null,                     // present when editing or branching
  callSettings?: { maxTokens, temperature, topP, presencePenalty, frequencyPenalty, seed },
  config?: { apiKey, baseUrl, modelName },
}
```

<Callout type="warn">
之前的传输格式会将 `callSettings` 和 `config` 字段展开到顶层（例如 `body.modelName`）。为保持兼容性，两种格式都会发送，但顶层字段已弃用。请从嵌套对象中读取这些字段。
</Callout>

端点使用 [`assistant-stream`](https://www.npmjs.com/package/assistant-stream) 库返回状态快照流（[PyPI](https://pypi.org/project/assistant-stream/)).

### 处理命令

```python
for command in request.commands:
    if command.type == "add-message":
        # Handle adding a user message
    elif command.type == "add-tool-result":
        # Handle tool execution result
    elif command.type == "my-custom-command":
        # Handle your custom command
```

### 流式更新

在运行回调中修改 `controller.state`：

```python
from assistant_stream import RunController, create_run
from assistant_stream.serialization import DataStreamResponse

@app.post("/assistant")
async def chat_endpoint(request: ChatRequest):
    async def run_callback(controller: RunController):
        controller.state["message"] = "Hello"      # emits "set" at ["message"]
        controller.state["message"] += " World"     # emits "append-text"

    stream = create_run(run_callback, state=request.state)
    return DataStreamResponse(stream)
```

状态变化会使用[流式传输协议](#streaming-protocol)中描述的操作自动进行流式传输。

### 取消

`create_run` 提供 `controller.is_cancelled` 和 `controller.cancelled_event`。如果响应流提前关闭（用户取消、客户端断开连接），它们会被设置，使循环能够正常退出。`create_run` 会在强制取消前为回调提供约 50 毫秒的协作式关闭窗口。请将关键清理逻辑放在 `finally` 块中。

```python
async def run_callback(controller: RunController):
    while not controller.is_cancelled:
        await asyncio.sleep(0.05)
```

```python
async def run_callback(controller: RunController):
    await controller.cancelled_event.wait()
    # cancellation-aware shutdown
```

## 流式传输协议

assistant-stream 通过两个操作复制任意 JSON 对象。

### 操作

这两个操作涵盖所有复杂的状态变更：`set` 用于值更新和结构变更，`append-text` 用于高效流式传输文本内容。

#### `set`

```json
// Operation
{ "type": "set", "path": ["status"], "value": "completed" }

// Before
{ "status": "pending" }

// After
{ "status": "completed" }
```

#### `append-text`

```json
// Operation
{ "type": "append-text", "path": ["message"], "value": " World" }

// Before
{ "message": "Hello" }

// After
{ "message": "Hello World" }
```

### 传输格式

<Callout type="warn">
未来版本将把传输格式迁移到 Server-Sent Events（SSE）。
</Callout>

灵感来自 [AI SDK 的数据流协议](https://sdk.vercel.ai/docs/ai-sdk-ui/stream-protocol).

**状态更新：**

```
aui-state:[{"type":"set","path":["status"],"value":"completed"}]
```

**错误：**

```
3:"error message"
```

## 构建前端

`useAssistantTransportRuntime` 接受：

```ts
{
  initialState: T,
  api: string,
  resumeApi?: string,
  resumeStateApi?: string,
  protocol?: "data-stream" | "assistant-transport",
  converter: (state: T, connectionMetadata: ConnectionMetadata) => AssistantTransportState,
  headers?: Record<string, string> | Headers | (() => Promise<Record<string, string> | Headers>),
  body?: object | (() => Promise<object | undefined>),
  prepareSendCommandsRequest?: (body: SendCommandsRequestBody) => Record<string, unknown> | Promise<Record<string, unknown>>,
  capabilities?: { edit?: boolean },
  adapters?: { attachments?: AttachmentAdapter; history?: ThreadHistoryAdapter },
  onResponse?: (response: Response) => void | Promise<void>,
  onFinish?: () => void,
  onError?: (error: Error, params: { commands: AssistantTransportCommand[]; updateState: (updater: (state: T) => T) => void }) => void | Promise<void>,
  onCancel?: (params: { commands: AssistantTransportCommand[]; updateState: (updater: (state: T) => T) => void; error?: Error }) => void
}
```

### 状态转换器

状态转换器会将代理状态转换为 assistant-ui 的消息格式：

```ts
(
  state: T,
  connectionMetadata: {
    pendingCommands: Command[],          // commands not yet sent
    isSending: boolean,                  // a request is in flight
    toolStatuses: Record<string, ToolExecutionStatus>,
  },
) => {
  messages: ThreadMessage[],
  isRunning: boolean,
  state?: ReadonlyJSONValue,
};
```

### 转换消息

### 来自命令的乐观更新

转换器还会接收 `connectionMetadata.pendingCommands`。使用它可以在后端响应前显示乐观 UI：

```ts
const converter = (state: State, connectionMetadata: ConnectionMetadata) => {
  const optimisticMessages = connectionMetadata.pendingCommands
    .filter((c) => c.type === "add-message")
    .map((c) => c.message);

  return {
    messages: [...state.messages, ...optimisticMessages],
    isRunning: connectionMetadata.isSending || false,
  };
};
```

## 错误与取消

`onError` 和 `onCancel` 会接收 `updateState`，因此你可以在客户端修改状态，而无需发起服务器请求：

```ts
const runtime = useAssistantTransportRuntime({
  // ... other options
  onError: (error, { commands, updateState }) => {
    updateState((s) => ({ ...s, lastError: error.message }));
  },
  onCancel: ({ commands, updateState }) => {
    updateState((s) => ({ ...s, status: "cancelled" }));
  },
});
```

`onError` 接收正在传输中的命令。用户直接取消时，`onCancel` 会接收正在传输中和已排队的命令；错误后调用时，它只接收已排队的命令（正在传输中的命令会传递给 `onError`）。

### 转换请求体

`prepareSendCommandsRequest` 允许你在发送前转换整个请求体：

```ts
const runtime = useAssistantTransportRuntime({
  // ...
  prepareSendCommandsRequest: (body) => ({
    ...body,
    trackingId: crypto.randomUUID(),
    commands: body.commands.map((cmd) =>
      cmd.type === "add-message"
        ? { ...cmd, trackingId: crypto.randomUUID() }
        : cmd,
    ),
  }),
});
```

## 编辑消息

默认情况下禁用编辑功能。启用它：

```ts
const runtime = useAssistantTransportRuntime({
  // ...
  capabilities: { edit: true },
});
```

`add-message` 命令始终包含 `parentId` 和 `sourceId`：

```ts
{
  type: "add-message",
  message: { role: "user", parts: [...] },
  parentId: "msg-3",   // insert after this message
  sourceId: "msg-4",   // ID of the message being replaced (null for new)
}
```

### 后端处理

当后端收到带有 `parentId` 的 `add-message` 时：

1. 截断父消息之后的所有消息。
2. 追加新消息。
3. 将更新后的状态流式传回。

```python
for command in request.commands:
    if command.type == "add-message":
        if hasattr(command, "parentId") and command.parentId is not None:
            parent_idx = next(
                i for i, m in enumerate(messages) if m.id == command.parentId
            )
            messages = messages[:parent_idx + 1]
        messages.append(command.message)
```

## 从同步服务器恢复

<Callout type="info">
同步服务器目前属于企业版计划；详情请联系我们。
</Callout>

当用户刷新页面或重新连接时，后端可能仍在生成内容。`resumeRun` 会重新连接到活动中的流。

```ts
const runtime = useAssistantTransportRuntime({
  // ...
  api: "http://localhost:8010/assistant",
  resumeApi: "http://localhost:8010/resume",
});
```

设置 `resumeStateApi` 后，还会从服务器保留的起始状态中恢复已恢复的运行。它要求同步服务器提供初始状态路由；不要将其配置到没有该路由的服务器上，因为预检失败会导致恢复流程直接失败：

```tsx
const runtime = useAssistantTransportRuntime({
  // ...
  resumeStateApi: "http://localhost:8010/initial-state",
});
```

恢复前，运行时会向 `resumeStateApi` 发送 `{ threadId }`。端点必须返回启动活动运行时的状态及其标识：

```json
{ "runId": "8b3a...", "state": { "messages": [] } }
```

运行时会将本地基础状态替换为此快照，并在恢复请求中包含 `runId`；请求不携带 `state`，因为服务器会从保留的快照中重放。如果该 ID 不再标识同一个运行，同步服务器应拒绝恢复，以防止将重放操作应用到已发生漂移或被替换的基础状态上。没有活动运行时，端点返回 `204 No Content`，运行时会跳过恢复且不会抛出错误。恢复时，`runId` 的优先级高于通过 `body` 提供的字段，并且会在 `prepareSendCommandsRequest` 中保留；它们中任何一个提供的 `state` 都会被移除。

```tsx
import { useAui } from "@assistant-ui/react";
import { useEffect, useRef } from "react";

function useResumeOnMount(threadId: string) {
  const aui = useAui();
  const checkedRef = useRef(false);

  useEffect(() => {
    if (checkedRef.current) return;
    checkedRef.current = true;

    (async () => {
      const status = await fetch(`/api/sync-server/status/${threadId}`).then((r) =>
        r.json(),
      );
      if (status.isRunning) {
        const parentId = aui.thread.getState().messages.at(-1)?.id ?? null;
        aui.thread.resumeRun({ parentId });
      }
    })();
  }, [aui, threadId]);
}
```

对于 `AssistantTransport`，不要传递 `stream` 参数；运行时会使用已配置的 `resumeApi`。

## 访问运行时状态

`useAssistantTransportState` 可以从任意组件读取当前代理状态：

```ts
import { useAssistantTransportState } from "@assistant-ui/react";

function MyComponent() {
  const state = useAssistantTransportState();
  return <div>{JSON.stringify(state)}</div>;
}

function MessageCount() {
  const messages = useAssistantTransportState((state) => state.messages);
  return <div>Message count: {messages.length}</div>;
}
```

### 类型安全

扩展模块，为代理状态添加类型：

```ts title="assistant.config.ts"
import "@assistant-ui/react";

declare module "@assistant-ui/react" {
  namespace Assistant {
    interface ExternalState {
      myState: {
        messages: Message[];
        customField: string;
      };
    }
  }
}
```

将此文件放置在项目中的任意位置；TypeScript 会通过模块解析找到它。`useAssistantTransportState` 将获得完整的类型支持。

### 访问原始消息

如果使用了 `createMessageConverter`，可以从任意 assistant-ui 状态中获取原始消息：

```ts
import { useAuiState } from "@assistant-ui/react";

function MyMessageComponent() {
  const message = useAuiState((s) => s.message);
  const original = messageConverter.toOriginalMessage(message);
  return <div>{original.yourCustomField}</div>;
}
```

当 `ThreadMessage` 由多个来源创建时，`toOriginalMessages` 会返回所有源消息。

## 前端参考实现

```tsx
"use client";

import {
  AssistantRuntimeProvider,
  AssistantTransportConnectionMetadata,
  useAssistantTransportRuntime,
} from "@assistant-ui/react";

type State = { messages: Message[] };

const converter = (
  state: State,
  connectionMetadata: AssistantTransportConnectionMetadata,
) => {
  const optimistic = connectionMetadata.pendingCommands
    .filter((c) => c.type === "add-message")
    .map((c) => c.message);

  return {
    messages: [...state.messages, ...optimistic],
    isRunning: connectionMetadata.isSending || false,
  };
};

export function MyRuntimeProvider({ children }) {
  const runtime = useAssistantTransportRuntime({
    initialState: { messages: [] },
    api: "http://localhost:8010/assistant",
    converter,
    headers: async () => ({ Authorization: "Bearer token" }),
    body: { "custom-field": "custom-value" },
    onError: (error, { commands, updateState }) => {
      updateState((s) => ({ ...s, lastError: error.message }));
    },
    onCancel: ({ commands, updateState }) => {
      updateState((s) => ({ ...s, status: "cancelled" }));
    },
  });

  return (
    <AssistantRuntimeProvider runtime={runtime}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

```python
for command in request.commands:
```

### 乐观更新

```ts
const converter = (state: State, connectionMetadata: ConnectionMetadata) => {
  const customCommands = connectionMetadata.pendingCommands.filter(
    (c) => c.type === "my-custom-command",
  );
  return {
    messages: state.messages,
    state: { ...state, customData: customCommands.map((c) => c.data) },
```

自定义命令遵循与内置命令相同的生命周期；如有需要，可以在 `onError` 和 `onCancel` 中检查它们。
