如果没有适合你的后端的[框架适配器](/docs/runtimes/pick-a-runtime)，本节将提供四种构建方式。它们都构建在两种核心运行时之一之上；理解其分层结构（参阅[架构](/docs/runtimes/concepts/architecture)）即可明确如何选择。

## 四种路径

| 路径 | 构建于 | 通信格式 | 适用场景 |
| --- | --- | --- | --- |
| [`LocalRuntime`](/docs/runtimes/custom/local-runtime) | Core | 你编写一个 `ChatModelAdapter.run` 函数 | 最简单的情况：你需要发起 `fetch` 调用，并希望 assistant-ui 处理状态 |
| [`ExternalStoreRuntime`](/docs/runtimes/custom/external-store) | Core | 你提供消息和回调 | 你已经在 redux、zustand、tanstack-query 或其他位置管理状态 |
| [`DataStream`](/docs/runtimes/custom/data-stream) | LocalRuntime + 协议 | 你的后端输出数据流协议 | 你需要精简的消息流契约，或正在从 AI SDK v4 迁移 |
| [`AssistantTransport`](/docs/runtimes/custom/assistant-transport) | ExternalStoreRuntime + 协议 | 你的后端流式传输 agent 状态快照 | 你的 agent 具有丰富的内部状态，并希望在 UI 中呈现；或者你需要双向命令 |

## 决策树

```text
do you have an AI SDK / LangGraph / Google ADK / A2A backend?
└── yes → use that framework adapter; you do not need this section
└── no → continue
    │
    do you already have message state in redux / zustand / tanstack-query?
    └── yes → ExternalStoreRuntime
    └── no → continue
        │
        do you control the backend wire format?
        └── yes, and i want simple fetch calls → LocalRuntime
        └── yes, and i want to stream a structured agent state → AssistantTransport
        └── no, the backend already speaks data stream protocol → DataStream
```

## 各路径提供的能力

**`LocalRuntime`** 是阻力最低的路径。你只需实现一个方法（`run` 或 `async *run`）。分支、编辑、重新生成、多线程和 adapter 插槽均无需额外代码即可使用。

**`ExternalStoreRuntime`** 则相反：你拥有消息数组，并为每次交互提供回调。UI 功能会根据你提供的回调启用。当聊天状态是现有存储中的一等实体时，这是理想选择。

**`DataStream`** 是 `LocalRuntime` 加上通信协议。你无需编写 `ChatModelAdapter`；后端会输出标准化的消息部分流，运行时直接消费该流。

**`AssistantTransport`** 是 `ExternalStoreRuntime` 加上状态流式传输协议。后端不会发送消息部分，而是发送其完整 agent 状态的快照。UI 是该状态之上的无状态视图。除内置的 `add-message` 和 `add-tool-result` 外，还支持自定义命令。

## 通用构建模块

无论选择哪种路径，[adapter](/docs/runtimes/concepts/adapters) 和 [thread](/docs/runtimes/concepts/threads) 接口的工作方式都相同。通过这些共享契约连接附件、历史记录、语音、反馈、建议和多线程支持。
