title: LocalRuntime
description: 实现可用聊天的最快路径。由它处理状态，你只需处理 API。
---

`LocalRuntime` 是连接自定义后端的最简单方式。你只需实现一个 `ChatModelAdapter`（一个 `run` 函数），运行时会处理其他所有事项：消息、线程、分支、编辑、重新生成和取消。

默认情况下，状态保存在运行时内部。多线程持久化和共享适配器通过标准接口添加，参见 [适配器](/docs/runtimes/concepts/adapters) 和 [线程](/docs/runtimes/concepts/threads)。

## 适用场景

在以下情况下选择 `LocalRuntime`：

- 希望由 assistant-ui 为你管理聊天状态。
- 后端提供函数调用形式的 API（REST、OpenAI SDK 或你自己的模型客户端）。
- 希望无需编写额外代码即可支持分支、编辑和重新生成。
- 希望组合使用适配器（附件、语音、反馈、历史记录和建议）。

如果你已经将消息保存在 redux、zustand、tanstack-query 或其他存储中，请改用 [`ExternalStoreRuntime`](/docs/runtimes/custom/external-store)。

## 流式响应

将 `run` 声明为 `async *` 生成器，并在每次迭代中 yield 完整的累积内容：

```tsx
import {
  ChatModelAdapter,
  ThreadMessage,
  type ModelContext,
} from "@assistant-ui/react";
import { OpenAI } from "openai";

const openai = new OpenAI();

const MyModelAdapter: ChatModelAdapter = {
  async *run({ messages, abortSignal, context }) {
    const stream = await openai.chat.completions.create({
      model: "gpt-5.6-luna",
      messages: convertToOpenAIMessages(messages),
      stream: true,
      signal: abortSignal,
    });

    let text = "";
    for await (const part of stream) {
      text += part.choices[0]?.delta?.content || "";
      yield {
        content: [{ type: "text", text }],
      };
    }
  },
};
```

每次 yield 都会替换之前的内容。每次都要 yield 完整状态，而不是增量。

### 只有最后一个部分进行流式传输

文本或推理部分只有在消息的最后一个部分时才会报告 `status.type === "running"`。之前的每个部分都会被视为已完成，响应流式传输的组件也会遵循这一状态：推理展开面板会在其部分运行时自动打开，并固定显示实时预览；部分状态指示器也会以相同方式完成。工具调用部分不受此限制，因为其状态取决于是否已有结果。

这使得末尾的空部分具有破坏性。yield `[reasoning, text("")]` 以预留文本槽位时，空文本部分一出现，就会将推理部分标记为已完成，即使推理仍在流式传输，而 UI 中不会说明原因。不要预留部分，而应在其收到第一个 token 时添加：

```tsx
let reasoning = "";
let text = "";

for await (const chunk of stream) {
  const delta = chunk.choices[0]?.delta;
  text += delta?.content ?? "";
  // Reasoning deltas are provider-specific; read whichever field yours sends
  reasoning += (delta as { reasoning?: string })?.reasoning ?? "";

  // Include each part only once it has content
  yield {
    content: [
      ...(reasoning ? [{ type: "reasoning" as const, text: reasoning }] : []),
      ...(text ? [{ type: "text" as const, text }] : []),
    ],
  };
}
```

应以这种方式保护每个文本或推理部分，而不仅是末尾部分。始终未被填充的空部分也会渲染为空块，而最终位于末尾的部分是唯一能够报告 `running` 的部分。

### 使用工具调用进行流式传输

在流式循环外部的 `Map` 中累积工具调用，使其能够跨数据块持久存在：

```tsx
async *run({ messages, abortSignal, context }) {
  const stream = await openai.chat.completions.create({
    model: "gpt-5.6-luna",
    messages: convertToOpenAIMessages(messages),
    tools: context.tools,
    stream: true,
    signal: abortSignal,
  });

  let text = "";
  const toolCallsMap = new Map();

  for await (const chunk of stream) {
    text += chunk.choices[0]?.delta?.content ?? "";

    for (const toolCall of chunk.choices[0]?.delta?.tool_calls ?? []) {
      toolCallsMap.set(toolCall.id, {
        type: "tool-call",
        toolName: toolCall.function?.name,
        toolCallId: toolCall.id,
        args: JSON.parse(toolCall.function?.arguments ?? "{}"),
      });
    }

    yield {
      content: [
        ...(text ? [{ type: "text" as const, text }] : []),
        ...Array.from(toolCallsMap.values()),
      ],
    };
  }
}
```

如果每次迭代都根据当前数据块重新创建 `content` 数组，那么当后续数据块只包含文本时，之前数据块中的工具调用就会消失。解决办法是将 Map 放在循环外部。

## 工具调用

`LocalRuntime` 支持兼容 OpenAI 的函数调用。通过提供商的 `config` 注册工具，这样运行时就会通过 `context.tools` 将工具暴露给你的适配器：

```tsx title="app/toolkit.tsx"
"use generative";

import { defineToolkit } from "@assistant-ui/react";
import { z } from "zod";

export default defineToolkit({
  getWeather: {
    description: "Get the current weather in a location",
    parameters: z.object({
      location: z.string(),
      unit: z.enum(["celsius", "fahrenheit"]).default("celsius"),
    }),
    execute: async ({ location, unit }) => {
      "use client";
      return fetchWeather(location, unit);
    },
    renderText: { running: "Checking the weather…", complete: "Weather ready" },
  },
});
```

```tsx title="app/MyRuntimeProvider.tsx"
import { AuiConfig, Tools } from "@assistant-ui/react";
import toolkit from "./toolkit";

function MyRuntimeProvider({ children }: { children: React.ReactNode }) {
  const runtime = useLocalRuntime(MyModelAdapter);
  const config = AuiConfig({ tools: Tools({ toolkit }) });
  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

有关高级模式，请参见[工具指南](/docs/tools/defining-tools)。

### 人在回路工具

`unstable_humanToolNames` 中列出的工具不会由代码执行。运行会在工具调用处暂停，用户通过工具 UI 提供结果：

```ts
const runtime = useLocalRuntime(MyModelAdapter, {
  unstable_humanToolNames: ["send_email"],
});
```

暂停由适配器返回的消息状态驱动；`LocalRuntime` 不会为你设置该状态。当模型请求人在回路工具调用时，使用 `status: { type: "requires-action", reason: "tool-calls" }` 结束运行。没有该状态，运行时会将消息标记为已完成，不会等待任何内容。只有在列出的工具调用缺少结果时才返回该状态：未列出的未解决工具调用不会阻止运行，因此运行时会立即再次调用你的适配器。

```tsx
const MyModelAdapter: ChatModelAdapter = {
  async run({ messages, abortSignal, unstable_getMessage }) {
    const toolResults = unstable_getMessage().content.flatMap((part) =>
      part.type === "tool-call" && part.result !== undefined
        ? [{ toolCallId: part.toolCallId, result: part.result }]
        : [],
    );

    const result = await fetch("<YOUR_API_ENDPOINT>", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ messages, toolResults }),
      signal: abortSignal,
    });
    const data = await result.json();

    if (data.toolCall) {
      return {
        content: [
          {
            type: "tool-call",
            toolCallId: data.toolCall.id,
            toolName: data.toolCall.name,
            args: data.toolCall.args,
            argsText: JSON.stringify(data.toolCall.args),
          },
        ],
        status: { type: "requires-action", reason: "tool-calls" },
      };
    }

    return { content: [{ type: "text", text: data.text }] };
  },
};
```

完整流程如下：

1. **运行暂停。** 当列出的工具调用没有结果时，运行时会停止调用你的适配器。未解决的工具调用部分会向其渲染器报告 `status.type === "requires-action"`。
2. **用户响应。** 工具 UI 使用 `addResult(...)` 完成调用。内置的 [`ToolFallback`](/elements/tool-fallback) 组件开箱即用地处理此流程：在 requires-action 状态下，它会显示 Allow 和 Deny 按钮，并将决定记录为工具结果。
3. **运行恢复。** 当每个列出的工具调用都有结果后，运行时会再次调用你的适配器。恢复后的调用会接收与之前相同的 `messages` 数组（该数组截止于用户消息；正在进行中的助手消息不属于其中的一部分），因此应像上面所示，从 `unstable_getMessage().content` 中读取已记录的结果。恢复调用返回的内容会追加到同一条助手消息中。

如需自定义确认 UI，请注册一个人在回路工具，其 `render` 使用 `addResult` 完成调用。结果载荷的结构由你定义；适配器会原样接收它，并将其转换为后端所需的格式：

```tsx
const toolkit = defineToolkit({
  send_email: {
    type: "human",
    description: "Send an email after the user confirms",
    parameters: z.object({ to: z.string(), subject: z.string() }),
    render: ({ args, result, addResult }) => {
      if (result) {
        return <p>{result.approved ? "Sent" : `Cancelled: ${result.reason}`}</p>;
      }
      return (
        <div>
          <p>
            Send "{args.subject}" to {args.to}?
          </p>
          <button onClick={() => addResult({ approved: true })}>Allow</button>
          <button
            onClick={() =>
              addResult({ approved: false, reason: "User declined" })
            }
          >
            Deny
          </button>
        </div>
      );
    },
  },
});
```

`unstable_humanToolNames` 尚不稳定；请参见[稳定性](/docs/runtimes/concepts/stability)。

### 审批门

[服务端审批门](/docs/tools/tool-ui#server-side-approval-gates)同样支持 `LocalRuntime`，适用于用户授权后由后端执行的操作。人在回路工具要求用户提供工具结果，而审批门要求用户允许或阻止适配器执行的操作。在工具调用部分发出 `approval: { id }`，并使用相同的 `requires-action` 状态结束运行：

```tsx
return {
  content: [
    {
      type: "tool-call",
      toolCallId: data.toolCall.id,
      toolName: data.toolCall.name,
      args: data.toolCall.args,
      argsText: JSON.stringify(data.toolCall.args),
      approval: { id: data.toolCall.id },
    },
  ],
  status: { type: "requires-action", reason: "tool-calls" },
};
```

带有待处理审批的工具调用会暂停运行，无论该工具是否列在 `unstable_humanToolNames` 中。始终以待处理状态发出审批门（`approval: { id }`，且不包含 `approved` 字段）；已经带有决定的部分会被视为已解决，运行时会立即再次调用适配器。内置 [`ToolFallback`](/elements/tool-fallback) 的 Allow 和 Deny 按钮，或调用 `respondToApproval({ approved, reason? })` 的自定义渲染器，会记录该决定：

- **Deny** 设置 `approval.approved: false`，并合成错误结果（`{ error: reason || "Tool approval denied" }`，其中包含 `isError: true`），使模型能够看到拒绝。
- **Allow** 设置 `approval.approved: true`，并保持结果为空；执行操作由你的适配器负责。

当消息中的所有待处理审批都已决定，且列出的每个人在回路工具都有结果后，运行时会再次调用你的适配器。从 `unstable_getMessage().content` 中读取决定，执行已批准的操作，并返回后续响应。携带审批的工具调用由审批门负责：即使其名称列在 `unstable_humanToolNames` 中，也不需要额外的结果。

## 恢复运行

`resumeRun` 会重新连接到正在进行的助手运行。适用于页面刷新、网络重连、标签页转入后台，或后端仍在生成内容时切换线程。

不同于 `startRun`（使用 `ChatModelAdapter`），`resumeRun` 要求提供 `stream` 参数；你需要提供用于生成响应的异步生成器。

```tsx
import { useAui } from "@assistant-ui/react";
import type { ChatModelRunResult } from "@assistant-ui/core";

const aui = useAui();

async function* createCustomStream(): AsyncGenerator<ChatModelRunResult> {
  yield { content: [{ type: "text", text: "Initial response" }] };
  await new Promise((r) => setTimeout(r, 500));
  yield {
    content: [
      { type: "text", text: "Initial response. And here's more content..." },
    ],
  };
}

aui.thread.resumeRun({
  parentId: "message-id",
  stream: createCustomStream,
});
```

一种常见模式是在挂载时检查后端是否仍在运行，然后重新连接：

```tsx
function useStreamReconnect(threadId: string) {
  const aui = useAui();
  const checkedRef = useRef(false);

  useEffect(() => {
    if (checkedRef.current) return;
    checkedRef.current = true;

    (async () => {
      const status = await fetch(`/api/status/${threadId}`).then((r) =>
        r.json(),
      );
      if (status.isRunning) {
        const parentId = aui.thread.getState().messages.at(-1)?.id ?? null;
        aui.thread.resumeRun({ parentId });
      }
    })();
  }, [aui, threadId]);
}
```

## 运行期间将消息加入队列

将 `unstable_enableMessageQueue` 设置为 true，可以在运行进行期间保持输入框可用。在排队运行期间发送的消息默认会进行 steer——它会进入 steer 队列，位于之前已排队的项目之前；`send({ steer: false })` 则会将后续消息排在它们之后。待处理项目会保存在 `composer.queue` 中，并在运行结束后逐个处理。

```tsx
const runtime = useLocalRuntime(MyModelAdapter, {
  unstable_enableMessageQueue: true,
});
```

使用 [`ComposerPrimitive.Queue`](/docs/api-reference/primitives/composer) 和 [`QueueItemPrimitive`](/docs/api-reference/primitives/queue-item) 渲染待处理消息。

## 集成示例

### OpenAI

```tsx
import { OpenAI } from "openai";

const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

const OpenAIAdapter: ChatModelAdapter = {
  async *run({ messages, abortSignal, context }) {
    const stream = await openai.chat.completions.create({
      model: "gpt-5.6-luna",
      messages: messages.map((m) => ({
        role: m.role,
        content: m.content
          .filter((c) => c.type === "text")
          .map((c) => c.text)
          .join("\n"),
      })),
      stream: true,
      signal: abortSignal,
    });

    let fullText = "";
    for await (const chunk of stream) {
      const content = chunk.choices[0]?.delta?.content;
      if (content) {
        fullText += content;
        yield { content: [{ type: "text", text: fullText }] };
      }
    }
  },
};
```

在 ChatGPT Plus 或 Pro 方案上进行本地开发时，只需将 `baseURL` 指向本地 OAuth 代理，并传入占位的 `apiKey`，同一个客户端无需真实 API 密钥即可运行；请参见 [ChatGPT Subscription](/docs/guides/chatgpt-subscription#openai-compatible-proxy)。

### 自定义 REST API

```tsx
const CustomAPIAdapter: ChatModelAdapter = {
  async run({ messages, abortSignal, unstable_threadId }) {
    const response = await fetch("/api/chat", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        messages: messages.map((m) => ({
          role: m.role,
          content: m.content,
        })),
        threadId: unstable_threadId,
      }),
      signal: abortSignal,
    });
    if (!response.ok) throw new Error(`API error: ${response.statusText}`);
    const data = await response.json();
    return { content: [{ type: "text", text: data.message }] };
  },
};
```

## 最佳实践

1. **始终将 `abortSignal` 传递给 `fetch` 和 SDK 调用**，以确保取消功能正常工作：
   ```tsx
   fetch(url, { signal: abortSignal });
   ```
2. **妥善处理错误。** 忽略 `AbortError`（它表示用户正在取消操作）；重新抛出其他错误，使其显示在 UI 中。
3. **Yield 累积状态，而不是增量。** 每次 yield 都会替换之前的内容；如果 yield 增量，UI 会闪烁。
4. **在流式循环外部累积工具调用**，否则它们会在第一个纯文本数据块中消失。

## 故障排除

**消息未显示。** 确保适配器返回正确的结构：`{ content: [{ type: "text", text: "..." }] }`。

**流式传输不起作用。** 使用 `async *run`（带星号）。普通的 `async run` 无法 yield。

**工具 UI 闪烁并消失。** 状态在数据块之间被重置。将工具调用累积在 `Map` 中，并在 `for await` 循环外部声明它。
