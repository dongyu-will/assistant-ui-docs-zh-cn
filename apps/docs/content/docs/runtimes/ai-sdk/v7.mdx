### 设置后端路由

对于 React Native 和 Ink，请在单独的后端项目中托管此路由，并将客户端运行时指向其绝对 URL。

```ts title="@/app/api/chat/route.ts"
import { openai } from "@ai-sdk/openai";
import {
  streamText,
  convertToModelMessages,
  tool,
  zodSchema,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from "ai";
import type { UIMessage } from "ai";
import { z } from "zod";

export const maxDuration = 30;

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: openai("gpt-5.6-luna"),
    messages: await convertToModelMessages(messages), // async in v7
    tools: {
      get_current_weather: tool({
        description: "Get the current weather",
        inputSchema: zodSchema(z.object({ city: z.string() })),
        execute: async ({ city }) => {
          return `The weather in ${city} is sunny`;
        },
      }),
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

## 前端工具和系统消息

`AssistantChatTransport`（默认使用）会在每次请求中将系统消息和前端工具转发到后端。使用 `frontendTools` 消费它们：

```ts title="@/app/api/chat/route.ts"
import { openai } from "@ai-sdk/openai";
import { streamText, convertToModelMessages, zodSchema, createUIMessageStreamResponse, toUIMessageStream } from "ai";
import type { UIMessage } from "ai";
import { frontendTools } from "@assistant-ui/ai-sdk";

export async function POST(req: Request) {
  const {
    messages,
    system,
    tools,
  }: {
    messages: UIMessage[];
    system?: string;
    tools?: any;
  } = await req.json();

  const result = streamText({
    model: openai("gpt-5.6-luna"),
    system,
    messages: await convertToModelMessages(messages),
    tools: {
      ...frontendTools(tools),
      // your backend tools...
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

前端工具通过 provider 的 `config` 注册（请参阅[工具指南](/docs/tools/defining-tools)），并通过 `frontendTools` 序列化后发送到后端。

## 多轮工具调用

AI SDK v7 支持通过 `stopWhen` 在单个请求中运行多轮工具调用。使用 `stepCountIs(N)` 限制迭代次数：

```ts title="@/app/api/chat/route.ts"
import { openai } from "@ai-sdk/openai";
import {
  streamText,
  convertToModelMessages,
  stepCountIs,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from "ai";

export async function POST(req: Request) {
  const { messages } = await req.json();

  const result = streamText({
    model: openai("gpt-5.6-luna"),
    messages: await convertToModelMessages(messages),
    tools: {
      /* ... */
    },
    stopWhen: stepCountIs(10), // cap at 10 tool-call iterations
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

如果没有 `stopWhen`，AI SDK 将运行单个推理步骤。当工具链需要多次调用时，请设置 `stepCountIs`（或 AI SDK 的其他停止条件之一）。

## 服务端工具审批

AI SDK v7 使用调用级 `toolApproval` 选项控制工具执行。服务端会暂停执行并发出一个 `approval-requested` 部分，客户端提交审批响应后恢复执行。assistant-ui 会在工具部分上通过 `approval` 暴露此控制门，并在渲染器上添加 `respondToApproval` 属性，使工具组件与 `chatHelpers` 保持解耦。

在后端，通过调用级 `toolApproval` 选项配置控制门（按工具状态或函数配置）：

```ts title="@/app/api/chat/route.ts"
import { openai } from "@ai-sdk/openai";
import { streamText, convertToModelMessages, tool, createUIMessageStreamResponse, toUIMessageStream } from "ai";
import { z } from "zod";

export async function POST(req: Request) {
  const { messages } = await req.json();

  const result = streamText({
    model: openai("gpt-5.6-luna"),
    messages: await convertToModelMessages(messages),
    tools: {
      deploy: tool({
        description: "Deploy the current build to an environment.",
        inputSchema: z.object({ target: z.string() }),
        execute: async ({ target }) => ({ deployed: target }),
      }),
    },
    toolApproval: {
      deploy: (input) =>
        input.target === "production" ? "user-approval" : "not-applicable",
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

在客户端，使用 `sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithApprovalResponses` 配置 `useChat`，以便用户做出决定后将响应发送回服务端：

```tsx title="@/app/page.tsx"
"use client";

import { useChat } from "@ai-sdk/react";
import {
  AssistantRuntimeProvider,
  useAISDKRuntime,
} from "@assistant-ui/ai-sdk";
import { lastAssistantMessageIsCompleteWithApprovalResponses } from "ai";
import { Thread } from "@/components/assistant-ui/elements/thread.aui";

export default function Page() {
  const chat = useChat({
    api: "/api/chat",
    sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithApprovalResponses,
  });
  const runtime = useAISDKRuntime(chat);

  return (
    <AssistantRuntimeProvider runtime={runtime}>
      <Thread />
    </AssistantRuntimeProvider>
  );
}
```

使用工具包条目渲染控制门。`approval` 字段携带控制门状态，而 `respondToApproval` 是确认该状态的唯一正确方式（它会从部分中读取审批 ID）：

```tsx title="@/app/page.tsx"
"use client";

import { useChat } from "@ai-sdk/react";
import {
  AssistantRuntimeProvider,
  AuiConfig,
  defineToolkit,
  Tools,
  type ToolApprovalResponse,
} from "@assistant-ui/react";
import { useAISDKRuntime } from "@assistant-ui/ai-sdk";
import { lastAssistantMessageIsCompleteWithApprovalResponses } from "ai";
import { Thread } from "@/components/assistant-ui/elements/thread.aui";

const toolkit = defineToolkit({
  deploy: {
    type: "backend",
    render: ({ args, approval, respondToApproval, result }) => {
      // A refused response rejects and a precondition throws, so `try`/`await`
      // covers both and the controls stay actionable.
      const answer = async (response: ToolApprovalResponse) => {
        try {
          await respondToApproval(response);
        } catch (failure) {
          console.error(failure);
        }
      };

      if (approval?.approved === undefined) {
        return (
          <div>
            <p>Approve deploy to {args.target}?</p>
            <button onClick={() => void answer({ approved: true })}>
              Approve
            </button>
            <button
              onClick={() =>
                void answer({ approved: false, reason: "user denied" })
              }
            >
              Deny
            </button>
          </div>
        );
      }
      if (approval?.approved === false) return <p>Denied</p>;
      if (result === undefined) return <p>Approved, deploying…</p>;
      return <p>Deployed {result.deployed}</p>;
    },
  },
});

export default function Page() {
  const chat = useChat({
    api: "/api/chat",
    sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithApprovalResponses,
  });
  const runtime = useAISDKRuntime(chat);
  const config = AuiConfig({ tools: Tools({ toolkit }) });
  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}>
      <Thread />
    </AssistantRuntimeProvider>
  );
}
```

有关 `approval.approved` 的完整三状态语义以及 `isAutomatic` 标志，请参阅[工具 UI 指南](/docs/tools/tool-ui#server-side-approval-gates)。

## 引用上下文

assistant-ui 的输入框可以将引用元数据附加到用户消息上（例如，用户选中文本并点击“引用”时）。在服务器端，`injectQuoteContext` 会将这些元数据展平为 Markdown 引用块前缀，使 LLM 能够看到被引用的文本：

```ts title="@/app/api/chat/route.ts"
import {
  streamText,
  convertToModelMessages,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from "ai";
import { injectQuoteContext } from "@assistant-ui/ai-sdk";
import { openai } from "@ai-sdk/openai";

export async function POST(req: Request) {
  const { messages } = await req.json();
  const result = streamText({
    model: openai("gpt-5.6-luna"),
    messages: await convertToModelMessages(injectQuoteContext(messages)),
  });
  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

`injectQuoteContext` 具有幂等性：如果引用块前缀已经存在，则不会重复添加。

## Token 用量

`useThreadTokenUsage` 会在客户端公开线程级别的 Token 用量。在服务器端，通过 `messageMetadata` 附加 `usage` 和 `modelId`：

```ts title="@/app/api/chat/route.ts"
import { streamText, convertToModelMessages, createUIMessageStreamResponse, toUIMessageStream } from "ai";
import { frontendTools } from "@assistant-ui/ai-sdk";

export async function POST(req: Request) {
  const { messages, tools, config } = await req.json();
  const result = streamText({
    model: getModel(config?.modelName),
    messages: await convertToModelMessages(messages),
    tools: frontendTools(tools),
  });
  return createUIMessageStreamResponse({
    stream: toUIMessageStream({
      stream: result.stream,
      messageMetadata: ({ part }) => {
        if (part.type === "finish") {
          return { usage: part.totalUsage };
        }
        if (part.type === "finish-step") {
          return { modelId: part.response.modelId };
        }
        return undefined;
      },
    }),
  });
}
```

```tsx title="@/components/TokenCounter.tsx"
"use client";

import { useThreadTokenUsage } from "@assistant-ui/ai-sdk";

export function TokenCounter() {
  const usage = useThreadTokenUsage();
  if (!usage) return null;
  return <div>{usage.totalTokens} total tokens</div>;
}
```

如果需要在线程中显示每条消息的用量，`getThreadMessageTokenUsage(message)` 会返回每条消息的用量。

## 附件

附件通过标准的[附件适配器](/docs/runtimes/concepts/adapters#attachment-adapter)工作。通过 `useChatRuntime` 传入该适配器：

```tsx
const runtime = useChatRuntime({
  adapters: { attachments: myAttachmentAdapter },
});
```

附件适配器的 `send` 应以 AI SDK 格式返回 `content` 部分，例如文件：

```ts
return {
  ...attachment,
  status: { type: "complete" },
  content: [
    {
      type: "file",
      mimeType: attachment.contentType ?? "",
      filename: attachment.name,
      data: await getFileDataURL(attachment.file),
    },
  ],
};
```

对于图片，请使用 `{ type: "image", image: <data url or remote url> }`。AI SDK 会将这些内容传递给接受多模态内容的提供商。

## 持久化聊天历史

默认情况下，消息只存在于内存中，重新加载后会重置。若要按线程持久化和恢复历史记录，请通过 `adapters.history` 提供 `ThreadHistoryAdapter`。

<Callout type="warn">
适配器**必须**实现 `withFormat`。`useChatRuntime` 通过 `withFormat(fmt)` 持久化历史记录，使消息能够往返转换为 AI SDK `UIMessage` 对象。缺少 `withFormat` 的适配器会在运行时抛出异常；AI SDK 路径不会使用顶层的 `load` 和 `append`。
</Callout>

<Callout type="info">
如需在无需编写适配器代码的情况下进行服务端云端持久化，请参阅 [AssistantCloud 集成](/docs/cloud/ai-sdk-assistant-ui)。
</Callout>

```tsx
"use client";

import { useChatRuntime } from "@assistant-ui/ai-sdk";
import type { ThreadHistoryAdapter } from "@assistant-ui/react";

const historyAdapter: ThreadHistoryAdapter = {
  // Required by the type — unused by useChatRuntime.
  async load() {
    return { headId: null, messages: [] };
  },
  async append() {},

  // fmt encodes UIMessage <-> storage rows (ai-sdk/v6 format).
  withFormat: (fmt) => ({
    async load() {
      const rows = await fetch("/api/history").then((r) => r.json());
      return { messages: rows.map(fmt.decode) };
    },
    async append(item) {
      await fetch("/api/history", {
        method: "POST",
        body: JSON.stringify({
          id: fmt.getId(item.message),
          parent_id: item.parentId,
          format: fmt.format,
          content: fmt.encode(item),
        }),
      });
    },
  }),
};

function Chat() {
  const runtime = useChatRuntime({ adapters: { history: historyAdapter } });
  // ...
}
```

每条持久化记录都遵循 `{ id, parent_id, format, content }`。`fmt.encode` 会生成 `content` 负载，而 `fmt.decode` 会将其还原，因此后端无需了解 `UIMessage` 的内部实现。

## 自定义传输层

`AssistantChatTransport` 是默认传输层。若要指向非默认端点，请使用自定义的 `api` 实例化它：

```tsx
import {
  useChatRuntime,
  AssistantChatTransport,
} from "@assistant-ui/ai-sdk";

const runtime = useChatRuntime({
  transport: new AssistantChatTransport({ api: "/my-custom-api/chat" }),
});
```

如果需要使用不继承自 `AssistantChatTransport` 的传输层，则会失去系统消息和前端工具的自动转发功能；此时，该传输层就是一个普通的 AI SDK `ChatTransport`，所有内容都需要由你显式控制。

## 运行时选项

除了传输层和适配器之外，`useChatRuntime`还接受用于控制线程路由、消息分组和运行恢复的选项。

### onThreadIdChange

每当运行时更改当前线程的已确定 ID 时调用，例如将当前线程同步到 URL 查询参数。通过受控的 `threadId` 选项提供的更改不会通过此回调再次传回。

```tsx
const runtime = useChatRuntime({
  onThreadIdChange: (threadId) => {
    const url = new URL(window.location.href);
    if (threadId) {
      url.searchParams.set("thread", threadId);
    } else {
      url.searchParams.delete("thread");
    }
    window.history.replaceState(null, "", url);
  },
});
```

这里只会发出已确定的 ID：新创建的线程尚未初始化时，其值为 `undefined`；线程初始化后才会发出真实 ID（对于 [AssistantCloud](/docs/cloud/ai-sdk-assistant-ui)，这是云端线程 ID）。临时本地 ID 永远不会暴露。

### joinStrategy

控制如何渲染连续的助手消息：

```tsx
const runtime = useChatRuntime({
  joinStrategy: "none",
});
```

`"concat-content"`（默认值）会将连续的助手消息合并为一条线程消息。`"none"`则会将每条助手消息保留为独立的线程消息；当后端将主动发送的助手消息或连续的助手消息持久化为独立条目时，这非常有用。有关底层合并语义，请参阅[外部状态存储指南](/docs/runtimes/custom/external-store#useexternalmessageconverter-with-join-strategy)。

### onResume

在调用 `runtime.thread.resumeRun(config)` 时调用。提供此选项可将恢复调用桥接到自定义重放通道，例如使用回合 ID 作为键的 SSE 重连端点：

```tsx
const runtime = useChatRuntime({
  onResume: async (config) => {
    await reconnectToRun(config.runConfig);
  },
});
```

省略此选项时，`resumeRun`会抛出`"Runtime does not support resuming runs."`。对于应在页面重新加载后继续的流式传输，如果不使用自定义通道，请改用内置的传输层路径：参阅[可恢复流](/docs/guides/resumable-streams)，它会在挂载时自动重新连接，并通过 `onResumeError` 报告失败。

### messageRepository

仅在 `useChat` 为空时，一次性导入支持分支的 AI SDK 消息树。完成初始导入后，实时更新仅来自 `useChat`。清空聊天或传入新的对象标识不会重新加载该树。已经通过 `adapters.history` 处理的持久化线程不需要此选项。

```tsx
const runtime = useChatRuntime({
  messageRepository: storedTree,
  unstable_onBranchChange: ({ headId }) => {
    saveSelectedBranch(headId);
  },
});
```

在显式执行 `switchToBranch` 后触发 `unstable_onBranchChange`（例如点击 BranchPicker）。它与 `setMessages` 互为补充，但不会自行启用切换功能。此回调不稳定，可能在不另行通知的情况下发生变化。

## 高级：useAISDKRuntime

当你需要直接访问 `useChat` 实例（例如与非 assistant-ui 代码共享该实例）时，可以改用 `useAISDKRuntime`：

```tsx
import { useChat } from "@ai-sdk/react";
import { useAISDKRuntime } from "@assistant-ui/ai-sdk";

const chat = useChat();
const runtime = useAISDKRuntime(chat);
```

`useAISDKRuntime` 不提供 `cloud` 或更高层级的适配器插槽；这些功能属于 `useChatRuntime`。如果你既需要自己的 `useChat` 访问能力，又需要云端线程支持，通常应使用 `useChatRuntime`，并改用 assistant-ui hooks 读取聊天状态。

`useAISDKRuntime` 接受 `joinStrategy`、`onResume`、`messageRepository` 和 `unstable_onBranchChange`（参见[运行时选项](#runtime-options)），此外还支持一个自身的选项 `cancelPendingToolCallsOnSend`：

```tsx
const runtime = useAISDKRuntime(chat, {
  cancelPendingToolCallsOnSend: false,
});
```

启用该选项时（默认设置），发送新消息会将所有待处理的交互式工具调用标记为失败，并返回一条说明用户已取消这些调用的错误。将其设置为 `false`，即可在用户发送新消息时保留待处理的工具调用，不对其进行处理。

| `@ai-sdk/react` | `@ai-sdk/react@^2` | `@ai-sdk/react@^4` |
| `convertToModelMessages` | 同步 | 异步（`await`） |
| 工具 schema | `parameters: z.object({...})` | `inputSchema: zodSchema(z.object({...}))` |
| 响应 | `toDataStreamResponse()` | `createUIMessageStreamResponse()` |

## 示例

[`examples/with-ai-sdk-v7`](https://github.com/assistant-ui/assistant-ui/tree/main/examples/with-ai-sdk-v7) 展示了一个完整的参考实现。

如果需要让响应在流式传输过程中重新加载页面后仍能继续，请参阅[可恢复流](/docs/guides/resumable-streams)，它封装了相同的 v7 字节流，并使用 `assistant-stream/resumable`。
