Message 原语负责单条消息的渲染：内容部分、附件、引用、悬停状态和错误显示。它是每个消息气泡中的构建模块，通过部分管线解析文本、图像、工具调用等内容。

## 快速开始

使用部分渲染的最小消息：

```tsx
import { MessagePrimitive } from "@assistant-ui/react";

<MessagePrimitive.Root>
  <MessagePrimitive.Parts />
</MessagePrimitive.Root>
```

`Root` 渲染一个 `<div>`，提供消息上下文并跟踪悬停状态。`Parts` 遍历消息的内容部分并逐一渲染。没有自定义组件时，各部分会使用合理的默认渲染方式：`Text` 渲染一个带有 `white-space: pre-line` 和流式传输指示器的 `<p>`，`Image` 通过 `MessagePartPrimitive.Image` 渲染；除非全局或内联注册了工具 UI，否则工具调用不会渲染任何内容。推理、来源、文件和音频部分默认不会渲染。

<Callout type="info">
运行时设置：原语需要运行时上下文。将 UI 包裹在带有运行时的 `AssistantRuntimeProvider` 中（例如 `useLocalRuntime(...)`）。请参阅[选择运行时](/docs/runtimes/pick-a-runtime)。
</Callout>

## 核心概念

### 部分管线

`MessagePrimitive.Parts` 现在优先使用 children 渲染函数。它会直接提供当前经过增强的部分状态，因此你可以内联分支，并准确返回所需的 UI：

```tsx
<MessagePrimitive.Parts>
  {({ part }) => {
    if (part.type === "text") return <MyTextRenderer />;
    if (part.type === "image") return <MyImageRenderer />;
    if (part.type === "tool-call")
      return part.toolUI ?? <GenericToolUI {...part} />;
    return null;
  }}
</MessagePrimitive.Parts>
```

<Callout type="info">
对于大多数新代码，建议使用带有 `children` 渲染函数的 `MessagePrimitive.Parts`。需要相邻分组时，请使用 `MessagePrimitive.GroupedParts`。
</Callout>

### 部分类型

消息部分分为三种类型。新功能属于哪种类型，应根据下面的列表决定，而不是逐个情况判断。

| 类型 | 部分 | 增长方式 |
|------|-------|----------|
| 模态 | `text`、`image`、`file` | 从不增长。`file` 通过其 `mimeType` 承载所有非图像二进制模态。 |
| 提供商通道 | `reasoning`、`source`、`tool-call`、`generative-ui` | 从不增长。这些部分对应模型已经输出的通道。 |
| 可扩展性 | `data` | 可自由增长，通过 `name` 实现。这是所有应用层功能的扩展路径。 |

`file` 是媒体载体。音频、视频、PDF 以及其他所有内容都是 `{ type: "file", mimeType: "audio/mpeg" }`，而不是各自独立的部分类型，因此一个渲染器和一个转换器分支就可以统一处理它们。负载可以是内联 base64 或 URL；`sourceType` 还支持不透明的存储 ID，LangChain 系列运行时会使用该 ID，其他适配器则会忽略它。

任何既不是模型消费的模态，也不是模型输出的通道，都是 `data` 部分，并由 `name` 路由：

```tsx
<MessagePrimitive.Parts
  components={{
    data: {
      by_name: { citation: MyCitation },
      Fallback: MyDataFallback,
    },
  }}
/>
```

<Callout type="warn">
`Unstable_AudioMessagePart` 和 `Unstable_Audio` 插槽已弃用。音频部分无法携带文件名，也无法声明其负载如何通过传输层发送（没有 `sourceType`，因此也没有存储 ID），并且只存在于用户消息中，所以返回音频的模型无法表达它。请改为将音频作为带有 `audio/*` MIME 类型的 `file` 部分发送，并为其提供文件名。

文件路径的适配器支持仍不一致，因此在依赖文件部分之前，请检查适配器的转换器。目前已知：`react-pi` 和 assistant-transport 运行时的用户内容表面完全没有文件部分，因此文件会被丢弃；`react-data-stream` 会携带负载，但不会携带文件名。现有音频部分仍可正常工作；它们不会新增字段。
</Callout>

### 工具解析

工具调用部分按以下顺序解析：

1. **`tools.Override`**：如果通过已弃用的 `components` prop 内联提供，则处理**所有**工具调用
2. **全局注册的工具**：通过 `Tools({ toolkit })` 注册的工具
3. **`tools.by_name[toolName]`**：通过已弃用的 `components` prop 为每个 `MessagePrimitive.Parts` 提供的内联覆盖
4. **`tools.Fallback`**：通过已弃用的 `components` prop 处理未匹配工具调用的兜底项
5. **`part.toolUI`**：在 children 渲染函数中直接公开已解析的工具 UI

在 children API 中，工具部分和数据部分会直接公开已解析的 UI 辅助函数：

```tsx
<MessagePrimitive.Parts>
  {({ part }) => {
    if (part.type === "tool-call")
      return part.toolUI ?? <ToolFallback {...part} />;

    if (part.type === "data")
      return part.dataRendererUI ?? null;

    return null;
  }}
</MessagePrimitive.Parts>
```

返回 `null` 仍会允许已注册的工具 UI 和数据渲染器 UI 自动渲染。如果希望完全抑制它们，请返回 `<></>`。

### Components Prop（已弃用）

`components` 已弃用。本节仅对其进行说明，以便理解旧代码：

- `ToolGroup` 包裹连续的工具调用部分
- `ReasoningGroup` 包裹连续的推理部分
- `components.ChainOfThought` 接管所有推理和工具调用的渲染（与 `ToolGroup`、`ReasoningGroup`、`tools` 和 `Reasoning` 互斥）。此旧版路径已弃用；新代码中请使用 `MessagePrimitive.GroupedParts` 来实现分组的思维链。
- `data.by_name` 和 `data.Fallback` 可用于路由自定义数据部分类型
- `Quote` 根据元数据渲染引用的消息
- `Empty` 可用于边缘渲染路径
- `Unstable_Audio` 已弃用；请改为从 `File` 插槽渲染 `audio/*`

```tsx
<MessagePrimitive.Parts
  components={{
    Text: () => (
      <p className="whitespace-pre-wrap">
        <MessagePartPrimitive.Text />
      </p>
    ),
    Image: () => <MessagePartPrimitive.Image className="max-w-sm rounded-xl" />,
    File: () => <div className="rounded-md border px-2 py-1 text-xs">File part</div>,
    tools: {
      by_name: {
        get_weather: () => <div>Weather tool</div>,
      },
      Fallback: ({ toolName }) => <div>Unknown tool: {toolName}</div>,
    },
    data: {
      by_name: {
        "my-event": ({ data }) => <pre>{JSON.stringify(data, null, 2)}</pre>,
      },
      Fallback: ({ name }) => <div>Unknown data event: {name}</div>,
    },
    ToolGroup: ({ children }) => (
      <div className="space-y-2 rounded-lg border p-2">{children}</div>
    ),
    ReasoningGroup: ({ children }) => (
      <details className="rounded-lg border p-2">
        <summary>Reasoning</summary>
        {children}
      </details>
    ),
    Empty: () => <span className="text-muted-foreground">...</span>,
    Unstable_Audio: () => null,
  }}
/>
```

对于新代码，请改用 `children` 渲染函数或 `GroupedParts`。

### 悬停状态

`MessagePrimitive.Root` 会自动跟踪鼠标进入和离开事件。`ActionBarPrimitive` 会使用此悬停状态实现自动隐藏行为，无需额外连接。

### MessagePartPrimitive

在自定义部分组件中，使用以下子原语访问实际内容：

- **`MessagePartPrimitive.Text`**：渲染文本部分的文本内容
- **`MessagePartPrimitive.Image`**：渲染图像部分的图像
- **`MessagePartPrimitive.InProgress`**：仅在部分仍处于流式传输时渲染

```tsx
function MyText() {
  return (
    <p className="whitespace-pre-wrap">
      <MessagePartPrimitive.Text />
      <MessagePartPrimitive.InProgress>
        <span className="animate-pulse">▊</span>
      </MessagePartPrimitive.InProgress>
    </p>
  );
}
```

## 部分

### Root

单条消息的容器。除非设置了 `asChild`，否则会渲染一个 `<div>` 元素。

```tsx
<MessagePrimitive.Root className="flex flex-col gap-2">
  <MessagePrimitive.Quote>
    {({ text }) => <blockquote className="mb-2 border-l pl-3 italic">{text}</blockquote>}
  </MessagePrimitive.Quote>
  <MessagePrimitive.Parts />
</MessagePrimitive.Root>
```

### Parts

根据类型解析组件并渲染每个内容部分。

```tsx
<MessagePrimitive.Parts>
  {({ part }) => {
    if (part.type === "text") return <MyTextRenderer />;
    if (part.type === "image") return <MyImageRenderer />;
    if (part.type === "tool-call")
      return part.toolUI ?? <GenericToolUI {...part} />;
    return null;
  }}
</MessagePrimitive.Parts>
```

<PrimitivesTypeTable type="MessagePrimitivePartsProps" parameters={MessagePrimitiveDocs.Parts.props} />

### GroupedParts

将相邻的消息部分分组为嵌套树。使用 `groupBy` 将每个部分映射到组键路径，然后在渲染函数中根据 `part.type` 进行切换。分组情况会渲染 `children`；叶节点情况则渲染其自身的 UI。对于常见的 `part.type → path` 情况，建议使用 `groupPartByType` 辅助函数。

```tsx
import { MessagePrimitive, groupPartByType } from "@assistant-ui/react";

<MessagePrimitive.GroupedParts
  groupBy={groupPartByType({
    reasoning: ["group-chainOfThought", "group-reasoning"],
    "tool-call": ["group-chainOfThought", "group-tool"],
  })}
>
  {({ part, children }) => {
    switch (part.type) {
      case "group-chainOfThought":
        return <div>{children}</div>;
      case "group-reasoning":
        return <ReasoningRoot>{children}</ReasoningRoot>;
      case "group-tool":
        return <ToolGroupRoot>{children}</ToolGroupRoot>;
      case "text":
        return <MarkdownText />;
      case "reasoning":
        return <Reasoning {...part} />;
      case "tool-call":
        return part.toolUI ?? <ToolFallback {...part} />;
      case "data":
        return part.dataRendererUI;
      default:
        return null;
    }
  }}
</MessagePrimitive.GroupedParts>
```

### Content

`Parts` 的旧版别名。

```tsx
<MessagePrimitive.Content>
  {({ part }) => {
```

### PartByIndex

渲染指定索引处的单个部分。

```tsx
<MessagePrimitive.PartByIndex
  index={0}
  components={{ Text: MyTextRenderer }}
/>
```

### Attachments

渲染用户消息的所有附件。

```tsx
<MessagePrimitive.Attachments>
  {({ attachment }) => {
    if (attachment.type === "image") {
      const imageSrc = attachment.content?.find((part) => part.type === "image")?.image;
      if (!imageSrc) return null;
      return <img src={imageSrc} alt={attachment.name} className="max-w-xs rounded-lg" />;
    }

    if (attachment.type === "document") {
      return (
        <div className="rounded-lg border p-2 text-sm">
          {attachment.name}
        </div>
      );
    }

    return null;
  }}
</MessagePrimitive.Attachments>
```

### Error

仅当消息存在错误时渲染 children。

```tsx
<MessagePrimitive.Error>
  <ErrorPrimitive.Root className="mt-2 rounded-md border border-destructive/20 bg-destructive/5 p-3">
    <ErrorPrimitive.Message />
  </ErrorPrimitive.Root>
</MessagePrimitive.Error>
```

### Quote

当当前消息包含引用时，渲染引用元数据。将其放置在 `MessagePrimitive.Parts` 上方。

```tsx
<MessagePrimitive.Quote>
  {({ text, messageId }) => (
    <blockquote className="mb-2 border-l pl-3 italic" data-message-id={messageId}>
      {text}
    </blockquote>
  )}
</MessagePrimitive.Quote>
```

### Unstable_PartsGrouped

```tsx

  groupingFunction={myGroupFn}
  components={{ Text: MyText, Group: MyGroupWrapper }}
/>
```

## 模式

### 自定义文本渲染

```tsx
function MarkdownText() {
  return (
    <div className="prose prose-sm">
      <MessagePartPrimitive.Text />
    </div>
  );
}

<MessagePrimitive.Parts>
  {({ part }) => {
    if (part.type === "text") return <MarkdownText />;
    return null;
  }}
</MessagePrimitive.Parts>
```

### 使用 by_name 的工具 UI

```tsx
<MessagePrimitive.Parts
  components={{
    Text: MyText,
    tools: {
      by_name: {
        get_weather: ({ result }) => (
          <div className="rounded-lg border p-3">
            <p className="font-medium">Weather</p>
            <p>{result?.temperature}°F, {result?.condition}</p>
          </div>
        ),
      },
      Fallback: ({ toolName, status }) => (
        <div className="text-muted-foreground text-sm">
          {status.type === "running" ? `Running ${toolName}...` : `${toolName} completed`}
        </div>
      ),
    },
  }}
/>
```

### 错误显示

```tsx
<MessagePrimitive.Root>
  <MessagePrimitive.Parts />
  <MessagePrimitive.Error>
    <div className="mt-2 rounded-md bg-destructive/10 p-2 text-sm text-destructive">
      Something went wrong. Please try again.
    </div>
  </MessagePrimitive.Error>
</MessagePrimitive.Root>
```

### 使用 ErrorPrimitive 的错误显示

如需更精细地控制错误渲染，`ErrorPrimitive` 提供了一个专用组件，可自动从消息状态中读取错误字符串：

```tsx
import { ErrorPrimitive, MessagePrimitive } from "@assistant-ui/react";

<MessagePrimitive.Root>
  <MessagePrimitive.Parts />
  <ErrorPrimitive.Root className="mt-2 rounded-md bg-destructive/10 p-2 text-sm text-destructive" role="alert">
    <ErrorPrimitive.Message />
  </ErrorPrimitive.Root>
</MessagePrimitive.Root>
```

`ErrorPrimitive.Root` 渲染一个带有 `role="alert"` 的 `<div>` 容器，而 `ErrorPrimitive.Message` 渲染一个用于显示错误文本的 `<span>`。`Root` 始终渲染。只有在没有错误时，`Message` 才会有条件地返回 `null`。如果希望整个区块都具有条件性，请将其包裹在 `<MessagePrimitive.Error>` 中。完整详情请参阅 [ErrorPrimitive API 参考](/docs/api-reference/primitives/error)。

### 流式传输完成后渲染

如果只希望在助手消息完成流式传输后渲染内容（例如后续卡片、反馈提示，或不应在部分状态间闪烁的生成式组件），请在 `s.message.status` 上使用 [`AuiIf`](/docs/api-reference/primitives/assistant-if) 对其进行控制：

```tsx
import { MessagePrimitive, AuiIf } from "@assistant-ui/react";

<MessagePrimitive.Root>
  <MessagePrimitive.Parts />

  <AuiIf
    condition={(s) =>
      s.message.role === "assistant" &&
      s.message.status?.type === "complete"
    }
  >
    <FollowUpCard />
  </AuiIf>
</MessagePrimitive.Root>;
```

`s.message.status` 是 `running | requires-action | complete | incomplete` 的判别联合，仅定义于助手消息上。`role === "assistant"` 守卫可确保谓词类型安全。对于由工具调用驱动、并在部分自身内部延迟渲染的生成式 UI，请参阅生成式 UI 指南中的[延迟渲染](/docs/tools/tool-ui#deferred-rendering)。

### 旧版和不稳定 API

- `MessagePrimitive.Unstable_PartsGrouped` 和 `MessagePrimitive.Unstable_PartsGroupedByParentId` 是用于非相邻自定义分组的不稳定 API。
- `Unstable_PartsGroupedByParentId` 已弃用，建议改用 `Unstable_PartsGrouped`。

### 基于角色的样式设置

`MessagePrimitive.Root` 会自动设置 `data-message-id`，但不会设置 `data-role` 属性。在消息组件中按角色设置样式：

```tsx
// In your ThreadPrimitive.Messages children render function:
function UserMessage() {
  return (
    <MessagePrimitive.Root data-role="user" className="flex justify-end">
      <MessagePrimitive.Parts />
    </MessagePrimitive.Root>
  );
}

function AssistantMessage() {
  return (
    <MessagePrimitive.Root data-role="assistant" className="flex justify-start">
      <MessagePrimitive.Parts />
    </MessagePrimitive.Root>
  );
}
```

## 与组件的关系

shadcn 的 [Thread](/elements/thread) 组件使用这些原语构建并渲染用户和助手消息。预构建的 `AssistantMessage` 和 `UserMessage` 组件负责文本渲染、工具 UI、错误显示和操作栏，其底层都使用 `MessagePrimitive`。

消息通常会与 [ActionBar](/docs/primitives/action-bar) 搭配，用于复制、重新加载和编辑操作；也会与 [BranchPicker](/docs/primitives/branch-picker) 搭配，用于在不同的备选响应之间导航。
