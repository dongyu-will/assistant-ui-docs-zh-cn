## 快速开始

最小示例：

```tsx
import { ComposerPrimitive } from "@assistant-ui/react";

<ComposerPrimitive.Root>
  <ComposerPrimitive.Input placeholder="Ask anything..." />
  <ComposerPrimitive.Send>Send</ComposerPrimitive.Send>
</ComposerPrimitive.Root>
```

`Root` 渲染一个 `<form>`，`Input` 渲染一个 `<textarea>`，而 `Send` 渲染一个 `<button>`。每个部分默认渲染其原生元素，并支持使用 `asChild` 替换元素。

<Callout type="info">
运行时设置：原语需要运行时上下文。将 UI 包裹在带有运行时的 `AssistantRuntimeProvider` 中（例如 `useLocalRuntime(...)`）。请参阅[选择运行时](/docs/runtimes/pick-a-runtime)。
</Callout>

## 核心概念

### 新消息与编辑模式

放置在 **Thread** 中的 Composer 用于编写新消息。放置在 **Message** 中的 Composer 用于编辑该消息。相同的原语可以处理这两种情况，并会根据上下文自动改变行为。

```tsx
// New message composer
<ThreadPrimitive.Root>
  <ComposerPrimitive.Root>
    <ComposerPrimitive.Input />
    <ComposerPrimitive.Send>Send</ComposerPrimitive.Send>
  </ComposerPrimitive.Root>
</ThreadPrimitive.Root>

// Edit composer (inside a message)
<MessagePrimitive.Root>
  <ComposerPrimitive.Root>
    <ComposerPrimitive.Input />
    <ComposerPrimitive.Send>Save</ComposerPrimitive.Send>
    <ComposerPrimitive.Cancel>Cancel</ComposerPrimitive.Cancel>
  </ComposerPrimitive.Root>
</MessagePrimitive.Root>
```

### `asChild` 模式

每个原语部分都接受 `asChild`，将其行为合并到你自己的元素上。这就是如何将原语与自己的设计系统结合使用：

```tsx
import { ComposerPrimitive } from "@assistant-ui/react";

<ComposerPrimitive.Input asChild>
  <textarea
    className="my-custom-textarea"
    placeholder="Type here..."
  />
</ComposerPrimitive.Input>

<ComposerPrimitive.Send asChild>
  <MyButton variant="primary">Send</MyButton>
</ComposerPrimitive.Send>
```

原语的行为（键盘处理、禁用状态、表单提交）会合并到你的元素上。样式由你定义，组件由你提供，原语负责连接。

<Callout type="info">
如果你需要完全掌控输入 DOM，例如使用无法通过 `asChild` 或 `render` 表达的 `contentEditable` 表面或编辑器库，请参阅[无头 Composer 输入框](/docs/guides/headless-composer-input)，了解可提供输入框文本和发送门控、且不依赖 `ComposerPrimitive.Input` 的不稳定 hook。
</Callout>

### 不稳定的触发器弹出层

Composer 包含一个用于字符触发弹出层的不稳定 **触发器弹出层**系统（例如，`@` 用于提及，`/` 用于斜杠命令）。多个触发器可以共存于单个 `TriggerPopoverRoot` 下。

```tsx
<ComposerPrimitive.Unstable_TriggerPopoverRoot>
  <ComposerPrimitive.Root>
    <ComposerPrimitive.Input placeholder="Type @ to mention, / for commands..." />

    {/* @ mention — inserts directive text into the message */}
    <ComposerPrimitive.Unstable_TriggerPopover
      char="@"
      adapter={mentionAdapter}
    >
      <ComposerPrimitive.Unstable_TriggerPopover.Directive formatter={formatter} />
      {/* popover UI */}
    </ComposerPrimitive.Unstable_TriggerPopover>

    {/* / slash command — runs a handler on selection; leaves an audit-trail chip by default */}
    <ComposerPrimitive.Unstable_TriggerPopover
      char="/"
      adapter={slashAdapter}
    >
      <ComposerPrimitive.Unstable_TriggerPopover.Action
        formatter={formatter}
        onExecute={(item) => commandHandlers[item.id]?.()}
      />
      <ComposerPrimitive.Unstable_TriggerPopoverItems>
        {(items) => items.map(item => (
          <ComposerPrimitive.Unstable_TriggerPopoverItem key={item.id} item={item}>
            {item.label}
          </ComposerPrimitive.Unstable_TriggerPopoverItem>
        ))}
      </ComposerPrimitive.Unstable_TriggerPopoverItems>
    </ComposerPrimitive.Unstable_TriggerPopover>
  </ComposerPrimitive.Root>
</ComposerPrimitive.Unstable_TriggerPopoverRoot>
```

完整文档请参阅[提及指南](/docs/guides/mentions)和[斜杠命令指南](/docs/guides/slash-commands)。

## 部件

### Root

用于编写消息的表单容器。除非设置了 `asChild`，否则会渲染一个 `<form>` 元素。

```tsx

  <ComposerPrimitive.Input placeholder="Ask anything..." />
  <ComposerPrimitive.Send>Send</ComposerPrimitive.Send>
</ComposerPrimitive.Root>
```

#### 紧凑模式

传入 `compact` 以启用紧凑模式检测。当输入最多只有单行文本，且输入框没有附件、引用、排队消息或正在进行的听写时，root 会渲染 `data-compact` 属性。此 prop 只提供该属性用于样式设置，本身不会改变布局。可以使用 CSS 定位该属性，将输入框折叠为单行：

```tsx
<ComposerPrimitive.Root
  compact
  className="group/composer flex flex-col data-[compact]:flex-row data-[compact]:items-center"
>
  <ComposerPrimitive.Input placeholder="Ask anything..." />
  <ComposerPrimitive.Send>Send</ComposerPrimitive.Send>
</ComposerPrimitive.Root>
```

文本换行到第二行后，输入框会展开，并保持展开状态，直到输入内容被清空，因此布局不会在换行边界来回变化。

### Unstable_TriggerPopover

声明一个触发器（通过 `char`、`adapter`），并渲染弹出层容器。通过在其中恰好渲染一个行为子原语来声明选择行为——可以是 `<Unstable_TriggerPopover.Directive>`（选择时插入指令），也可以是 `<Unstable_TriggerPopover.Action>`（选择时运行 `onExecute`）。只有当该触发器在输入框中处于活动状态时，才会渲染其 DOM（及其子元素）。

```tsx
<ComposerPrimitive.Unstable_TriggerPopover
  char="@"
  adapter={mentionAdapter}
  className="rounded-lg border bg-popover p-1 shadow-md"
>
  <ComposerPrimitive.Unstable_TriggerPopover.Directive formatter={formatter} />
  <ComposerPrimitive.Unstable_TriggerPopoverCategories>
    {(categories) => categories.map((category) => (
      <ComposerPrimitive.Unstable_TriggerPopoverCategoryItem
        key={category.id}
        categoryId={category.id}
      >
        {category.label}
      </ComposerPrimitive.Unstable_TriggerPopoverCategoryItem>
    ))}
  </ComposerPrimitive.Unstable_TriggerPopoverCategories>
</ComposerPrimitive.Unstable_TriggerPopover>
```

行为由以下两个子原语中的一个提供：

- `<Unstable_TriggerPopover.Directive formatter={...} onInserted={...} />` — 将 `:type[label]{name=id}` 写入输入框文本（提及行为）
- `<Unstable_TriggerPopover.Action onExecute={...} removeOnExecute={...} />` — 在选择时运行回调；默认在执行后保留一个指令芯片（斜杠命令行为）

### Unstable_TriggerPopover.Directive

行为子原语。向其父级 `TriggerPopover` 注册指令插入行为。不渲染任何内容。

```tsx
<ComposerPrimitive.Unstable_TriggerPopover.Directive
  formatter={unstable_defaultDirectiveFormatter}
  onInserted={(item) => track("mention", item.id)}
/>
```

### Unstable_TriggerPopover.Action

行为子原语。向其父级 `TriggerPopover` 注册操作行为。默认在执行后保留一个指令芯片（审计轨迹）；传入 `removeOnExecute` 可完全移除触发器文本。不渲染任何内容。

```tsx
<ComposerPrimitive.Unstable_TriggerPopover.Action
  onExecute={(item) => commandHandlers[item.id]?.()}
  removeOnExecute={false}
/>
```

## 使用模式

### 添加附件

```tsx
<ComposerPrimitive.Root>
  <ComposerPrimitive.Attachments>
    {({ attachment }) => {
      if (attachment.type === "image") return <ImagePreview />;
      if (attachment.type === "document") return <DocumentPreview />;
      return <GenericPreview />;
    }}
  </ComposerPrimitive.Attachments>
  <ComposerPrimitive.Input placeholder="Ask anything..." />
  <ComposerPrimitive.AddAttachment>
    Attach
  </ComposerPrimitive.AddAttachment>
  <ComposerPrimitive.Send>Send</ComposerPrimitive.Send>
</ComposerPrimitive.Root>
```

### 添加拖放功能

将输入框包裹在 `AttachmentDropzone` 中，以支持将文件直接拖动到输入区域：

```tsx
<ComposerPrimitive.AttachmentDropzone className="rounded-xl border-2 border-dashed data-[dragging]:border-primary data-[dragging]:bg-primary/5">
  <ComposerPrimitive.Root>
    <ComposerPrimitive.Attachments>
      {() => <MyAttachment />}
    </ComposerPrimitive.Attachments>
    <ComposerPrimitive.Input placeholder="Drop files or type..." />
    <ComposerPrimitive.AddAttachment>Attach</ComposerPrimitive.AddAttachment>
    <ComposerPrimitive.Send>Send</ComposerPrimitive.Send>
  </ComposerPrimitive.Root>
</ComposerPrimitive.AttachmentDropzone>
```

当文件拖动到拖放区域上方时，该区域会设置 `data-dragging`，因此你可以使用 CSS 设置活动状态的样式。它需要运行时的附件能力（附件适配器）；没有该能力时，拖放区域会保持非活动状态。

### 添加语音输入

```tsx
<ComposerPrimitive.Root>
  <ComposerPrimitive.Input placeholder="Ask or speak..." />
  <AuiIf condition={(s) => s.composer.dictation != null}>
    <ComposerPrimitive.DictationTranscript className="text-sm text-muted-foreground" />
  </AuiIf>
  <AuiIf condition={(s) => s.composer.dictation == null}>
    <ComposerPrimitive.Dictate>Mic</ComposerPrimitive.Dictate>
  </AuiIf>
  <AuiIf condition={(s) => s.composer.dictation != null}>
    <ComposerPrimitive.StopDictation>Stop</ComposerPrimitive.StopDictation>
  </AuiIf>
  <ComposerPrimitive.Send>Send</ComposerPrimitive.Send>
</ComposerPrimitive.Root>
```

`DictationTranscript` 会渲染一个 `<span>`，在用户说话时显示临时的语音转文本结果。

<Callout type="info">
语音输入需要在运行时中配置 `DictationAdapter`。设置方法请参阅[听写](/docs/guides/dictation)。
</Callout>

### 自定义提交行为

在 `Root` 上使用 `onSubmit` 来拦截提交：

```tsx
<ComposerPrimitive.Root
  onSubmit={(e) => {
    // Runs before the message is sent
    // e.g., track analytics, transform input
    // Call e.preventDefault() to cancel the send
  }}
>
  <ComposerPrimitive.Input />
  <ComposerPrimitive.Send>Send</ComposerPrimitive.Send>
</ComposerPrimitive.Root>
```

### 根据外部状态控制发送

有时你希望用户在发送暂时被阻止时仍然可以输入，例如工具配置、身份验证或首个模型上下文仍在加载时。通过 `isDisabled` 禁用整个线程虽然可行，但也会禁用文本输入，用户体验不佳。

在运行时适配器上使用 `isSendDisabled`，即可在阻止发送的同时保持输入可用：

```tsx
const runtime = useExternalStoreRuntime({
  isSendDisabled: !toolsLoaded,
  onNew,
  messages,
  // ...
});
```

当 `isSendDisabled` 为 `true` 时：

- `composer.canSend` 变为 `false`
- `<ComposerPrimitive.Send>` 被禁用
- Enter 和 `Cmd/Ctrl+Shift+Enter` 发送快捷键不执行任何操作
- `aui.composer.send()` 会在运行时提前返回，因此直接调用也无法绕过该门控

使用 `<AuiIf>` 从 React 中读取相同的标志，以便在输入框旁渲染提示：

```tsx
<ComposerPrimitive.Root>
  <ComposerPrimitive.Input placeholder="Ask anything..." />
  <AuiIf condition={(s) => !s.composer.canSend}>
    <p className="text-sm text-muted-foreground">Loading tools, hang on...</p>
  </AuiIf>
  <ComposerPrimitive.Send>Send</ComposerPrimitive.Send>
</ComposerPrimitive.Root>
```

`canSend` 反映输入框自身是否允许发送（编辑模式、内容非空且未设置 `isSendDisabled`）。不支持排队时正在运行的任务等跨线程门控，则会由 `<ComposerPrimitive.Send>` 自动叠加处理。

`isSendDisabled` 仅控制线程输入框。保存正在进行的消息编辑不受影响，因为它是针对单条消息的操作，而不是新的发送。

关于 `isDisabled` 和 `isSendDisabled` 的区别，请参阅[外部状态存储适配器参考](/docs/runtimes/custom/external-store)。

### 使用 Ctrl+Enter 提交

```tsx
<ComposerPrimitive.Root>
  <ComposerPrimitive.Input submitMode="ctrlEnter" />
  <ComposerPrimitive.Send>Send</ComposerPrimitive.Send>
</ComposerPrimitive.Root>
```

使用 `submitMode="ctrlEnter"` 后，普通 Enter 会插入换行，而 Ctrl/Cmd+Enter 会提交。

### 移动设备 / 触摸设备

```tsx
<ComposerPrimitive.Root>
  <ComposerPrimitive.Input unstable_insertNewlineOnTouchEnter />
  <ComposerPrimitive.Send>Send</ComposerPrimitive.Send>
</ComposerPrimitive.Root>
```

`unstable_insertNewlineOnTouchEnter` 会在以触摸为主的设备上将 Enter 切换为插入换行（通过 `(pointer: coarse) and (not (any-pointer: fine))` 检测），这样屏幕上的 Return 键就不会意外发送未完成的消息。提交操作会转移到显式的 Send 按钮，与 WhatsApp、Slack、Discord、iMessage、ChatGPT 和 Claude.ai 的行为一致。

桌面端行为不变。如果为配备硬件键盘的平板电脑设置了 `submitMode="ctrlEnter"` 或 `"none"`，它仍会获得 `submitMode` 的通常语义——该标志只会降低默认的 `"enter"` 模式。

### 浮动输入框

原语不受任何布局限制。下面介绍此文档站点中的浮动输入框是如何构建的：使用相同的 `ComposerPrimitive.Root` 和 `ComposerPrimitive.Input`，并通过 CSS 定位：

```tsx
import { ComposerPrimitive } from "@assistant-ui/react";

function FloatingComposer() {
  return (
    <div className="fixed bottom-6 left-1/2 z-40 w-full max-w-md -translate-x-1/2">
      <ComposerPrimitive.Root>
        <div className="rounded-xl border bg-background/80 shadow-lg backdrop-blur-sm">
          <ComposerPrimitive.Input
            asChild
            unstable_focusOnRunStart={false}
            unstable_focusOnScrollToBottom={false}
          >
            <textarea
              placeholder="Ask a question..."
              className="w-full resize-none bg-transparent px-3 py-2.5 text-sm focus:outline-none"
              rows={1}
            />
          </ComposerPrimitive.Input>
        </div>
      </ComposerPrimitive.Root>
    </div>
  );
}
```

原语负责处理消息编写的所有功能。布局、动画和可见性逻辑则完全由你控制。

## 与组件的关系

[Thread](/elements/thread) 组件包含一个由这些原语构建的完整输入框。如果你需要快速构建可用的聊天 UI，可以从那里开始。当你需要一个不适合放在会话线程中的输入框，例如浮动输入框、侧边栏输入框或多步骤表单时，可以直接使用 `ComposerPrimitive`。
