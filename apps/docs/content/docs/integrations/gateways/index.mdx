LLM 网关位于路由处理程序与上游提供商之间。它们提供一个面向多个提供商的统一端点，并支持多提供商故障转移、提示缓存以及 BYOK（自带密钥）流程等功能。大多数网关兼容 OpenAI API，因此集成只需在 `createOpenAI` 中对来自 `@ai-sdk/openai` 的 `baseURL` 进行替换。

如果你只需要可观测性（记录每次调用的代理），请参阅 [Helicone](/docs/integrations/observability/helicone)。本页介绍的网关在理念上有所重叠，但侧重点是路由而不是日志记录。对于本地个人项目，同样存在一种无需密钥、采用 `baseURL`-替换形式的选项：通过本地 OAuth 代理，并将费用计入你的 ChatGPT 订阅；请参阅 [ChatGPT 订阅](/docs/guides/chatgpt-subscription)。

## 对比

| 网关 | 基础 URL | 认证标头 | 主要特性 |
| --- | --- | --- | --- |
| [OpenRouter](#openrouter) | `https://openrouter.ai/api/v1` | `Authorization: Bearer <key>` | 提供 100 多个模型的目录，并使用 `vendor/model` ID |
| [Portkey](#portkey) | `https://api.portkey.ai/v1` | `x-portkey-api-key` | 由配置驱动的多提供商故障转移 |
| [LiteLLM Proxy](#litellm-proxy) | 自托管 | `Authorization: Bearer <virtual key>` | 开源、支持自托管、为每个租户提供虚拟密钥 |

如果你只需要记录请求，Helicone 也符合相同的结构，并在其他文档中单独介绍。

## 通用模式

下面的三个网关都使用 OpenAI API。使用 `createOpenAI` 将它们接入：

```ts title="app/api/chat/route.ts"
import { createOpenAI } from "@ai-sdk/openai";
import { streamText, convertToModelMessages } from "ai";
import type { UIMessage } from "ai";

const openai = createOpenAI({
  baseURL: "<gateway base url>",
  headers: { /* gateway-specific auth */ },
});

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();
  const result = streamText({
    model: openai("<model id>"),
    messages: await convertToModelMessages(messages),
  });
  return result.toUIMessageStreamResponse();
}
```

本页其余内容介绍了针对每个网关，需要在 `baseURL`、`headers` 和 `model(...)` 中填写的内容。

## OpenRouter

[OpenRouter](https://openrouter.ai/) 通过一个兼容 OpenAI 的端点聚合 100 多个模型。模型 ID 为 `provider/model`（例如 `anthropic/claude-sonnet-4.6`、`openai/gpt-5.6-luna`、`meta-llama/llama-3.3-70b-instruct`）。

```sh title=".env.local"
OPENROUTER_API_KEY=sk-or-...
SITE_URL=https://your-app.example
```

```ts title="app/api/chat/route.ts"
import { createOpenAI } from "@ai-sdk/openai";
import { streamText, convertToModelMessages } from "ai";
import type { UIMessage } from "ai";

const openrouter = createOpenAI({
  baseURL: "https://openrouter.ai/api/v1",
  apiKey: process.env.OPENROUTER_API_KEY,
  headers: {
    "HTTP-Referer": process.env.SITE_URL ?? "http://localhost:3000",
    "X-Title": "My App",
  },
});

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();
  const result = streamText({
    model: openrouter("anthropic/claude-sonnet-4.6"),
    messages: await convertToModelMessages(messages),
  });
  return result.toUIMessageStreamResponse();
}
```

`HTTP-Referer` 和 `X-Title` 是可选的归属标头；OpenRouter 会在使用情况仪表板中显示它们。

适用场景：你希望多个模型共用一张账单，允许用户从较长的列表中选择模型，或者需要运行开放权重模型而不自行管理推理服务。

## Portkey

[Portkey](https://portkey.ai/) 是一个结合可观测性功能的网关，并提供由配置驱动的路由器。其差异化特性在于 *config*：这是一个由服务器定义的对象，用于描述路由规则（先尝试 Anthropic，失败后回退到 OpenAI，再回退到本地模型）、重试和缓存策略。

```sh title=".env.local"
PORTKEY_API_KEY=...
PORTKEY_VIRTUAL_KEY=...
```

```ts title="app/api/chat/route.ts"
import { createOpenAI } from "@ai-sdk/openai";

const portkey = createOpenAI({
  baseURL: "https://api.portkey.ai/v1",
  apiKey: "no-auth-here",
  headers: {
    "x-portkey-api-key": process.env.PORTKEY_API_KEY!,
    "x-portkey-virtual-key": process.env.PORTKEY_VIRTUAL_KEY!,
  },
});
```

配置存储在 Portkey 控制面板中；如果需要使用特定的路由策略，可在标头中通过 `x-portkey-config: <config-id>` 引用配置。

适用场景：你需要跨提供商故障转移，或需要 AI SDK 默认不提供的提示缓存命中率。

## LiteLLM Proxy

[LiteLLM Proxy](https://docs.litellm.ai/docs/simple_proxy) 是开源且支持自托管。你负责运行它，在服务器端配置提供商密钥，并向客户端发放虚拟密钥（按租户或用户区分）。对于 BYOK SaaS 或隔离网络部署，这是唯一可行的路径。

先运行代理（可以使用 Docker、k8s 或单个 Node 进程）。然后让 AI SDK 指向你的实例：

```sh title=".env.local"
LITELLM_BASE_URL=https://litellm.example.com
LITELLM_VIRTUAL_KEY=sk-...
```

```ts title="app/api/chat/route.ts"
import { createOpenAI } from "@ai-sdk/openai";

const litellm = createOpenAI({
  baseURL: process.env.LITELLM_BASE_URL!,
  apiKey: process.env.LITELLM_VIRTUAL_KEY!,
});

const result = streamText({
  model: litellm("gpt-5.6-luna"),
  messages: await convertToModelMessages(messages),
});
```

模型 ID 取决于你对代理的配置方式。LiteLLM 会根据配置，将这些 ID 重写为上游提供商对应的 ID。

适用场景：必须自托管、需要为终端用户统计 BYOK 用量，或需要由平台团队统一管理多个提供商的账单。

## 注意事项

- **仅限服务器端。** 网关密钥具备操作你账单账户的写入权限。切勿将其设置在客户端代码中；路由处理程序才是正确的边界。
- **流式传输、工具、附件。** 三个网关对 AI SDK 都是透明的；直接使用 OpenAI 时支持的所有功能，通过这些网关同样支持。
- **与可观测性结合使用。** 网关和可观测性工具并不互斥。在 OpenRouter 前接入 Helicone 是一种常见的技术栈：OpenRouter 负责路由，Helicone 负责记录调用。
