将 Mastra 作为独立服务运行，让 assistant-ui 前端通过 HTTP 访问它。两部分可以独立部署、扩展和管理版本。这样做的代价是多了一次网络跳转，并且需要配置 CORS（跨域资源共享）。

如果需要更简单的进程内变体，请参阅[全栈集成](/docs/integrations/frameworks/mastra/full-stack)。

## 设置

设置分为两部分。第 1 步到第 4 步在 **Mastra 服务器**项目中完成；第 5 步到第 7 步在**单独的 assistant-ui 前端**项目中完成。最后你将打开两个终端：每个开发服务器各使用一个终端。

<Steps>

<Step>

### 创建 Mastra 服务器项目

在与前端不同的目录中，创建一个 Mastra 项目：

```sh
npx create-mastra@latest
```

按照向导提示操作。完成后，进入新目录并添加 AI SDK 适配器：

```sh
cd your-mastra-server
```

<InstallCommand npm={["@mastra/ai-sdk@latest"]} />

在 `.env.development` 中设置模型提供商密钥（`OPENAI_API_KEY` 等）。`create-mastra` 向导会提示你设置部分密钥，但请确认你计划调用的所有提供商都已配置。

</Step>

<Step>

### 定义助手

```ts title="src/mastra/agents/chefAgent.ts"
import { Agent } from "@mastra/core/agent";

export const chefAgent = new Agent({
  name: "chef-agent",
  instructions:
    "You are Michel, a practical and experienced home chef. " +
    "You help people cook with whatever ingredients they have available.",
  model: "openai/gpt-5.6-luna",
});
```

</Step>

<Step>

### 注册助手、聊天路由和 CORS

打开 Mastra 入口文件。在同一个 `Mastra` 构造函数中设置三项内容：助手、聊天路由，以及针对前端来源的 CORS。

```ts title="src/mastra/index.ts"
import { Mastra } from "@mastra/core";
import { chefAgent } from "./agents/chefAgent";
import { chatRoute } from "@mastra/ai-sdk";

export const mastra = new Mastra({
  agents: { chefAgent },
  server: {
    cors: {
      origin: process.env.FRONTEND_ORIGIN ?? "http://localhost:3000",
      credentials: true,
    },
    apiRoutes: [
      chatRoute({ path: "/chat/:agentId" }),
    ],
  },
});
```

请注意以下几点：

- `:agentId` 匹配的是 `agents` 对象中的 **JavaScript 键**，而不是助手的 `name` 字段。因此，`chefAgent` 可通过 `/chat/chefAgent`（camelCase）访问，而不是 `/chat/chef-agent`。
- 将更多助手添加到 `agents` 对象后，它们都可以通过这一条路由调用。
- 在生产环境中，`FRONTEND_ORIGIN` 应设置为已部署前端的 URL。如果未配置 CORS，浏览器会阻止请求，聊天也会静默失败。

</Step>

<Step>

### 运行 Mastra 服务器

```bash npm2yarn
npm run dev
```

服务器默认在 `http://localhost:4111` 启动。在其余步骤中保持服务器运行。

</Step>

<Step>

### 初始化 assistant-ui 前端

在与 Mastra 服务器**不同的目录**中，创建前端：

```sh title="New project"
npx assistant-ui@latest create
```

```sh title="Existing project"
npx assistant-ui@latest init
```

这会创建一个默认聊天页面，以及位于 `app/api/chat/route.ts` 的本地 API 路由。由于助手运行在独立的 Mastra 服务器上，因此不会使用该本地路由；完成下一步配置后将其删除。

</Step>

<Step>

### 将运行时指向 Mastra 服务器

打开包含 `useChatRuntime` 的文件（通常是 `app/assistant.tsx`），并传入明确的 `api` URL：

```tsx title="app/assistant.tsx" {8}
"use client";

import { AssistantRuntimeProvider } from "@assistant-ui/react";
import { AssistantChatTransport, useChatRuntime } from "@assistant-ui/ai-sdk";
import { Thread } from "@/components/assistant-ui/elements/thread.aui";

export const Assistant = () => {
  const runtime = useChatRuntime({
    transport: new AssistantChatTransport({
      api: process.env.NEXT_PUBLIC_MASTRA_URL!,
    }),
  });

  return (
    <AssistantRuntimeProvider runtime={runtime}>
      <Thread />
    </AssistantRuntimeProvider>
  );
};
```

在前端的环境变量中设置该 URL：

```sh title=".env.local"
NEXT_PUBLIC_MASTRA_URL=http://localhost:4111/chat/chefAgent
```

`NEXT_PUBLIC_*` 会使该 URL 可在浏览器中访问。在生产环境中，将其指向已部署的 Mastra 服务器。Mastra 自身使用 `.env.development` 保存服务器密钥；两个项目使用彼此独立的环境文件。

</Step>

<Step>

### 运行并验证

确保 Mastra 服务器（第 4 步）仍在自己的终端中运行，然后在新终端中启动前端：

```bash npm2yarn
npm run dev
```

打开 `http://localhost:3000`，发送一条消息，并确认：

- 响应逐个 token 以流式方式输出。
- 网络面板显示 `POST` 正在发送到 `http://localhost:4111/chat/chefAgent`，而不是本地的 `/api/chat`。
- 控制台中没有 CORS 错误；如果看到 `blocked by CORS policy`，请重新检查第 3 步。

</Step>

</Steps>

## 说明

- **前端与 Mastra 之间的身份验证**：上面的示例是开放的。在生产环境中，应通过请求头或 Cookie 检查保护 Mastra 路由，并从前端转发凭据（`AssistantChatTransport` 接受 `headers` 和 `credentials` 选项）。
- **单个助手与路由器**：`chatRoute({ path: "/chat/:agentId" })` 适用于在 `Mastra` 实例上注册的任何助手。要从前端切换助手，只需将 `NEXT_PUBLIC_MASTRA_URL` 指向其他助手 ID。
- **Mastra 高级功能**（记忆、工具、工作流、评估）都定义在助手中。前端只能看到最终的流式结果。请参阅 [Mastra 文档](https://mastra.ai/docs).
