---
title: 弃用政策
description: assistant-ui 功能的稳定性保证和弃用时间表。
---

assistant-ui 致力于提供稳定的 API，让你可以将时间投入到构建出色的应用上。

我们很少需要弃用已经发布的功能，因为这通常意味着该功能存在性能、可用性或安全问题。
在这种情况下，我们会尽快通过将该功能标记为 `@deprecated` 并在文档中发布通知，传达移除该功能的意图。

弃用和破坏性变更主要会影响新发布的功能。某个 API 在库中存在的时间越长，被弃用的可能性就越低。
对于已经在库中存在较长时间的功能，我们会提供更长的弃用通知期（如下所述）。

下面列出了被视为稳定和实验性的功能。

## 实验性功能

这些功能可能会在不另行通知的情况下随时被移除。

- 任何标记为 `unstable_`、`experimental_` 或 `internal` 的内容
- `RuntimeCore` API（被视为内部 API）

## Beta 功能

弃用这些功能时，将经过较短的弃用通知期（&lt;1 个月）。

- TailwindCSS 插件（例如 `tw-shimmer`、`tw-glass`）
- Context API
- Runtime API
- 消息类型
- 样式化 UI 组件
- 原语 Hooks（例如 useBranchPickerNext）
- 附件 API
- shadcn/ui 样式

## 稳定功能

弃用这些功能时，将经过较长的弃用通知期（&gt;3 个月）。

以下功能被视为稳定：

- 原语（`AttachmentPrimitive` 除外）
