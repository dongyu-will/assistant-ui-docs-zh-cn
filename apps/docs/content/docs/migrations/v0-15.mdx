---
title: 迁移到 v0.15
description: 移除 v0.12 时代的旧版运行时钩子、已弃用的工具映射以及 "mcp-app" 组键。作用域访问器改为属性。
---

v0.15 完成了 v0.12 开始的弃用周期：旧版上下文钩子已移除，改用 `useAui` / `useAuiState`，并且 `aui` 作用域访问器改为属性。

## 使用 AI Agent 迁移

将以下内容粘贴到 AI 编码代理中，即可为你执行迁移：

```text
Migrate this codebase from assistant-ui v0.14 to v0.15.

1. Read the migration guide: https://assistant-ui.com/docs/migrations/v0-15
2. Run `npx assistant-ui@latest upgrade` to apply the codemods.
3. Apply the remaining changes from the guide by hand:
   - Replace removed legacy hooks with the useAui / useAuiState
     equivalents from the guide's mapping table.
   - Replace availability checks with `aui.<scope>.source != null`.
   - Replace `s.tools.tools` reads with `s.tools.toolUIs`.
   - Replace the "mcp-app" groupPartByType key with "standalone-tool-call".
4. Typecheck, build, and run tests; fix any remaining fallout.
```

## 自动迁移

```bash
npx assistant-ui@latest upgrade
```

此操作会运行 `v0-15/aui-accessor-calls-to-properties` codemod，将无参数访问器调用（`aui.thread()`）重写为属性访问（`aui.thread`）。

## 作用域访问器现在是属性

无参数作用域访问器现在是属性。调用它们仍然有效，但已弃用：

```ts
// Before
aui.thread().getState();
aui.threads().switchToNewThread();

// After
aui.thread.getState();
aui.threads.switchToNewThread();
```

选择不可用的作用域不再抛出异常：`aui.thread` 始终会成功，并且始终为真值。作用域不可用时，其 `source` 为 `null`，读取任何其他属性（或进行调用）都会抛出异常。请通过以下方式检查可用性：

```ts
if (aui.thread.source != null) {
  // scope is available
}
```

访问器会将 `source`、`query` 和 `name` 选择元数据作为属性暴露出来——这些元数据此前位于访问器函数上，现在位于代理对象中名称相同的属性上。这三个名称是保留名称，永远不会解析为作用域方法。

## 移除旧版上下文钩子

v0.12 时代的运行时钩子已移除。请使用 `useAuiState` 替代状态读取，使用 `useAui` 替代操作：

| 已移除                                                       | 替代方案                                     |
| ------------------------------------------------------------- | ----------------------------------------------- |
| `useAssistantRuntime()`                                        | `useAui()`                                      |
| `useThreadList(selector)`                                      | `useAuiState((s) => s.threads)`                 |
| `useThreadRuntime()`                                           | `useAui().thread`                               |
| `useThread(selector)`                                          | `useAuiState((s) => s.thread)`                  |
| `useThreadComposer(selector)`                                  | `useAuiState((s) => s.thread.composer)`         |
| `useThreadModelContext(selector)`                              | `useAuiState((s) => s.thread.modelContext)`     |
| `useMessageRuntime()`                                          | `useAui().message`                              |
| `useMessage(selector)`                                         | `useAuiState((s) => s.message)`                 |
| `useEditComposer(selector)`                                    | `useAuiState((s) => s.message.composer)`        |
| `useComposerRuntime()`                                         | `useAui().composer`                             |
| `useComposer(selector)`                                        | `useAuiState((s) => s.composer)`                |
| `useMessagePartRuntime()`                                      | `useAui().part`                                 |
| `useMessagePart(selector)`                                     | `useAuiState((s) => s.part)`                    |
| `useAttachmentRuntime()`                                       | `useAui().attachment`                           |
| `useAttachment(selector)`                                      | `useAuiState((s) => s.attachment)`              |
| `useThreadListItemRuntime()`                                   | `useAui().threadListItem`                       |
| `useThreadListItem(selector)`                                  | `useAuiState((s) => s.threadListItem)`          |

附件变体（`useThreadComposerAttachment(Runtime)`、`useEditComposerAttachment(Runtime)`、`useMessageAttachment(Runtime)`）也会随之移除；请使用 `useAui().attachment` / `useAuiState((s) => s.attachment)`。

```tsx
// Before
const runtime = useAssistantRuntime();
const isRunning = useThread((s) => s.isRunning);
runtime.threads.switchToNewThread();

// After
const aui = useAui();
const isRunning = useAuiState((s) => s.thread.isRunning);
aui.threads.switchToNewThread();
```

## `ToolsState.tools` 已移除

仅限组件的工具 UI 映射已由 `toolUIs` 替代，其条目会将渲染器与展示选项一同携带：

```tsx
// Before
const Render = useAuiState((s) => s.tools.tools[toolName]?.[0]);

// After
const Render = useAuiState((s) => s.tools.toolUIs[toolName]?.[0]?.render);
```

## `"mcp-app"` 组键已移除

`groupPartByType` 不再接受 `"mcp-app"` 键。请使用 `"standalone-tool-call"`，它是一个超集，既匹配 MCP-app 工具调用，也匹配注册 UI 选择独立显示的任何工具调用：

```tsx
// Before
groupPartByType({
  "tool-call": ["group-tool"],
  "mcp-app": [],
});

// After
groupPartByType({
  "tool-call": ["group-tool"],
  "standalone-tool-call": [],
});
```

## `useAui` `{ parent }` 配置已移除

第二个参数（`useAui(clients, { parent })`）已移除。请改为通过上下文提供父级：使用 `AuiProvider` 包裹，并在其下调用上下文形式。

```tsx
// Before
const aui = useAui(scopes, { parent });

// After
const Scoped = ({ children }) => {
  const aui = useAui();
  const config = AuiConfig(scopes);
  return (
    <AuiProvider extends={aui} config={config}>
      {children}
    </AuiProvider>
  );
};

const rootConfig = AuiConfig({});

<AuiProvider extends={parent} config={rootConfig}>
  <Scoped />
</AuiProvider>;
```

如果之前使用 `{ parent: null }` 脱离上下文，请改用 `<AuiProvider extends={null} config={config}>`；其中 `const config = AuiConfig({})` 现在会提供一个隔离的空根。

## `AuiProvider` 语法

`AuiProvider` 接受使用 `AuiConfig(...)` 构建的 `config` ——直接使用对象字面量会产生类型错误。在顶层，仅使用 `config` 即可创建子树的客户端。在父级 provider 下嵌套时，必须使用 `extends`：`extends={aui}` 会扩展父级，`extends={null}` 会进行隔离（由开发环境强制执行）。挂载后，`ref` 会接收生成的客户端。

```tsx
const aui = useAui();
const config = AuiConfig({ tools: Tools({ toolkit }) });

// Top-level root
<AuiProvider config={config}>

// Nested: extend the parent
<AuiProvider extends={aui} config={config}>

// Nested: isolate from the parent
<AuiProvider extends={null} config={config}>
```

`AuiConfig` 从 `@assistant-ui/store` 导出，并从 `@assistant-ui/react`、`@assistant-ui/react-native` 和 `@assistant-ui/react-ink` 重新导出。

### `value` prop 已弃用

```tsx
// Before
<AuiProvider value={client}>
<AuiProvider value={null}>

// After
const config = AuiConfig({});

<AuiProvider extends={client} config={config}>
<AuiProvider extends={null} config={config}>
```

替代方案会暴露一个扩展给定客户端的客户端，而不是同一个实例——其下的 `useAui()` 会返回新客户端，并将作用域访问委托给 `client`。已弃用的 `value={client}` 形式行为相同：它同样会暴露派生客户端，而不是完全相同的实例，并且给定客户端必须实现 `subscribe`。

### `useAui({ ... })` 扩展重载已弃用

```tsx
// Before
const aui = useAui({ tools: Tools({ toolkit }) });
return <AuiProvider value={aui}>{children}</AuiProvider>;

// After
const aui = useAui();
const config = AuiConfig({ tools: Tools({ toolkit }) });
return (
  <AuiProvider extends={aui} config={config}>
    {children}
  </AuiProvider>
);
```

如果之前将扩展后的客户端传递给 `<AssistantRuntimeProvider aui={aui}>`，请改用新的 `config` prop——这些作用域会与运行时的线程作用域一同提供：

```tsx
// Before
const aui = useAui({ tools: Tools({ toolkit }) });
return (
  <AssistantRuntimeProvider aui={aui} runtime={runtime}>
    {children}
  </AssistantRuntimeProvider>
);

// After
const config = AuiConfig({ tools: Tools({ toolkit }) });
return (
  <AssistantRuntimeProvider runtime={runtime} config={config}>
    {children}
  </AssistantRuntimeProvider>
);
```

## 线程切换事件：`threads.selectionChanged`

逐项线程切换事件已弃用，改用线程列表上的单个事件。`threads.selectionChanged` 每次切换触发一次，并携带转换前后的两端：

```ts
// Before
useAuiEvent("threadListItem.switchedTo", ({ threadId }) => {
  // threadId: the newly selected thread
});
useAuiEvent("threadListItem.switchedAway", ({ threadId }) => {
  // threadId: the thread that was switched away from
});

// After
useAuiEvent("threads.selectionChanged", ({ threadId, previousThreadId }) => {
  // threadId: the newly selected thread
  // previousThreadId: the thread that was switched away from
});
```

与之前的事件一样，它不会在挂载时为初始选中的线程触发。已弃用的事件仍会触发，并将持续有效到下一个 major 版本。

已弃用的事件对会按作用域过滤：在逐项的 `threadListItem` 作用域内（例如 `ThreadListPrimitive.Items`），`threadListItem.switchedTo` 只会针对该项触发。`threads.selectionChanged` 会根据共享的 `threads` 作用域进行解析，因此每个监听器都会在每次切换时触发。按 id 进行过滤，即可复现逐项行为：

```ts
const id = useAuiState((s) => s.threadListItem.id);
useAuiEvent("threads.selectionChanged", ({ threadId }) => {
  if (threadId !== id) return;
  // this item became selected
});
```

新事件还会在已弃用事件对不会触发的情况下触发：`InMemoryThreadList` 会在选择发生变化时触发（此前不会发出切换事件），`switchToNewThread()` 会为新创建的线程触发。由选择驱动的默认值（例如 `scrollToBottomOnThreadSwitch` 和 `unstable_focusOnThreadSwitched`）现在会在这两种情况下生效。挂载后解析深层链接 `threadId`/`initialThreadId` 的运行时（例如 `useRemoteThreadListRuntime`）会从占位的新线程开始，因此深层链接的解析也会触发该事件——在这种情况下，`previousThreadId` 就是占位线程。

## 仍处于弃用状态（未移除）

- 原语 `If` 组件（`ThreadPrimitive.If`、`MessagePrimitive.If`、`ThreadPrimitive.Empty`）——由 `AuiIf` 替代。codemod 会迁移这些组件。
- `useMessagePartText` / `useMessagePartReasoning` / `useMessagePartSource` / `useMessagePartImage` / `useMessagePartFile` / `useMessagePartData`——使用 `useAuiState` 选择并缩小 `s.part`。
- 原语上的 `components` prop——由 children 渲染函数模式替代（请参阅 [v0.14 指南](/docs/migrations/v0-14)）。
