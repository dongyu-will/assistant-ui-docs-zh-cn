---
title: 迁移到 v0.14
description: 移除自 v0.11/v0.12 起已弃用的 API，并将原语从 components 属性迁移到 children 渲染函数。
---

v0.14 完成了 v0.11 和 v0.12 开始的弃用周期，并将原语上的 `components` 属性替换为 children 渲染函数模式。如果你的应用使用 v0.13 且没有弃用警告，则唯一需要进行的更改就是迁移 children API。

## 自动迁移

CLI 附带的 codemod 会处理 v0.12 的 hook 重命名（`useAssistantApi` → `useAui` 等），这些 API 也会在 v0.14 中移除：

```bash
npx assistant-ui@latest upgrade
```

下面列出的其他移除项只是简单的重命名，可以使用查找和替换完成。

## 移除 Hook 别名

这些轻量别名仅用于向后兼容：

| 移除项                              | 替代项                  |
| ------------------------------------ | ---------------------------- |
| `useAssistantApi`                    | `useAui`                     |
| `useAssistantState`                  | `useAuiState`                |
| `useAssistantEvent`                  | `useAuiEvent`                |
| `AssistantIf`                        | `AuiIf`                      |
| `useLocalThreadRuntime`              | `useLocalRuntime`            |
| `unstable_useRemoteThreadListRuntime`| `useRemoteThreadListRuntime` |
| `unstable_useCloudThreadListAdapter` | `useCloudThreadListAdapter`  |
| `unstable_RemoteThreadListAdapter`   | `RemoteThreadListAdapter`    |
| `unstable_InMemoryThreadListAdapter` | `InMemoryThreadListAdapter`  |

## 运行时 API 清理

### `AssistantRuntime`

| 移除项                                  | 替代项                               |
| ---------------------------------------- | ----------------------------------------- |
| `runtime.threadList`                     | `runtime.threads`                         |
| `runtime.switchToNewThread()`            | `runtime.threads.switchToNewThread()`     |
| `runtime.switchToThread(id)`             | `runtime.threads.switchToThread(id)`      |
| `runtime.registerModelConfigProvider(p)` | `runtime.registerModelContextProvider(p)` |
| `runtime.reset({ initialMessages })`     | `runtime.thread.reset(initialMessages)`   |

### `ThreadRuntime`

| 移除项                                    | 替代项                         |
| ------------------------------------------ | ----------------------------------- |
| `thread.startRun(parentId)`（位置参数）   | `thread.startRun({ parentId })`     |
| `thread.unstable_resumeRun(config)`        | `thread.resumeRun(config)`          |
| `thread.unstable_loadExternalState(state)` | `thread.importExternalState(state)` |
| `thread.getModelConfig()`                  | `thread.getModelContext()`          |

### `MessageState` / `MessageRuntime`

重复的顶层 `submittedFeedback` 字段已被移除。它始终是从 `message.metadata.submittedFeedback` 镜像得到的，而后者仍然是事实来源：

```tsx
// Before
useAuiState((s) => s.message.submittedFeedback);

// After
useAuiState((s) => s.message.metadata.submittedFeedback);
```

### `ChatModelRunOptions`

如果你编写了自定义的 `ChatModelAdapter`，则旧别名 `options.config`（它镜像了 `options.context`）已被移除：

```ts
// Before
const adapter: ChatModelAdapter = {
  async run({ messages, config }) {
    /* config.tools, config.config, ... */
  },
};

// After
const adapter: ChatModelAdapter = {
  async run({ messages, context }) {
    /* context.tools, context.config, ... */
  },
};
```

## 外部状态存储辅助函数

`getExternalStoreMessage`（单数形式）已被移除。请使用 `getExternalStoreMessages`（复数形式），它始终返回数组，即使只绑定了一条源消息：

```ts
// Before
const original = getExternalStoreMessage<MyMessage>(threadMessage);

// After
const [original] = getExternalStoreMessages<MyMessage>(threadMessage);
```

## 助手传输层辅助函数

`toAISDKTools` 和 `getEnabledTools`（从 `@assistant-ui/react` 重新导出）已被移除。两者封装的功能现在由 `assistant-stream` 直接提供：

```ts
// Before
import { toAISDKTools } from "@assistant-ui/react";
const schemas = toAISDKTools(tools);

// After
import { toToolsJSONSchema } from "assistant-stream";
const schemas = toToolsJSONSchema(tools);
```

`toToolsJSONSchema` 默认会过滤掉 `disabled` 和 `backend` 工具。若要完全复现旧版 `toAISDKTools` 的行为（无论工具类型都包含），请传入 `{ filter: () => true }`。

## react-langgraph

`useLangGraphRuntime` 的 `onSwitchToThread` 选项已被移除。请使用 `load`，其签名相同，并额外支持可选的 `AbortSignal`：

```ts
// Before
useLangGraphRuntime({
  stream,
  onSwitchToThread: async (threadId) => {
    return await fetchThread(threadId);
  },
});

// After
useLangGraphRuntime({
  stream,
  load: async (threadId, { signal } = {}) => {
    return await fetchThread(threadId, { signal });
  },
});
```

## 原语的 Children API

v0.14 将原语上的 `components` 属性替换为 children 渲染函数模式。这样你可以通过简单的内联逻辑，完全控制渲染过程。

### ThreadPrimitive.Messages

**之前：**

```tsx
<ThreadPrimitive.Messages
  components={{
    UserMessage,
    EditComposer,
    AssistantMessage,
  }}
/>
```

**之后：**

```tsx
<ThreadPrimitive.Messages>
  {({ message }) => {
    if (message.composer.isEditing) return <EditComposer />;
    if (message.role === "user") return <UserMessage />;
    return <AssistantMessage />;
  }}
</ThreadPrimitive.Messages>
```

### MessagePrimitive.Parts

**之前：**

```tsx
<MessagePrimitive.Parts
  components={{
    Text: MarkdownText,
    Reasoning,
    tools: { Fallback: ToolFallback },
  }}
/>
```

**之后：**

```tsx
<MessagePrimitive.Parts>
  {({ part }) => {
    if (part.type === "text") return <MarkdownText />;
    if (part.type === "reasoning") return <Reasoning {...part} />;
    if (part.type === "tool-call")
      return part.toolUI ?? <ToolFallback {...part} />;
    return null;
  }}
</MessagePrimitive.Parts>
```

### `part.toolUI` 和 `part.dataRendererUI`

工具调用部分现在会公开一个 `toolUI` 属性，该属性会解析为已注册的工具 UI（通过 `useAssistantToolUI` / `makeAssistantToolUI`），如果没有注册则解析为 `null`。数据部分同样会公开 `dataRendererUI`。

```tsx
// Renders the registered tool UI if available, otherwise ToolFallback
if (part.type === "tool-call")
  return part.toolUI ?? <ToolFallback {...part} />;

// Renders the registered data renderer if available
if (part.type === "data")
  return part.dataRendererUI ?? null;
```

### 返回 `null`

从 children 函数返回 `null` 时，注册表会自动渲染已注册的工具 UI 和数据渲染器 UI。若要显式地不渲染任何内容（抑制已注册的 UI），请返回 `<></>`。

```tsx
<MessagePrimitive.Parts>
  {({ part }) => {
    if (part.type === "text") return <MarkdownText />;
    return null; // registered tool/data UIs still render
  }}
</MessagePrimitive.Parts>
```

### ThreadPrimitive.Suggestions

**之前：**

```tsx
<ThreadPrimitive.Suggestions
  components={{ Suggestion: SuggestionItem }}
/>
```

**之后：**

```tsx
<ThreadPrimitive.Suggestions>
  {() => <SuggestionItem />}
</ThreadPrimitive.Suggestions>
```

### ThreadListPrimitive.Items

**之前：**

```tsx
<ThreadListPrimitive.Items
  components={{ ThreadListItem: MyThreadListItem }}
/>
```

**之后：**

```tsx
<ThreadListPrimitive.Items>
  {() => <MyThreadListItem />}
</ThreadListPrimitive.Items>
```

### 附件

**之前：**

```tsx
<ComposerPrimitive.Attachments
  components={{ Attachment: MyAttachment }}
/>
```

**之后：**

```tsx
<ComposerPrimitive.Attachments>
  {() => <MyAttachment />}
</ComposerPrimitive.Attachments>
```

### `addResult` / `resume` 在增强的部分状态上

使用 children API 时，工具调用部分会直接在部分对象上包含 `addResult` 和 `resume` 方法。这意味着 `<ToolFallback {...part} />` 无需包装组件提供这些方法即可正常工作。

### 向后兼容

`components` 属性在所有原语上仍受支持，但已被弃用，并将在未来版本中移除。

## 仍处于弃用状态（尚未移除）

一些标记为 `@deprecated` 的 API 会被特意保留到下一个版本，以便下游运行时有时间完成迁移：

- `ThreadState.threadId` 和 `ThreadState.metadata` — 请使用 `useThreadListItem()`（参见 [v0.12 指南](/docs/migrations/v0-12)）。将在未来的小版本中移除。
- `legacy-runtime/hooks/*` 下的旧版上下文 hook（`useThreadRuntime`、`useMessageRuntime` 等）— 已在 v0.12 中由 `useAui()` / `useAuiState()` 替代。codemod 会迁移这些 API。
- 原语 `If` 组件（`ThreadIf`、`MessageIf`、`ComposerIf`、`ThreadEmpty`）— 已由 `AuiIf` 替代。codemod 会迁移这些组件。

你仍会在这些 API 上看到弃用警告；预计它们将在未来的小版本中移除。
