title: "推理"
description: "一个可折叠的助手推理渲染器，会跟随当前的消息部分。"
---

Reasoning 为模型的思维链提供了独立的展示轨道：流式传输时显示闪烁的触发器，打开后显示可滚动的推理轨迹，模型继续处理后则显示为普通的折叠行。在运行时环境中，它会跟随当前的推理消息部分；独立使用时，则由你通过自己的 props 驱动相同的展开控件。它有两种设计：运行时变体渲染一条连续的 markdown 推理轨迹，而静态变体 `ReasoningPanel` 则沿时间线渲染带标题的离散步骤（参见[步骤面板设计](#the-step-panel-design)）。

## 快速开始

<RuntimeMode>

运行时会将 `reasoning` 消息部分与消息的其余部分一同进行流式传输。连续的推理部分会合并为一个 `group-reasoning` 部分，展开控件包裹的就是这个分组。

<Steps>
  <Step>

### 分组推理部分并组合展开控件

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
import { MessagePrimitive, groupPartByType } from "@assistant-ui/react";
import {
  ReasoningContent,
  ReasoningRoot,
  ReasoningText,
  ReasoningTrigger,
} from "@/components/assistant-ui/elements/reasoning.aui";

<MessagePrimitive.GroupedParts
  groupBy={groupPartByType({ reasoning: ["group-reasoning"] })}
>
  {({ part, children }) => {
    if (part.type !== "group-reasoning") return null;
    const running = part.status.type === "running";
    return (
      <ReasoningRoot streaming={running}>
        <ReasoningTrigger active={running} />
        <ReasoningContent aria-busy={running}>
          <ReasoningText>{children}</ReasoningText>
        </ReasoningContent>
      </ReasoningRoot>
    );
  }}
</MessagePrimitive.GroupedParts>
```

`groupBy` 决定哪些连续的部分类型应折叠为一个分组；`children` 已经是该范围内渲染完成的部分，因此 `ReasoningText` 只需负责排列它们。工具包中的 `ReasoningGroup` 导出面向 `MessagePrimitive.Parts` 上较旧的 `components.ReasoningGroup` prop；上面的 `MessagePrimitive.GroupedParts` 才是 `Thread` 自身使用的实现，因此应优先使用它。`Thread` 元素已经内置了这一组合，因此安装 `@assistant-ui/thread` 后，无需完成上述步骤即可获得推理轨迹（参见 [Thread](/elements/thread)）。

  </Step>
  <Step>

### 渲染单独的推理部分

大多数运行时会将推理作为连续部分进行流式传输，但单个未分组的 `reasoning` 部分仍然需要渲染器：

```tsx
case "reasoning":
  return <Reasoning {...part} />;
```

`Reasoning` 会将该部分的文本渲染为 markdown，不包含展开控件的外观。若单独的部分仍应获得可折叠外壳，请自行将其包裹在 `ReasoningRoot` / `ReasoningTrigger` / `ReasoningContent` 中。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

独立使用时，该元素是在已有内容之上的展开控件 UI：不需要消息部分，不需要分组，只需要文本和流式传输标志。

<Steps>
  <Step>

### 组合展开控件

```tsx title="app/trace.tsx"
"use client";

import {
  ReasoningContent,
  ReasoningRoot,
  ReasoningText,
  ReasoningTrigger,
} from "@/components/assistant-ui/elements/reasoning";

export function Trace({
  text,
  streaming,
}: {
  text: string;
  streaming: boolean;
}) {
  return (
    <ReasoningRoot streaming={streaming}>
      <ReasoningTrigger active={streaming} />
      <ReasoningContent aria-busy={streaming}>
        <ReasoningText>{text}</ReasoningText>
      </ReasoningContent>
    </ReasoningRoot>
  );
}
```

  </Step>
  <Step>

### 控制打开状态

在非受控模式下，只要 `streaming` 为 true，根元素就会自动打开；当 `defaultOpen` 变为 false 后，它会再次关闭。传入 `open` 和 `onOpenChange` 即可自行驱动它，例如让最新的推理轨迹保持展开：

```tsx
const [open, setOpen] = useState(false);

<ReasoningRoot open={open} onOpenChange={setOpen} streaming={streaming}>
  {/* ... */}
</ReasoningRoot>;
```

  </Step>
</Steps>

</StandaloneMode>

## 组成结构

```tsx
<div data-slot="reasoning-root" data-variant="outline">
  <button data-slot="reasoning-trigger">
    <BrainIcon />
    <span>{/* "Reasoning" or "Reasoning (12s)" */}</span>
    <ChevronDownIcon />
  </button>
  <div data-slot="reasoning-content">
    <div data-slot="reasoning-fade" /> {/* top edge, always */}
    <div data-slot="reasoning-text">{/* the trace */}</div>
    <div data-slot="reasoning-fade" /> {/* bottom edge, streaming only */}
  </div>
</div>
```

当 `streaming` 为 true 且面板处于打开状态时，推理轨迹会作为实时的底部固定预览显示：新 token 到达时自动滚动到最新内容；只有读者手动向上滚动时才会停止，并在读者滚回底部后恢复。流式传输结束后，打开状态会恢复为 `defaultOpen`，除非读者之前至少手动切换过一次展开控件；一旦发生这种情况，读者的选择就会保持不变，流式传输不再覆盖该选择。`ReasoningTrigger` 的 `active` prop 同时控制闪烁标签和计时文本；无论如何，打开时都会旋转箭头。运行时 `ReasoningRoot` 还会在每次打开或关闭动画期间锁定外围线程视口的滚动位置，因此展开推理轨迹不会拉动消息列表；独立使用的根元素没有可锁定的视口，因此会跳过此步骤。

## 示例

### 变体

`ReasoningRoot` 接受一个 `variant`：`outline` 绘制边框和内边距（默认值），`ghost` 两者都不添加，而 `muted` 使用柔和背景填充来替代边框。

```tsx
<ReasoningRoot variant="muted" streaming={streaming}>
  {/* ... */}
</ReasoningRoot>
```

### 触发器时长

传入 `duration`（秒），即可在触发器标签后追加计时后缀：

```tsx
<ReasoningTrigger active={streaming} duration={12} />
// renders: Reasoning (12s)
```

### 推理部分的来源

<RuntimeMode>

分组上的 `status.type`（`"running" | "complete" | ...`）会驱动 `streaming`；当模型对该分组的推理流结束时，它会切换状态，这也是值得显示时长的时机：

```tsx
const running = part.status.type === "running";
<ReasoningTrigger active={running} duration={running ? undefined : elapsedSeconds} />
```

</RuntimeMode>

<StandaloneMode>

独立使用时，`text` 和 `streaming` 来自你获取它们的任意位置，例如一个追加 token 并在其 `done` 事件中切换标志的 SSE 端点。该元素本身不假设任何特定的传输方式。

</StandaloneMode>

## API 参考

<RuntimeMode>

### Reasoning

| 导出 | 类型 | 说明 |
|--------|------|-------|
| `Reasoning` | `ReasoningMessagePartComponent` | 将推理部分的 `text` 渲染为 markdown。不包含展开控件的外观；用于未分组的 `reasoning` 部分。 |

### Reasoning 消息部分

| 字段 | 类型 | 描述 |
|-------|------|--------------|
| `text` | `string` | 到目前为止的推理文本。 |
| `status` | `MessagePartStreamStatus \| undefined` | 此部分的流式传输状态。 |
| `unstable_summary` | `string \| undefined` | 存在时由提供商提供的摘要。`Reasoning` 不会渲染它；如有需要，请自行读取。 |

### 子组件

`ReasoningRoot` 包裹独立使用的根元素，并在展开控件动画期间额外锁定线程视口的滚动。`ReasoningTrigger`、`ReasoningContent`、`ReasoningText`、`ReasoningFade` 和 `reasoningVariants` 会从下面的独立模块中原样重新导出。

</RuntimeMode>

<StandaloneMode>

### ReasoningRoot

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `variant` | `"outline" \| "ghost" \| "muted"` | `"outline"` | 根元素的视觉样式。 |
| `streaming` | `boolean` | | 通过实时预览保持展开控件打开；完整的打开状态约定请参见“组成结构”。 |
| `open` | `boolean` | | 受控的打开状态。 |
| `onOpenChange` | `(open: boolean) => void` | | 每次切换时调用，无论是否受控。 |
| `defaultOpen` | `boolean` | `false` | 非受控模式下的初始打开状态。 |
| `onAnimationStart` | `() => void` | | 展开控件即将执行动画前调用，包括手动切换和流式传输状态转换。 |
| `className` | `string` | | 合并到根元素上。 |

其他所有 `Collapsible` props 都会被转发。

### ReasoningTrigger

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `active` | `boolean` | | 为 true 时使标签闪烁。 |
| `duration` | `number` | | 秒数；将 `(Ns)` 追加到标签。 |
| `className` | `string` | | 合并到触发器上。 |

其他所有 `CollapsibleTrigger` props 都会被转发。

### ReasoningContent、ReasoningText 和 ReasoningFade

`ReasoningContent` 和 `ReasoningText` 会分别将其余 props 转发给 `CollapsibleContent` 和 `div`；两者都接受 `className`。`ReasoningFade` 接受 `side`（`"top" | "bottom"`，默认值为 `"bottom"`）和一个 `className`；`ReasoningContent` 始终在顶部渲染一个，而在实时预览激活期间，还会在底部渲染第二个。

</StandaloneMode>


## 步骤面板设计

栏中的 Static 变体是同一展开控件的第二种设计：`ReasoningPanel` 渲染带标题的有序步骤列表，并使用闪烁的“Thinking”触发器，完成后变为静态摘要，而不是一条连续的 markdown 推理轨迹。它是一个完全由 props 驱动、无需依赖运行时的单一组件：

```sh
npx shadcn@latest add "@assistant-ui/elements-reasoning-panel"
```

<RuntimeMode>

将消息的 `"reasoning"` 部分映射为步骤即可完成接入。`s.message.parts` 是 store 自身的数组，因此直接选择它的成本很低；派生步骤仍需要 `useMemo`，因为每次调用都映射出新数组会导致面板在 store 每次更新时重新渲染。

```tsx title="components/assistant-ui/elements/reasoning-panel.tsx"
"use client";

import { useMemo, useState } from "react";
import { useAuiState, useMessageTiming } from "@assistant-ui/react";
import {
  ReasoningPanel,
  type ReasoningStep,
} from "@/components/assistant-ui/elements/reasoning-panel";

function AssistantReasoning() {
  const parts = useAuiState((s) => s.message.parts);
  const steps = useMemo<ReasoningStep[]>(
    () =>
      parts.flatMap((part) =>
        part.type === "reasoning"
          ? [{ title: part.unstable_summary ?? "Thinking", body: part.text }]
          : [],
      ),
    [parts],
  );
  const streaming = useAuiState((s) => {
    if (s.message.status?.type !== "running") return false;
    return s.message.parts.some(
      (part) => part.type === "reasoning" && part.status.type === "running",
    );
  });
  const timing = useMessageTiming();
  const [userOpen, setUserOpen] = useState<boolean | null>(null);

  if (steps.length === 0) return null;

  return (
    <ReasoningPanel
      steps={steps}
      visibleSteps={steps.length}
      streaming={streaming}
      open={userOpen ?? streaming}
      onOpenChange={setUserOpen}
      restingLabel={
        timing?.totalStreamTime
          ? `Thought for ${Math.round(timing.totalStreamTime / 1000)}s`
          : "Done thinking"
      }
    />
  );
}
```

`visibleSteps` 其实就是 `steps.length`：随着新的推理部分进行流式传输，数组本身会不断增长。`open` 会跟随 `streaming`，直到读者手动切换一次；之后就会保持读者的选择。

</RuntimeMode>

<StandaloneMode>

独立使用时，由你持有步骤列表、决定显示多少个步骤，并自行切换 `open`。要重放已保存的推理轨迹，可以使用 `visibleSteps` 配合 `streaming={visibleSteps < steps.length}` 通过计时器递增。

```tsx title="app/trace.tsx"
"use client";

import { useState } from "react";
import {
  ReasoningPanel,
  type ReasoningStep,
} from "@/components/assistant-ui/elements/reasoning-panel";

const STEPS: ReasoningStep[] = [
  { title: "Reading the request", body: "Working out what changed and why." },
  { title: "Locating the seam", body: "Finding where the fix actually belongs." },
];

export function Trace() {
  const [open, setOpen] = useState(true);
  return (
    <ReasoningPanel
      steps={STEPS}
      visibleSteps={STEPS.length}
      streaming={false}
      open={open}
      onOpenChange={setOpen}
      restingLabel="Thought for 4s"
    />
  );
}
```

</StandaloneMode>

触发器会在闪烁的实时标签（以及提供时的 `elapsed` 徽标）和 `restingLabel` 之间切换，并通过为自身宽度设置动画来避免突然跳变。`visibleSteps` 会被限制在 0 和 `steps.length` 之间；当 `streaming` 为 true 时，只有最后一个显示的步骤会获得脉冲标记。

### ReasoningPanel

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `steps` | `ReasoningStep[]` | 必填 | 按顺序排列的 `{ title: string; body: string }[]`。 |
| `visibleSteps` | `number` | 必填 | 要显示的前置步骤数量；限制在 0 和 `steps.length` 之间。 |
| `streaming` | `boolean` | 必填 | 在实时标签和 `restingLabel` 之间切换，并将最后一个显示的步骤标记为活跃。 |
| `open` | `boolean` | 必填 | 可折叠面板是否展开。 |
| `onOpenChange` | `(open: boolean) => void` | 必填 | 触发器激活时调用。 |
| `restingLabel` | `string` | 必填 | 当 `streaming` 为 `false` 后显示的触发器文本。 |
| `elapsed` | `string \| undefined` | | 当 `streaming` 为 `true` 时，显示在实时标签旁边。 |
| `className` | `string` | | 合并到根元素上；初始值为 `w-full max-w-sm`。 |
