title: "Canvas"
description: "线程退到一旁，让文档占据空间，并在你阅读时持续编写。"
---

Canvas 分栏会将文档放在 thread 旁边，而不是其中：对话在一侧收窄为消息栏，文档占据其余空间，并在你阅读时持续增长。assistant-ui 没有专用的 canvas 或 artifact 原语，因此在运行时中，这种模式由所有结构化回答都使用的相同工具调用渲染组成；单独使用时，则直接将文档的文本和状态传递给各个组件。

### 从工具调用渲染文档

一个以文档作为结果的工具，其参数会随着模型编写文档而流式传输，这正是此模式中“持续编写”部分的基础。通过 `MessagePrimitive.Parts` 为它注册渲染器：

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
"use client";

import { MessagePrimitive, useToolArgsStatus, type ToolCallMessagePartProps } from "@assistant-ui/react";
import { CanvasSplitDocument, CanvasSplitHeader, CanvasSplitBody, CanvasSplitLine } from "./canvas-split";

type DocArgs = { title: string; content: string };

function DocumentTool({ args, status }: ToolCallMessagePartProps<DocArgs>) {
  const { propStatus } = useToolArgsStatus<DocArgs>();
  return (
    <CanvasSplitDocument>
      <CanvasSplitHeader
        title={args.title ?? "Untitled"}
        version={1}
        saved={status.type === "complete"}
      />
      <CanvasSplitBody writing={propStatus.content === "streaming"}>
        <CanvasSplitLine>{args.content}</CanvasSplitLine>
      </CanvasSplitBody>
    </CanvasSplitDocument>
  );
}

<MessagePrimitive.Parts components={{ tools: { by_name: { write_document: DocumentTool } } }} />
```

模型仍在流式传输工具调用时，`args` 是一个不完整的解析结果，字段可能缺失或不完整，因此 `useToolArgsStatus` 会告诉你 `content` 是否仍在传输，而不是只检查整个调用的 `status`。

  </Step>
  <Step>

### 为 thread 分配独立区域

对话部分是一个普通但更窄的 thread：使用相同的 `ThreadPrimitive.Viewport` 和 `.Messages`，通过 `CanvasSplitThread` 和 `CanvasSplitMessage` 设置样式，而不是使用全宽布局：

```tsx
<CanvasSplit>
  <ThreadPrimitive.Viewport asChild>
    <CanvasSplitThread>
      <ThreadPrimitive.Messages>
        {({ message }) => (
          <CanvasSplitMessage speaker={message.role === "user" ? "user" : "assistant"}>
            <MessagePrimitive.Parts components={{ tools: { by_name: { write_document: DocumentTool } } }} />
          </CanvasSplitMessage>
        )}
      </ThreadPrimitive.Messages>
    </CanvasSplitThread>
  </ThreadPrimitive.Viewport>
  {/* CanvasSplitDocument renders itself, from inside DocumentTool above */}
</CanvasSplit>
```

  </Step>
</Steps>

### 布局两个部分

```tsx title="app/canvas.tsx"
"use client";

import {
  CanvasSplit,
  CanvasSplitThread,
  CanvasSplitMessage,
  CanvasSplitDocument,
  CanvasSplitHeader,
  CanvasSplitBody,
  CanvasSplitLine,
} from "@/components/assistant-ui/elements/canvas-split";

export function Canvas() {
  return (
    <CanvasSplit>
      <CanvasSplitThread>
        <CanvasSplitMessage speaker="user">Draft a project outline.</CanvasSplitMessage>
        <CanvasSplitMessage speaker="assistant">Here's a first pass, on the right.</CanvasSplitMessage>
      </CanvasSplitThread>
      <CanvasSplitDocument>
        <CanvasSplitHeader title="Project outline" version={1} saved onCopy={() => {}} onClose={() => {}} />
        <CanvasSplitBody>
          <CanvasSplitLine heading>Goals</CanvasSplitLine>
          <CanvasSplitLine>Ship the first milestone by Friday.</CanvasSplitLine>
        </CanvasSplitBody>
      </CanvasSplitDocument>
    </CanvasSplit>
  );
}
```

  </Step>
  <Step>

### 显示持续编写状态

在你自己的生成过程中切换 `writing`；插入符会追加到已经渲染的行之后：

```tsx
<CanvasSplitBody writing={isGenerating}>
  {lines.map((line, i) => (
    <CanvasSplitLine key={i} heading={line.heading}>{line.text}</CanvasSplitLine>
  ))}
</CanvasSplitBody>
```

## 组成

```tsx
<div data-slot="canvas-split">
  <div data-slot="canvas-split-thread">{/* narrow message rail */}</div>
  <div data-slot="canvas-split-document">
    <div data-slot="canvas-split-header">{/* title, version, saved or editing, copy, close */}</div>
    <div data-slot="canvas-split-body">{/* lines, blinking caret while writing */}</div>
  </div>
</div>
```

在 `md` 以下，thread 和文档会垂直堆叠，而不是并排分栏；在 `md` 及以上时，布局会变为横向排列。无论 `onCopy` 还是 `onClose` 被置为 `undefined`，`CanvasSplitHeader` 的复制和关闭按钮都会像 `ChatPanelComposer` 的发送按钮一样自动禁用。`CanvasSplitBody` 的闪烁插入符纯粹用于展示：只要 `writing` 为 true 就会渲染，并追加到你传入的 `children` 之后，因此始终位于最后一行的末尾。

## 示例

### 复制和关闭

```tsx
<CanvasSplitHeader
  title="Q3 report outline"
  version={3}
  saved={true}
  onCopy={() => navigator.clipboard.writeText(text)}
  onClose={() => setOpen(false)}
/>
```

省略 `onCopy` 或 `onClose` 会禁用对应按钮，而不是将其隐藏，这样无论某个操作是否可用，标题栏的宽度都能保持稳定。

### 不使用工具调用的文档

## API 参考

<RuntimeMode>

### 原语部分

| 部分 | 渲染内容 | 说明 |
|------|---------|-------|
| `MessagePrimitive.Parts` | children | `components.tools.by_name[toolName]` 会为该工具的调用注册渲染器。 |
| `ThreadPrimitive.Viewport` / `.Messages` | `div` / children | thread 消息栏；与其他 thread 使用相同的原语，只是更窄。 |

### 工具调用部分

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `args` | `TArgs`（流式传输期间为部分内容） | 模型目前已经生成的参数。 |
| `status.type` | `"running" \| "complete" \| "incomplete"` | 调用自身的生命周期，而不是每个字段的生命周期。 |
| `useToolArgsStatus().propStatus` | `Partial<Record<keyof TArgs, "streaming" \| "complete">>` | 每个参数的流式传输状态；在工具渲染器内部调用。 |

</RuntimeMode>

<StandaloneMode>

### CanvasSplit 系列

| 部分 | 渲染内容 | Props | 描述 |
|------|---------|-------|-------------|
| `CanvasSplit` | `div` | `className` | 根部件；在 `md` 以下堆叠，在 `md` 及以上按行分栏。 |
| `CanvasSplitThread` | `div` | `className` | 窄消息栏。 |
| `CanvasSplitMessage` | `div` | `speaker: "user" \| "assistant"`、`className` | `"user"` 使用右对齐气泡，`"assistant"` 使用纯文本。 |
| `CanvasSplitDocument` | `div` | `className` | 文档列。 |
| `CanvasSplitHeader` | `div` | `title: string`、`version: number`、`saved: boolean`、`onCopy?`、`onClose?`、`className` | 没有对应处理器时，复制和关闭按钮会被禁用。 |
| `CanvasSplitBody` | `div` | `writing?: boolean`、`className` | 在 `writing` 期间，将闪烁插入符追加到 `children` 之后。 |
| `CanvasSplitLine` | `p` | `heading?: boolean`、`className` | `heading` 会渲染更粗且完全不透明的文本。 |

每个部分的其他 Props 都会转发到其根元素。

</StandaloneMode>
