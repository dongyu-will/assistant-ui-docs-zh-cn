title: "网页搜索"
description: "搜索查询及其结果会随着助手读取内容逐一呈现。"
---

网页搜索会在药丸形标签中显示实时查询、状态行以及不断增长的结果列表；每条结果都包含带域名字母的头像、标题和来源域名。在运行时中，查询和结果来自模型发起的工具调用；在独立使用时，你可以控制 `query`、`results` 以及可见结果的数量。

## 开始使用

<RuntimeMode>

搜索工具通过该工具自身的工具包条目进行渲染：模型的参数以 `args` 的形式传入，提供方的结果以 `result` 的形式传入，而调用的生命周期则通过 `status` 表示。

<Steps>
  <Step>

### 定义搜索工具包

```tsx title="app/toolkit.tsx"
"use generative";

import { defineToolkit, externalTool } from "@assistant-ui/react";
import { WebSearch } from "@/components/assistant-ui/elements/web-search";

export default defineToolkit({
  web_search: {
    execute: externalTool(),
    render: ({ args, result, status }) => (
      <WebSearch
        query={args.query ?? ""}
        results={result?.results ?? []}
        visibleResults={result?.results.length ?? 0}
        searching={status.type === "running"}
        cycle={0}
      />
    ),
  },
});
```

`execute: externalTool()` 表示该工具由后端路由或提供方运行，而不是在浏览器中运行：编译器会将其从客户端包中移除，只保留 `render`。如果搜索本身应在客户端运行，请为 `execute` 提供一个实际函数。

  </Step>
  <Step>

### 注册工具包

```tsx title="app/MyRuntimeProvider.tsx"
"use client";

import { AssistantRuntimeProvider, AuiConfig, Tools } from "@assistant-ui/react";
import { useChatRuntime } from "@assistant-ui/ai-sdk";
import { Thread } from "@/components/assistant-ui/elements/thread.aui";
import toolkit from "./toolkit";

export function App() {
  const runtime = useChatRuntime();
  const config = AuiConfig({ tools: Tools({ toolkit }) });

  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}>
      <Thread />
    </AssistantRuntimeProvider>
  );
}
```

线程中的每个 `web_search` 工具调用现在都会渲染为此元素，无论 `MessagePrimitive.Parts` 将它放置在助手回复中的什么位置。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

独立使用时，`WebSearch` 完全受控：你需要保存查询、完整的结果列表以及要显示的结果数量。

<Steps>
  <Step>

### 保存搜索状态

```tsx title="app/answer.tsx"
"use client";

import { useState } from "react";
import {
  WebSearch,
  type WebSearchResult,
} from "@/components/assistant-ui/elements/web-search";

const RESULTS: readonly WebSearchResult[] = [
  { title: "Persisting composer state across threads", domain: "assistant-ui.com" },
  { title: "Draft autosave patterns in chat UIs", domain: "patterns.dev" },
];

export function Search() {
  const [searching, setSearching] = useState(true);
  const [visibleResults, setVisibleResults] = useState(0);

  return (
    <WebSearch
      query="assistant-ui draft persistence"
      results={RESULTS}
      visibleResults={visibleResults}
      searching={searching}
      cycle={0}
    />
  );
}
```

  </Step>
  <Step>

### 搜索完成后逐步显示结果

结果准备好后，将 `searching` 关闭，并将 `visibleResults` 逐步增加，而不是直接跳转到完整列表：

```tsx
useEffect(() => {
  fetchResults(query).then((found) => {
    setSearching(false);
    found.forEach((_, i) => {
      setTimeout(() => setVisibleResults((n) => Math.max(n, i + 1)), i * 300);
    });
  });
}, [query]);
```

  </Step>
</Steps>

</StandaloneMode>

## 组成结构

```tsx
<div data-slot="web-search">
  <span>{/* query, in a rounded field with a search icon */}</span>
  <div>{/* "Searching" (shimmer) while searching, else fixed "Read 3 sources" text */}</div>
  <div>{/* the first `visibleResults` results: domain-initial avatar, title, domain */}</div>
</div>
```

`visibleResults` 会限制在 `0…results.length` 范围内，因此超出范围的值不会抛出异常：负数或 `NaN` 会显示为空，超过末尾一个位置则会显示全部内容。“读取 3 个来源”这一行是源代码中的字面文本，并非根据 `results.length` 派生；如果数量应与传入的内容保持一致，请直接编辑它。`cycle` 会混入每个可见结果的 key 中，因此即使 `results` 和 `visibleResults` 未发生变化，增加它也会重新触发进入动画；对于以相同答案结构再次运行的搜索，这很有用。空的 `results` 数组会渲染状态行，但其下方没有任何行；无论是否为空，结果区域都会保留预留高度。

## 示例

### 流式传输到达的查询

<RuntimeMode>

`args.query` 是模型仍在编写工具调用时的部分解析结果。`useToolArgsStatus` 会报告哪些参数字段仍在流式传输，因此药丸形标签可以显示占位符，而不是显示输入到一半的字符串：

```tsx
import { useToolArgsStatus, type ToolCallMessagePartProps } from "@assistant-ui/react";
import {
  WebSearch,
  type WebSearchResult,
} from "@/components/assistant-ui/elements/web-search";

type SearchArgs = { query: string };
type SearchResult = { results: WebSearchResult[] };

function SearchToolUI({
  args,
  result,
  status,
}: ToolCallMessagePartProps<SearchArgs, SearchResult>) {
  const { propStatus } = useToolArgsStatus<SearchArgs>();

  return (
    <WebSearch
      query={propStatus.query === "streaming" ? "Searching…" : (args.query ?? "")}
      results={result?.results ?? []}
      visibleResults={result?.results.length ?? 0}
      searching={status.type === "running"}
      cycle={0}
    />
  );
}
```

</RuntimeMode>

### 重新设置结果样式

两个区域的根元素都接收 `className`。查询药丸形标签使用共享的 `field` 表面，域名标签使用 `mono`；二者都来自 `surfaces.tsx`，因此重新设置这些设计令牌的主题后，所有基于它们构建的元素都会同步更新主题。

```tsx
<WebSearch className="max-w-none" /* ... */ />
```

## API 参考

<RuntimeMode>

### 工具渲染 props

| Prop | Type | Description |
|------|------|-------------|
| `args` | `{ query?: string }` | 模型提供的参数。流式传输期间可能不完整；使用 `useToolArgsStatus` 区分已完成的字段和仍在传入的字段。 |
| `result` | `{ results: WebSearchResult[] } \| undefined` | 工具调用解析后设置。 |
| `status.type` | `"running" \| "complete" \| "incomplete" \| "requires-action"` | 调用的生命周期。只有 `"running"` 状态应显示搜索中的 shimmer 动画。 |

`WebSearchResult` 是 `{ title: string; domain: string }`。有关完整的工具调用部分结构，请参阅[工具 UI](/docs/tools/tool-ui)。

</RuntimeMode>

<StandaloneMode>

### WebSearch

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `query` | `string` | required | 在药丸形标签中显示的搜索查询。 |
| `results` | `readonly WebSearchResult[]` | required | 完整的结果列表。 |
| `visibleResults` | `number` | required | 要渲染的结果数量，从 `results` 的开头开始计算。 |
| `searching` | `boolean` | required | 为 true 时，用带 shimmer 动画的“正在搜索”标签替代结果数量。 |
| `cycle` | `number` | required | 混入每个结果的 key，以强制重新播放其进入动画。请在不同搜索之间传入递增的值；如果只搜索一次，也可以传入常量。 |
| `className` | `string` | | 合并到根元素上。 |

`WebSearchResult` 是 `{ title: string; domain: string }`。其他所有 `div` props 都会转发到根元素。

</StandaloneMode>
