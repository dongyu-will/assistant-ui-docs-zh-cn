---
title: "权限授予"
description: "授予一项能力，而不是批准单个操作，并明确说明其作用范围。"
---

这是能力的门控，而不是单个操作的批准：在用户确认之前，明确说明请求的内容、请求者，以及用户同意后究竟会允许什么。对于运行时，此门控来自工具调用的批准状态；单独使用时，则由你自行掌控这一决策。

## 快速开始

<RuntimeMode>

如果运行时的后端声明了工具批准门控（例如 AG-UI 或 ACP agent），它会将一个 `approval` 对象附加到工具调用部分。读取该对象，并在显示工具正常结果的同一个渲染器中对其作出响应。

<Steps>
  <Step>

### 从工具调用中读取批准门控

```tsx title="app/shell-toolkit.tsx"
"use client";

import type { ToolApprovalResponse, ToolCallMessagePartProps } from "@assistant-ui/react";

function ShellApprovalGate({ args, approval, respondToApproval }: ToolCallMessagePartProps<{ command: string }, string>) {
  if (!approval || approval.approved !== undefined || approval.resolution !== undefined) {
    return null;
  }

  // A refused response rejects and a precondition (an unknown option, an answer
  // the request does not take) throws, so `try`/`await` covers both and the
  // controls stay actionable.
  const answer = async (response: ToolApprovalResponse) => {
    try {
      await respondToApproval(response);
    } catch (failure) {
      console.error(failure);
    }
  };

  return (
    <div className="flex flex-col gap-3.5 rounded-[20px] border p-4">
      <p className="text-sm font-medium">Run: {args.command}</p>
      <div className="flex flex-wrap gap-2">
        {(approval.options ?? []).map((option) => (
          <button key={option.id} type="button" onClick={() => void answer({ optionId: option.id })}>
            {option.label ?? option.kind}
          </button>
        ))}
      </div>
    </div>
  );
}
```

`approval.approved === undefined` 且没有 `resolution` 时，表示门控仍处于开放状态；主机记录决策后，该部分会重新渲染并设置 `approval.approved`，此时返回 `null`。

  </Step>
  <Step>

### 使用 respondToApproval 作出响应

每个声明的选项都带有自己的 `grants`，用于说明选择该选项后将持久化的模式或规则。在用户确认之前展示这些内容，而不是之后：

```tsx
{(approval.options ?? []).map((option) => (
  <div key={option.id} className="flex flex-col gap-1">
    <button type="button" onClick={() => void answer({ optionId: option.id })}>
      {option.label ?? option.kind}
    </button>
    {option.grants?.map((grant) => <span key={grant}>{grant}</span>)}
  </div>
))}
```

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

单独使用时，该元素完全由你控制：由你决定授予什么，以及是否作出授予决定。

<Steps>
  <Step>

### 暂存授予决定

```tsx title="app/approval.tsx"
"use client";

import { useState } from "react";
import { PermissionGrant, type GrantScope } from "@/components/assistant-ui/elements/permission-grant";

export function ShellApproval() {
  const [scope, setScope] = useState<GrantScope | "pending">("pending");
  return (
    <PermissionGrant
      capability="Run shell commands"
      requester="deploy-agent"
      reach={["./workspace/**", "npm run *"]}
      scope={scope}
      onGrant={setScope}
    />
  );
}
```

  </Step>
  <Step>

### 在 onGrant 中完成解析

`onGrant` 只触发一次，并携带用户选择的 `"denied"`、`"session"` 或 `"always"`。根据它设置 `scope` 即可；卡片仅在 `scope` 为 `"pending"` 时渲染其按钮。

  </Step>
</Steps>

</StandaloneMode>

## 结构

```tsx
<div data-slot="permission-grant">
  <div>{/* icon, capability, "requested by {requester}" */}</div>
  <div>{/* "this grants", then one line per reach item */}</div>
  <div>
    {/* pending: Deny / This session / Always */}
    {/* resolved: one badge, keyed on scope so it fades in on change */}
  </div>
</div>
```

三个待处理按钮与已解析徽章互斥：一旦 `scope` 不再是 `"pending"`，按钮就会消失，卡片会显示 `"denied"` 或 `"granted · {scope}"`。

## 示例

### 确认持久授予

<RuntimeMode>

带有 `confirm: true`（或 `{ title, description }` 对象）的选项需要两步确认：在调用 `respondToApproval` 之前先显示该选项自己的确认步骤，与 `option.grants` 已经承诺的内容保持一致。

```tsx
const [confirmingId, setConfirmingId] = useState<string | null>(null);
const confirming = approval.options?.find((o) => o.id === confirmingId);

if (confirming) {
  return (
    <div>
      <p>{typeof confirming.confirm === "object" ? confirming.confirm.title : `${confirming.label}?`}</p>
      <button onClick={() => void answer({ optionId: confirming.id })}>Confirm</button>
      <button onClick={() => setConfirmingId(null)}>Back</button>
    </div>
  );
}
```

</RuntimeMode>

### 简单允许或拒绝

<RuntimeMode>

`approval.options` 是可选的。如果缺少它，门控就是简单的允许或拒绝：使用 `approved` 作出响应，而不是使用 `optionId`。

```tsx
<button type="button" onClick={() => void answer({ approved: true })}>
  Allow
</button>
<button type="button" onClick={() => void answer({ approved: false })}>
  Deny
</button>
```

</RuntimeMode>

### 重新设置卡片样式

两个分支都会在根元素上接收 `className`。根元素使用共享的 `paper` surface，“授予内容”标签使用 `mono`，已解析徽章同时使用 `field` 和 `mono`，Always 按钮使用 `inkButton`。因此，在 `surfaces.tsx` 中重新指定这些样式，就能同时重新设置此卡片以及其他基于它们构建的内容的样式。

## API 参考

<RuntimeMode>

### 批准门控

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `approval.id` | `string` | 此批准请求的标识符。 |
| `approval.approved` | `boolean \| undefined` | 门控仍处于开放状态时为 `undefined`。 |
| `approval.options` | `readonly ToolApprovalOption[] \| undefined` | 可用的决策；缺少该字段表示简单的允许或拒绝。 |
| `approval.optionId` | `string \| undefined` | 存在选项时，解析时选中的选项。 |
| `approval.resolution` | `"cancelled" \| "expired" \| undefined` | 请求结束但用户未作出决策时由主机设置。 |
| `respondToApproval(response)` | `(response: ToolApprovalResponse) => Promise<void>` | 回应门控。接受 `{ approved }`、`{ optionId }`、两者，或在请求接受自由格式回答时接受 `{ text }`。仅当 `approved` 和 `resolution` 均未设置时有效。 |

### ToolApprovalOption

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `id` | `string` | 由主机定义的标识符。 |
| `kind` | `"allow-once" \| "allow-always" \| "reject-once" \| "reject-always"` 或自定义字符串 | 已知类型会自动解析 `approved`；自定义类型始终需要显式的 `approved` 值。 |
| `label` | `string` | 可选；缺少时，渲染器会根据类型使用默认值。 |
| `grants` | `readonly string[]` | 此选项将持久化的模式或规则，由主机提供。 |
| `confirm` | `boolean \| { title?, description? }` | 在此选项解析之前选择性启用的确认步骤。 |

</RuntimeMode>

<StandaloneMode>

### PermissionGrant

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `capability` | `string` | 必填 | 要授予的内容。 |
| `requester` | `string` | 必填 | 请求授予权限的对象。 |
| `reach` | `readonly string[]` | 必填 | 此授予将覆盖的模式或规则，在用户确认之前显示。 |
| `scope` | `GrantScope \| "pending"` | 必填 | `"pending"` 会显示三个按钮；任何其他值都会显示已解析徽章。 |
| `onGrant` | `(scope: GrantScope) => void` | | 从所按下的待处理按钮中调用一次。 |
| `className` | `string` | | 合并到根元素上。 |

`GrantScope` 是 `"session" | "always" | "denied"`。

</StandaloneMode>
