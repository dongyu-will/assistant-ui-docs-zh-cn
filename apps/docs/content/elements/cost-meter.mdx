title: "成本计量器"
description: "按模型拆分运行消耗，并与会话总计进行对比。"
---

CostMeter 以醒目的数字、按模型拆分的分段条，以及每个模型一行的令牌数量和价格，展示一次运行的成本。使用运行时，你可以根据消息自身每个步骤的使用情况计算这些数值；独立使用时，你已经持有这些数值。

## 入门

<RuntimeMode>

assistant-ui 会跟踪一次运行中每个步骤的 token 用量，但不会跟踪费用，也不会记录某个步骤由哪个模型生成；这两项都需要由你自行记录。最接近真实数据的是 `message.metadata.steps`，即一个由 `{ usage: { inputTokens, outputTokens } }` 条目组成的数组。

### 将一次运行的步骤转换为成本明细

```tsx title="components/assistant-ui/elements/run-cost.tsx"
"use client";

import { useAuiState } from "@assistant-ui/react";
import {
  CostMeter,
  type CostLine,
} from "@/components/assistant-ui/elements/cost-meter";

const PRICE_PER_MILLION = { in: 3, out: 15 };

function useRunCost(model: string): CostLine {
  const usage = useAuiState((s) =>
    s.message.role === "assistant"
      ? s.message.metadata.steps.reduce(
          (total, step) => ({
            inputTokens: total.inputTokens + (step.usage?.inputTokens ?? 0),
            outputTokens: total.outputTokens + (step.usage?.outputTokens ?? 0),
          }),
          { inputTokens: 0, outputTokens: 0 },
        )
      : { inputTokens: 0, outputTokens: 0 },
  );
  const dollars =
    (usage.inputTokens / 1_000_000) * PRICE_PER_MILLION.in +
    (usage.outputTokens / 1_000_000) * PRICE_PER_MILLION.out;
  return { model, ...usage, cost: `$${dollars.toFixed(2)}`, share: 1 };
}

export function RunCost({ model }: { model: string }) {
  const line = useRunCost(model);
  return <CostMeter runCost={line.cost} sessionCost={line.cost} lines={[line]} />;
}
```

`PRICE_PER_MILLION` 和 `model` 标签由你定义；assistant-ui 从不会指定价格或提供商。

  </Step>
  <Step>

### 添加会话总计

```tsx
const sessionTokens = useAuiState((s) =>
  s.thread.messages.reduce(
    (total, message) =>
      message.role === "assistant"
        ? message.metadata.steps.reduce(
            (sum, step) =>
              sum + (step.usage?.inputTokens ?? 0) + (step.usage?.outputTokens ?? 0),
            total,
          )
        : total,
    0,
  ),
);
```

`s.thread.messages` 包含活动分支中的每条消息，因此汇总其中助手消息的步骤，就能得到真实的会话 token 总量。要将其转换为 `sessionCost`，仍然需要使用你自己的价格表；如果一个线程确实调用了多个模型，你也需要自行跟踪每条消息使用的是哪个模型，因为 `ThreadStep` 不包含模型名称。

  </Step>

### 保留明细和总计

```tsx title="app/usage.tsx"
"use client";

import {
  CostMeter,
  type CostLine,
} from "@/components/assistant-ui/elements/cost-meter";

const LINES: CostLine[] = [
  { model: "Opus 5", inputTokens: 48_200, outputTokens: 12_400, cost: "$1.66", share: 0.62 },
  { model: "Sonnet 5", inputTokens: 92_800, outputTokens: 21_100, cost: "$0.86", share: 0.29 },
  { model: "Haiku 4.5", inputTokens: 140_000, outputTokens: 8_900, cost: "$0.24", share: 0.09 },
];

export function Usage() {
  return <CostMeter runCost="$2.76" sessionCost="$18.40" lines={LINES} />;
}
```

## 结构

```tsx
<div data-slot="cost-meter">
  <div>
    <span>{/* runCost, large */}</span>
    <span>this run</span>
    <span>{/* "{sessionCost} session" */}</span>
  </div>
  <div>{/* segmented bar, one span per line, width = share */}</div>
  <div>
    {/* one row per line: model name, token counts, cost */}
  </div>
</div>
```

分段条的颜色按索引而不是按数值分配：第一行始终使用纯蓝色调，第二行使用淡蓝色调，之后的每一行都共用一种中性灰色，无论其 `share` 数值多大。`share` 不会与其他值进行校验，因此总和不为 1 的份额会导致分段条显示不足或超出。`inputTokens` 和 `outputTokens` 是原始数字，组件会将其格式化为以千为单位、保留一位小数的形式（`48200` 会变为 `"48.2k in"`）；`runCost`、`sessionCost` 以及每一行的 `cost` 都是已经格式化的字符串，组件只负责显示，不会自行进行货币计算。

## 示例

### 重新设置计量器样式

两个泳道都在根元素上接收 `className`。根元素使用 `paper`；令牌计数和成本使用 `mono`。

```tsx
<CostMeter className="max-w-none" /* ... */ />
```

### 根据原始成本计算占比

无论哪个泳道提供金额，`share` 都只是每一行占总额的比例，条形图不会替你计算。

```tsx
const raw = [
  { model: "Opus 5", inputTokens: 48_200, outputTokens: 12_400, dollars: 1.66 },
  { model: "Sonnet 5", inputTokens: 92_800, outputTokens: 21_100, dollars: 0.86 },
];
const total = raw.reduce((sum, r) => sum + r.dollars, 0);
const lines: CostLine[] = raw.map((r) => ({
  model: r.model,
  inputTokens: r.inputTokens,
  outputTokens: r.outputTokens,
  cost: `$${r.dollars.toFixed(2)}`,
  share: total > 0 ? r.dollars / total : 0,
}));
```

## API 参考

<RuntimeMode>

### 消息和线程状态

| 选择器 | 类型 | 描述 |
|----------|------|-------------|
| `s.message.metadata.steps` | `readonly ThreadStep[]` | 助手消息中提供。每个步骤的 `usage` 会给出该步骤的 `inputTokens` / `outputTokens`；将所有步骤相加即可得到一条消息的运行成本。 |
| `s.thread.messages` | `readonly MessageState[]` | 活动分支中的每条消息。将其中助手消息的 `.metadata.steps` 相加，即可得到整个会话的总量。 |

assistant-ui 跟踪的是令牌数量，而不是金额，并且 `ThreadStep` 不包含模型名称。`cost`、`share` 以及按模型拆分的任何数据，都需要根据你自己的价格表，以及你自己记录的每条消息由哪个模型运行来计算。

</RuntimeMode>

<StandaloneMode>

### CostMeter

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `runCost` | `string` | 必填 | 此次运行的预格式化总额，以大字号显示。 |
| `sessionCost` | `string` | 必填 | 预格式化的实时累计总额，显示在标题行末尾。 |
| `lines` | `readonly CostLine[]` | 必填 | 每个模型占一行，顺序与其渲染顺序一致。 |
| `className` | `string` | | 合并到根元素。 |

### CostLine

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `model` | `string` | 行标签，过长时会截断。 |
| `inputTokens` | `number` | 由组件格式化为 `"{n}k in"`。 |
| `outputTokens` | `number` | 由组件格式化为 `"{n}k out"`。 |
| `cost` | `string` | 预格式化后原样显示。 |
| `share` | `number` | 此行在分段条中的占比。前两行使用不同的蓝色调，其余行共用一种中性色调；占比不会由组件代为归一化。 |

所有其他 `div` 属性都会转发到根元素。

</StandaloneMode>
