---
title: "时间线"
description: "时间轴上的事件，展示已发生的内容和即将发生的内容。"
---

垂直轴上的一系列事件，每个事件均标有日期，并由连接线串联；连接线在过去部分为实线，跨入未来后变为空心线。在运行时中，事件来自工具结果；独立使用时，则由你自行维护事件列表。

## 快速开始

<RuntimeMode>

此元素没有自己的 assistant-ui 原语，因此运行时接线使用的是工具渲染器，而非原语组合。时间线通常是针对你在其他位置跟踪内容的真实查询，因此事件应位于工具的 `result` 上，而不是其流式传输的 `args` 上。

<Steps>
  <Step>

### 注册渲染函数

```tsx title="app/toolkit.tsx"
"use client";

import { defineToolkit } from "@assistant-ui/react";
import { Timeline } from "@/components/assistant-ui/elements/timeline";

export const toolkit = defineToolkit({
  get_incident_timeline: {
    type: "backend",
    render: ({ args, result }) => {
      if (!result) return <p>Loading the timeline for {args.issueId}…</p>;
      return (
        <Timeline
          events={result.events}
          visibleCount={result.events.length}
        />
      );
    },
  },
});
```

由于整个时间线会作为一个结果返回，而不是以流式步骤返回，`visibleCount` 就是 `result.events.length`；没有需要据此确定大小的部分状态。

  </Step>
  <Step>

### 让消息列表渲染它

```tsx title="app/MyRuntimeProvider.tsx"
import {
  AssistantRuntimeProvider,
  AuiConfig,
  Tools,
} from "@assistant-ui/react";
import { useChatRuntime } from "@assistant-ui/ai-sdk";
import { toolkit } from "./toolkit";

export function MyRuntimeProvider({
  children,
}: {
  children: React.ReactNode;
}) {
  const runtime = useChatRuntime();
  const config = AuiConfig({ tools: Tools({ toolkit }) });
  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

注册 toolkit 后，`Thread` 以及任何基于 assistant-ui 消息部分原语（`MessagePrimitive.Parts` 或 `MessagePrimitive.GroupedParts`）构建的自定义消息列表，都会在消息中出现 `get_incident_timeline` 调用的位置自动渲染已注册的 UI，无需手动放置任何内容。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

独立使用时，此元素是一个普通展示组件：它不维护自身状态，因此最简单的用法是一次性展示一组固定事件。

<Steps>
  <Step>

### 直接传入事件

```tsx title="app/issue-timeline.tsx"
"use client";

import {
  Timeline,
  type TimelineEvent,
} from "@/components/assistant-ui/elements/timeline";

const events: readonly TimelineEvent[] = [
  { id: "1", when: "past", time: "09:02", title: "Issue filed" },
  { id: "2", when: "past", time: "09:40", title: "Reproduced" },
  { id: "3", when: "now", time: "10:15", title: "Fix in review" },
  { id: "4", when: "future", time: "11:00", title: "Release 0.14.1" },
];

export function IssueTimeline() {
  return <Timeline events={events} visibleCount={events.length} />;
}
```

  </Step>
  <Step>

### 按自己的节奏显示事件

```tsx
"use client";

import { useEffect, useState } from "react";

export function IssueTimeline() {
  const [visibleCount, setVisibleCount] = useState(0);

  useEffect(() => {
    if (visibleCount >= events.length) return;
    const id = setTimeout(() => setVisibleCount((n) => n + 1), 600);
    return () => clearTimeout(id);
  }, [visibleCount]);

  return <Timeline events={events} visibleCount={visibleCount} />;
}
```

  </Step>
</Steps>

</StandaloneMode>

## 结构

```tsx
<div data-slot="timeline">
  {/* one row per visible event, in array order */}
  <span>{/* event.time, right aligned */}</span>
  <span>
    {/* dot, styled by event.when */}
    {/* connector down to the next row, omitted after the last visible row */}
  </span>
  <div>
    <span>{/* event.title */}</span>
    <span>{/* optional event.detail */}</span>
  </div>
</div>
```

与其他结构化输出元素一样，`visibleCount` 会向下取整并限制在 `0…events.length` 范围内：NaN 或负数会映射为 0，超过数组长度的任何值会映射为数组长度。各行会按你传入 `events` 的顺序渲染；组件绝不会按 `time` 或 `when` 排序。最后一个可见行之后的连接线会被省略，因此部分显示时不会在最后一个已显示圆点后留下悬空线段。圆点及其连接线的颜色仅由该事件自身的 `when` 决定：`"now"` 显示为实心蓝色，外围带圆环；`"past"` 显示为实心灰色；`"future"` 显示为空心轮廓，并使用较暗的连接线段；列表中的位置不会产生任何影响。

## 示例

### 过去、现在和未来

一条时间线中通常应只有一个事件带有 `"now"`，因为它是唯一会加粗标题并在圆点外围添加圆环的值。组件不会对此施加限制；由你决定哪个事件（如果有）是当前事件。

```tsx
const events: readonly TimelineEvent[] = [
  { id: "1", when: "past", time: "Mon", title: "Kickoff" },
  { id: "2", when: "now", time: "Wed", title: "In progress" },
  { id: "3", when: "future", time: "Fri", title: "Due" },
];
```

### 事件来源

<RuntimeMode>

后端入口只声明查询键。模型提供 `issueId`，你的服务器解析其余内容，包括哪个事件算作 `"now"`，而客户端渲染器只会看到最终完成的数据结构。

```ts title="app/api/chat/route.ts"
get_incident_timeline: tool({
  description: "Look up the timeline of a tracked issue.",
  inputSchema: z.object({ issueId: z.string() }),
  execute: async ({ issueId }) => getIssueTimeline(issueId),
}),
```

</RuntimeMode>

<StandaloneMode>

当事件来自你自己的请求而非固定常量时，获取一次事件后重置显示计数，以便动画从头开始播放。

```tsx
async function loadTimeline(issueId: string) {
  const { events: nextEvents } = await fetchIssueTimeline(issueId);
  setEvents(nextEvents);
  setVisibleCount(0);
}
```

</StandaloneMode>

### 重设时间线样式

两个区域都可在根元素上接受 `className`。时间列使用来自 `surfaces.tsx` 的共享 `mono` 表面，因此重设该 token 的样式会重设使用它的所有元素。


```tsx
<Timeline className="max-w-none gap-0" /* ... */ />
```

## API 参考

<RuntimeMode>

### 渲染 props

| Prop | 类型 | 描述 |
|------|------|-------------|
| `args` | `{ issueId: string }` | 工具的参数，即模型提供的查询键。 |
| `result` | `{ events: TimelineEvent[] } \| undefined` | 已完成的时间线；在后端执行器解析完成前为 undefined。 |

### get_incident_timeline 结果

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `events[].id` | `string` | 稳定标识符，用作 React key。 |
| `events[].when` | `"past" \| "now" \| "future"` | 决定该行圆点、连接线和标题的样式。 |
| `events[].time` | `string` | 在时间列中以等宽字体显示。 |
| `events[].title` | `string` | 事件标题。 |
| `events[].detail` | `string` | 标题下方的可选文本行。 |

</RuntimeMode>

<StandaloneMode>

### Timeline

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `events` | `readonly TimelineEvent[]` | 必填 | 完整事件列表，仅渲染前 `visibleCount` 个。 |
| `visibleCount` | `number` | 必填 | 要显示的事件数量，向下取整并限制在 `0…events.length` 范围内。 |
| `className` | `string` | | 合并到根元素上。 |

所有其他 `div` props 都会转发给根元素。

### TimelineEvent

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `id` | `string` | 稳定标识符，用作 React key。 |
| `when` | `"past" \| "now" \| "future"` | 决定该行圆点、连接线和标题的样式。 |
| `time` | `string` | 在时间列中以等宽字体显示。 |
| `title` | `string` | 事件标题。 |
| `detail` | `string` | 标题下方的可选文本行。 |

</StandaloneMode>
