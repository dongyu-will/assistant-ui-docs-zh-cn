title: "工具时间线"
description: "将整个工作会话概括为动词、目标和文件统计信息。"

工具时间线会将一次助手回合执行的所有操作合并为一行可折叠内容，展开后显示一条垂直轨迹：每个步骤包含一个动词、一个图标和一个标签，最后以一行文件变更统计信息收尾。使用运行时（runtime）时，你可以从消息自身的各个部分派生步骤；单独使用时，则由你自行维护步骤列表。

## 快速开始

<RuntimeMode>

单个工具调用会通过该工具自身的 `render` 字段进行渲染，但时间线会一次性概括消息中的所有调用，因此它会直接读取 `s.message.parts`，而不是注册为某个工具的渲染器（renderer）。

### 从消息的各个部分派生步骤

```tsx title="components/assistant-ui/elements/session-timeline.tsx"
"use client";

import { useState } from "react";
import {
  FileSearchIcon,
  PenLineIcon,
  TerminalIcon,
  type LucideIcon,
} from "lucide-react";
import { useAuiState, type ToolCallMessagePart } from "@assistant-ui/react";
import {
  ToolTimeline,
  type TimelineStat,
  type TimelineStep,
} from "@/components/assistant-ui/elements/tool-timeline";

const TOOL_META: Record<string, { verb: string; icon: LucideIcon }> = {
  read_file: { verb: "Read", icon: FileSearchIcon },
  run_command: { verb: "Ran", icon: TerminalIcon },
  edit_file: { verb: "Edited", icon: PenLineIcon },
};

function toStep(part: ToolCallMessagePart): TimelineStep {
  const meta = TOOL_META[part.toolName];
  const args = part.args as Record<string, unknown>;
  return {
    verb: meta?.verb ?? part.toolName,
    chip: String(args.path ?? args.command ?? part.toolCallId),
    icon: meta?.icon ?? TerminalIcon,
  };
}

function toStats(parts: readonly ToolCallMessagePart[]): TimelineStat[] {
  return parts
    .filter((part) => part.toolName === "edit_file" && part.result)
    .map((part) => {
      const result = part.result as { file: string; added: number; removed: number };
      return { file: result.file, added: result.added, removed: result.removed };
    });
}

export function SessionTimeline() {
  const [open, setOpen] = useState(false);
  const toolCalls = useAuiState((s) =>
    s.message.parts.filter(
      (part): part is ToolCallMessagePart => part.type === "tool-call",
    ),
  );
  const streaming = useAuiState((s) => s.message.status?.type === "running");
  const steps = toolCalls.map(toStep);
  const stats = toStats(toolCalls);

  if (steps.length === 0) return null;

  return (
    <ToolTimeline
      steps={steps}
      visibleSteps={steps.length}
      streaming={streaming}
      open={open}
      onOpenChange={setOpen}
      restingLabel={`${steps.length} steps · ${stats.length} files changed`}
      activeLabel="Working"
      stats={stats}
    />
  );
}
```

  </Step>
  <Step>

### 将其放在消息部分旁边，而不是其中

`SessionTimeline` 会替代工具调用和推理的逐部分渲染，因此请在 `MessagePrimitive.Parts` 中停用这些渲染，以避免重复显示相同步骤：

```tsx
<MessagePrimitive.Root>
  <SessionTimeline />
  <MessagePrimitive.Parts
    components={{ tools: { Fallback: () => null }, Reasoning: () => null }}
  />
</MessagePrimitive.Root>
```

### 保存步骤列表

```tsx title="app/session.tsx"
"use client";

import { useState } from "react";
import { FileSearchIcon, PenLineIcon, TerminalIcon } from "lucide-react";
import {
  ToolTimeline,
  type TimelineStat,
  type TimelineStep,
} from "@/components/assistant-ui/elements/tool-timeline";

const STEPS: TimelineStep[] = [
  { verb: "Read", chip: "thread.tsx", icon: FileSearchIcon },
  { verb: "Ran", chip: "pnpm vitest", icon: TerminalIcon },
  { verb: "Edited", chip: "composer.tsx", icon: PenLineIcon },
];

const STATS: TimelineStat[] = [{ file: "composer.tsx", added: 14, removed: 3 }];

export function Session() {
  const [open, setOpen] = useState(false);

  return (
    <ToolTimeline
      steps={STEPS}
      visibleSteps={STEPS.length}
      streaming={false}
      open={open}
      onOpenChange={setOpen}
      restingLabel="3 steps · 1 file changed"
      activeLabel="Working"
      stats={STATS}
    />
  );
}
```

  </Step>

### 随工作进行显示步骤

`visibleSteps` 与数组长度无关，因此某个步骤可以先存在于 `steps` 中，之后再显示：

```tsx
const [visibleSteps, setVisibleSteps] = useState(0);

useEffect(() => {
  if (visibleSteps >= STEPS.length) return;
  const id = setTimeout(() => setVisibleSteps((n) => n + 1), 1000);
  return () => clearTimeout(id);
}, [visibleSteps]);
```

</Steps>

## 组成

```tsx
<div data-slot="tool-timeline">
  <button>{/* chevron, shimmering activeLabel while streaming, else restingLabel */}</button>
  <div>
    {/* one row per visible step: icon, verb, chip */}
    {/* a wrapped row of file chips, only when stats.length > 0 */}
  </div>
</div>
```

`visibleSteps` 会限制在 `steps` 的长度范围内，并将小数或负数向下取整为零，因此可以在显示之前将步骤加入队列。只有最后一个可见步骤会显示闪烁效果，并且仅当 `streaming` 为 true 时才会显示；即使运行尚未结束，之前的每个步骤也都会显示为已完成。当 `stats` 为空时，统计信息行会完全隐藏；如果某条统计信息缺少 `added` 或 `removed`，则会省略计数中的对应部分，而不是将其显示为零。

## 示例

### 重新设置时间线样式

两个通道都会在根元素上接收 `className`。行、标签和闪烁标签都会读取 `surfaces.tsx` 中的共享令牌。

```tsx
<ToolTimeline className="max-w-none" /* ... */ />
```

### 仅显示最近的部分

面板会从数组开头开始显示步骤，因此应限制数组本身，而不只是限制 `visibleSteps`，这样才能在较长的运行过程中仅显示最近的步骤：

```tsx
<ToolTimeline steps={steps.slice(-6)} visibleSteps={6} /* ... */ />
```

## API 参考

<RuntimeMode>

### 消息状态

| 选择器 | 类型 | 描述 |
|----------|------|-------------|
| `s.message.parts` | `readonly ThreadAssistantMessagePart[]` | 消息中的每个部分。筛选 `part.type === "tool-call"` 以构建步骤列表。 |
| `s.message.status` | `MessageStatus \| undefined` | 消息仍在流式传输时的 `status?.type === "running"`。 |

这里没有专用的时间线原语：你需要自行编写从 `parts` 到 `steps` 和 `stats` 的映射，就像上面的 `toStep` 和 `toStats` 所做的那样。完整的 `ToolCallMessagePart` 结构请参阅 [工具 UI](/docs/tools/tool-ui)。

</RuntimeMode>

<StandaloneMode>

### ToolTimeline

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `steps` | `readonly TimelineStep[]` | 必填 | 按顺序排列的完整步骤列表。 |
| `visibleSteps` | `number` | 必填 | 从 `steps` 开始渲染的步骤数量。 |
| `streaming` | `boolean` | 必填 | 为 true 时，使触发器标签和最后一个可见步骤显示闪烁效果。 |
| `open` | `boolean` | 必填 | 是否展开披露面板。 |
| `onOpenChange` | `(open: boolean) => void` | 必填 | 点击触发器时调用。 |
| `restingLabel` | `string` | 必填 | `streaming` 为 false 后显示的触发器文本。 |
| `activeLabel` | `string` | 必填 | `streaming` 为 true 时显示的闪烁触发器文本。 |
| `stats` | `TimelineStat[]` | 必填 | 显示在步骤下方的文件变更标签。传入 `[]` 可省略该行。 |
| `className` | `string` | | 合并到根元素上。 |

`TimelineStep` 是 `{ verb: string; chip: string; icon: LucideIcon }`。`TimelineStat` 是 `{ file: string; added?: number; removed?: number }`。

</StandaloneMode>
