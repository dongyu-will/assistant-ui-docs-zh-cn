title: "上下文拆解"
description: "上下文窗口实际被什么占用：提示词、工具、文件、对话，以及剩余空间。"
---

一个带标签的条形图和图例，用于展示模型的上下文窗口被哪些内容占用；剩余余量会自动计算，而不是作为参数传入。在运行时环境中，其中两个标签来自线程每轮实际的 token 使用量；独立使用时，每个区段及其颜色都由你自行定义。

## 快速开始

<RuntimeMode>

在运行时环境中，assistant-ui 不会像此元素一样按类别标注上下文使用情况。`ChatModelAdapter` 能为每轮报告两个真实数值：输入 token 和输出 token，它们会附带在每条助手消息的生成步骤上。

<Steps>
  <Step>

### 推导实际存在的区段

将工具架构 token 与提示词的其余部分分开，或将文件与持续进行的对话分别计量，这种更细的拆分并不是线程状态所跟踪的内容：服务提供商会将输入报告为一个合并后的数值。请使用运行时能够告知你的两个区段；只有在你已经自行跟踪相关成本时，才将固定的、应用已知的区段（例如固定的系统提示词成本）一并添加。


```tsx title="components/assistant-ui/elements/thread-context-breakdown.tsx"
"use client";

import { useAuiState } from "@assistant-ui/react";
import {
  ContextBreakdown,
  type ContextSegment,
} from "@/components/assistant-ui/elements/context-breakdown";

function useTurnUsage() {
  return useAuiState((s) =>
    s.thread.messages.reduce(
      (sum, message) => {
        for (const step of message.metadata.steps ?? []) {
          sum.input += step.usage?.inputTokens ?? 0;
          sum.output += step.usage?.outputTokens ?? 0;
        }
        return sum;
      },
      { input: 0, output: 0 },
    ),
  );
}

const MODEL_CONTEXT_WINDOW = 128_000;

export function ThreadContextBreakdown() {
  const usage = useTurnUsage();
  const segments: ContextSegment[] = [
    { label: "Prompt", tokens: usage.input, tint: "bg-foreground/30" },
    { label: "Reply", tokens: usage.output, tint: "bg-blue-500/70" },
  ];
  return <ContextBreakdown segments={segments} limit={MODEL_CONTEXT_WINDOW} />;
}
```

</Steps>

独立使用时，`ContextBreakdown` 会渲染你传入的任意区段；它只会将这些区段的 token 总数与 `limit` 相比较，以计算条形图宽度和剩余余量。

### 传入区段和限制

```tsx title="app/context-panel.tsx"
"use client";

import { ContextBreakdown } from "@/components/assistant-ui/elements/context-breakdown";

const segments = [
  { label: "System prompt", tokens: 1_400, tint: "bg-foreground/20" },
  { label: "Tools", tokens: 3_100, tint: "bg-foreground/35" },
  { label: "Conversation", tokens: 42_000, tint: "bg-blue-500/70" },
];

export function ContextPanel() {
  return <ContextBreakdown segments={segments} limit={128_000} />;
```

## 组成结构

```tsx
<div data-slot="context-breakdown">
  <div>
    <span>Context</span>
    <span>{/* used / limit, amber past 85% */}</span>
  </div>
  <div>{/* stacked bar, one span per segment, widths from tokens / limit */}</div>
  <div>
    {/* one row per segment: dot, label, count */}
    <div>{/* Headroom row: fixed dot, limit minus used, clamped at 0 */}</div>
  </div>
</div>
```

余量不是需要传入的区段；它等于 `limit` 减去所有区段的 `tokens` 之和，结果取不小于零的值，并且不会拥有自己的条形图切片，只会显示为一行图例。零 `limit` 会被视为零压力，而不是用它进行除法，因此标题会保持普通样式，不会显示红色或异常的百分比。每个区段都会提供自己的 `tint`，这是条形图切片和图例圆点共同使用的 Tailwind 背景类，二者因此始终保持一致。

## 示例

### 选择色调

任何 Tailwind 背景工具类都可以使用；如上面的运行时示例所示，当区段的色调统一沿着透明度或色相变化时，显示效果会更加清晰。

```tsx
{ label: "Conversation", tokens: 42000, tint: "bg-blue-500/70" }
```

### 重新设置面板样式

```tsx
<ContextBreakdown className="max-w-xs gap-2" segments={segments} limit={limit} />
```

## API 参考

<RuntimeMode>

### 线程状态

| 选择器 | 类型 | 描述 |
|----------|------|-------------|
| `s.thread.messages` | `readonly MessageState[]` | 活动线程中的每条消息。每条助手消息的 `metadata.steps` 都是一个 `readonly ThreadStep[]`；当模型适配器报告相关信息时，一个步骤还可能携带 `usage: { inputTokens: number; outputTokens: number }`。 |

没有用于获取模型上下文窗口大小的选择器，也没有用于获取输入和输出之外的类别拆分的选择器；二者都按照上面的方式提供。

</RuntimeMode>

<StandaloneMode>

### ContextBreakdown

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `segments` | `readonly ContextSegment[]` | 必填 | 按堆叠顺序排列的窗口占用内容。余量会自动推导，而不是传入。 |
| `limit` | `number` | 必填 | 窗口大小。当区段总量超过窗口大小的 85% 时，标题会变为琥珀色。零限制会被视为零压力，而不是用它进行除法。 |
| `className` | `string` | | 合并到根元素上。 |

### ContextSegment

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `label` | `string` | 必填 | 此窗口切片所代表的内容，会显示在图例中。 |
| `tokens` | `number` | 必填 | 原始 token 数量。该元素会负责格式化。 |
| `tint` | `string` | 必填 | 条形图切片和图例圆点共同使用的背景类，确保二者始终一致。 |

所有其他 `div` 属性都会转发到根元素。

</StandaloneMode>
