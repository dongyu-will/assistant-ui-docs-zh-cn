---
title: "Markdown 文本"
description: "包含标题、列表、链接、表格和代码块的助手 Markdown。"
---

MarkdownText 将助手消息的文本部分渲染为格式化 Markdown：标题、强调、链接、列表、引用块、表格，以及带语言标签和复制按钮的围栏代码。它始终渲染当前消息部分；不存在独立的、由 props 驱动的形式。

## 入门

<RuntimeMode>

MarkdownText 通过 `MarkdownTextPrimitive` 读取当前消息部分，该 API 直接从部分的上下文中获取流式文本。它必须在文本部分内部渲染，因此需要作为该部分类型的渲染器接入，而不是单独挂载。

<Steps>
  <Step>

### 接入消息

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
import { MessagePrimitive } from "@assistant-ui/react";
import { MarkdownText } from "@/components/assistant-ui/elements/markdown-text";

function AssistantMessage() {
  return (
    <MessagePrimitive.Root>
      <MessagePrimitive.Parts components={{ Text: MarkdownText }} />
    </MessagePrimitive.Root>
  );
}
```

`Thread` 元素已经内置了这一组合，因此安装 `@assistant-ui/thread` 后即可获得格式化的助手消息，无需自行接入 MarkdownText。

  </Step>
  <Step>

### 添加语法高亮

MarkdownText 会为围栏代码渲染语言标签和复制按钮，但在接入高亮器之前，代码本身仍是纯文本。通过 `components` prop 传入高亮器，或安装已经接入高亮器的工具包：参见 [Shiki 高亮器](/elements/shiki-highlighter)（推荐，感知运行时）或 [Syntax 高亮器](/elements/syntax-highlighter)（基于 Prism）。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

单独使用时，MarkdownText 没有受控形式：它唯一的 prop 是 `components`，并且它渲染的文本始终来自周围的消息部分，而不是来自你传入的值。若要在消息部分之外渲染 Markdown，请直接渲染 `react-markdown`，就像 [生成式 UI](/elements/generative-ui) 的 `Markdown` 覆盖实现一样。

</StandaloneMode>

## 结构

```tsx
<div data-status="running">
  {/* data-status is "running" | "complete" | "incomplete" */}
  {/* one element per parsed markdown block: h1-h6, p, a, blockquote, ul, ol, hr, table, li, strong, sup */}
  <div> {/* aui-code-header-root: language label + copy button, one per fenced code block */}
    <span>{/* language */}</span>
    <button aria-label="Copy" />
  </div>
  <pre><code>{/* the fenced code's text, unhighlighted until you add a SyntaxHighlighter */}</code></pre>
</div>
```

根元素的 `data-status` 会反映部分的流式状态：文本仍在到达时为 `running`（或者在使用原语默认的平滑显示时，文本虽已到达但界面仍在追赶时也是如此）；稳定后为 `complete`；如果该部分提前结束，则为 `incomplete`。每个渲染的元素都带有 `aui-md-*` 类（`aui-md-h1`、`aui-md-p`、`aui-md-table` 等），因此你可以针对单个元素进行定位，而无需替换整组元素。行内代码会获得背景和圆角；围栏代码则不会，因为复制按钮和代码标题已经提供了外框。复制成功后三秒内，复制按钮会切换为勾选图标，随后恢复。

## 示例

### 覆盖单个元素

`components` 会合并到默认值上，因此传入一个键不会影响其余设置。

```tsx
import { MarkdownText } from "@/components/assistant-ui/elements/markdown-text";

<MarkdownText
  components={{
    a: ({ className, ...props }) => (
      <a {...props} className={className} target="_blank" rel="noreferrer" />
    ),
  }}
/>;
```

### 扩展代码块标题

`CodeHeader` 会渲染在每个围栏代码块上方、复制按钮旁边。替换它即可添加例如“运行”操作：

```tsx
import type { CodeHeaderProps } from "@assistant-ui/react-markdown";

const CustomCodeHeader = ({ language, code }: CodeHeaderProps) => (
  <div className="aui-code-header-root ...">
    <span>{language}</span>
    <button onClick={() => runSnippet(code)}>Run</button>
  </div>
);

<MarkdownText components={{ CodeHeader: CustomCodeHeader }} />;
```

### GitHub 风格 Markdown

表格、任务列表复选框、删除线和裸自动链接都能正常渲染，因为 `remarkGfm` 已经传递给 `MarkdownTextPrimitive`；对于包含这些内容的消息，无需额外设置。

```md
| Model | Context |
| ----- | ------- |
| gpt-5 | 400k    |

- [x] Ship the renderer
- [ ] Add highlighting

~~deprecated~~ · https://assistant-ui.com
```

## API 参考

<RuntimeMode>

### MarkdownTextPrimitive

| 部分 | 渲染内容 | 说明 |
|------|---------|-------|
| `MarkdownTextPrimitive` | `div` | 通过 `useMessagePartText()` 读取当前消息部分。`data-status` 会反映部分的流式状态。必须在文本（或推理）部分的作用域内渲染。 |

### MarkdownText

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `components` | `Parameters<typeof memoizeMarkdownComponents>[0]` | | 合并到默认元素渲染器（`h1`-`h6`、`p`、`a`、`blockquote`、`ul`、`ol`、`hr`、`table`、`th`、`td`、`tr`、`li`、`strong`、`sup`、`pre`、`code`、`CodeHeader`）。缺失的键会回退到默认值。`SyntaxHighlighter` 默认使用纯文本、无高亮的代码，除非你进行设置。 |

不存在 `className` prop。`smooth` 和 `defer` 是固定启用的：该原语始终会为流式文本设置动画，并以较低优先级延迟重新解析。

</RuntimeMode>

<StandaloneMode>

除 `components` 外，MarkdownText 没有独立使用时的其他 props，也没有可以在消息部分之外传入的内容。关于它读取的唯一内容，请参见上方的 `MarkdownTextPrimitive` 行；关于 `components`，请参阅运行时 API 参考。

</StandaloneMode>
