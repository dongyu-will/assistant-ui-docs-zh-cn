title: "流式文本"
description: "Token 轻柔抵达：最新词语落在蓝色中，并逐渐沉淀为墨色。"
---

文本逐词显示：流式传输期间，最新的几个词会染成蓝色，末尾带有插入符；较早的词会在接下来的几百毫秒内逐渐淡回普通文本。使用运行时（runtime）时，你只需向它传入某个 part 不断增长的文本及其运行状态；单独使用时，则需要自行保存 segments 和 reveal count。

## 开始使用

<RuntimeMode>

`MessagePrimitive.Parts` 会将 part 自身的字段作为 props 传给自定义 part renderer（part 渲染器），包括 `text` 和 `status`，因此完全不需要编写选择器：`count` 只需跟踪该字符串当前包含多少个词。

<Steps>
  <Step>

### 将其注册为 part renderer

```tsx title="components/assistant-ui/elements/streaming-text.tsx"
"use client";

import { useMemo } from "react";
import type { TextMessagePartComponent } from "@assistant-ui/react";
import { StreamingText, type Segment } from "@/components/assistant-ui/elements/streaming-text";

const StreamingTextPart: TextMessagePartComponent = ({ text, status }) => {
  const segments = useMemo<Segment[]>(() => [{ text }], [text]);
  const count = useMemo(() => text.split(" ").length, [text]);
  return <StreamingText segments={segments} count={count} streaming={status.type === "running"} />;
};
```

`TextMessagePartComponent` 与 `MessagePrimitive.Parts` 为其 `Text` 插槽所需的组件类型相同，因此两者之间不需要包装器或适配器。

  </Step>
  <Step>

### 将其接入 parts 列表

```tsx
import { MessagePrimitive } from "@assistant-ui/react";

<MessagePrimitive.Parts components={{ Text: StreamingTextPart, Reasoning: StreamingTextPart }} />
```

同一个组件可用于两个插槽：`ReasoningMessagePartComponent` 携带相同的 `text` 和 `status` 字段。当某个 part 的 `status.type` 变为 `"complete"` 后，插入符会消失，最后几个词也会自行沉淀为普通文本。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

单独使用时，由你决定 segments 的内容以及当前显示多少个词；该元素只负责淡出效果和着色。

<Steps>
  <Step>

### 保存 segments 和 reveal count

```tsx title="app/answer.tsx"
"use client";

import { useState } from "react";
import { StreamingText, type Segment } from "@/components/assistant-ui/elements/streaming-text";

const SEGMENTS: Segment[] = [
  { text: "The response streams in as" },
  { text: "useAuiState", mono: true },
  { text: "resolves each part." },
];

export function Answer() {
  const [count, setCount] = useState(0);
  return <StreamingText segments={SEGMENTS} count={count} streaming={count < 12} />;
}
```

对 segment 使用 `mono: true` 会将该段词语渲染在代码样式的 span 中；该样式会应用于该 segment 内的每个词。

  </Step>
  <Step>

### 手动推进计数

```tsx
useEffect(() => {
  const id = setInterval(() => setCount((c) => Math.min(c + 1, 12)), 90);
  return () => clearInterval(id);
}, []);
```

`count` 不会自行推进；超出范围的值会被限制，而不会抛出异常，因此可以安全地超额设置。

  </Step>
</Steps>

</StandaloneMode>

## 工作原理

```tsx
<p data-slot="streaming-text">
  {/* revealed words, newest two tinted while streaming */}
  <span aria-hidden />{/* caret, only while streaming and at least one word is shown */}
</p>
```

每个 segment 的文本都会按空格拆分，再重新连接为由单个空格分隔的词语：segment 自身的换行或连续空格不会保留在渲染结果中。`count` 会被限制在 0 到词语总数之间（负数或 `NaN` 计数不会显示任何内容，过大的计数则会显示全部内容）。当 `streaming` 为 `true` 时，当前显示的最后两个词会以着色显示；更早的词显示为普通文本，而已经超出末尾窗口的词会在 700ms 内过渡回普通文本，而不是立即切换。只有当 `streaming` 为 `true` 且至少显示一个词时，末尾插入符才会渲染。

## 示例

### 将文本范围标记为代码

```tsx
const segments: Segment[] = [
  { text: "Read the value from" },
  { text: "response.data", mono: true },
  { text: "before formatting it." },
];
```

### 重新设置文本样式

两种方式都可以在根元素上接收 `className`，其初始值为 `min-h-[8.5rem] max-w-sm text-sm leading-relaxed`。着色和插入符都固定使用 `text-blue-500`/`bg-blue-500`；这两种颜色均没有对应的 prop。

```tsx
<StreamingText className="max-w-none text-base" /* ... */ />
```

## API 参考

<RuntimeMode>

### Part renderer props

| Prop | 类型 | 描述 |
|------|------|-------------|
| `text` | `string` | 到目前为止通过流式传输得到的 part 字符串。 |
| `status` | `MessagePartStatus` | 在 part 完成前为 `status.type === "running"`。 |

这些字段会传入注册在 `MessagePrimitive.Parts` 的 `Text` 或 `Reasoning` 插槽下的任意组件；`TextMessagePartComponent` 和 `ReasoningMessagePartComponent` 都会携带这些字段。

</RuntimeMode>

<StandaloneMode>

### StreamingText

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `segments` | `Segment[]` | 必填 | `{ text: string; mono?: boolean }[]`，按空格拆分并连接成一个词语流。 |
| `count` | `number` | 必填 | 要显示的词数，限制在 0 到词语总数之间。 |
| `streaming` | `boolean` | 必填 | 为当前显示的最新两个词着色，并渲染末尾插入符。 |
| `className` | `string` | | 合并到根元素上。 |

除 `children`、`segments`、`count` 和 `streaming` 外，所有其他 `p` props 都会转发到根元素。

</StandaloneMode>
