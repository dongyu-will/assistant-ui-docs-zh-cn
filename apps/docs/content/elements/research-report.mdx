ResearchReport 是一个实时大纲：一个标题列表，用于在助手处理过程中跟踪待处理、编写中和已完成状态，并显示每节的来源数量。在运行时中，模型写入内容时，各节会以流式方式传输；单独使用时，你已经持有完整列表。

## 快速开始

<RuntimeMode>

assistant-ui 会在模型写入工具调用的参数时，以部分 JSON 的形式流式传输这些参数，因此报告本身可以直接作为参数，而不必等待完成的结果后再显示。要求模型以结构化的 `args` 形式返回报告，并实时读取这些内容。

<Steps>
  <Step>

### 渲染实时参数

```tsx title="components/assistant-ui/elements/write-report-tool-ui.tsx"
"use client";

import type { ToolCallMessagePartComponent } from "@assistant-ui/react";
import {
  ResearchReport,
  type ReportSection,
} from "@/components/assistant-ui/elements/research-report";

type WriteReportArgs = {
  title: string;
  sections: ReportSection[];
  sourcesRead: number;
};

export const WriteReportToolUI: ToolCallMessagePartComponent<
  WriteReportArgs,
  void
> = ({ args }) => (
  <ResearchReport
    title={args.title ?? "Untitled report"}
    sections={args.sections ?? []}
    sourcesRead={args.sourcesRead ?? 0}
  />
);
```

`args` 是工具调用处于 `running` 状态时的部分解析结果：模型写入前，`title` 可能会被 `undefined`，`sections` 可能比最终列表更短，而最后一项的 `preview` 可能只是写到一半的句子。回退值可以避免因某个字段尚未传输到而导致渲染中断。

  </Step>
  <Step>

### 注册工具

此工具不需要执行任何操作：报告就是参数本身，而不是之后再获取的内容。让 schema 与 `ReportSection` 具有相同的形状，这样模型自身的输出就已经携带了 `state`。

```tsx title="app/toolkit.ts"
import { defineToolkit } from "@assistant-ui/react";
import { z } from "zod";
import { WriteReportToolUI } from "@/components/assistant-ui/elements/write-report-tool-ui";

const section = z.object({
  id: z.string(),
  heading: z.string(),
  state: z.enum(["pending", "writing", "done"]),
  sources: z.number(),
  preview: z.string().optional(),
});

export const toolkit = defineToolkit({
  write_report: {
    type: "frontend",
    description: "Write a structured research report, section by section.",
    parameters: z.object({
      title: z.string(),
      sections: z.array(section),
      sourcesRead: z.number(),
    }),
    execute: async () => {},
    render: WriteReportToolUI,
  },
});
```

`execute` 不执行任何工作；它只是让工具调用在模型完成写入后结束，与其他前端工具相同。使用 `Tools({ toolkit })` 接入工具包；参见 [工具 UI](/docs/tools/tool-ui)。

  </Step>
</Steps>

### 保存各节

```tsx title="app/report.tsx"
"use client";

import { useState } from "react";
import {
  ResearchReport,
  type ReportSection,
} from "@/components/assistant-ui/elements/research-report";

const INITIAL: ReportSection[] = [
  {
    id: "intro",
    heading: "Why this matters",
    state: "done",
    sources: 3,
    preview: "Three independent benchmarks agree on the direction.",
  },
  { id: "method", heading: "How it was measured", state: "writing", sources: 1 },
  { id: "results", heading: "Results", state: "pending", sources: 0 },
];

export function Report() {
  const [sections, setSections] = useState(INITIAL);
  return (
    <ResearchReport title="Adoption trends" sections={sections} sourcesRead={7} />
  );
}
```

### 推进一节

完成一节并开始下一节，实际上是对同一个数组进行两次写入。

```tsx
function finishSection(id: string, preview: string) {
  setSections((prev) => {
    const i = prev.findIndex((section) => section.id === id);
    return prev.map((section, j) => {
      if (j === i) return { ...section, state: "done", preview };
      if (j === i + 1) return { ...section, state: "writing" };
      return section;
    });
  });
}
```

  </Step>

## 结构

```tsx
<div data-slot="research-report">
  <div>
    <span>{title}</span>
    <span>{/* "D/T sections · S sources read" */}</span>
  </div>
  <div>
    {/* one row per section, top-bordered except the first */}
    <span>{/* check, spinner, or pending dot */}</span>
    <span>{/* heading */}</span>
    <span>{/* "N src", only when sources > 0 */}</span>
    <p>{/* preview, only when present */}</p>
  </div>
</div>
```

标题中的 `done` 数量是通过筛选 `sections` 中的 `state === "done"` 计算得出的；`sourcesRead` 是你单独提供的数字，永远不会与每节自身的 `sources` 交叉校验。标题亮度表示两种状态，而不是三种：`pending` 会使标题变暗，而 `writing` 和 `done` 都会以完全不透明的效果渲染标题，因此只有标题旁的图标——静态圆点、旋转加载器或勾号——能够区分编写中和已完成状态。只有当某节的来源数量大于零时，才会渲染该数量；`0` 会被隐藏，而不是显示为 `0 src`。`preview` 仅在字符串非空时渲染；显式传入空字符串时，其效果与省略该字段相同，都会将其隐藏。第一节的行没有顶部边框；之后的每一节都有顶部边框。空的 `sections` 数组只会渲染标题，显示 `0/0 sections`，不会显示占位行。

## 示例

### 节状态来自模型，而不是 assistant-ui

<RuntimeMode>

`state` 是模型作为 `sections` 一部分写入的普通数据；assistant-ui 不会自行根据流式传输进度推断待处理、编写中或已完成状态。如果你不希望依赖模型准确地自我报告，`useToolArgsStatus` 会报告整个 `sections` 参数是否已经完成流式传输。工具调用结束后，你可以用它强制将每一节设置为 `"done"`，而不考虑模型为各项写入了什么状态。

```tsx
import { useToolArgsStatus } from "@assistant-ui/react";

function useIsReportSettled() {
  const { status } = useToolArgsStatus<WriteReportArgs>();
  return status === "complete";
}
```

</RuntimeMode>

### 重新设置报告样式

两条样式通道都会在根元素上接收 `className`。标题元信息行和每节的来源数量读取共享的 `mono` token，而卡片本身读取 `paper`；两者都来自 `surfaces.tsx`。

```tsx
<ResearchReport className="max-w-none p-6" /* ... */ />
```

## API 参考

<RuntimeMode>

### 工具调用渲染属性

| 属性 | 类型 | 描述 |
|------|------|-------------|
| `args` | `TArgs` | 已解析的参数。模型仍在流式传输参数时，该值是部分内容。 |
| `argsText` | `string` | 模型流式传输的原始 JSON 参数文本。 |
| `result` | `TResult \| undefined` | 工具完成后的返回值。运行期间为 `undefined`。 |
| `status` | `ToolCallMessagePartStatus` | `status.type` 的值为 `"running"`、`"requires-action"`、`"complete"` 或 `"incomplete"`。 |
| `toolName` | `string` | 模型调用的工具名称。 |
| `toolCallId` | `string` | 此次调用的稳定 ID。 |
| `isError` | `boolean \| undefined` | `result` 是否表示工具执行错误。 |

将渲染器注册到工具包条目的 `render` 字段，并使用 `Tools({ toolkit })` 接入工具包。完整的渲染属性列表请参见[工具 UI](/docs/tools/tool-ui)，其中包括 `addResult`、人工工具和审批门。

</RuntimeMode>

<StandaloneMode>

### ResearchReport

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `title` | `string` | 必填 | 报告标题。它会覆盖原生的 `title` 属性，该属性不会被转发到其他属性中。 |
| `sections` | `readonly ReportSection[]` | 必填 | 按顺序排列的大纲。 |
| `sourcesRead` | `number` | 必填 | 标题元信息行中显示的来源总数。独立于每节自身的 `sources`。 |
| `className` | `string` | | 合并到根元素上。 |

### ReportSection

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `id` | `string` | |
| `heading` | `string` | |
| `state` | `"pending" \| "writing" \| "done"` | 控制状态图标和标题亮度。 |
| `sources` | `number` | 每节的引用数量。`0` 时隐藏。 |
| `preview` | `string`（可选） | 字符串非空后显示在标题下方。 |

所有其他 `div` 属性都会被转发到根元素，但 `title` 除外；该属性会被组件自身的属性替换。

</StandaloneMode>
