将两个选项并列展示，每个选项都有自己的特征，其中一个被标记为最终选择，并在下方用一句话说明选择理由。在运行时中，比较结果来自模型一次完成的工具调用；单独使用时，则由你自行提供选项和理由。

## 快速开始

<RuntimeMode>

此元素没有自己的 assistant-ui 原语，因此运行时接入使用的是工具渲染器，而不是原语组合。比较结果没有自然的逐行展示过程：随着 JSON 流式传输，选项卡片以乱序填充，看起来会像是渲染出错，而不是渐进式展示。因此，在这些情况下，值得等待调用完成后再挂载任何内容。

<Steps>
  <Step>

### 注册渲染函数

```tsx title="app/toolkit.tsx"
"use client";

import { defineToolkit } from "@assistant-ui/react";
import { ComparisonCard } from "@/components/assistant-ui/elements/comparison-card";

export const toolkit = defineToolkit({
  compare_options: {
    type: "backend",
    render: ({ args, status }) => {
      if (status.type !== "complete") return null;
      return <ComparisonCard {...args} />;
    },
  },
});
```

在 `status.type` 为 `"complete"` 之前返回 `null`，可以让卡片使用最终参数挂载一次，而不是在每次部分解析后都重新渲染。有关通用模式，请参阅[延迟渲染](/docs/tools/tool-ui#deferred-rendering)。

  </Step>
  <Step>

### 让消息列表进行渲染

```tsx title="app/MyRuntimeProvider.tsx"
import {
  AssistantRuntimeProvider,
  AuiConfig,
  Tools,
} from "@assistant-ui/react";
import { useChatRuntime } from "@assistant-ui/ai-sdk";
import { toolkit } from "./toolkit";

export function MyRuntimeProvider({
  children,
}: {
  children: React.ReactNode;
}) {
  const runtime = useChatRuntime();
  const config = AuiConfig({ tools: Tools({ toolkit }) });
  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

注册工具包后，`Thread` 以及任何基于 assistant-ui 消息部分原语构建的自定义消息列表（`MessagePrimitive.Parts` 或 `MessagePrimitive.GroupedParts`），都会在消息中出现 `compare_options` 调用的位置自动渲染已注册的 UI，因此无需手动放置任何内容。

  </Step>
</Steps>

</RuntimeMode>

### 直接传入选项

```tsx title="app/runtime-choice.tsx"
"use client";

import {
  ComparisonCard,
  type ComparisonOption,
} from "@/components/assistant-ui/elements/comparison-card";

const traitLabels = ["Streaming", "Multi-thread", "Self-hosted"] as const;

const options: readonly ComparisonOption[] = [
  {
    id: "local",
    name: "Local runtime",
    headline: "You own the loop",
    traits: ["Streams", "Multi-thread", "Self-hosted"],
  },
  {
    id: "external",
    name: "External store",
    headline: "Your state is the source",
    traits: ["Streams", "Multi-thread", false],
  },
];

export function RuntimeChoice() {
  return (
    <ComparisonCard
      traitLabels={traitLabels}
      options={options}
      recommendedId="local"
      reason="You already hold messages in your own store, but you want the runtime to drive streaming and branching, so the local runtime costs you less wiring."
    />
  );
}
```

  </Step>
  <Step>

### 将最终选择指向其他选项

根据比较结果的决定来源，重新计算 `recommendedId` 和 `reason`；卡片自身不会记住之前的选择。

```tsx
export function RuntimeChoice({ selfHostedOnly }: { selfHostedOnly: boolean }) {
  const recommendedId = selfHostedOnly ? "local" : "external";
  const reason = selfHostedOnly
    ? "Local keeps everything on your own infrastructure, which is what self-hosted rules out for the other option."
    : "External store fits well once your own service already owns message state.";

  return (
    <ComparisonCard
      traitLabels={traitLabels}
      options={options}
      recommendedId={recommendedId}
      reason={reason}
    />
  );
}
```

  </Step>
</Steps>

</StandaloneMode>

## 组成结构

```tsx
<div data-slot="comparison-card">
  <div>
    {/* one card per option, in array order */}
    <div>
      <span>{/* option.name */}{/* "pick" label when recommended */}</span>
      <span>{/* option.headline */}</span>
      <div>
        {/* one row per traitLabels[i], paired with option.traits[i] */}
        <span>{/* check or minus icon */}</span>
        <span>{/* trait value when present, else the trait label, dimmed */}</span>
      </div>
    </div>
  </div>

  <p>{/* reason */}</p>
</div>
```

与其他结构化输出元素不同，该元素既不接受 `visibleCount`，也不接受 `take()`：你传入的数组中的每个选项和每个特征行都会无条件渲染。选项是否为推荐项完全由 `option.id === recommendedId` 决定，因此，如果某个 id 与任何选项都不匹配，所有卡片都会保持未着色状态，任何地方都不会显示“最终选择”标签；不存在备用高亮。仅当 `option.traits[i]` 为真值时，特征才会被视为存在：传入 `false`，或者让 `traits` 短于 `traitLabels`，该行就会显示该特征自身的标签，并在减号图标后以变暗样式呈现，而不是显示选项的值。

## 示例

### 将特征标记为不存在

不存在的特征不是空字符串，而是 `false` 或缺失的数组项。两种情况都会回退到共享的 `traitLabels` 条目，并以变暗样式显示，因此该行仍会说明选项缺少什么，而不是留下空白。

```tsx
const options: readonly ComparisonOption[] = [
  { id: "a", name: "Plan A", headline: "Everything included", traits: ["Streams", "Multi-thread", "Self-hosted"] },
  { id: "b", name: "Plan B", headline: "Lighter footprint", traits: ["Streams", false] },
];
```

### 比较结果的来源

<RuntimeMode>

模型会自行分析这些选项，因此后端无需查询任何内容；`execute` 只需返回参数，以满足类型系统和线格式的要求。

```ts title="app/api/chat/route.ts"
compare_options: tool({
  description: "Compare two options and name the one you would pick.",
  inputSchema: z.object({
    traitLabels: z.array(z.string()),
    options: z.array(
      z.object({
        id: z.string(),
        name: z.string(),
        headline: z.string(),
        traits: z.array(z.union([z.string(), z.literal(false)])),
      }),
    ),
    recommendedId: z.string(),
    reason: z.string(),
  }),
  execute: async (args) => args,
}),
```

</RuntimeMode>

<StandaloneMode>

当比较结果来自你自己的数据，而不是固定常量时，请同时推导 `options` 和 `recommendedId`，这样它们就不会对推荐的选项 id 产生分歧。

```tsx
const options = plans.map((plan) => ({
  id: plan.id,
  name: plan.name,
  headline: plan.headline,
  traits: traitLabels.map((label) => plan.traits[label] ?? false),
}));
const recommendedId = pickBestPlan(plans).id;
```

</StandaloneMode>

### 重新设置卡片样式

两个区域的根元素都接受 `className`。“最终选择”标签使用共享的 `mono` 表面，非推荐选项的卡片使用共享的 `field` 表面；二者都来自 `surfaces.tsx`。因此，重新设置这些设计令牌的样式，就会重新设置所有使用它们的元素。

```tsx
<ComparisonCard className="max-w-lg gap-4" /* ... */ />
```

## API 参考

<RuntimeMode>

### 渲染属性

| 属性 | 类型 | 描述 |
|------|------|-------------|
| `args` | `{ traitLabels: string[]; options: ComparisonOption[]; recommendedId: string; reason: string }` | 工具的参数；当 `status.type` 为 `"running"` 时，这些参数是部分解析结果。 |
| `status` | `ToolCallMessagePartStatus` | 模型仍在发出 `args` 时为 `"running"`，调用完成后为 `"complete"`。请根据 `"complete"` 控制渲染，以避免显示未构建完成的卡片。 |

### compare_options 参数

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `traitLabels` | `string[]` | 按列顺序显示在每个选项中的特征名称。 |
| `options[].id` | `string` | 与 `recommendedId` 匹配，以决定高亮哪个卡片。 |
| `options[].name` | `string` | 选项的名称。 |
| `options[].headline` | `string` | 名称下方的一行文字。 |
| `options[].traits` | `(string \| false)[]` | 与 `traitLabels` 按位置对应；`false` 或缺失的条目会将该特征渲染为不存在。 |
| `recommendedId` | `string` | 要高亮为最终选择的选项的 `id`。 |
| `reason` | `string` | 卡片下方用于说明选择理由的句子。 |

</RuntimeMode>

<StandaloneMode>

### ComparisonCard

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `traitLabels` | `readonly string[]` | 必填 | 按列顺序显示在每个选项中的特征名称。 |
| `options` | `readonly ComparisonOption[]` | 必填 | 要比较的选项，按数组顺序渲染。 |
| `recommendedId` | `string` | 必填 | 要高亮为最终选择的选项的 `id`。 |
| `reason` | `string` | 必填 | 卡片下方用于说明选择理由的句子。 |
| `className` | `string` | | 合并到根元素上。 |

其他所有 `div` 属性都会转发到根元素。

### ComparisonOption

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `id` | `string` | 与 `recommendedId` 匹配，以决定高亮哪个卡片。 |
| `name` | `string` | 选项的名称。 |
| `headline` | `string` | 名称下方的一行文字。 |
| `traits` | `readonly (string \| false)[]` | 与 `traitLabels` 按位置对应；`false` 或缺失的条目会将该特征渲染为不存在。 |

</StandaloneMode>
