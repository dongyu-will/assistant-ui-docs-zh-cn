---
title: "Shiki 高亮器"
description: "使用 Shiki 进行代码高亮，并将标记化延迟到消息部分稳定后执行。"
---

SyntaxHighlighter 使用 Shiki 为一个 fenced code block 进行标记化；当 `streaming` 为 true 时会完全跳过高亮，并渲染 Shiki 稍后将进行标记化的相同纯文本代码。在运行时中，它会从活动消息部分派生此标志；单独使用时，则由你自行传入 `streaming`。

## 快速开始

<RuntimeMode>

该工具包封装了基础高亮器，并读取当前消息部分是否仍在运行，因此不会将 Shiki 的处理时间浪费在即将再次变化的代码上。

<Steps>
  <Step>

### 将其添加到 MarkdownText 的组件中

```tsx title="components/assistant-ui/elements/markdown-text.tsx"
import { SyntaxHighlighter } from "./shiki-highlighter.aui";

const defaultComponents = memoizeMarkdownComponents({
  SyntaxHighlighter,
  h1: /* ... */,
  // ...other elements...
});
```

助手消息中的每个 fenced code block 现在都会使用 Shiki 进行高亮，并跳过仍在流式传输的代码块的标记化。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

单独使用时，由你自行管理流式传输标志。

<Steps>
  <Step>

### 使用受控的流式传输标志渲染代码

```tsx
import { SyntaxHighlighter } from "@/components/assistant-ui/elements/shiki-highlighter";

<SyntaxHighlighter language="tsx" code={code} streaming={isStreaming} />;
```

当 `streaming` 为 true 时，代码会在同一容器中以纯文本形式渲染，不进行高亮；源代码确定后，将其切换为 `false`，代码便会进行标记化。

  </Step>
</Steps>

</StandaloneMode>

## 组成

```tsx
<div className="aui-shiki-base">
  {/* streaming: <pre><code>{code}</code></pre>, unhighlighted */}
  {/* settled: useShikiHighlighter's tokenized output */}
</div>
```

当 `streaming` 时，根元素还会获得 `aui-shiki-streaming` 类，并将去除首尾空白的源代码渲染为纯 `<pre><code>`。当 `streaming` 为 false 后，`useShikiHighlighter` 会对代码进行标记化；在此完成之前，会显示相同的纯文本回退内容，因此两种状态切换之间不会闪现空内容。

## 示例

### 设置固定主题

```tsx
<SyntaxHighlighter language="tsx" code={code} theme="github-dark-default" />
```

默认值为 `{ dark: "github-dark-default", light: "github-light-default" }`。传入单个主题名称，可在两种模式下固定使用同一个主题；也可以传入用于多主题输出的 `{ light, dark, ... }` 映射。

### 调整流式传输延迟

```tsx
<SyntaxHighlighter language="tsx" code={code} delay={0} />
```

`delay`（默认值为 `150`）表示代码最后一次变化后，`useShikiHighlighter` 等待多少毫秒再进行标记化。默认值可以吸收平滑文本显示在底层消息部分已经稳定后逐渐输出的最后几个字符。

### 重新设置容器样式

两条路径都会在根元素上接收 `className`；渲染出的 `<pre>` 会从固定的 `aui-shiki-base` 选择器中获取边框、背景和内边距样式。

```tsx
<SyntaxHighlighter className="[&_pre]:rounded-none" language="tsx" code={code} />
```

## API 参考

<RuntimeMode>

### 消息部分状态

| 选择器 | 类型 | 描述 |
|----------|------|-------------|
| `s.optional.part?.status.type === "running"` | `boolean` | 使用 `useAuiState` 读取。转发为 `streaming`。当当前消息部分存在且正在运行时为 `true`。 |

下面的其他所有 prop 都会原样转发。`node` 和 `components`（react-markdown 的代码块包装器 prop）会被接受，以便与 `MarkdownText` 的 `SyntaxHighlighter` 插槽保持类型兼容，但除此之外不会使用。

</RuntimeMode>

### SyntaxHighlighter

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `code` | `string` | 必填 | 要高亮的代码。渲染前会去除首尾空白。 |
| `language` | `ShikiHighlighterProps["language"]` | 必填 | 传递给 `useShikiHighlighter`。 |
| `theme` | `ShikiHighlighterProps["theme"]` | `{ dark: "github-dark-default", light: "github-light-default" }` | 单个主题名称或 `{ light, dark, ... }` 映射。 |
| `streaming` | `boolean` | `false` | 当 `true` 时跳过标记化并渲染纯文本代码。 |
| `delay` | `number` | `150` | `useShikiHighlighter` 在 `code` 最后一次变化后等待的毫秒数，然后再进行标记化。 |
| `className` | `string` | | 合并到根元素上。 |

其他所有 `react-shiki` 选项（`showLineNumbers`、`langStyle`、Shiki 自身的 `codeToHast` 选项等）都会直接转发给 `useShikiHighlighter`；但 `addDefaultStyles` 和 `showLanguage` 除外。react-shiki 仅使用它们提供自身的默认样式和语言标签；此组件不会提供这两项，因此它们会被接受但忽略。

<StandaloneMode>

如上面的单独使用步骤所示，自行传入 `streaming`；其他每个 prop 的行为都与运行时路径相同。

</StandaloneMode>
