专为手机设计的输入框：键盘弹出后会收起到一旁的快捷操作行、附件按钮、单行输入框，以及在运行过程中变为停止按钮的发送按钮。使用运行时时，每个部分都是已经连接到发送、取消和附件功能的输入框原语；单独使用时，则需要自行管理文本、运行标志和所有回调。

## 开始使用

<RuntimeMode>

`ComposerPrimitive.Root`、`.Input`、`.AddAttachment`、`.Send` 和 `.Cancel` 已经自行管理文本、附件流程以及发送/取消门控，因此此输入栏完全不需要手动处理 `value`、`onValueChange`、`onSend` 或 `onStop`；它只需要布局和运行标志，以便在 Send 和 Cancel 之间进行选择。

### 使用输入框原语组合输入栏

```tsx title="components/assistant-ui/elements/mobile-composer-bar.tsx"
"use client";

import { ArrowUpIcon, MicIcon, PlusIcon, SquareIcon } from "lucide-react";
import { ComposerPrimitive, ThreadPrimitive, useAuiState } from "@assistant-ui/react";
import { cn } from "@/lib/utils";
import { field, ghostButton, inkButton, mono } from "@/components/assistant-ui/elements/surfaces";

const ACTIONS = ["Summarize", "Translate", "Explain"];

export function MobileComposerBar({ keyboardOpen }: { keyboardOpen: boolean }) {
  const isRunning = useAuiState((s) => s.thread.isRunning);
  const isEmpty = useAuiState((s) => s.composer.isEmpty);

  return (
    <ComposerPrimitive.Root
      className={cn(
        "bg-background border-foreground/[0.07] flex w-full max-w-[19rem] flex-col gap-2.5 rounded-t-[20px] border-t px-3 pt-3",
        keyboardOpen ? "pb-3" : "pb-6",
      )}
    >
      {!keyboardOpen && (
        <div className="-mx-3 flex gap-1.5 overflow-x-auto px-3 pb-0.5">
          {ACTIONS.map((action) => (
            <ThreadPrimitive.Suggestion
              key={action}
              prompt={action}
              className={cn(field, "text-foreground/60 shrink-0 rounded-full px-3 py-1.5 text-xs whitespace-nowrap")}
            >
              {action}
            </ThreadPrimitive.Suggestion>
          ))}
        </div>
      )}

      <div className="flex items-end gap-2">
        <ComposerPrimitive.AddAttachment className={cn(ghostButton, field, "size-9 shrink-0")}>
          <PlusIcon className="size-4" />
        </ComposerPrimitive.AddAttachment>

        <div className={cn(field, "flex min-w-0 flex-1 items-center gap-2 rounded-[18px] px-3 py-2")}>
          <ComposerPrimitive.Input
            placeholder="Message"
            className="text-foreground/85 placeholder:text-foreground/30 min-w-0 flex-1 resize-none bg-transparent text-[16px] outline-none"
          />
          {isEmpty && <MicIcon className="text-foreground/35 size-4 shrink-0" />}
        </div>

        {isRunning ? (
          <ComposerPrimitive.Cancel className={cn(inkButton, "flex size-9 shrink-0 items-center justify-center rounded-full")}>
            <SquareIcon className="size-3 fill-current" />
          </ComposerPrimitive.Cancel>
        ) : (
          <ComposerPrimitive.Send className={cn(inkButton, "flex size-9 shrink-0 items-center justify-center rounded-full")}>
            <ArrowUpIcon className="size-4" />
          </ComposerPrimitive.Send>
        )}
      </div>

      {!keyboardOpen ? (
        <span aria-hidden className="bg-foreground/15 mx-auto h-1 w-28 rounded-full" />
      ) : (
        <span className={cn(mono, "text-foreground/25 text-center")}>return to send</span>
      )}
    </ComposerPrimitive.Root>
  );
}
```

`ComposerPrimitive.Root` 会渲染一个 `<form>`，因此 `ComposerPrimitive.Input` 自带的按 Enter 发送功能已经会通过它触发；这里不需要重新实现独立元素手动编写的按键处理逻辑。`keyboardOpen` 仍然必须从外部提供，通常来自输入框原生的 focus 和 blur 事件，或来自 `visualViewport` 监听器，因为运行时状态不会跟踪屏幕键盘是否已弹出。

</Steps>

### 保存输入框状态

```tsx title="app/mobile-bar.tsx"
"use client";

import { useState } from "react";
import { MobileComposer } from "@/components/assistant-ui/elements/mobile-composer";

export function MobileBar() {
  const [value, setValue] = useState("");
  const [running, setRunning] = useState(false);
  const [keyboardOpen, setKeyboardOpen] = useState(false);

  return (
    <MobileComposer
      value={value}
      keyboardOpen={keyboardOpen}
      running={running}
      actions={["Summarize", "Translate", "Explain"]}
      onAction={(action) => setValue(action)}
      onAttach={() => console.log("attach")}
      onValueChange={setValue}
      onSend={() => {
        setRunning(true);
        setValue("");
      }}
      onStop={() => setRunning(false)}
      onFocus={() => setKeyboardOpen(true)}
    />
  );
}
```

## 结构

```tsx
<div data-slot="mobile-composer">
  {/* quick actions, hidden entirely while keyboardOpen */}
  <div>{/* one button per action, disabled together when onAction is absent */}</div>
  <div>
    <button aria-label="Add an attachment" />
    <input aria-label="Message" placeholder="Message" />
    {/* mic icon, only while the input is empty */}
    <button aria-label="Stop | Send" />
  </div>
  {/* a grabber handle, or "return to send", never both */}
</div>
```

独立元素会渲染单行 `<input>`；上面的运行时组合会渲染 `ComposerPrimitive.Input`，也就是可以扩展到多行的自动调整大小的 `<textarea>`，这与目录中每个输入框所采用的取舍相同。只有在 `!running && value !== ""` 时，按 Enter 才会触发发送。未运行时，按钮使用相同的空值门控（仅在 `value === ""` 时禁用）；运行时，按键和按钮都不再表示“发送”，因为按钮的标签、图标和处理器已经切换为 Stop。附件按钮和所有操作芯片仅根据是否传入了对应的处理器 prop 一起禁用（`onAttach`、`onAction`）；它们不会自行响应 `running` 或 `value`，因此在运行期间对它们进行门控是调用方的责任。麦克风图标以及发送/停止图标的切换纯粹用于呈现：这里不会启动听写，停止图标也不代表取消已经发生，只表示已调用 `onStop`。

## 示例

### 重新设置输入栏样式

两种方案都会在根元素上接收 `className`。附件、输入框和操作芯片表面都会读取共享的 `field` token，发送按钮则读取 `inkButton`，因此重新设置这两个 token 的主题即可覆盖整个输入栏。

```tsx
<MobileComposer className="max-w-xs" /* ... */ />
```

### 连接感知键盘状态的布局

<RuntimeMode>

由于 `keyboardOpen` 并非运行时状态，应从平台获取它：可以在输入框的 focus 和 blur 事件中切换它；或者在移动端 Web 上，为获得更准确的信号，可以使用 `window.visualViewport` 的 `resize` 事件，将视口高度与布局高度进行比较。

</RuntimeMode>

<StandaloneMode>

上面的示例将 `keyboardOpen` 与输入框的 `onFocus` 关联起来，这已经足够应对大多数情况；再次关闭它（在 blur 时，或通过虚拟键盘自身的收起操作）需要由你自行处理，因为该元素没有自己的 blur 回调。

</StandaloneMode>

## API 参考

<RuntimeMode>

### ComposerPrimitive

| 部件 | 渲染内容 | 说明 |
|------|---------|-------|
| `Root` | `form` | 处理提交发送，并在点击空白区域时聚焦输入框。 |
| `Input` | `textarea`（自动调整大小） | 根据 `s.composer.text` 控制自身的值；除非按住 Shift，否则按 Enter 会提交最近的表单。 |
| `AddAttachment` | `button` | 打开文件选择器，并将每个文件添加为附件。当输入框不处于编辑模式时禁用。 |
| `Send` | `button` | 发送输入框内容。当 `s.composer.canSend` 为 false（为空、不在编辑状态或线程禁止发送），或在不支持排队时有任务正在运行，都会禁用。 |
| `Cancel` | `button` | 取消正在运行的任务。当 `s.composer.canCancel` 为 false 时禁用，其中包括“没有可取消的任务”的情况。 |

快捷操作芯片是 `ThreadPrimitive.Suggestion`，与 [启动器](/elements/launcher-bubble) 用于其初始提示的原语相同；默认情况下，它会替换输入框文本，而不是直接发送。

### 线程和输入框状态

| 选择器 | 类型 | 描述 |
|----------|------|-------------|
| `s.thread.isRunning` | `boolean` | 是否显示 Cancel 以替代 Send。 |
| `s.composer.isEmpty` | `boolean` | 是否显示麦克风操作入口以替代空白区域。 |

</RuntimeMode>

<StandaloneMode>

### MobileComposer

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `value` | `string` | 必填 | 输入框的值。 |
| `keyboardOpen` | `boolean` | 必填 | 隐藏快捷操作行，并将拖拽条替换为“返回发送”提示。 |
| `running` | `boolean` | 必填 | 将发送按钮替换为停止按钮，并阻止按 Enter 发送。 |
| `actions` | `readonly string[]` | 必填 | 显示在输入框上方的快捷操作标签。 |
| `onAction` | `(action: string) => void` | | 按下操作芯片时，使用该操作的标签调用。未提供时会禁用所有芯片。 |
| `onAttach` | `() => void` | | 按下附件按钮时调用。未提供时会禁用该按钮。 |
| `onValueChange` | `(value: string) => void` | | 每次输入发生变化时调用。 |
| `onSend` | `() => void` | | 在按 Enter（可发送时）或按发送按钮时调用。 |
| `onStop` | `() => void` | | 当 `running` 为 true 时，通过按钮调用。 |
| `onFocus` | `() => void` | | 输入框获得焦点时调用。 |
| `className` | `string` | | 合并到根元素上。 |

其他所有 `div` props 都会转发到根元素。

</StandaloneMode>
