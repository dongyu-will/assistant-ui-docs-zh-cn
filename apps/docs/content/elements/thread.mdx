Thread 是完整的聊天界面：消息列表、输入框、自动滚动，以及欢迎、加载历史记录和运行中状态，全部连接到一个运行时。它没有独立的表单，因为它渲染的所有内容都来自实时线程状态，而不是你需要传入的 props。

## 开始使用

<RuntimeMode>

`Thread`除了组件树上层的运行时提供器外，不需要任何其他配置。

<Steps>
  <Step>

### 在应用中使用

```tsx title="app/page.tsx"
import { Thread } from "@/components/assistant-ui/elements/thread.aui";

export default function Chat() {
  return (
    <div className="h-full">
      <Thread />
    </div>
  );
}
```

需要一个 `AssistantRuntimeProvider` 祖先组件；`Thread` 本身不接收运行时 prop，而是读取最近的运行时。

  </Step>
  <Step>

### 覆盖插槽

```tsx
import {
  Thread,
  type ThreadComponents,
} from "@/components/assistant-ui/elements/thread.aui";

const THREAD_COMPONENTS: ThreadComponents = {
  ToolFallback: MyToolFallback,
  ToolGroup: MyToolGroup,
};

export default function Chat() {
  return <Thread components={THREAD_COMPONENTS} />;
}
```

在模块作用域中定义一次 `components`，或对其进行记忆化，以免父组件每次重新渲染时消息子树也重新渲染。对于按工具定制的 UI，建议按工具名称注册渲染器，而不是覆盖 `ToolFallback`：按照 [工具 UI](/docs/tools/tool-ui) 中的说明，将 `render` 放到匹配的工具包条目上。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

Thread 没有由 props 驱动的对应组件：欢迎屏幕、消息列表、流式传输状态和输入框都来自实时线程状态，而不是你需要传入的 props。如果需要完全不同的布局，可以直接将它封装的原语 `ThreadPrimitive`、`ComposerPrimitive` 和 `MessagePrimitive` 连接到你自己的运行时；它已经提供的消息级组件也各自有独立文档，例如 [消息分支](/elements/message-branches)中的分支选择器和 [推理](/elements/reasoning)中的推理轨迹。

</StandaloneMode>

## 结构

```tsx
<ThreadPrimitive.Root>
  <ThreadPrimitive.Viewport>
    {/* no messages, and not mid history-load: */}
    <Welcome />
    {/* switched to a thread whose own history is still loading: */}
    <ThreadHistorySkeleton />

    <ThreadPrimitive.Messages>
      {({ message }) =>
        message.role === "user" ? <UserMessage /> : <AssistantMessage />
      }
    </ThreadPrimitive.Messages>

    <ThreadPrimitive.ViewportFooter>
      <ThreadPrimitive.ScrollToBottom />
      <ThreadFollowupSuggestions />
      <Composer />
      {/* new chat, nothing typed yet: */}
      <ThreadPrimitive.Suggestions>
        {() => <SuggestionItem />}
      </ThreadPrimitive.Suggestions>
    </ThreadPrimitive.ViewportFooter>
  </ThreadPrimitive.Viewport>
</ThreadPrimitive.Root>
```

欢迎屏幕的显示条件比“没有消息”更严格：启动时，整个线程列表可能仍在加载，而当前线程的历史记录尚未解析完成；此时显示历史记录骨架屏，随后又立即变成欢迎屏幕，只会造成闪烁。因此，Thread 将“没有消息，且未处于加载状态，或整个列表仍在加载”视为新聊天视图，并仅在切换线程且只有该线程的历史记录仍在加载时显示骨架屏。每条助手消息的操作栏会在该响应运行期间隐藏；空闲后，最后一条响应始终显示操作栏（`hideWhenRunning`、`autohide="not-last"`）。旁边的分支选择器在只有一个分支时会完全隐藏，其行为与[消息分支](/elements/message-branches)中的一致。编辑用户消息时，会将其原地替换为输入框，而不是打开对话框。

## 示例

### 组件覆盖

未通过 `components` 传入的插槽会保留内置渲染方式；只有你指定的插槽会被替换。

```tsx
const THREAD_COMPONENTS: ThreadComponents = {
  Welcome: () => (
    <div className="mb-6 text-center">
      <h1 className="text-2xl font-medium">Ask me anything</h1>
    </div>
  ),
};
```

### 重新设置外壳样式

`Thread` 直接将 `--thread-max-width`、`--composer-bg`、`--composer-radius` 和 `--composer-padding` 设置为 `ThreadPrimitive.Root` 上的内联样式。由于这些样式是在那里设置的，而不是通过继承获得的，因此要覆盖它们，需要编辑你复制的 `thread.aui.tsx`，而不是从外部叠加一个 class：

```tsx
style={{
  ["--thread-max-width" as string]: "56rem",
  ["--composer-radius" as string]: "0.75rem",
}}
```

### 欢迎屏幕上的建议

```tsx
import { AssistantRuntimeProvider, AuiConfig, Suggestions } from "@assistant-ui/react";
import { useChatRuntime } from "@assistant-ui/ai-sdk";

function App({ children }: { children: React.ReactNode }) {
  const runtime = useChatRuntime();
  const config = AuiConfig({
    suggestions: Suggestions(["What's the weather?", "Tell me a joke"]),
  });

  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

请参阅[建议指南](/docs/guides/suggestions)，了解完整的配置选项，包括每条建议的标题和描述。

## API 参考

<RuntimeMode>

### ThreadProps

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `components` | `ThreadComponents \| undefined` | 无 | 插槽覆盖，详见下文。 |
| `autoFocus` | `boolean \| undefined` | `true` | 在挂载、运行开始、切换线程和滚动到底部时聚焦输入框。设置为 `false` 可让页面保持当前焦点。 |

### ThreadComponents

| 插槽 | 类型 | 描述 |
|------|------|--------------|
| `AssistantMessage` | `ComponentType` | 替换整个助手消息，包括操作栏和分支选择器。 |
| `Welcome` | `ComponentType` | 替换新聊天中显示的欢迎屏幕。 |
| `ToolFallback` | `ToolCallMessagePartComponent` | 渲染没有已注册 UI 的工具调用。按名称注册的工具 UI 优先于此插槽。 |
| `ToolGroup` | `ComponentType<PropsWithChildren<{ group: ThreadGroupPart }>>` | 包裹一组连续的工具调用；接收该组的 `indices` 和 `status`。 |
| `ReasoningGroup` | `ComponentType<PropsWithChildren<{ group: ThreadGroupPart }>>` | 包裹一组连续的推理部分；接收相同的结构。 |

### 原语

| 命名空间 | 用途 |
|-----------|----------|
| `ThreadPrimitive` | 根组件、可滚动视口、消息列表、页脚、滚动到底部和欢迎屏幕建议。 |
| `ComposerPrimitive` | 输入、附件拖放区、发送、取消，以及开始/停止听写。 |
| `MessagePrimitive` | 消息根组件、渲染消息的各个部分、按类型对连续部分分组，以及每条消息的错误插槽。 |
| `ActionBarPrimitive` / `ActionBarMorePrimitive` | 复制、重新加载、编辑、导出为 Markdown，以及包含导出操作的溢出菜单。 |
| `BranchPickerPrimitive` | 每条消息旁边的 `n / m` 步进器；请参阅[消息分支](/elements/message-branches)。 |
| `AuiIf` | 下方的所有条件插槽。 |

### 线程状态

| 选择器 | 类型 | 描述 |
|----------|------|--------------|
| `s.thread.capabilities.dictation` | `boolean` | 输入框的麦克风按钮是否可以渲染。 |
| `s.thread.isRunning` | `boolean` | 将输入框的发送操作替换为取消操作。 |
| `s.composer.isEmpty` | `boolean` | 控制欢迎屏幕建议的显示：仅在新聊天且尚未输入任何内容时显示。 |
| `s.composer.dictation` | `DictationState \| undefined` | 听写激活时为非 null；将麦克风按钮替换为停止按钮。 |
| `s.message.role` | `"user" \| "assistant" \| "system"` | 选择要渲染的消息组件。 |
| `s.message.composer.isEditing` | `boolean` | 将用户消息替换为其编辑输入框。 |
| `s.message.isCopied` | `boolean` | 复制后将复制图标替换为勾选标记。 |

</RuntimeMode>
