---
title: "编辑已发送的消息"
description: "就地重写一个回合，并预先告知编辑操作会丢弃多少条回复。"
---

已发送的消息气泡会就地变成一个小型输入框：重写消息时，警告会显示发送编辑内容将丢弃多少条回复。在运行时中，编辑会在消息自身的输入框中打开同一条消息，并在发送时创建一个新分支；独立使用时，则需要自行维护值、编辑状态标志和警告计数。

## 快速开始

<RuntimeMode>

`s.message.composer.isEditing` 会在按下 `ActionBarPrimitive.Edit` 的瞬间变为 true；为 true 时，将编辑输入框渲染在气泡原本的位置。

<Steps>
  <Step>

### 从消息气泡触发编辑

```tsx title="components/assistant-ui/elements/edit-message.tsx"
"use client";

import { ActionBarPrimitive, MessagePrimitive, useAuiState } from "@assistant-ui/react";
import { PencilLineIcon } from "lucide-react";
import { cn } from "@/lib/utils";
import { field, ghostButton } from "@/components/assistant-ui/elements/surfaces";

export function UserTurn() {
  const isEditing = useAuiState((s) => s.message.composer.isEditing);

  return (
    <MessagePrimitive.Root className="flex w-full max-w-sm flex-col items-end gap-1">
      {isEditing ? (
        <EditComposer />
      ) : (
        <div className={cn(field, "flex items-center gap-2 rounded-2xl px-3.5 py-2.5")}>
          <MessagePrimitive.Parts />
          <ActionBarPrimitive.Edit aria-label="Edit message" className={cn(ghostButton, "size-6 shrink-0")}>
            <PencilLineIcon className="size-3.5" />
          </ActionBarPrimitive.Edit>
        </div>
      )}
    </MessagePrimitive.Root>
  );
}
```

  </Step>
  <Step>

### 渲染编辑输入框

在正在编辑的消息中，`ComposerPrimitive.*` 会将作用域限定为该消息自身的输入框，而不是线程的输入框。

```tsx
import { ComposerPrimitive } from "@assistant-ui/react";

function EditComposer() {
  return (
    <ComposerPrimitive.Root className={cn(field, "flex w-full flex-col gap-3 rounded-2xl p-3.5")}>
      <ComposerPrimitive.Input rows={2} autoFocus className="resize-none bg-transparent px-3 py-2.5 text-[13.5px] outline-none" />
      <div className="flex items-center justify-end gap-2">
        <ComposerPrimitive.Cancel className="h-8 rounded-full px-3.5 text-xs font-medium">
          Cancel
        </ComposerPrimitive.Cancel>
        <ComposerPrimitive.Send className="bg-foreground text-background h-8 rounded-full px-3.5 text-xs font-medium">
          Send
        </ComposerPrimitive.Send>
      </div>
    </ComposerPrimitive.Root>
  );
}
```

`Thread` 已经为用户消息和助手消息提供了这一完整的切换逻辑，但不包含下文介绍的丢弃警告；安装 `@assistant-ui/thread` 即可获得完整组合。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

独立使用时，`EditMessage` 是一个受控组件：气泡会调用 `onStartEdit`，而在 `editing` 为 true 时，它会渲染一个 textarea，以及 Cancel 和 Send。

<Steps>
  <Step>

### 保存编辑状态

```tsx title="app/turn.tsx"
"use client";

import { useState } from "react";
import { EditMessage } from "@/components/assistant-ui/elements/edit-message";

export function Turn() {
  const [editing, setEditing] = useState(false);
  const [value, setValue] = useState("What's the capital of France?");

  return (
    <EditMessage
      value={value}
      discardedReplies={2}
      editing={editing}
      onValueChange={setValue}
      onStartEdit={() => setEditing(true)}
      onCancel={() => setEditing(false)}
      onSave={async () => {
        await resend(value);
        setEditing(false);
      }}
    />
  );
}
```

  </Step>
  <Step>

### 自行计算 `discardedReplies`

该元素只会渲染你传入的数字；在渲染前，从你自己的记录状态中统计这条消息之后的回复数量。

  </Step>
</Steps>

</StandaloneMode>

## 结构

```tsx
<div data-slot="edit-message">
  <button>{/* the sent bubble; click to start editing */}</button>
</div>
```

编辑时，同一个插槽会改为渲染另一种结构：

```tsx
<div data-slot="edit-message">
  <textarea />
  <div>{/* "sending discards N replies", only when discardedReplies > 0 */}</div>
  <div>
    <button>Cancel</button>
    <button>Send</button>
  </div>
</div>
```

独立使用时，`discardedReplies` 是你提供的普通数字，其定义方式可以符合应用对删除的建模方式。在运行时中，编辑不会删除任何内容：发送时会调用消息编辑输入框的 `send()`，在同一父级下将重写内容追加为原消息的新同级分支，行为与重新加载助手消息完全一致。原消息及其下的所有内容都会保留在线程历史中，并且可以通过分支选择器的 `n / m` 步进器再次访问，因此实际上没有任何内容被丢弃，只是不再显示在当前分支中。如果希望提供同样的预先警告，请计算将从视图中消失的数量：当前显示分支中位于这条消息之后的助手回复数量。

## 示例

### 计算警告数量

<RuntimeMode>

`s.message.index` 是这条消息在当前显示分支中的位置；位于它之后、将不再显示的所有内容就是 `s.thread.messages.slice(s.message.index + 1)`。

```tsx
const discardedReplies = useAuiState(
  (s) => s.thread.messages.slice(s.message.index + 1).filter((m) => m.role === "assistant").length,
);
```

</RuntimeMode>

<StandaloneMode>

这里没有可供推导的记录；请传入与你的应用实际如何处理重新发送相匹配的数量。有些应用确实会删除内容，此时该数量就是实际被删除的数量。

</StandaloneMode>

### Cancel 丢弃草稿，而不是分支

<RuntimeMode>

`ComposerPrimitive.Cancel` 会调用编辑输入框的 `cancel()`，丢弃正在进行的编辑文本，并将 `isEditing` 重置为 false；由于没有发送任何内容，原消息不会受到影响。

</RuntimeMode>

<StandaloneMode>

`onCancel` 也应执行相同操作：将 `value` 重置为原始文本（或者只将 `editing` 重置为 false，让父组件重新填充初始值），而不要修改消息列表实际保存的内容。

</StandaloneMode>

### 重新设置输入框样式

两种状态都会在根元素上接收 `className`；`field` 中的 `surfaces.tsx` token 是两种状态唯一使用的表面样式。

```tsx
<EditMessage className="max-w-none" /* ... */ />
```

## API 参考

<RuntimeMode>

### ActionBarPrimitive 和 ComposerPrimitive

| 部件 | 渲染内容 | 说明 |
|------|---------|-------|
| `ActionBarPrimitive.Edit` | `button` | 为此消息调用 `aui.composer.beginEdit()`；正在编辑时禁用。 |
| `ComposerPrimitive.Root` | `form` | 在正在编辑的消息中渲染时，作用域限定为该消息的编辑输入框。 |
| `ComposerPrimitive.Input` | `textarea` | 可编辑的文本。 |
| `ComposerPrimitive.Cancel` | `button` | 丢弃编辑内容并退出编辑模式。 |
| `ComposerPrimitive.Send` | `button` | 将编辑内容作为新的同级分支发送；文本为空时禁用。 |

### 消息和输入框状态

| 选择器 | 类型 | 描述 |
|----------|------|-------------|
| `s.message.composer.isEditing` | `boolean` | 此消息当前是否正在编辑。 |
| `s.message.index` | `number` | 此消息在当前显示分支中的位置。 |
| `s.thread.messages` | `readonly MessageState[]` | 按顺序排列的完整显示分支。 |

</RuntimeMode>

<StandaloneMode>

### EditMessage

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `value` | `string` | 必填 | 编辑 textarea 中的文本。 |
| `discardedReplies` | `number` | 必填 | 大于 `0` 时显示在警告行中。 |
| `editing` | `boolean` | 必填 | 在气泡和输入框之间切换。 |
| `onValueChange` | `(value: string) => void` | | textarea 内容变化时调用。 |
| `onSave` | `() => void` | | 按下 Send 时调用。 |
| `onCancel` | `() => void` | | 按下 Cancel 时调用。 |
| `onStartEdit` | `() => void` | | 点击气泡时调用。 |
| `className` | `string` | | 合并到根元素上。 |

其他所有 `div` props 都会转发到根元素。

</StandaloneMode>
