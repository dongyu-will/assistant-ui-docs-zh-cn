聊天面板是一个线程最小但完整的切片：可滚动的消息列表、每种角色对应的消息气泡、回复进行中的短暂等待，以及用于发送消息的输入框。使用运行时（runtime）时，这些部分会连接到实时线程状态；独立使用时，你可以围绕传入的消息和处理函数，按相同方式组织这些部分。

## 开始使用

<RuntimeMode>

assistant-ui 的 `Thread` 元素已经提供了这一组合的完整版本，从视口到输入框端到端连接。只有在想要使用更小的自定义外壳，而不是完整的 `Thread` 时，才需要自行用这些部分进行构建。

<Steps>
  <Step>

### 渲染消息列表

`ThreadPrimitive.Viewport` 接管 `ChatPanelMessages` 的滚动；将它作为 `asChild` 目标传入，这样面板可以保留 `ChatPanelMessages` 的外观，同时由视口负责行为：

```tsx title="components/assistant-ui/elements/chat-panel.tsx"
"use client";

import { ThreadPrimitive, MessagePrimitive } from "@assistant-ui/react";
import { ChatPanel, ChatPanelMessages, ChatPanelUserMessage, ChatPanelAssistantMessage } from "./chat-panel";

export function LiveChatPanel() {
  return (
    <ChatPanel>
      <ThreadPrimitive.Viewport asChild>
        <ChatPanelMessages>
          <ThreadPrimitive.Messages>
            {({ message }) =>
              message.role === "user" ? (
                <ChatPanelUserMessage>
                  <MessagePrimitive.Parts />
                </ChatPanelUserMessage>
              ) : (
                <ChatPanelAssistantMessage>
                  <MessagePrimitive.Parts />
                </ChatPanelAssistantMessage>
              )
            }
          </ThreadPrimitive.Messages>
        </ChatPanelMessages>
      </ThreadPrimitive.Viewport>
    </ChatPanel>
  );
}
```

`ThreadPrimitive.Messages` 的渲染函数会针对每条消息调用一次，并且已经限定在该消息的作用域内，因此其中的 `MessagePrimitive.Parts` 和 `message.role` 都会解析为对应的消息。

  </Step>
  <Step>

### 添加输入框和运行状态

```tsx
import { AuiIf, ComposerPrimitive } from "@assistant-ui/react";
import { ChatPanelComposer, ChatPanelTyping } from "./chat-panel";

<AuiIf condition={(s) => s.thread.isRunning}>
  <ChatPanelTyping />
</AuiIf>

<ComposerPrimitive.Root className="mx-3 mb-3 flex h-10 shrink-0 items-center rounded-full">
  <ComposerPrimitive.Input placeholder="Message..." />
  <ComposerPrimitive.Send />
</ComposerPrimitive.Root>
```

只要流式传输连接到后端，`s.thread.isRunning` 就会处于 `true` 状态；此时 `ChatPanelTyping` 的弹跳效果表示正在思考。每当输入框没有可发送的内容时，`ComposerPrimitive.Send` 会像 `ChatPanelComposer` 的按钮一样自动禁用。

  </Step>
</Steps>

</RuntimeMode>

独立使用时，你需要自行维护消息记录，并将每一轮交给匹配的部分。

<Steps>
  <Step>

### 组装面板

```tsx title="app/panel.tsx"
"use client";

import {
  ChatPanel,
  ChatPanelMessages,
  ChatPanelUserMessage,
  ChatPanelAssistantMessage,
  ChatPanelTyping,
  ChatPanelComposer,
} from "@/components/assistant-ui/elements/chat-panel";

export function Panel() {
  return (
    <ChatPanel>
      <ChatPanelMessages>
        <ChatPanelUserMessage>What's the capital of France?</ChatPanelUserMessage>
        <ChatPanelAssistantMessage>Paris.</ChatPanelAssistantMessage>
        <ChatPanelTyping />
      </ChatPanelMessages>
      <ChatPanelComposer placeholder="Message..." onSend={() => {}} />
    </ChatPanel>
  );
}
```

  </Step>
  <Step>

### 处理发送

`ChatPanelComposer` 将 `placeholder` 显示为静态文本，并在点击时调用 `onSend`；它本身不保存文本值，因此如果需要可用的输入框，请将它与自有的输入状态结合使用：

```tsx
const [sending, setSending] = useState(false);

<ChatPanelComposer
  placeholder={sending ? "Sending..." : "Message..."}
  onSend={!sending ? () => setSending(true) : undefined}
/>
```

当 `onSend` 保持为 `undefined` 时，发送按钮会自动禁用。

  </Step>
</Steps>

</StandaloneMode>

## 结构

```tsx
<div data-slot="chat-panel">
  <div data-slot="chat-panel-messages">
    <div data-slot="chat-panel-user-message" />
    <p data-slot="chat-panel-assistant-message" />
    <div data-slot="chat-panel-typing" />
  </div>
  <div data-slot="chat-panel-composer">
    <span>{/* placeholder text */}</span>
    <button aria-label="Send" />
  </div>
</div>
```

`ChatPanelComposer` 是一个外壳，而不是文本字段：`placeholder` 是它显示的文本，而不是绑定值；发送按钮唯一的行为是在存在 `onSend` 时调用它。当 `onSend` 为 `undefined` 时，它会被渲染为禁用状态，这与 `EmptyStateComposer` 遵循相同的规则。`ChatPanelTyping` 和 `ChatPanelUserMessage` 都会在挂载时淡入并滑入；如果希望新消息重新播放这一入场动画，可以修改它们的 `key`。

## 示例

### 单独复用各个部分

每个部分，包括 `ChatPanel`、`ChatPanelMessages`、`ChatPanelUserMessage`、`ChatPanelAssistantMessage`、`ChatPanelTyping` 和 `ChatPanelComposer`，都接受 `className`，并会向其根元素转发其余 props。因此，这些部分可以脱离默认卡片形状重新组合，例如使用全高页面外壳，而不是固定的 `h-[270px]` 卡片：

```tsx
<ChatPanel className="h-full max-w-none rounded-none border-none">
  {/* ... */}
</ChatPanel>
```

### 输入状态

<RuntimeMode>

根据线程的运行标志控制 `ChatPanelTyping`，使其仅在回复进行中时显示：

```tsx
<AuiIf condition={(s) => s.thread.isRunning}>
  <ChatPanelTyping />
</AuiIf>
```

</RuntimeMode>

<StandaloneMode>

独立使用时，只要你自己的状态表明回复正在等待，就可以渲染它；组件内部不会自行读取经过的时间或消息状态。

</StandaloneMode>

## API 参考

<RuntimeMode>

### 原语部分

| 部分 | 渲染内容 | 备注 |
|------|---------|-------|
| `ThreadPrimitive.Viewport` | `div` | 可滚动的消息区域；默认会在新消息到达时自动滚动到底部。接受 `asChild`。 |
| `ThreadPrimitive.Messages` | children | 每条消息调用一次其 `children` 渲染函数，并且已经限定在该消息的作用域内。 |
| `MessagePrimitive.Parts` | children | 渲染当前消息的内容。 |
| `ComposerPrimitive.Root` / `.Input` / `.Send` | `form` / `textarea` / `button` | 真正的输入框；当输入框无法发送时，`.Send` 会自动禁用。 |
| `AuiIf` | children | 当 `condition` 从状态中选择 `true` 时，渲染 `children`。 |

### 线程状态

| 选择器 | 类型 | 描述 |
|----------|------|-------------|
| `s.thread.isRunning` | `boolean` | 当流式传输连接到后端时为 `true`。 |
| `s.message.role` | `"user" \| "assistant" \| "system"` | 在 `ThreadPrimitive.Messages` 的渲染函数中读取，用于选择消息气泡。 |

</RuntimeMode>

<StandaloneMode>

### ChatPanel 系列

| 部分 | 渲染内容 | Props | 描述 |
|------|---------|-------|-------------|
| `ChatPanel` | `div` | `className` | 根卡片。固定的 `h-[270px]`、`max-w-md`。 |
| `ChatPanelMessages` | `div` | `className` | 可滚动、锚定到底部的消息列表。 |
| `ChatPanelUserMessage` | `div` | `className` | 右对齐的消息气泡。在挂载时淡入并滑入。 |
| `ChatPanelAssistantMessage` | `p` | `className` | 左对齐、不带气泡的文本行。 |
| `ChatPanelTyping` | `div` | `className`（无 `children`） | 三个弹跳的点。 |
| `ChatPanelComposer` | `div` | `placeholder`（必需的 `string`）、`onSend?: () => void`、`className` | 显示静态占位文本和发送按钮；点击时触发 `onSend`，未提供该函数时按钮会被禁用。 |

每个部分的其他 props 都会转发到其根元素。

</StandaloneMode>
