---
title: "已停止的运行"
description: "你按下了停止。已写入一半的答案会保留，继续生成只需轻触一下。"
---

StoppedRun 展示取消生成后留下的内容：停止前已经到达的文字、一个简短的原因徽章，以及继续处理或放弃它的方式。在运行时中，文字和原因来自被取消的消息；独立使用时，则由你传入所捕获的内容。

## 快速开始

<RuntimeMode>

被取消的消息会以 `status.type === "incomplete"` 状态和 `status.reason === "cancelled"` 稳定下来。在此之前生成的内容仍会保留；只是运行停止了。

<Steps>
  <Step>

### 检测被取消的消息并连接其操作

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
"use client";

import { useAui, useAuiState } from "@assistant-ui/react";
import { StoppedRun } from "@/components/assistant-ui/elements/stopped-run";

function CancelledNotice() {
  const aui = useAui();
  const status = useAuiState((s) =>
    s.message.role === "assistant" ? s.message.status : undefined,
  );
  const words = useAuiState((s) =>
    s.message.role === "assistant"
      ? s.message.content
          .filter((part): part is { type: "text"; text: string } => part.type === "text")
          .flatMap((part) => part.text.split(" "))
      : [],
  );

  if (status?.type !== "incomplete" || status.reason !== "cancelled") return null;

  return (
    <StoppedRun
      words={words}
      reason="stopped by you"
      onContinue={() => aui.message.reload()}
      onDiscard={() => aui.message.delete()}
    />
  );
}
```

  </Step>
  <Step>

### 了解 Continue 的实际行为

`reload()` 会为同一轮次启动一次新的运行；它不会从被截断的确切文本处继续，因为 assistant-ui 没有内置的前缀继续原语。支持字面续写的后端需要获取部分文本，例如通过 `reload` 的 `runConfig.custom` 传入，并在你的 `ChatModelAdapter` 中读取。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

独立使用时，StoppedRun 仅负责展示：由你决定什么算作已停止，并提供已经流式输出的文字。

<Steps>
  <Step>

### 流停止时冻结文字

```tsx title="app/answer.tsx"
"use client";

import { useState } from "react";
import { StoppedRun } from "@/components/assistant-ui/elements/stopped-run";

export function Answer() {
  const [words, setWords] = useState<string[]>([]);
  const [stopped, setStopped] = useState(false);

  function onStop() {
    controller.abort();
    setStopped(true);
  }

  if (!stopped) return null;

  return (
    <StoppedRun
      words={words}
      reason="stopped by you"
      onContinue={() => resume(words)}
      onDiscard={() => setStopped(false)}
    />
  );
}
```

  </Step>
  <Step>

### 连接 Continue 和 Discard

这两个 prop 都没有默认行为；在传入处理函数之前，它们都不会执行任何操作。`onContinue` 用于获取答案的剩余部分；`onDiscard` 用于将其从你自己的列表中删除。

  </Step>
</Steps>

</StandaloneMode>

## 组成

```tsx
<div data-slot="stopped-run">
  <p>{/* words joined by a space, with a blinking cursor after them */}</p>
  <div>
    <span>{/* the reason badge, e.g. "stopped by you" */}</span>
    <button>Continue</button>
    <button>Discard</button>
  </div>
</div>
```

光标仅用于装饰（`aria-hidden`），组件挂载期间始终会渲染；内部没有“仍在流式传输”状态可以将其关闭。`reason` 是自由格式文本，而不是固定枚举，因此徽章可以描述运行未完成就结束的任何情况，而不仅是手动停止。

## 示例

### 运行停止的其他原因

<RuntimeMode>

`status.reason` 涵盖的不只是手动停止：`"length"`、`"content-filter"`、`"tool-calls"` 和 `"error"` 都是与 `"cancelled"` 并列的实际值。同一个组件可以通过不同标签适配其中任何一种情况：

```tsx
const LABEL: Record<string, string> = {
  cancelled: "stopped by you",
  length: "hit the length limit",
  "content-filter": "blocked by a content filter",
  error: "failed partway through",
};

<StoppedRun words={words} reason={LABEL[status.reason] ?? "stopped early"} />
```

</RuntimeMode>

<StandaloneMode>

组件本身并未将 `reason` 专门与取消关联；任何用于说明文本为何提前停止的简短标签都可以作为有效值。

```tsx
<StoppedRun words={words} reason="connection lost" />
```

</StandaloneMode>

### Discard 的去向

<RuntimeMode>

```tsx
const onDiscard = () => aui.message.delete();
```

`delete()` 会从线程中移除消息。它的 `Promise<void>` 返回值存在的原因是，持久化运行时的删除操作是异步的；你通常不需要在点击处理函数中等待它完成。

</RuntimeMode>

<StandaloneMode>

独立使用时，Discard 的行为就是从你自己的列表中移除草稿；组件只负责调用处理函数。

```tsx
const onDiscard = () => setDrafts((prev) => prev.filter((d) => d.id !== draftId));
```

</StandaloneMode>

### 重新设置徽章和操作的样式

两条区域都会在根元素上接收 `className`。徽章会从 `surfaces.tsx` 读取共享的 `field` 和 `mono` 表面。

```tsx
<StoppedRun className="max-w-none" /* ... */ />
```

## API 参考

<RuntimeMode>

### 消息状态

| 选择器 / 方法 | 类型 | 描述 |
|--------------------|------|-------------|
| `s.message.status` | `MessageStatus \| undefined` | 当你按下停止并导致消息停止时的 `{ type: "incomplete", reason: "cancelled" }`。其他 `incomplete` 原因包括：`"length"`、`"content-filter"`、`"tool-calls"`、`"error"` 和 `"other"`。 |
| `aui.thread.cancelRun()` | `() => void` | 停止活动运行；流式传输中的消息会稳定为上述的 `incomplete` 状态。 |
| `aui.message.reload(config?)` | `(config?: { runConfig?: RunConfig }) => void` | 为此轮次启动一次新的运行。重新开始生成；不会从被截断的文本处继续。 |
| `aui.message.delete()` | `() => void \| Promise<void>` | 从线程中移除消息。 |

</RuntimeMode>

<StandaloneMode>

### StoppedRun

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `words` | `readonly string[]` | 必填 | 已经流式输出的文字，以空格连接，并在末尾添加光标。 |
| `reason` | `string` | 必填 | 显示在徽章中的自由格式标签。 |
| `onContinue` | `() => void` | | 按下 Continue 时调用。 |
| `onDiscard` | `() => void` | | 按下 Discard 时调用。 |
| `className` | `string` | | 合并到根元素上。 |

其他所有 `div` props 都会转发到根元素。

</StandaloneMode>
