位于输入框组件栏中的环形按钮。悬停或聚焦时，它会打开一个小型明细面板，显示系统、工具和消息令牌相对于模型上下文窗口的使用情况，环本身也会相应填充。使用运行时（runtime）时，累计总数来自线程自身的令牌使用量；单独使用时，则需要自行计算并传入每个数值。

## 开始使用

<RuntimeMode>

使用运行时时，assistant-ui 不会自行跟踪系统、工具和消息的拆分情况。它跟踪的是每轮使用量：`ChatModelAdapter` 可以为每个生成步骤报告 `inputTokens` 和 `outputTokens`，线程会将这些信息附加到每条助手消息上。

<Steps>
  <Step>

### 读取累计总数

将每条消息的步骤归约为一个总数。没有 `usage` 对象的步骤（不报告该对象的提供商，或仍在流式传输的消息）不会计入总数。

```tsx title="components/assistant-ui/elements/composer-context-rail.tsx"
"use client";

import { useAuiState } from "@assistant-ui/react";

function useThreadTokensUsed(): number {
  return useAuiState((s) =>
    s.thread.messages.reduce((sum, message) => {
      const steps = message.metadata.steps ?? [];
      return (
        sum +
        steps.reduce(
          (stepSum, step) =>
            stepSum +
            (step.usage?.inputTokens ?? 0) +
            (step.usage?.outputTokens ?? 0),
          0,
        )
      );
    }, 0),
  );
}
```

  </Step>
  <Step>

### 为令牌环提供数据

`ComposerContext` 需要类别明细，而运行时不会按类别统计令牌。系统提示词和工具 schema 在每轮的成本大致相同，可以将它们视为已知的常量；真正会增长的是对话，这也是上面唯一真实的数值。这里的值按千为单位读取（环会追加 `k`，不会进行除法换算），总数则是当前活动模型的上下文窗口大小；该大小已由你选择，线程状态不会将其暴露出来。

```tsx
import { ComposerContext } from "@/components/assistant-ui/elements/composer";

const SYSTEM_PROMPT_TOKENS = 1;
const TOOL_SCHEMA_TOKENS = 3;
const MODEL_CONTEXT_WINDOW = 200;

export function ComposerContextRail() {
  const used = useThreadTokensUsed();
  return (
    <ComposerContext
      usage={{
        system: SYSTEM_PROMPT_TOKENS,
        tools: TOOL_SCHEMA_TOKENS,
        messages: Math.round(used / 1000),
        total: MODEL_CONTEXT_WINDOW,
      }}
    />
  );
}
```

每个新线程都会从空数组重新执行归约，因此切换线程会重置令牌环，无需额外维护状态。

  </Step>
</Steps>

</RuntimeMode>

单独使用时，`ComposerContext` 完全由它唯一的 `usage` prop 控制。该元素不会测量令牌；计算工作由你负责，并传入计算结果。

<Steps>
  <Step>

### 传入明细

三个类别值和总数都按千为单位读取：`system: 12` 表示 12k，而不是 12 个令牌。

```tsx title="app/composer-rail.tsx"
"use client";

import { ComposerContext } from "@/components/assistant-ui/elements/composer";

export function ComposerRail() {
  return (
    <ComposerContext usage={{ system: 12, tools: 8, messages: 54, total: 200 }} />
  );
}
```

  </Step>
</Steps>

## 组成

```tsx
<div data-slot="composer-context">
  <div>{/* hover/focus panel: header, stacked bar, per-segment legend, total line */}</div>
  <button aria-label="Context usage">{/* ring svg */}</button>
</div>
```

触发器始终是一个环：包含外部轨道和前景弧线，其 `stroke-dashoffset` 根据 `system + tools + messages` 相对于 `total` 的比例变化。总数为 0 时会视为 0 比例，而不是进行除法运算。超过 85% 后，令牌环、百分比读数和触发器本身都会变成红色。明细面板通过 CSS group 状态在悬停或键盘聚焦时打开；它没有用于控制打开状态的 `open` prop，不同于 `ComposerMenu`。它的三个分段（System、Tools、Messages）使用不透明度逐渐增加的固定颜色，无法单独为各分段重新设置样式；如果你需要使用自定义颜色的任意带标签类别，请改用 `Context breakdown`。

## 示例

### 将其放入工具栏

令牌环的尺寸适合放在发送按钮旁边，并位于 `ComposerActions` 内。

```tsx
<ComposerToolbar>
  <ComposerActions>
    <ComposerAttachButton onClick={pick} />
  </ComposerActions>
  <ComposerActions>
    <ComposerContext usage={usage} />
    <ComposerSend streaming={streaming} idle={!value} onClick={send} />
  </ComposerActions>
</ComposerToolbar>
```

### 重新设置触发器样式

`className` 会合并到根元素上，而根元素同时包裹触发器按钮和面板；通过它设置令牌环的尺寸。

```tsx
<ComposerContext className="[&_button]:size-9" usage={usage} />
```

## API 参考

<RuntimeMode>

### 线程状态

| 选择器 | 类型 | 描述 |
|----------|------|-------------|
| `s.thread.messages` | `readonly MessageState[]` | 活动线程中的每条消息。每条助手消息的 `metadata.steps` 都是一个 `readonly ThreadStep[]`；当模型适配器报告令牌使用情况时，步骤可能会携带 `usage: { inputTokens: number; outputTokens: number }`。 |

没有用于类别明细或模型上下文窗口大小的选择器；两者都会按照上文所示进行派生或提供。

</RuntimeMode>

<StandaloneMode>

### ComposerContext

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `usage` | `ComposerUsage` | 必填 | 系统、工具和消息令牌，均按千为单位读取，并与 `total` 对比。令牌环根据三者之和进行填充；超过 85% 时变成红色。总数为 0 时会视为 0，而不是进行除法运算。 |
| `className` | `string` | | 合并到根元素上。 |

`ComposerUsage` 是 `{ system: number; tools: number; messages: number; total: number }`。所有其他 `div` props 都会转发到根元素。

</StandaloneMode>
