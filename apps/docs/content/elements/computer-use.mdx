围绕助手所查看内容的浏览器窗口框架，光标会移动到每个操作的位置，并在其后留下逐渐淡出的轨迹。在运行时中，这是由多个工具调用分组组合而成的，而不是随产品提供的原语；单独使用时，你需要传入步骤和当前索引。

## 开始使用

<RuntimeMode>

没有内置的“计算机使用”工具。这是一个由你自行定义的 `computer` 工具，每次操作调用一次，并通过将对它的连续调用分组来统一渲染。

  <Step>

### 将操作定义为工具调用

```tsx title="app/computer-toolkit.tsx"
"use client";

import type { ToolCallMessagePartComponent } from "@assistant-ui/react";
import { defineToolkit } from "@assistant-ui/react";
import { MousePointer2Icon } from "lucide-react";
import { z } from "zod";

type ComputerArgs = { action: string; target: string; x: number; y: number };

const ComputerStepMarker: ToolCallMessagePartComponent<ComputerArgs> = ({ args, status }) => (
  <MousePointer2Icon
    className="absolute size-4 fill-blue-500 text-blue-500 transition-[left,top] duration-500"
    style={{ left: `${args.x}%`, top: `${args.y}%`, opacity: status?.type === "running" ? 1 : 0.4 }}
  />
);

const toolkit = defineToolkit({
  computer: {
    type: "backend",
    description: "Click, type, or scroll at a point on the screen.",
    parameters: z.object({ action: z.string(), target: z.string(), x: z.number(), y: z.number() }),
    render: ComputerStepMarker,
  },
});
```

`action`、`target`、`x` 和 `y` 是本示例自定义的参数 schema，而不是内置结构；计算机使用提供商的实际工具可以定义它所需的任意字段。

  </Step>
  <Step>

### 将连续操作分组到同一个屏幕中

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
import { MessagePrimitive } from "@assistant-ui/react";

function AssistantMessage() {
  return (
    <MessagePrimitive.GroupedParts
      groupBy={(part) =>
        part.type === "tool-call" && part.toolName === "computer" ? ["group-computer"] : []
      }
    >
      {({ part, children }) => {
        switch (part.type) {
          case "group-computer":
            return <div className="relative overflow-hidden rounded-2xl border">{children}</div>;
          case "tool-call":
            return part.toolUI ?? null;
          default:
            return null;
        }
      }}
    </MessagePrimitive.GroupedParts>
  );
}
```

`groupBy` 在这里根据 `part.toolName` 进行分支，而不是使用 `groupPartByType` 的 part 类型映射，因为分组键不是 part 类型，而是被调用的工具。分组包装器是 `position: relative`；每个 `ComputerStepMarker` 会在其中使用 `absolute` 定位自身，因此连续调用会直接排列成轨迹，无需额外的连接逻辑。

  </Step>
</Steps>

</RuntimeMode>

### 保存步骤和当前索引

```tsx title="app/screen.tsx"
"use client";

import { useState } from "react";
import { ComputerUse, type ComputerStep } from "@/components/assistant-ui/elements/computer-use";

const steps: ComputerStep[] = [
  { id: "1", action: "click", target: "Sign in", x: 62, y: 24 },
  { id: "2", action: "type", target: "harry@example.com", x: 40, y: 38 },
];

export function Screen() {
  const [activeIndex, setActiveIndex] = useState(0);
  return (
    <ComputerUse url="app.example.com/login" steps={steps} activeIndex={activeIndex}>
      <img src="/screenshot.png" alt="" className="size-full object-cover" />
    </ComputerUse>
  );
}
```

  </Step>
  <Step>

### 随运行时的流式传输推进

```tsx
useEffect(() => {
  const id = setInterval(() => setActiveIndex((i) => i + 1), 1200);
  return () => clearInterval(id);
}, []);
```

`activeIndex` 会在内部限制到有效范围内，因此安全起见，你可以继续递增到最后一个步骤之后。

  </Step>
</Steps>

## 结构

```tsx
<div data-slot="computer-use">
  <div>{/* traffic-light dots, url */}</div>
  <div>{/* children (the screen), trail dots, cursor */}</div>
  {/* footer: action, target, "n/total"; only when steps is non-empty */}
</div>
```

`activeIndex` 会将索引限制在 `0…steps.length - 1` 范围内，因此负数或超出范围的索引仍会解析为实际步骤，而不是空值。轨迹由当前激活步骤之前的两个步骤以及当前激活步骤本身组成，透明度为 `0.18 * (i + 1)`，并逐渐向光标完全不透明的标记淡入。步骤数为零时，不会显示光标或页脚，只显示页眉和 `children`。

## 示例

### 提供屏幕内容

<RuntimeMode>

第二步中的分组包装器就是放置实时屏幕的位置，同时还可以使用 `children` 通过 `MessagePrimitive.GroupedParts` 提供的标记：

```tsx
case "group-computer":
  return (
    <div className="relative overflow-hidden rounded-2xl border">
      <img src={screenshotUrl} alt="" className="absolute inset-0 size-full object-cover" />
      {children}
    </div>
  );
```

</RuntimeMode>

<StandaloneMode>

`children` 是必需的，而不是可选项：在传入它之前，框架在轨迹下方没有任何内容可显示。

```tsx
<ComputerUse url={url} steps={steps} activeIndex={activeIndex}>
  <iframe src={liveViewUrl} className="size-full" />
</ComputerUse>
```

</StandaloneMode>

### 随调用完成逐渐淡出标记

<RuntimeMode>

上面的 `ComputerStepMarker` 已经读取 `status?.type`；仍处于 `"running"` 状态的调用会使用完全不透明的光标样式，而已完成的调用则会变成较暗的轨迹圆点，供下一次调用的标记继续经过。

</RuntimeMode>

### 重新设置框架样式

两个层级都会在根元素上接收 `className`。窗口框架使用共享的 `field`、`mono` 和 `paper` token；交通灯圆点和光标颜色则是元素自身上的 Tailwind 类，因此要重新设置这些样式，需要直接编辑组件的 className 字符串，而不是修改共享 token。

## API 参考

<RuntimeMode>

没有专用的计算机使用原语：这是 `MessagePrimitive.GroupedParts` 加上普通的工具调用渲染器，因此下表列出的是该模式读取的渲染 props，而不是随产品提供的 API 表面。

### 使用的渲染 props

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `args` | 你的工具的 `TArgs` | 你声明的任意参数 schema；上面的 `action`/`target`/`x`/`y` 是一种约定，而不是内置结构。 |
| `status` | `ToolCallMessagePartStatus` | 读取 `status?.type === "running"`，以区分正在进行的调用和已完成的调用。 |

</RuntimeMode>

<StandaloneMode>

### ComputerUse

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `url` | `string` | 必填 | 显示在窗口框架的地址栏中。 |
| `steps` | `readonly ComputerStep[]` | 必填 | 要沿其绘制轨迹的操作。 |
| `activeIndex` | `number` | 必填 | 当前步骤的索引，会被限制在有效范围内。 |
| `children` | `ReactNode` | 必填 | 屏幕内容，会渲染在轨迹和光标下方。 |
| `className` | `string` | | 合并到根元素上。 |

### ComputerStep

| 字段 | 类型 | 描述 |
|------|------|-------------|
| `id` | `string` | React key。 |
| `action` | `string` | 显示在页脚中，例如 `"click"`。 |
| `target` | `string` | 操作所作用的对象。 |
| `x`、`y` | `number` | 相对于框架的百分比位置，`0…100`。 |

所有其他 `div` props 都会转发到根元素。

</StandaloneMode>
