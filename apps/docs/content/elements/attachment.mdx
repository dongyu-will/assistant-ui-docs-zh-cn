---
title: "附件"
description: "用于输入框和消息的运行时附件，支持预览、进度显示和移除。"
---

Attachment 将单个文件渲染为一个小卡片：包含缩略图、悬停时显示文件名的工具提示，以及（在附件仍暂存于输入框中时）上传加载指示器、错误状态和移除按钮。在运行时环境中，它会直接从输入框或已发送的消息中读取附件；不存在此卡片的独立形式，因为上传进度和移除操作只有针对实时附件时才有意义。它有两种设计：运行时变体渲染实时附件卡片，而静态变体 `MessageAttachments` 则将已发送消息中的文件渲染为普通行（请参阅[已接收文件设计](#the-received-files-design)）。

## 入门

<RuntimeMode>

`Thread` 默认已经渲染了下面的所有部分；如果你要自行组合布局，而不是使用 `Thread`，可以直接使用这些部分。

<Steps>
  <Step>

### 在输入框中渲染附件

将输入区域包裹在 `ComposerPrimitive.AttachmentDropzone` 中，以便接受拖放的文件；使用 `ComposerPrimitive.Attachments` 列出暂存的附件，并添加 `ComposerAddAttachment` 作为文件选择器按钮。

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
import { ComposerPrimitive } from "@assistant-ui/react";
import {
  ComposerAddAttachment,
  ComposerAttachments,
} from "@/components/assistant-ui/elements/attachment.aui";

function Composer() {
  return (
    <ComposerPrimitive.Root>
      <ComposerPrimitive.AttachmentDropzone>
        <ComposerAttachments />
        <ComposerPrimitive.Input placeholder="Send a message..." />
        <ComposerAddAttachment />
      </ComposerPrimitive.AttachmentDropzone>
    </ComposerPrimitive.Root>
  );
}
```

  </Step>
  <Step>

### 在已发送的消息上渲染附件

`UserMessageAttachments` 使用 `MessagePrimitive.Attachments` 列出用户消息实际携带的文件。它只会在用户消息中渲染，因为助手消息不携带附件。

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
import { MessagePrimitive } from "@assistant-ui/react";
import { UserMessageAttachments } from "@/components/assistant-ui/elements/attachment.aui";

function UserMessage() {
  return (
    <MessagePrimitive.Root>
      <UserMessageAttachments />
      <MessagePrimitive.Parts />
    </MessagePrimitive.Root>
  );
}
```

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

单独使用时，没有任何需要暂存或上传的内容：此元素的作用是将运行时自身的附件状态（包括进度和移除状态）反映回 UI。请改用已接收文件设计来渲染已发送消息中的文件（请参阅[已接收文件设计](#the-received-files-design)）；该设计通过 props 接收普通的附件记录。

</StandaloneMode>

## 结构

<RuntimeMode>

```tsx
<div> {/* AttachmentPrimitive.Root */}
  <button aria-label="Image attachment" /* or "Document attachment" / "File attachment", plus ", uploading" / ", upload failed" */>
    {/* thumbnail: the image itself, or a file icon fallback */}
    {/* uploading: a blurred spinner overlay */}
    {/* error: a blurred alert overlay */}
  </button>
  <button aria-label="Remove file">{/* composer only */}</button>
</div>
```

移除按钮以及上传/错误覆盖层只会在输入框附件上渲染；消息附件仅显示卡片本身。消息中单独存在的图片附件会比其他附件渲染得更大。点击源地址已解析的图片附件卡片，会打开全屏预览对话框；其他类型的卡片，或尚未解析出源地址的图片，则只渲染可点击目标，不会有任何对话框行为。

</RuntimeMode>

## 示例

<RuntimeMode>

### 输入框附件与消息附件

两个导出项渲染相同的卡片，区别仅在于来源不同。对于暂存附件，`aui.attachment.source` 是 `"composer"`；对于已经发送的附件，则是 `"message"`。这正是决定是否显示移除按钮和拖入动画的依据。

```tsx
<ComposerAttachments />       {/* ComposerPrimitive.Attachments, source: "composer" */}
<UserMessageAttachments />    {/* MessagePrimitive.Attachments, source: "message" */}
```

### 读取已解析的预览源

`useAttachmentSrc()` 会解析图片附件可用于显示的 URL：对于仍在内存中的文件，它返回对象 URL；附件上传完成后，则返回第一个 `image` 内容部分。非图片附件会解析为 `undefined`，这正是自定义预览回退到图标时所使用的信号。

```tsx
import { useAttachmentSrc } from "@/hooks/use-attachment-src";

function CustomThumb() {
  const src = useAttachmentSrc();
  if (!src) return <FileIcon />;
  return <img src={src} alt="" />;
}
```

### 添加附件选择器

`ComposerAddAttachment` 会打开原生文件选择器，并将范围限定为输入框自身的 `attachmentAccept`，同时支持一次选择多个文件。当输入框不可编辑时（例如运行正在进行流式传输时），它不会渲染任何内容。

```tsx
<ComposerAddAttachment />
```

</RuntimeMode>

## API 参考

<RuntimeMode>

### Kit 部分

| 部分 | 渲染内容 | 说明 |
|------|---------|-------|
| `ComposerAttachments` | 列表 | 包裹 `ComposerPrimitive.Attachments`；每个暂存附件对应一个卡片。 |
| `ComposerAddAttachment` | `button` | 包裹 `ComposerPrimitive.AddAttachment`；打开原生文件选择器。当输入框不可编辑时，渲染 `null`。 |
| `UserMessageAttachments` | 列表 | 包裹 `MessagePrimitive.Attachments`；为当前用户消息中的每个附件渲染一个卡片。 |

### 组合的原语

| 部分 | 说明 |
|------|-------|
| `AttachmentPrimitive.Root` | 包裹一个卡片，并提供附件作用域。 |
| `AttachmentPrimitive.Name` | 以文本形式显示附件的文件名。 |
| `AttachmentPrimitive.Remove` | 调用 `aui.attachment.remove()`。 |
| `ComposerPrimitive.AttachmentDropzone` | 当文件被拖到其上方时设置 `data-dragging="true"`；当线程的 `attachments` 能力关闭时不执行任何操作。 |

### 附件状态

| 选择器 | 类型 | 描述 |
|----------|------|-------------|
| `s.attachment.type` | `"image" \| "document" \| "file" \| string` | 当前附件的类型。 |
| `s.attachment.name` | `string` | 文件名。 |
| `s.attachment.status.type` | `"running" \| "requires-action" \| "incomplete" \| "complete"` | 上传时为 `"running"`（携带一个 `progress`）；带有 `reason: "error"` 的 `"incomplete"` 会携带可选的 `message`。 |
| `aui.attachment.source` | `"message" \| "composer"` | 当前附件所属的界面。 |

</RuntimeMode>

## 已接收文件设计

侧栏中的 Static 变体是消息文件的第二种设计：`MessageAttachments` 将图片渲染为填充式缩略图按钮，将文档或其他文件渲染为图标行，而不是上文所示的输入框样式卡片。它是一个由 props 驱动、无运行时依赖的单一组件：

```sh
npx shadcn@latest add "@assistant-ui/elements-message-attachment"
```

<RuntimeMode>

可以将用户消息的附件映射为项目来连接它；与上面的 `UserMessageAttachments` 一样，这只适用于用户消息内部。`s.message.attachments` 是存储自身的数组，其中每个条目都已经完整（仍在上传的附件会存在于输入框自身的附件中），因此直接选择它的开销很小；派生项目仍需要 `useMemo`，因为每次调用都映射出新数组会导致列表在每次存储更新时重新渲染。

```tsx title="components/assistant-ui/elements/message-attachment.tsx"
"use client";

import { useMemo } from "react";
import { useAuiState } from "@assistant-ui/react";
import {
  MessageAttachments,
  type MessageAttachmentItem,
} from "@/components/assistant-ui/elements/message-attachment";

function UserReceivedFiles() {
  const attachments = useAuiState((s) => s.message.attachments);
  const items = useMemo<MessageAttachmentItem[]>(
    () =>
      attachments.map((a) => ({
        id: a.id,
        name: a.name,
        size: formatFileSize(a),
        kind: a.type === "image" || a.type === "document" ? a.type : "file",
      })),
    [attachments],
  );

  if (items.length === 0) return null;
  return (
    <MessageAttachments attachments={items} onOpen={(id) => openViewer(id)} />
  );
}
```

运行时会携带 `id`、`type`、`name` 和 `contentType`，但不会携带格式化后的大小字符串或页数，因此上面的 `formatFileSize` 需要由你自行编写；提供商定义的自定义 `type` 会折叠为 `"file"`，因为 `kind` 只接受所展示的三个值。

</RuntimeMode>

<StandaloneMode>

单独使用时，项目列表（包括大小信息）由你自行维护，并决定打开某个项目时执行的操作：

```tsx title="app/received-files.tsx"
"use client";

import {
  MessageAttachments,
  type MessageAttachmentItem,
} from "@/components/assistant-ui/elements/message-attachment";

const attachments: MessageAttachmentItem[] = [
  { id: "1", name: "diagram.png", size: "1.2 MB", kind: "image", swatch: "url(/diagram-thumb.png)" },
  { id: "2", name: "spec.pdf", size: "340 KB", kind: "document", pages: 12 },
];

export function ReceivedFiles() {
  return (
    <MessageAttachments attachments={attachments} onOpen={(id) => openViewer(id)} />
  );
}
```

</StandaloneMode>

`image` 项目会渲染为填充式缩略图按钮，并在 `swatch` 上方显示其名称和大小；而 `document` 或普通的 `file` 则会渲染为图标行，并且仅当设置了 `pages` 时才会追加页数。两者都会调用 `onOpen(id)`，自身都不会打开任何内容；请将 `onOpen` 连接到你自己的灯箱或下载流程。

### MessageAttachments

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `attachments` | `readonly MessageAttachmentItem[]` | 必填 | 按顺序排列的已接收文件。 |
| `onOpen` | `(id: string) => void` | | 点击附件时调用。 |
| `className` | `string` | | 合并到根元素上。 |

`MessageAttachmentItem` 是 `{ id: string; name: string; size: string; kind: "image" | "document" | "file"; pages?: number; swatch?: string }`。其他所有 `div` props 都会转发到根元素。
