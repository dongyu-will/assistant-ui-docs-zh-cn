---
title: "引用"
description: "选择消息文本，从浮动工具栏引用，并将其带入输入框。"
---

引用功能允许用户选择助手消息中的文本，从浮动工具栏引用，并在发送前将其显示在输入框上方。在运行时中，这三个部分会读写输入框的实时引用状态以及被引用的消息；独立使用时，则由你通过自己管理的 props 驱动相同的流程。它有两种设计：运行时变体将三个部分连接到实时的浏览器选区，而静态变体 `QuoteReply` 是一个单独的组件，用三操作工具栏渲染预先拆分的段落（参见[引用回复设计](#the-quote-reply-design)）。

## 入门

<RuntimeMode>

<Steps>
  <Step>

### 在消息中显示引用

在用户消息中将 `MessagePrimitive.Quote` 渲染在 `MessagePrimitive.Parts` 上方。只有当该消息携带引用时，它才会渲染内容。

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
import { QuoteBlock } from "@/components/assistant-ui/elements/quote.aui";
import { MessagePrimitive } from "@assistant-ui/react";

function UserMessage() {
  return (
    <MessagePrimitive.Root>
      <MessagePrimitive.Quote>
        {(quote) => <QuoteBlock {...quote} />}
      </MessagePrimitive.Quote>
      <MessagePrimitive.Parts />
    </MessagePrimitive.Root>
  );
}
```

  </Step>
  <Step>

### 添加浮动选区工具栏

在运行时作用域内的任意位置渲染 `SelectionToolbar`。它会监听整个文档中的文本选区，并且只有当选区位于某条消息内时，才会将自身通过 portal 渲染到选区上方。

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
import { SelectionToolbar } from "@/components/assistant-ui/elements/quote.aui";
import { ThreadPrimitive } from "@assistant-ui/react";

function Thread() {
  return (
    <ThreadPrimitive.Root>
      <ThreadPrimitive.Viewport>{/* messages, composer */}</ThreadPrimitive.Viewport>
      <SelectionToolbar />
    </ThreadPrimitive.Root>
  );
}
```

点击其中的 Quote 按钮，会根据当前选区设置输入框的引用，并清除浏览器选区；无需额外连接逻辑。

  </Step>
  <Step>

### 在输入框中预览引用

在输入框中添加 `ComposerQuotePreview`。在设置引用之前它不会渲染内容，其关闭按钮会清除引用。

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
import { ComposerQuotePreview } from "@/components/assistant-ui/elements/quote.aui";
import { ComposerPrimitive } from "@assistant-ui/react";

function Composer() {
  return (
    <ComposerPrimitive.Root>
      <ComposerQuotePreview />
      <ComposerPrimitive.Input placeholder="Send a message..." />
      <ComposerPrimitive.Send />
    </ComposerPrimitive.Root>
  );
}
```

  </Step>
  <Step>

### 将引用传递给模型

引用存储在消息元数据中，而不是消息内容中，因此除非路由处理程序将其添加进去，否则模型永远不会看到它。`injectQuoteContext` 会在转换之前，将引用文本作为 Markdown 引用块添加到前面。

```typescript title="app/api/chat/route.ts"
import { convertToModelMessages, streamText } from "ai";
import { injectQuoteContext } from "@assistant-ui/ai-sdk";

export async function POST(req: Request) {
  const { messages } = await req.json();

  const result = streamText({
    model: myModel,
    messages: await convertToModelMessages(injectQuoteContext(messages)),
  });

  return result.toUIMessageStreamResponse();
}
```

  </Step>
</Steps>

独立使用时，请自行构建相同的流程：将引用文本保存在状态中，将其显示在输入框上方，并在发送或关闭时清除它。下面的[引用回复设计](#the-quote-reply-design)正是这一流程的现成实现，底层不依赖运行时。

## 组成结构

<RuntimeMode>

```tsx
{/* inside the quoting user message, only when it carries a quote */}
<div data-slot="quote-block">
  <svg data-slot="quote-block-icon" />
  <p data-slot="quote-block-text">{quote.text}</p>
</div>

{/* portaled to document.body, only while a selection resolves to one message */}
<div data-slot="selection-toolbar">
  <button data-slot="selection-toolbar-quote" />
</div>

{/* inside the composer, only while a quote is set */}
<div data-slot="composer-quote">
  <svg data-slot="composer-quote-icon" />
  <span data-slot="composer-quote-text">{quote.text}</span>
  <button data-slot="composer-quote-dismiss" aria-label="Dismiss quote" />
</div>
```

这三个部分都会根据各自的条件挂载或渲染为空：引用块取决于当前消息的元数据是否携带引用，工具栏取决于当前文本选区是否恰好解析到一条消息，而输入框预览取决于输入框是否设置了引用。它们彼此之间无需传递信息。

</RuntimeMode>

## 示例

<RuntimeMode>

### 重新设置各部分样式

这三个组件都公开了各自的子部分，可完全控制样式；每个组件都接受 `className`。

```tsx
<QuoteBlock.Root className="my-custom-class">
  <QuoteBlock.Icon />
  <QuoteBlock.Text>{quote.text}</QuoteBlock.Text>
</QuoteBlock.Root>

<SelectionToolbar.Root>
  <SelectionToolbar.Quote>Reply with quote</SelectionToolbar.Quote>
</SelectionToolbar.Root>

<ComposerQuotePreview.Root>
  <ComposerQuotePreview.Icon />
  <ComposerQuotePreview.Text />
  <ComposerQuotePreview.Dismiss />
</ComposerQuotePreview.Root>
```

### 不使用 QuoteBlock 读取引用

`useMessageQuote()` 返回与 `MessagePrimitive.Quote` 渲染时使用的相同 `QuoteInfo`，可据此从头构建自定义显示：

```tsx
import { useMessageQuote } from "@assistant-ui/react";

function CustomQuoteDisplay() {
  const quote = useMessageQuote();
  if (!quote) return null;
  return <blockquote className="italic">{quote.text}</blockquote>;
}
```

### 从其他位置清除引用

运行时内部的任何组件都可以清除输入框的引用，例如从 `ComposerQuotePreview` 外部的自定义操作中清除：

```tsx
import { useAui } from "@assistant-ui/react";

function ClearQuoteButton() {
  const aui = useAui();
  return (
    <button type="button" onClick={() => aui.composer.setQuote(undefined)}>
      Clear quote
    </button>
  );
}
```

</RuntimeMode>

## API 参考

<RuntimeMode>

### QuoteBlock

| 部分 | 渲染内容 | 说明 |
|------|---------|-------|
| `Root` | `div` | 包裹图标和文本。 |
| `Icon` | `svg` | 引用符号。 |
| `Text` | `p` | 引用文本，最多显示两行。 |

类型为 `QuoteMessagePartComponent`，因此也可以直接作为 `MessagePrimitive.Parts` 的 `components.Quote` 传入，而不必使用上面的 render prop 形式。

### SelectionToolbar

| 部分 | 渲染内容 | 说明 |
|------|---------|-------|
| `Root` | `div` | 通过 portal 渲染到 `document.body`；在有效的单消息选区存在之前渲染 `null`。 |
| `Quote` | `button` | 没有活动选区时处于禁用状态。点击后设置输入框的引用，并清除浏览器选区。 |

### ComposerQuotePreview

| 部分 | 渲染内容 | 说明 |
|------|---------|-------|
| `Root` | `div` | 在设置 `composer.quote` 之前渲染 `null`。 |
| `Icon` | `svg` | 引用符号。 |
| `Text` | `span` | 引用文本；为空时渲染 `null`。 |
| `Dismiss` | `button` | 清除输入框的引用。 |

### 引用状态和操作

| 选择器 / 调用 | 类型 | 描述 |
|------------------|------|-------------|
| `s.composer.quote` | `QuoteInfo \| undefined` | 输入框中待发送的引用。 |
| `useMessageQuote()` | `() => QuoteInfo \| undefined` | 当前消息附带的引用，从 `message.metadata.custom.quote` 中读取。 |
| `aui.composer.setQuote(quote)` | `(quote: QuoteInfo \| undefined) => void` | 设置或清除输入框的引用。消息发送时会自动清除。 |
| `injectQuoteContext(messages)` | `(messages: UIMessage[]) => UIMessage[]` | 路由处理程序辅助函数。在 `convertToModelMessages` 之前，将每条被引用用户消息的文本作为 `>` 引用块部分添加到前面。 |

`QuoteInfo` 是 `{ text: string; messageId: string }`。

</RuntimeMode>

## 引用回复设计

侧栏中的 Static 变体是相同流程的第二种设计：`QuoteReply` 将预先拆分为引用短语的段落与三操作工具栏一起渲染，而不是读取实时的浏览器选区。这是一个由 props 驱动的单独组件，不依赖运行时：

```sh
npx shadcn@latest add "@assistant-ui/elements-quote-reply"
```

<RuntimeMode>

该设计的工具栏显示三个操作；运行时的 `SelectionToolbar` 仅提供 `Quote`，因为没有定义可调用的运行时行为来执行解释和改写。在同一个 `Root` 内添加一个相邻按钮，并由它自行读取实时选区：只有 `Root` 自身的 mousedown 处理逻辑，才能防止浏览器在点击生效前清除选区。

```tsx
<SelectionToolbar.Root>
  <SelectionToolbar.Quote>Quote</SelectionToolbar.Quote>
  <button onClick={() => explain(window.getSelection()?.toString())}>Explain</button>
</SelectionToolbar.Root>
```

</RuntimeMode>

<StandaloneMode>

你需要保存拆分后的文本、工具栏操作以及 `quoted` 状态；通过自己的选区变更处理逻辑驱动 `toolbarVisible`。

```tsx title="app/answer.tsx"
"use client";

import { useState } from "react";
import { QuoteReply, type QuoteAction } from "@/components/assistant-ui/elements/quote-reply";

const actions: QuoteAction[] = [
  { key: "quote", label: "Quote", icon: "quote" },
  { key: "explain", label: "Explain", icon: "explain" },
  { key: "rewrite", label: "Rewrite", icon: "rewrite" },
];

export function Answer() {
  const [quoted, setQuoted] = useState<string>();

  return (
    <QuoteReply
      before="The treaty was signed in "
      selection="1648"
      after=", ending the Thirty Years' War."
      actions={actions}
      toolbarVisible
      quoted={quoted}
      onAction={(key) => {
        if (key === "quote") setQuoted("1648");
      }}
    />
  );
}
```

</StandaloneMode>

这里的工具栏完全是展示性的：`selection` 和 `toolbarVisible` 只是 props，`QuoteReply` 中的任何内容都不会读取实际的浏览器选区。在运行时中，`SelectionToolbar` 会在 `mouseup`、`keyup` 和选区变更事件上监听选区，而不是将其作为 prop 接收。

### QuoteReply

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `before` | `string` | 必需 | 选中短语之前的文本。 |
| `selection` | `string` | 必需 | 高亮显示的短语。 |
| `after` | `string` | 必需 | 选中短语之后的文本。 |
| `actions` | `readonly QuoteAction[]` | 必需 | 工具栏按钮。 |
| `toolbarVisible` | `boolean` | 必需 | 显示工具栏。 |
| `quoted` | `string` | | 设置后显示在“回复对象”块中。 |
| `onAction` | `(key: string) => void` | | 使用所按下操作的 `key` 调用。 |
| `className` | `string` | | 合并到根元素上。 |

`QuoteAction` 是 `{ key: string; label: string; icon: "quote" | "explain" | "rewrite" }`。所有其他 `div` props 都会转发到根元素。
