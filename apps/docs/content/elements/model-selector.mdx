---
title: "模型选择器"
description: "支持搜索的运行时模型选择器，按提供商分组，并提供推理强度控制。"
---

模型选择器是一个弹出框，用于列出 AI 模型；对于支持该功能的模型，还会列出推理强度级别：Low、Medium、High 或自定义集合。在运行时中，选择会自动注册到 assistant-ui 的 `ModelContext` 系统，因此每次请求都会将其传递到后端；单独使用时，则由你自行保存模型值和推理强度。它有两种设计：运行时版本会渲染一个包含模型和推理强度控制的弹出框；静态版本 `ModelPicker` 则会渲染按系列分组的整页列表，并显示价格和能力标签（参见[模型选择器设计](#the-model-picker-design)）。

### 添加选择器

每个模型都需要一个 `id` 和用于显示的 `name`；其他配置均为可选。

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
import { ModelSelector } from "@/components/assistant-ui/elements/model-selector.aui";

function ComposerAction() {
  return (
    <ModelSelector
      models={[
        { id: "gpt-5.6-luna", name: "GPT-5.6 Luna", description: "Fast and efficient" },
        { id: "gpt-5.6-terra", name: "GPT-5.6 Terra", description: "Balanced performance" },
        { id: "gpt-5.6-sol", name: "GPT-5.6 Sol", description: "Most capable", efforts: true },
      ]}
      defaultValue="gpt-5.6-luna"
      defaultEffort="medium"
      size="sm"
    />
  );
}
```

### 在 API 路由中读取选择结果

所选模型的 `id` 会以 `config.modelName` 的形式传入；如果模型支持推理强度，其强度级别则会以 `config.reasoningEffort` 的形式传入。

```tsx title="app/api/chat/route.ts"
export async function POST(req: Request) {
  const { messages, config } = await req.json();

  const result = streamText({
    model: openai(config?.modelName ?? "gpt-5.6-luna"),
    providerOptions: {
      openai:
        config?.reasoningEffort !== undefined
          ? { reasoningEffort: config.reasoningEffort }
          : {},
    },
    messages: await convertToModelMessages(messages),
  });

  return result.toUIMessageStreamResponse();
}
```

### 自行保存值

```tsx title="app/chat.tsx"
"use client";

import { useState } from "react";
import {
  ModelSelectorRoot,
  ModelSelectorTrigger,
  ModelSelectorContent,
} from "@/components/assistant-ui/elements/model-selector";

const MODELS = [
  { id: "gpt-5.6-luna", name: "GPT-5.6 Luna" },
  { id: "gpt-5.6-sol", name: "GPT-5.6 Sol", efforts: true },
];

export function ModelSelect() {
  const [value, setValue] = useState("gpt-5.6-luna");
  const [effort, setEffort] = useState<string>();

  return (
    <ModelSelectorRoot
      models={MODELS}
      value={value}
      onValueChange={setValue}
      effort={effort}
      onEffortChange={setEffort}
    >
      <ModelSelectorTrigger />
      <ModelSelectorContent />
    </ModelSelectorRoot>
  );
}
```

## 组成结构

```tsx
<button role="combobox" aria-haspopup="listbox" data-slot="model-selector-trigger" />

<div data-slot="model-selector-content"> {/* a Command (cmdk) list */}
  <input data-slot="model-selector-search" /> {/* only when searchable */}
  <div data-slot="model-selector-list">
    <div data-slot="model-selector-empty" /> {/* only when search has no matches */}
    <div data-slot="model-selector-group">
      <div data-slot="model-selector-item" /> {/* one per model */}
    </div>
  </div>
  <div data-slot="model-selector-effort" /> {/* only when the selected model declares efforts */}
</div>
```

Thinking 行（`Effort`）仅在所选模型设置了 `efforts` 时挂载；切换到不支持该功能的模型时，该行会隐藏，但不会丢弃你选择的推理强度；切换回支持该功能的模型时，只要该模型也提供之前选择的级别，就会恢复之前选择的级别。`Content` 需要一个获得焦点的输入框来驱动键盘操作：如果没有自定义的 `children`（或 `searchable={false}`），它会自动渲染一个视觉隐藏的 `FocusAnchor`；同时省略 `Search` 和 `searchable={false}` 的自定义布局没有锚点，需要手动添加一个，才能保持键盘可操作性。

## 示例

### 推理强度

声明了 `efforts` 的模型会显示 Thinking 行。`efforts: true` 启用默认的 Low / Medium / High 级别；改为使用 `{ id, name }` 对象列表即可定义自定义集合，而省略 `efforts` 则会为该模型完全隐藏该行。

```tsx
{
  id: "gpt-5.6-sol",
  name: "GPT-5.6 Sol",
  efforts: [
    { id: "minimal", name: "Minimal" },
    { id: "high", name: "High" },
  ],
}
```

### 自定义推理强度 UI

`Effort` 的默认布局是水平分段，当模型提供多个级别时就会溢出。`useModelSelectorEfforts` 会公开所选模型的级别和当前选择，便于在 `Content` 内部实现其他布局：

```tsx
import { useModelSelectorEfforts } from "@/components/assistant-ui/elements/model-selector";
import {
  DropdownMenu,
  DropdownMenuContent,
  DropdownMenuRadioGroup,
  DropdownMenuRadioItem,
  DropdownMenuTrigger,
} from "@/components/ui/dropdown-menu";

function EffortDropdown() {
  const { efforts, effort, setEffort } = useModelSelectorEfforts();
  if (!efforts?.length) return null;

  return (
    <DropdownMenu>
      <DropdownMenuTrigger>{efforts.find((e) => e.id === effort)?.name ?? "Select"}</DropdownMenuTrigger>
      <DropdownMenuContent align="end">
        <DropdownMenuRadioGroup value={effort} onValueChange={setEffort}>
          {efforts.map((option) => (
            <DropdownMenuRadioItem key={option.id} value={option.id}>
              {option.name}
            </DropdownMenuRadioItem>
          ))}
        </DropdownMenuRadioGroup>
      </DropdownMenuContent>
    </DropdownMenu>
  );
}
```

将其渲染在 `Content` 中，替代 `Effort`。

### 提供商图标

每个模型的 `icon` 接受任意 `ReactNode`，并会同时渲染在触发器和下拉菜单项中。[模型图标](/elements/logos)提供了可直接使用的 `OpenAILogo`、`ClaudeLogo` 和 `GeminiLogo` 标记。

```tsx
{ id: "claude-opus-4.5", name: "Claude Opus 4.5", icon: <ClaudeLogo /> }
```

### 搜索

搜索默认关闭：将 `searchable` 传递给已连接的 `ModelSelector`；如果直接渲染其默认子元素，也可以将其传递给 `ModelSelectorContent`。匹配会针对每个模型的 `id`、`name` 和 `keywords` 执行；将提供商名称添加到 `keywords` 后，输入该名称即可找到该提供商的模型。

```tsx
<ModelSelector models={models} searchable />
{/* or, standalone: */}
<ModelSelectorContent searchable />
```

### 变体和尺寸

`variant` 和 `size` 位于触发器上：将它们传递给已连接的 `ModelSelector`；在单独使用的布局中，也可以直接传递给 `ModelSelectorTrigger`。

```tsx
<ModelSelector variant="ghost" size="lg" />
{/* or, standalone: */}
<ModelSelectorTrigger variant="ghost" size="lg" />
```

| 变体 | 描述 |
|---------|-------------|
| `outline` | 边框、透明背景（默认） |
| `ghost` | 无背景 |
| `muted` | 实色次要背景 |

| 尺寸 | 描述 |
|------|-------------|
| `sm` | 紧凑，`h-8` |
| `default` | 标准，`h-9` |
| `lg` | 较大，`h-10` |

## API 参考

<RuntimeMode>

### ModelSelector

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `models` | `ModelOption[]` | 必需 | 要显示的模型。 |
| `value` / `defaultValue` | `string` | 第一个模型 | 受控的或初始选中的模型 id。 |
| `onValueChange` | `(value: string) => void` | | 选择发生变化时调用。 |
| `effort` / `defaultEffort` | `string` | | 受控的或初始的推理强度级别 id。 |
| `onEffortChange` | `(effort: string) => void` | | 推理强度级别发生变化时调用。 |
| `searchable` | `boolean` | `false` | 在模型列表上方渲染搜索输入框。 |
| `variant` | `"outline" \| "ghost" \| "muted"` | `"outline"` | 触发器样式。 |
| `size` | `"sm" \| "default" \| "lg"` | `"default"` | 触发器尺寸。 |
| `align` | `"start" \| "center" \| "end"` | `"start"` | 弹出框相对于触发器的对齐方式。 |
| `className` / `contentClassName` | `string` | | 合并到触发器 / 弹出框内容上。 |

### 注册机制

1. `ModelSelector` 使用选中的 id 作为 `config.modelName` 调用 `aui.modelContext.register()`；如果所选模型支持所选级别，还会传入 `config.reasoningEffort`。
2. `AssistantChatTransport`（来自 `@assistant-ui/ai-sdk`）会将 `config` 包含在每个聊天请求的请求体中。
3. API 路由读取 `config.modelName` 和 `config.reasoningEffort`。

`ModelSelector.Root`（即下文介绍的相同 `ModelSelectorRoot`）自身不会执行注册；它纯粹用于展示。

</RuntimeMode>

<StandaloneMode>

### ModelSelectorRoot 和子组件

| 导出 | 渲染内容 | 说明 |
|--------|---------|-------|
| `ModelSelectorRoot` | provider + Popover | 保存 `models` 以及受控/非受控的值、推理强度和打开状态。自身不产生 DOM。 |
| `ModelSelectorTrigger` | `button` | `role="combobox"`；获得焦点时，`ArrowDown`/`ArrowUp` 会打开弹出框。 |
| `ModelSelectorValue` | `span` | 所选模型的图标、名称，以及（如果有 `showEffort`）推理强度名称；未选择任何内容时显示占位符。 |
| `ModelSelectorContent` | 弹出框 + `Command` | 包装 cmdk `Command`；`searchable` 和 `side` 是值得注意的属性。 |
| `ModelSelectorSearch` | `input`（cmdk） | 根据输入内容筛选 `List`。 |
| `ModelSelectorFocusAnchor` | 视觉隐藏的 `input` | 没有可见搜索框时，为键盘导航提供锚点。 |
| `ModelSelectorList` | cmdk 列表 | 默认将所有模型渲染在一个 `Group` 下。 |
| `ModelSelectorEmpty` | cmdk 空状态 | 搜索没有匹配项时显示。 |
| `ModelSelectorGroup` | cmdk 分组 | 带标签的项目组，例如每个提供商一个分组。 |
| `ModelSelectorSeparator` | cmdk 分隔符 | 分组或项目之间的分隔线。 |
| `ModelSelectorItem` | cmdk 项目 | 一个模型；接受 `model: ModelOption` 属性。 |
| `ModelSelectorEffort` | `div` + radiogroup | Thinking 行；所选模型没有 `efforts` 时渲染 `null`。 |

### ModelOption

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `id` | `string` | 由已连接的 `ModelSelector` 作为 `modelName` 发送到后端；`ModelSelectorRoot` 自身不会读取该字段。 |
| `name` | `string` | 显示在触发器和项目中。 |
| `description` | `string` | 项目中名称下方的可选副标题。 |
| `icon` | `ReactNode` | 可选，显示在名称前。 |
| `disabled` | `boolean` | 禁止选择该模型。 |
| `keywords` | `string[]` | 除 `id` 和 `name` 外，供 `ModelSelectorSearch` 匹配的其他词条。 |
| `efforts` | `boolean \| { id: string; name: string }[]` | 对默认 Low/Medium/High 使用 `true`；自定义集合使用列表；省略则为该模型隐藏 Thinking 行。 |

### 推理强度辅助工具

| 导出 | 类型 | 描述 |
|--------|------|-------------|
| `useModelSelectorEfforts()` | `() => { efforts, effort, setEffort }` | 所选模型的推理强度级别和当前选择；必须在 `ModelSelectorRoot` 内调用。 |
| `resolveModelEffort(models, modelId, effort)` | `(models, modelId, effort) => string \| undefined` | 如果给定模型支持该功能，则返回 `effort`，否则返回 `undefined`；粘性选择规则 `ModelSelectorRoot` 在内部生效。 |
| `useModelSelectorContext()` | `() => ModelSelectorContextValue` | 子组件读取的原始上下文；在 `ModelSelectorRoot` 外部调用会抛出异常。不会从 `.aui` 路径重新导出。 |

</StandaloneMode>


## 模型选择器设计

侧栏中的 Static 变体是同一选择器的第二种设计：`ModelPicker` 会将所有模型渲染为按系列分组的整页列表，每行包含上下文窗口、价格和能力标签，并用勾选标记显示当前模型，而不是使用可搜索的弹出框。它是一个仅由 props 驱动、无运行时依赖的单一组件：

```sh
npx shadcn@latest add "@assistant-ui/elements-model-picker"
```

<RuntimeMode>

在运行时中，没有可供读取的可用模型目录：assistant-ui 会跟踪下一次调用的模型配置，而不是维护所有可切换模型的目录。与弹出框不同，`ModelPicker` 自身不会执行注册，因此应注册一个报告所选 id 的 provider，并根据模型上下文当前报告的内容设置初始选择，例如使用服务器上的默认值。

```tsx title="components/assistant-ui/elements/model-picker.tsx"
"use client";

import { useAui, useAuiState } from "@assistant-ui/react";
import { useEffect, useState } from "react";
import {
  ModelPicker,
  type PickableModel,
} from "@/components/assistant-ui/elements/model-picker";

export function ModelPickerPanel({
  models,
}: {
  models: readonly PickableModel[];
}) {
  const aui = useAui();
  const activeModelName = useAuiState((s) => s.modelContext.modelName);
  const [selectedId, setSelectedId] = useState(
    () => models.find((model) => model.id === activeModelName)?.id ?? models[0]!.id,
  );

  useEffect(() => {
    return aui.modelContext.register({
      getModelContext: () => ({ config: { modelName: selectedId } }),
    });
  }, [aui, selectedId]);

  return (
    <ModelPicker models={models} selectedId={selectedId} onSelect={setSelectedId} />
  );
}
```

</RuntimeMode>

<StandaloneMode>

单独使用时，`ModelPicker` 是一个普通的受控列表：它按系列对 `models` 进行分组，保留每个系列首次出现的顺序，并通过 `onSelect` 报告所选模型。

```tsx title="app/model-picker-panel.tsx"
"use client";

import { useState } from "react";
import {
  ModelPicker,
  type PickableModel,
} from "@/components/assistant-ui/elements/model-picker";

const MODELS: PickableModel[] = [
  { id: "sonnet", name: "Claude Sonnet", family: "Anthropic", context: "200k", price: "$3 / 1M", capabilities: ["vision", "tools"] },
  { id: "gpt-5", name: "GPT-5", family: "OpenAI", context: "400k", price: "$5 / 1M", capabilities: ["tools", "thinking"] },
];

export function ModelPickerPanel() {
  const [selectedId, setSelectedId] = useState(MODELS[0]!.id);
  return (
    <ModelPicker models={MODELS} selectedId={selectedId} onSelect={setSelectedId} />
  );
}
```

</StandaloneMode>

系列根据带有 `[...new Set(models.map((m) => m.family))]` 的 `models` 派生，因此系列的位置由第一个命名该系列的模型决定，而不是按字母顺序排列。每一行都是普通的切换按钮（`aria-pressed`，而不是列表框选项），因此内置的键盘方向键导航；Tab 会像在任何按钮列表中一样在各行之间移动。无论该行是否被选中，勾选标记所在列都会保持宽度不变，因此选择变化时行不会发生偏移。

### ModelPicker

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `models` | `PickableModel[]` | 必需 | `{ id, name, family, context, price, capabilities }[]`。系列保留首次出现的顺序；`context` 和 `price` 是预先格式化的字符串（该元素不会执行货币计算），`capabilities` 会渲染为标签文字。 |
| `selectedId` | `string` | 必需 | 当前激活的模型。 |
| `onSelect` | `(id: string) => void` | | 选择模型时调用。 |
| `className` | `string` | | 合并到根元素上。 |
