---
title: "连接状态"
description: "套接字断开后，运行仍在服务器上继续，流式传输随后会恢复。"
---

连接状态横幅会在运行期间的传输层出现短暂故障时提示读者：套接字已断开、运行仍在服务器端继续，或流式传输刚刚恢复。在运行时中，这对应于捕获传输失败并恢复运行；单独使用时，则由你直接驱动阶段。

## 快速开始

<RuntimeMode>

assistant-ui 不会在线程状态上暴露单独的连接字段，因为套接字断开是适配器观察到的情况，而不是运行时自身建模的概念。它提供的是可恢复的运行：在适配器报告失败的位置捕获错误，显示横幅，然后调用 `resumeRun` 恢复同一个运行。

<Steps>
  <Step>

### 跟踪运行周围的阶段

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
"use client";

import { useEffect, useState } from "react";
import { useAui, useAuiState } from "@assistant-ui/react";
import { ConnectionState, type ConnectionPhase } from "./connection-state";

function ConnectionBanner({ resumeFromId }: { resumeFromId: string | null }) {
  const aui = useAui();
  const isRunning = useAuiState((s) => s.thread.isRunning);
  const [phase, setPhase] = useState<ConnectionPhase>("online");

  useEffect(() => {
    if (phase === "reconnecting" && isRunning) setPhase("resumed");
  }, [phase, isRunning]);

  return (
    <ConnectionState
      phase={phase}
      onRetry={() => {
        setPhase("reconnecting");
        aui.thread.resumeRun({ parentId: resumeFromId });
      }}
    />
  );
}
```

`phase` 首次切换为 `"dropped"` 的位置取决于适配器：也就是传输层暴露网络故障的位置，`ConnectionState` 本身对此不做任何规定。`resumeRun` 不会返回可等待的 promise；观察 `isRunning` 切回 `true`，即可确认重新连接确实成功。

  </Step>
  <Step>

### 恢复而不是重新启动

`resumeRun` 接受与 `startRun` 相同的配置形状：一个 `parentId`（以及可选的 `sourceId` 和 `runConfig`），而不是原始连接句柄。究竟是继续同一代运行还是启动新的一代运行，取决于适配器：assistant-ui 的可恢复传输会在服务器端保留运行并重放它，而不是再次请求模型：

```tsx
aui.thread.resumeRun({ parentId: resumeFromId, sourceId: null });
```

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

单独使用时，`ConnectionState` 只是一个纯展示组件：由你管理阶段，它会渲染匹配的横幅，或者什么也不渲染。

<Steps>
  <Step>

### 驱动阶段

```tsx title="app/banner.tsx"
"use client";

import { useState } from "react";
import { ConnectionState, type ConnectionPhase } from "@/components/assistant-ui/elements/connection-state";

export function Banner() {
  const [phase, setPhase] = useState<ConnectionPhase>("online");
  return (
    <ConnectionState
      phase={phase}
      attempt={phase === "reconnecting" ? 1 : undefined}
      onRetry={() => setPhase("reconnecting")}
    />
  );
}
```

  </Step>
  <Step>

### 恢复后清除状态

`"resumed"` 用于短暂确认，而不是稳定状态；经过短暂延迟后，将其切回 `"online"`，后者不会渲染任何内容：

```tsx
useEffect(() => {
  if (phase !== "resumed") return;
  const id = setTimeout(() => setPhase("online"), 2000);
  return () => clearTimeout(id);
}, [phase]);
```

  </Step>
</Steps>

</StandaloneMode>

## 组成

```tsx
<div data-slot="connection-state">
  {/* dropped: icon, message, Reconnect button */}
  {/* reconnecting: spinner, message, attempt count */}
  {/* resumed: check, message, resumed token count */}
</div>
```

当 `phase` 为 `"online"` 时，`ConnectionState` 完全不会渲染，这是唯一不显示横幅的阶段。其他三个阶段互斥，并且分别显示不同的图标和消息；`attempt` 和 `resumedTokens` 是可选计数器，仅在传入时显示。

## 示例

### 所有阶段

```tsx
<ConnectionState phase="dropped" onRetry={() => {}} />
<ConnectionState phase="reconnecting" attempt={2} />
<ConnectionState phase="resumed" resumedTokens={340} />
```

### 明确静默在线状态

由于 `phase="online"` 已经渲染 `null`，是否有条件地挂载横幅并非必需；让它保持挂载状态，可以在阶段每次离开 `"online"` 时，通过自身的淡入淡出和滑动过渡动画进出。

## API 参考

<RuntimeMode>

### 线程方法

| 方法 | 类型 | 描述 |
|--------|------|-------------|
| `aui.thread.resumeRun(config)` | `(config: CreateResumeRunConfig) => void` | 为 `config.parentId` 重新连接到运行（或根据适配器重新启动运行）。形状与 `startRun` 相同。 |
| `aui.thread.cancelRun()` | `() => void` | 直接取消正在进行的运行，而不是恢复它。 |

没有用于判断“套接字已断开”的内置选择器：该阶段存在于你的适配器及其周围的应用状态中，而不在 `AssistantState` 中。

</RuntimeMode>

<StandaloneMode>

### ConnectionState

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `phase` | `"online" \| "dropped" \| "reconnecting" \| "resumed"` | 必填 | `"online"` 不会渲染任何内容。 |
| `attempt` | `number` | | 设置后显示在 `"reconnecting"` 消息旁边。 |
| `resumedTokens` | `number` | | 设置后显示在 `"resumed"` 消息旁边。 |
| `onRetry` | `() => void` | | 由 `"dropped"` 阶段的“重新连接”按钮调用。 |
| `className` | `string` | | 合并到根元素上。 |

其他所有 `div` 属性都会转发到根元素。

</StandaloneMode>
