---
title: "工具回退"
description: "用于没有专用 UI 的工具调用的默认运行时渲染器。"
---

Tool fallback 会渲染没有专属 UI 的任何工具调用：默认显示为折叠的单行摘要，展开后可查看参数、结果，以及（当工具正在等待决策时）用于响应的按钮。在运行时中，它会读取实时的工具调用部分，并回调到同一次运行中；由于工具调用与其所属的运行本质上是同一个整体，因此不存在独立表单。

## 入门

<RuntimeMode>

`Thread` 已经会为每个没有自身 UI 的工具调用渲染此内容。

<Steps>
  <Step>

### 它已经是你的默认选项

在 `Thread` 的消息渲染器中，当没有更具体的渲染器（例如针对单个工具的渲染器或生成式 UI）优先处理工具调用部分时，它会回退到 `ToolFallback`。

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
case "tool-call":
  return part.toolUI ?? <ToolFallbackComponent {...part} />;
```

  </Step>
  <Step>

### 为所有未注册工具替换它

将 `components.ToolFallback` 传递给 `Thread`，即可替换在工具调用没有专用 UI 时使用的渲染器。拥有自身注册渲染器的工具仍然优先于此覆盖项，就像它优先于内置的 `ToolFallback` 一样。

```tsx
<Thread components={{ ToolFallback: MyToolCard }} />
```

`MyToolCard` 接收的 props 与 `ToolFallback` 本身相同。请参阅下面的 API 参考。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

单独使用时，没有可供回退的内容：`ToolFallback` 专门用于渲染运行时交给它的 `ToolCallMessagePart`，并回调到同一次运行中，因此仅接收 props 的版本只会静态呈现你已有的相同结构。请直接根据你自己的数据构建工具调用卡片，而不要使用此元素。

</StandaloneMode>

## 组成结构

<RuntimeMode>

```tsx
<div> {/* ToolFallbackRoot, a Collapsible */}
  <button aria-expanded={/* open */}>
    {/* status icon: spinner / check / X-circle / alert */}
    <span>{/* "Used tool: <name>" or "Cancelled tool: <name>" */}</span>
    <span>{/* elapsed duration, while known */}</span>
    {/* chevron, rotates open */}
  </button>
  <div> {/* ToolFallbackContent */}
    {/* error, only while status is "incomplete" and carries one */}
    {/* args, only when argsText is non-empty */}
    {/* approval controls, only while requires-action and unanswered */}
    {/* result, hidden while cancelled, only when result is defined */}
  </div>
</div>
```

当工具调用的状态为 `"requires-action"` 时，该行默认展开；在其他情况下，则保持用户离开时的状态。只有调用记录了开始时间后才会显示持续时间；调用运行期间每秒持续递增，完成后则冻结在记录的总时长。

</RuntimeMode>

## 示例

<RuntimeMode>

### 未声明选项的批准

当部分中既没有 `approval`，也没有 `interrupt` 时，一对普通的“允许 / 拒绝”按钮会直接使用固定的 approved 或 denied 字符串调用 `addResult`。设置 `interrupt` 后，同一对按钮则会改为调用 `resume({ approved })`，以恢复暂停的前端工具执行。

```tsx
<ToolFallback {...part} />
```

### 已声明选项的批准

设置 `part.approval.options` 后，每个选项都会渲染一个按钮，而不是普通的成对按钮：先显示 allow 类型的选项（第一个使用主要按钮样式），然后是 custom 类型的选项，最后是 reject 类型的选项。选项可以选择在解析前加入确认步骤。

```tsx
approval: {
  id: "call-1",
  options: [
    { id: "once", kind: "allow-once", label: "Allow" },
    { id: "always", kind: "allow-always", label: "Always allow", confirm: true },
    { id: "deny", kind: "reject-once", label: "Deny" },
  ],
}
```

在此处选择“始终允许”会先显示确认 / 返回步骤，然后再调用 `respondToApproval({ optionId: "always" })`；另外两个选项则会立即解析。设置 `approval.approved` 或 `approval.resolution` 后，整个批准区块将停止渲染。

### 重新设置部分样式

每个部分都是具名导出，可以重新组合，并且各自携带 `data-slot`，以便进行有针对性的样式设置。

```tsx
import { ToolFallbackTrigger, ToolFallbackContent } from "@/components/assistant-ui/elements/tool-fallback.aui";

<ToolFallbackTrigger toolName={part.toolName} status={part.status} className="text-sm" />
```

</RuntimeMode>

## API 参考

<RuntimeMode>

### 部分

| 部分 | 渲染内容 | 备注 |
|------|---------|-------|
| `ToolFallback` | 完整组合 | 默认导出；完整的 `ToolCallMessagePartComponent`。 |
| `ToolFallbackRoot` | `div` | 可折叠容器。在 `"requires-action"` 时自动展开。 |
| `ToolFallbackTrigger` | `button` | 接收 `toolName` 和 `status`。 |
| `ToolFallbackContent` | `div` | 可折叠面板。 |
| `ToolFallbackArgs` | `pre` | 接收 `argsText`；为空时渲染 `null`。 |
| `ToolFallbackResult` | `pre` | 接收 `result`；当 `undefined` 时渲染 `null`。将非字符串结果转换为字符串。 |
| `ToolFallbackError` | 文本 | 接收 `status`；除非 `status.type === "incomplete"` 且其中包含错误，否则渲染 `null`。 |
| `ToolFallbackApproval` | 按钮 | 接收 `approval`、`interrupt`、`status`、`addResult`、`resume`、`respondToApproval`。 |

### 工具调用部分字段

`ToolFallback`（以及上面的每个部分）会将当前工具调用作为 `ToolCallMessagePartProps` 接收，同时接收完整的 `ToolCallMessagePart` 和三个回调：

| 字段 | 类型 | 描述 |
|-------|------|--------------|
| `toolCallId` | `string` | 此次调用的稳定 ID。 |
| `toolName` | `string` | 模型调用的工具名称。 |
| `argsText` | `string` | 模型目前已流式传输的原始 JSON，可能不完整。 |
| `result` | `TResult \| undefined` | 工具产生结果后的工具结果。 |
| `isError` | `boolean \| undefined` | 结果是否表示失败。 |
| `status` | `ToolCallMessagePartStatus` | `"running"`、`"complete"`、`"incomplete"`（带有 `reason`，例如 `"cancelled"`），或 `"requires-action"`（`reason: "tool-calls" \| "interrupt"`）。 |
| `timing` | `ToolCallTiming \| undefined` | 在进行跟踪时记录的实际开始 / 完成时间。 |
| `interrupt` | `{ type: "human"; payload: unknown } \| undefined` | 暂停的人类输入请求。 |
| `approval` | 对象 `\| undefined` | 服务端批准门：`id`、`approved?`、`options?`、`optionId?`、`resolution?`。 |

### 回调

| 回调 | 类型 | 描述 |
|----------|------|-------------|
| `addResult` | `(result) => void` | 从渲染器设置此部分的结果，而不是使用工具的 `execute`。 |
| `resume` | `(payload: unknown) => void` | 使用请求的 payload 恢复暂停的前端工具执行。 |
| `respondToApproval` | `(response: ToolApprovalResponse) => Promise<void>` | 响应批准门：`{ approved }`、`{ optionId }`、两者，或者当请求接收自由格式答案时使用 `{ text }`。 |

### 组合

| 部分 | 类型 | 描述 |
|------|------|-------------|
| `components.ToolFallback` | `ToolCallMessagePartComponent` | `Thread` prop，用于替换所有没有专用 UI 的工具调用所使用的渲染器。 |
| `useToolCallElapsed()` | `number \| undefined` | 当前工具调用部分经过的毫秒数；在工具调用作用域之外或没有记录计时时为 `undefined`。 |

</RuntimeMode>
