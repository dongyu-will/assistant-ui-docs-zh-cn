---
title: "消息队列"
description: "运行进行期间输入的消息会排队，并可在运行结束前取消。"
---

回复正在流式输出时，你随后发送的消息不会被阻塞或丢弃：它会堆叠在实时的“运行中”行下方，并且在轮到它之前一直可以取消。在运行时中，队列属于输入框组件本身，只需在运行处于活动状态时正常发送消息即可填充；单独使用时，则需要自行保存运行中的文本和消息列表。

## 快速开始

<RuntimeMode>

支持排队的运行时会在 `s.composer.queue` 上跟踪待发送消息；除了在 `s.thread.isRunning` 已经为 true 时发送消息外，无需任何特殊操作即可将消息加入队列。

<Steps>
  <Step>

### 渲染队列

`ComposerPrimitive.Queue` 会遍历待处理项目；`QueueItemPrimitive.Text` 和 `.Remove` 用于读取并操作当前作用域中的项目。

```tsx title="components/assistant-ui/elements/message-queue.tsx"
"use client";

import { ComposerPrimitive, QueueItemPrimitive, useAuiState } from "@assistant-ui/react";
import { ArrowUpIcon, XIcon } from "lucide-react";
import { cn } from "@/lib/utils";
import { field, ghostButton, mono } from "@/components/assistant-ui/elements/surfaces";

export function MessageQueue() {
  const queueLength = useAuiState((s) => s.composer.queue.length);

  return (
    <div className="flex w-full max-w-sm flex-col gap-2">
      {queueLength > 0 && (
        <div className="flex items-baseline justify-between px-1">
          <span className={cn(mono, "text-foreground/35")}>{queueLength} queued</span>
          <span className={cn(mono, "text-foreground/35")}>sends when this finishes</span>
        </div>
      )}
      <ul className="flex flex-col gap-1.5">
        <ComposerPrimitive.Queue>
          {({ queueItem }) => (
            <li
              key={queueItem.id}
              className={cn(field, "flex items-center gap-2.5 rounded-2xl py-2 pr-2 pl-3")}
            >
              <span className="text-foreground/60 min-w-0 flex-1 truncate text-[13.5px]">
                <QueueItemPrimitive.Text />
              </span>
              <ArrowUpIcon className="text-foreground/25 size-3 shrink-0" />
              <QueueItemPrimitive.Remove aria-label="Remove from queue" className={cn(ghostButton, "size-6 shrink-0")}>
                <XIcon className="size-3.5" />
              </QueueItemPrimitive.Remove>
            </li>
          )}
        </ComposerPrimitive.Queue>
      </ul>
    </div>
  );
}
```

  </Step>
  <Step>

### 显示正在运行的消息

与队列不同，没有用于获取运行中提示文本的单一选择器；当 `s.thread.isRunning` 为 true 时，它就是最近发送的用户消息。

```tsx
const running = useAuiState((s) =>
  s.thread.isRunning ? [...s.thread.messages].reverse().find((m) => m.role === "user") : undefined,
);
```

当 `running` 解析为一条消息后，渲染独立元素所使用的相同脉冲圆点行；用户消息的 `content` 是由多个部分组成的数组，而不是普通字符串，因此需要自行拼接文本部分：`running.content.filter((p) => p.type === "text").map((p) => p.text).join(" ")`。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

单独使用时，`MessageQueue` 会完全按照你传入的两个数组进行渲染：运行中消息的文本，以及其后的排队消息。

<Steps>
  <Step>

### 保存运行中的文本和队列

```tsx title="app/queue.tsx"
"use client";

import { useState } from "react";
import { MessageQueue, type QueuedMessage } from "@/components/assistant-ui/elements/message-queue";

export function Queue() {
  const [queued, setQueued] = useState<QueuedMessage[]>([
    { id: "1", text: "Now add tests for the auth flow" },
  ]);

  return (
    <MessageQueue
      running="Refactor the login form to use the new validation hook"
      queued={queued}
      onCancel={(id) => setQueued((q) => q.filter((m) => m.id !== id))}
    />
  );
}
```

  </Step>
  <Step>

### 运行结束后发送下一条消息

这里没有自动交接机制：运行完成后，将数组中的第一条排队消息移出，使其开始运行，并使用缩短后的队列重新渲染。

  </Step>
</Steps>

</StandaloneMode>

## 组成

```tsx
<div data-slot="message-queue">
  <div>{/* running: pulsing dot, text, "running" badge */}</div>
  <div>{/* "n queued · sends when this finishes", only when queued.length > 0 */}</div>
  <ul>
    <li>{/* index, text, arrow, remove button */}</li>
  </ul>
</div>
```

任何时候都只有一条消息处于“运行中”状态；`onCancel` 只提供给排队消息，并且每条消息添加时都会淡入并滑入，同时以消息 id 作为 key，因此已经显示的消息不会重复播放动画。单独使用时，这是一个扁平列表，除了数组位置外没有其他顺序概念。在运行时中，`s.composer.queue` 还可以通过 `aui.composer.queueItem({ id }).move({ insertAfter, insertBefore })` 重新排序，也可以通过 `aui.composer.queueItem({ id }).move({ lane: "steer", insertAfter: null })` 让某条消息跳到其他消息前面；这个简单视图不会呈现这些功能。排队本身是一项能力，而不是保证：在假设运行期间发送的消息会进入队列而不是被拒绝之前，请先检查 `s.thread.capabilities.queue`。

## 示例

### 将排队消息移到最前面

<RuntimeMode>

`QueueItemPrimitive.Steer` 会让排队消息下一条运行，而不是等待轮到它：

```tsx
<QueueItemPrimitive.Steer className={cn(ghostButton, "px-2 text-xs")}>
  Run now
</QueueItemPrimitive.Steer>
```

</RuntimeMode>

<StandaloneMode>

这里没有内置的重新排序功能；将按下的消息移到 `queued` 数组的最前面，然后重新渲染。

```tsx
setQueued((q) => {
  const item = q.find((m) => m.id === id)!;
  return [item, ...q.filter((m) => m.id !== id)];
});
```

</StandaloneMode>

### 重新设置队列样式

两个区域的根元素都接收 `className`，而 `surfaces.tsx` 中的 `field`、`ghostButton` 和 `mono` 令牌分别用于排队消息行、移除按钮和小型大写标签。

```tsx
<MessageQueue className="gap-3" /* ... */ />
```

## API 参考

<RuntimeMode>

### ComposerPrimitive 和 QueueItemPrimitive

| 部分 | 渲染内容 | 说明 |
|------|---------|-------|
| `ComposerPrimitive.Queue` | fragment | 按顺序为每个待处理的队列项目提供 render prop。 |
| `QueueItemPrimitive.Text` | `span` | 拼接该项目的文本部分。 |
| `QueueItemPrimitive.Remove` | `button` | 从队列中移除该项目。 |
| `QueueItemPrimitive.Steer` | `button` | 让该项目下一条运行，而不是等待轮到它。 |

### 输入框状态

| 选择器 | 类型 | 描述 |
|----------|------|-------------|
| `s.composer.queue` | `readonly { id: string; parts: ... }[]` | 按队列顺序排列的待发送消息。 |
| `s.thread.isRunning` | `boolean` | 当消息正在运行时为 true。 |
| `s.thread.capabilities.queue` | `boolean` | 此运行时是否会将运行期间发送的消息加入队列。 |
| `aui.composer.queueItem({ id }).move(placement)` | `(placement: { lane?: "queue" \| "steer"; insertAfter?: string \| null; insertBefore?: string \| null }) => void` | 重新排列项目，或让其下一条运行。 |
| `aui.composer.queueItem({ id }).remove()` | `() => void` | 从队列中移除该项目。 |

</RuntimeMode>

<StandaloneMode>

### MessageQueue

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `running` | `string` | 必填 | 当前运行中消息的文本。 |
| `queued` | `readonly QueuedMessage[]` | 必填 | 按顺序排列的待处理消息。 |
| `onCancel` | `(id: string) => void` | | 按下排队项目的移除按钮时调用。 |
| `className` | `string` | | 合并到根元素上。 |

`QueuedMessage` 是 `{ id: string; text: string }`。其他所有 `div` 属性都会转发到根元素。

</StandaloneMode>
