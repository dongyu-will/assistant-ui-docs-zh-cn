---
title: "在会话中搜索"
description: "在长线程中查找内容，并在滚动条旁的轨道上标记每个匹配项。"
---

用于搜索屏幕上已有消息的查找栏：输入查询内容，逐个浏览匹配项，并在形似滚动条的侧边轨道上查看每个匹配项的标记。在运行时中，查询会针对线程自身的消息执行；单独使用时，则由你自行提供匹配项。

## 快速开始

<RuntimeMode>

运行时没有搜索原语；线程只会公开其消息。读取 `s.thread.messages` 并扫描每条消息的文本部分，即可得到独立元素所需的同一个 `hits` 数组。这样无需往返服务器，就能使用真实的会话数据驱动它。

### 从线程收集匹配项

```tsx title="components/assistant-ui/elements/thread-search-bar.tsx"
"use client";

import { useMemo, useState } from "react";
import { useAuiState } from "@assistant-ui/react";
import {
  ConversationSearch,
  type SearchHit,
} from "@/components/assistant-ui/elements/conversation-search";

const CONTEXT = 24;

export function ThreadSearchBar() {
  const messages = useAuiState((s) => s.thread.messages);
  const [query, setQuery] = useState("");
  const [activeIndex, setActiveIndex] = useState(0);

  const hits = useMemo<SearchHit[]>(() => {
    if (query === "") return [];
    const needle = query.toLowerCase();
    const found: SearchHit[] = [];

    messages.forEach((message, messageIndex) => {
      const text = message.parts
        .filter((part) => part.type === "text")
        .map((part) => part.text)
        .join(" ");
      const haystack = text.toLowerCase();

      let from = 0;
      let at: number;
      while ((at = haystack.indexOf(needle, from)) !== -1) {
        found.push({
          id: `${message.id}-${at}`,
          before: text.slice(Math.max(0, at - CONTEXT), at),
          match: text.slice(at, at + query.length),
          after: text.slice(at + query.length, at + query.length + CONTEXT),
          position: (messageIndex / Math.max(1, messages.length - 1)) * 100,
        });
        from = at + query.length;
      }
    });

    return found;
  }, [messages, query]);

  return (
    <ConversationSearch
      query={query}
      hits={hits}
      activeIndex={activeIndex}
      onQueryChange={(next) => {
        setQuery(next);
        setActiveIndex(0);
      }}
      onStep={(delta) => {
        if (hits.length === 0) return;
        const next = (activeIndex + delta + hits.length) % hits.length;
        setActiveIndex(next);
        const [, messageId] = hits[next]!.id.match(/^(.+)-\d+$/) ?? [];
        document
          .querySelector(`[data-message-id="${messageId}"]`)
          ?.scrollIntoView({ block: "center", behavior: "smooth" });
      }}
    />
  );
}
```

每条渲染后的消息都会由 `MessagePrimitive.Root` 设置 `data-message-id`，因此匹配项的 id 中包含足够的信息，可以直接滚动到对应位置。

  </Step>
</Steps>

</RuntimeMode>

### 保存搜索状态

```tsx title="app/transcript.tsx"
"use client";

import { useMemo, useState } from "react";
import {
  ConversationSearch,
  type SearchHit,
} from "@/components/assistant-ui/elements/conversation-search";

const lines = [
  "The migration touches three tables.",
  "Rollback drops the new columns and restores the index.",
  "The index rebuild takes about four minutes on staging.",
];

export function Transcript() {
  const [query, setQuery] = useState("");
  const [activeIndex, setActiveIndex] = useState(0);

  const hits = useMemo<SearchHit[]>(() => {
    if (query === "") return [];
    const needle = query.toLowerCase();
    return lines
      .map((line, i) => ({ line, i, at: line.toLowerCase().indexOf(needle) }))
      .filter(({ at }) => at !== -1)
      .map(({ line, i, at }) => ({
        id: `${i}`,
        before: line.slice(0, at),
        match: line.slice(at, at + query.length),
        after: line.slice(at + query.length),
        position: (i / (lines.length - 1)) * 100,
      }));
  }, [query]);

  return (
    <ConversationSearch
      query={query}
      hits={hits}
      activeIndex={activeIndex}
      onQueryChange={(next) => {
        setQuery(next);
        setActiveIndex(0);
      }}
      onStep={(delta) =>
        setActiveIndex((i) => (hits.length === 0 ? 0 : (i + delta + hits.length) % hits.length))
      }
    />
  );
}
```

  </Step>
</Steps>

</StandaloneMode>

## 结构

```tsx
<div data-slot="conversation-search">
  <div>
    <input aria-label="Find in conversation" placeholder="Find in conversation" />
    <span>{/* n/hits.length, or "0" */}</span>
    <button aria-label="Previous match" />
    <button aria-label="Next match" />
  </div>
  {/* the active hit's context, when one exists */}
  <div>{/* before / match / after */}</div>
  <div>
    {/* one mark per hit, positioned on a side track like a scrollbar */}
  </div>
</div>
```

该元素不负责索引计算：`onStep` 报告的是原始的 `-1` 或 `1`，而不是计算后的目标，因此是否循环（或限制范围）由调用方决定，正如上面的两个示例所示。渲染前，`activeIndex` 本身会被限制在 `0…hits.length - 1` 范围内；当没有匹配项时，它在内部读取为 `-1`，此时不会显示激活的上下文面板，计数器显示为 `0`。上一个和下一个按钮始终会渲染；元素本身不会禁用它们，因此除非调用方进行保护，否则在空匹配列表中浏览只会静默地不执行任何操作。每个匹配项都会在侧边轨道上获得一个标记，并根据自身的 `position` 百分比定位；当前激活匹配项的标记为实心，其余标记则会变暗。

## 示例

### 匹配项的来源

<RuntimeMode>

针对 `s.thread.messages` 进行匹配意味着搜索会跟随线程：切换线程（或让运行过程以流式传输方式输入更多文本）后，同一个 `ThreadSearchBar` 会自动重新扫描，因为 `useAuiState` 会在每次状态存储更新时重新渲染。与快速开始示例一样，只扫描文本部分，这样推理部分和工具调用部分就不会因为返回匹配项而跳转到用户从未输入或阅读、且不会以可见内容形式渲染的文本。

</RuntimeMode>

<StandaloneMode>

单独使用时，该元素不会读取正在搜索的消息，因此你可以自由限制搜索来源：只搜索可见页面、最近 N 个回合，或一份从未渲染为聊天气泡的对话记录。每当来源文本或查询内容发生变化时，都应重新计算 `hits`，如上面的示例所示。

</StandaloneMode>

### 重新设置标记样式

两个轨道都会在根元素上接收 `className`。显示当前激活匹配项的面板使用 `field` 表面，高亮匹配文本则是普通的 `bg-amber-400/35` span，因此覆盖这两个工具类即可一次性更改所有匹配项的外观。

```tsx
<ConversationSearch className="max-w-md" /* ... */ />
```

## API 参考

<RuntimeMode>

该元素没有专用原语：全文搜索不属于运行时的一部分，因此上面的 `ThreadSearchBar` 只是读取线程状态的普通应用代码。

### 线程状态

| 选择器 | 类型 | 描述 |
|----------|------|-------------|
| `s.thread.messages` | `readonly MessageState[]` | 当前分支中的每条消息。每条消息的 `parts` 保存其内容；筛选 `part.type === "text"` 即可获取可搜索文本。 |

`MessagePrimitive.Root` 会在每条消息上渲染 `data-message-id`，无需调用其他 API 即可将匹配项滚动到可视区域。

</RuntimeMode>

<StandaloneMode>

### ConversationSearch

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `query` | `string` | 必填 | 当前搜索文本。 |
| `hits` | `readonly SearchHit[]` | 必填 | 要显示的匹配项，按文档顺序排列。 |
| `activeIndex` | `number` | 必填 | 高亮匹配项的索引。限制在 `0…hits.length - 1` 范围内；当 `hits` 为空时忽略。 |
| `onQueryChange` | `(query: string) => void` | | 用户输入时使用下一个值调用。 |
| `onStep` | `(delta: number) => void` | | 按下上一个或下一个按钮时，使用 `-1` 或 `1` 调用。 |
| `className` | `string` | | 合并到根元素上。 |

所有其他 `div` 属性都会转发到根元素。

### SearchHit

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `id` | `string` | 匹配项的唯一键。 |
| `before` | `string` | 匹配项正前方的上下文文本。 |
| `match` | `string` | 匹配的子字符串，以高亮形式渲染。 |
| `after` | `string` | 匹配项正后方的上下文文本。 |
| `position` | `number` | 此匹配项标记在侧边轨道上的位置，范围从 `0` 到 `100`。 |

</StandaloneMode>
