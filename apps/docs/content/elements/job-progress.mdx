---
title: "作业进度"
description: "以分钟衡量的工作：加权阶段、预计剩余时间，以及取消方式。"
---

一个单独的长时间运行作业：包含标题、一组加权阶段，以及一条总进度条。随着当前阶段向列表末尾推进，总进度条也会逐渐填充。在运行时中，阶段序列来自工具调用，其结果来自该调用的返回值；单独使用时，则需要在作业运行期间实时自行驱动 `stageIndex` 和 `stageProgress`。

## 开始使用

<RuntimeMode>

此元素本身没有专属的 assistant-ui 原语，因此运行时连接使用的是工具渲染器，而不是原语组合。工具调用的结果是一次性值：设置结果后调用就会完成，因此后端无法通过某个通道持续向已经打开的调用推送新的阶段编号。结果能够如实报告的，是作业在调用完成时进行到了哪一步，无论是完成了所有阶段，还是只进行到中途停止的阶段；卡片自身是否显示勾选标记，仍然只取决于最终的 `stageIndex` 是否到达 `stages` 的末尾。

  <Step>

### 注册渲染函数

```tsx title="app/toolkit.tsx"
"use client";

import { defineToolkit } from "@assistant-ui/react";
import { JobProgress } from "@/components/assistant-ui/elements/job-progress";

export const toolkit = defineToolkit({
  run_ci_job: {
    type: "backend",
    render: ({ args, result, addResult }) => {
      if (!result) {
        return (
          <JobProgress
            title={args.target}
            stages={args.stages ?? []}
            stageIndex={0}
            stageProgress={0}
            eta="starting"
            onCancel={() =>
              addResult({ stageIndex: 0, stageProgress: 0, eta: "cancelled" })
            }
          />
        );
      }
      return (
        <JobProgress
          title={args.target}
          stages={args.stages ?? []}
          stageIndex={result.stageIndex}
          stageProgress={result.stageProgress}
          eta={result.eta}
        />
      );
    },
  },
});
```

`args.stages` 是模型启动作业时预先声明的内容，因此在任何结果存在之前就已经可用，这使加载分支能够渲染真正的 `JobProgress`，而不是一个空占位符。`stageIndex`、`stageProgress` 和 `eta` 仅存在于 `result` 上；由于设置结果会完成调用，`onCancel` 只适用于 `result` 仍为 undefined 的分支。一旦结果存在，就没有需要取消的内容了。终止结果仍然可以报告尚未达到 `stages.length` 的 `stageIndex`，表示作业中途失败或被取消；此时卡片会保留进行中的加载旋转样式，而不是显示勾选标记，因为“完成”完全取决于传入的数值，而不是工具调用本身是否已经完成。

  </Step>
  <Step>

### 让消息列表渲染它

```tsx title="app/MyRuntimeProvider.tsx"
import {
  AssistantRuntimeProvider,
  AuiConfig,
  Tools,
} from "@assistant-ui/react";
import { useChatRuntime } from "@assistant-ui/ai-sdk";
import { toolkit } from "./toolkit";

export function MyRuntimeProvider({
  children,
}: {
  children: React.ReactNode;
}) {
  const runtime = useChatRuntime();
  const config = AuiConfig({ tools: Tools({ toolkit }) });
  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

注册工具包后，`Thread` 以及任何基于 assistant-ui 消息部分原语构建的自定义消息列表（`MessagePrimitive.Parts` 或 `MessagePrimitive.GroupedParts`），都会在消息中出现 `run_ci_job` 调用的位置自动渲染已注册的 UI，因此无需手动放置。

  </Step>
</Steps>

### 随作业实际运行推进进度

轮询或订阅负责运行作业的服务，将其进度写入状态；然后将 `onCancel` 连接到真正能够停止工作的对象，例如让 fetch 调用监听的 `AbortController`。

```tsx
"use client";

import { useEffect, useRef, useState } from "react";

export function CiJob({ jobId }: { jobId: string }) {
  const [stageIndex, setStageIndex] = useState(0);
  const [stageProgress, setStageProgress] = useState(0);
  const controller = useRef(new AbortController());

  useEffect(() => {
    const source = subscribeToJob(jobId, controller.current.signal, (update) => {
      setStageIndex(update.stageIndex);
      setStageProgress(update.stageProgress);
    });
    return () => source.close();
  }, [jobId]);

  return (
    <JobProgress
      title="Verify the fix on CI"
      stages={stages}
      stageIndex={stageIndex}
      stageProgress={stageProgress}
      eta="about 3 min"
      onCancel={() => controller.current.abort()}
    />
  );
}
```

  </Step>
</Steps>

## 结构

```tsx
<div data-slot="job-progress">
  <div>
    {/* check icon once finished, else a spinning loader */}
    <span>{/* title */}</span>
    <span>{/* eta, or "done" once finished */}</span>
    {/* cancel button, hidden once finished */}
  </div>

  <span>{/* overall progress bar */}</span>

  <div>
    {/* one label per stage, dimmed by position relative to the current stage */}
  </div>
</div>
```

`stageIndex` 会向下取整，并限制在 `0…stages.length` 中，而不是 `0…stages.length − 1` 中。因此，达到 `stages.length`（即超过最后一个阶段自身索引的位置）才表示“完成”。此时会显示勾选标记、“已完成”标签和填满的绿色进度条，同时取消按钮会消失。`stageProgress` 会被限制在 `0…1` 中，并且只会缩放当前阶段对总进度条的贡献；无论 `stageProgress` 如何，已经完成的阶段都会计入其完整的 `weight`。阶段权重只会求和一次；如果总和原本会是 `0`，则回退到 `1`。因此，全为零或为空的 `stages` 数组不会发生除零，只是永远不会填充。阶段名称标签会根据位置调整明暗：已完成的阶段显示为较浅的颜色，当前阶段显示为明亮颜色，尚未开始的阶段显示为最浅的颜色。

## 示例

### 完成状态

将 `stageIndex` 设置为 `stages.length`，而不是最后一个阶段自身的索引，即可将作业显示为已完成。`stageProgress` 一旦越过这一界限就不再重要。

```tsx
<JobProgress
  title="Verify the fix on CI"
  stages={stages}
  stageIndex={stages.length}
  stageProgress={0}
  eta="seconds"
/>
```

### 进度来源

<RuntimeMode>

无论作业实际运行多久，后端入口只需要解析一次；工具调用通道本身不会发送中途更新。如果作业中途失败或被取消，应解析为它停止时所在的位置，而不是抛出错误，这样完成后的卡片仍然可以显示作业进行到了哪里。

```ts title="app/api/chat/route.ts"
run_ci_job: tool({
  description: "Kick off CI for the current change and report where it lands.",
  inputSchema: z.object({
    target: z.string(),
    stages: z.array(z.object({ name: z.string(), weight: z.number() })),
  }),
  execute: async ({ target }) => runCiJob(target),
}),
```

</RuntimeMode>

<StandaloneMode>

上一步中的 `subscribeToJob` 代表你已经使用的任意传输方式。`WebSocket`、服务器发送事件以及按固定时间间隔进行的普通轮询，最终都可以归结为相同的形式：每当收到新更新时，就将 `{ stageIndex, stageProgress }` 写入状态。

```tsx
function pollJob(jobId: string, onUpdate: (u: JobUpdate) => void) {
  const id = setInterval(async () => {
    onUpdate(await fetchJobStatus(jobId));
  }, 2000);
  return { close: () => clearInterval(id) };
}
```

</StandaloneMode>

### 重新设置进度条样式

两条轨道都会在根元素上接收 `className`。预计剩余时间文本和阶段标签使用共享的 `mono` 表面，取消按钮使用共享的 `ghostButton` 表面；二者都来自 `surfaces.tsx`，因此重新设置这些令牌的样式后，所有使用它们的元素都会同步更新。

```tsx
<JobProgress className="max-w-none gap-4" /* ... */ />
```

## API 参考

<RuntimeMode>

### 渲染 props

| Prop | 类型 | 描述 |
|------|------|-------------|
| `args` | `{ target: string; stages: { name: string; weight: number }[] }` | 工具的参数；即使结果尚不存在，加载分支也会渲染 `stages`。 |
| `result` | `{ stageIndex: number; stageProgress: number; eta: string } \| undefined` | 调用的一次性结果，在执行器解析之前为 undefined；设置后，调用就已经完成。 |
| `addResult` | `(result: TResult) => void` | 从渲染器本身提供结果；此处用于在 `result` 存在之前用户取消时提前完成调用。 |

### run_ci_job 参数

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `target` | `string` | 要验证的内容，会显示为作业标题。 |
| `stages[].name` | `string` | 阶段标签，以等宽字体显示。 |
| `stages[].weight` | `number` | 此阶段占总进度条的相对比例。 |

### run_ci_job 结果

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `stageIndex` | `number` | 作业进行到的阶段；`stages.length` 表示所有阶段均已完成。 |
| `stageProgress` | `number` | 该阶段的进度，`0…1`。 |
| `eta` | `string` | 当 `stageIndex` 尚未达到 `stages.length` 时，替代“已完成”显示。 |

</RuntimeMode>

<StandaloneMode>

### JobProgress

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `title` | `string` | 必填 | 作业标题。 |
| `stages` | `readonly JobStage[]` | 必填 | 加权阶段序列。 |
| `stageIndex` | `number` | 必填 | 当前阶段的索引，会向下取整并限制在 `0…stages.length` 中。 |
| `stageProgress` | `number` | 必填 | 当前阶段的进度，会限制在 `0…1` 中。 |
| `eta` | `string` | 必填 | 作业运行期间替代“已完成”显示。 |
| `onCancel` | `() => void` | | 按下取消按钮时调用。按钮自身是否显示只取决于 `stageIndex`，与是否提供此属性无关。 |
| `className` | `string` | | 合并到根元素上。 |

其他所有 `div` props 都会转发到根元素。

### JobStage

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `name` | `string` | 阶段标签，以等宽字体显示。 |
| `weight` | `number` | 此阶段占总进度条的相对比例。 |

</StandaloneMode>
