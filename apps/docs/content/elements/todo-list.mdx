---
title: "待办事项列表"
description: "助手自己的工作列表，会在运行过程中发现其他所需事项时重新编写。"
---

待办事项列表展示助手当前正在执行的计划：哪些已完成、哪些正在进行，以及哪些仍待处理。在运行时中，列表来自模型不断重写的工具调用；单独使用时，则由你自行传入这些项目。

## 开始使用

<RuntimeMode>

运行时不会自行跟踪待办事项列表。列表只是普通的工具输出：定义一个参数为当前项目的工具，并使用 `TodoList` 元素进行渲染。

<Steps>
  <Step>

### 定义待办事项工具

这里使用前端工具就足够了：模型只需要一个写入计划的位置，而渲染器会直接从 `args` 读取计划。

```tsx title="app/toolkit.ts"
import { defineToolkit } from "@assistant-ui/react";
import { z } from "zod";
import { TodoList } from "@/components/assistant-ui/elements/todo-list";

export const toolkit = defineToolkit({
  update_todos: {
    type: "frontend",
    description: "Replace the visible working list with the current plan.",
    parameters: z.object({
      items: z.array(
        z.object({
          id: z.string(),
          text: z.string(),
          status: z.enum(["pending", "active", "done"]),
        }),
      ),
    }),
    execute: async ({ items }) => ({ count: items.length }),
    render: ({ args }) => <TodoList items={args.items ?? []} />,
  },
});
```

有关工具包注册和服务端连接方式，请参阅[定义工具](/docs/tools/defining-tools)。

  </Step>
  <Step>

### 注册工具包

```tsx title="app/MyRuntimeProvider.tsx"
"use client";

import { AssistantRuntimeProvider, AuiConfig, Tools } from "@assistant-ui/react";
import { useChatRuntime } from "@assistant-ui/ai-sdk";
import { toolkit } from "./toolkit";

export function MyRuntimeProvider({ children }: { children: React.ReactNode }) {
  const runtime = useChatRuntime();
  const config = AuiConfig({ tools: Tools({ toolkit }) });
  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

每次调用 `update_todos` 都会成为独立的工具调用消息部分，因此模型修改三次计划后，记录中会留下三张卡片。在条目上设置 `display: "standalone"`，即可让每张卡片脱离内联思维链轨迹，并作为独立区块呈现。

  </Step>
</Steps>

</RuntimeMode>

### 保存待办事项状态

```tsx title="app/plan.tsx"
"use client";

import { useState } from "react";
import { TodoList, type TodoItem } from "@/components/assistant-ui/elements/todo-list";

const initialItems: TodoItem[] = [
  { id: "1", text: "Read the failing test", status: "done" },
  { id: "2", text: "Reproduce locally", status: "active" },
  { id: "3", text: "Write the fix", status: "pending" },
];

export function Plan() {
  const [items, setItems] = useState(initialItems);
  return <TodoList items={items} />;
}
```

  </Step>
  <Step>

### 更新项目状态

替换项目，而不是修改它；行以 `id` 作为键，因此相同的 id 会保留原位置，同时新状态会重新渲染其图标和文本样式。

```tsx
function advance(id: string) {
  setItems((prev) =>
    prev.map((item) =>
      item.id === id
        ? { ...item, status: item.status === "pending" ? "active" : "done" }
        : item,
    ),
  );
}
```

  </Step>
</Steps>

## 构成

```tsx
<div data-slot="todo-list">
  <div>
    <span>Todos</span>
    <span>{/* n/m, or n/m · rev r when revision is set */}</span>
  </div>
  <ul>
    <li>
      <span>{/* status icon: check, spinner, or empty box */}</span>
      <span>{/* item text */}</span>
    </li>
    {/* one row per item */}
  </ul>
</div>
```

每一行会显示三种状态图标之一：`done` 对应已勾选的方框，`active` 对应旋转的加载图标，`pending` 对应空的轮廓方框。完成后，文本会变暗并添加删除线；进行中时保持完整不透明度；待处理时则使用较低的不透明度。各行以 `item.id` 作为键；传入包含相同 id 的新数组只会重新设置现有行的样式，而真正新增的 id 会挂载一个淡入并滑入的行。

当项目数为零时，标题仍会渲染 `0/0`，列表则保持为空；不会显示占位消息。`revision` 仅用于装饰，不会影响计数或渲染；只有在传入数字时，它才会在比例旁追加 `· rev {revision}`。

## 示例

### 项目状态

无论列表如何生成，三种状态都会同时渲染：

```tsx
<TodoList
  items={[
    { id: "1", text: "Read the failing test", status: "done" },
    { id: "2", text: "Reproduce locally", status: "active" },
    { id: "3", text: "Write the fix", status: "pending" },
  ]}
/>
```

### 列表的来源

<RuntimeMode>

工具调用仍在流式传输时，`args.items` 是部分解析结果：在模型完成写入之前，字段可能缺失。`useToolArgsStatus` 会报告 `items` 参数本身是否仍在接收，这足以让整个列表变暗，而无需断言某个具体项目已经确定：

```tsx
import { useToolArgsStatus } from "@assistant-ui/react";

function TodoToolUI({ args }: { args: { items?: TodoItem[] } }) {
  const { propStatus } = useToolArgsStatus<{ items: TodoItem[] }>();
  return (
    <TodoList
      items={args.items ?? []}
      className={propStatus.items === "streaming" ? "opacity-70" : undefined}
    />
  );
}
```

</RuntimeMode>

<StandaloneMode>

发现一个步骤时，只需追加即可；组件不会区分“助手发现了新工作”和其他任何更新：

```tsx
function addItem(text: string) {
  setItems((prev) => [
    ...prev,
    { id: crypto.randomUUID(), text, status: "pending" },
  ]);
}
```

</StandaloneMode>

### 重新设置列表样式

两条路径都会在根元素上接收 `className`，而修订计数器使用来自 `surfaces.tsx` 的共享 `mono` 表面。

```tsx
<TodoList className="max-w-md gap-2" items={items} revision={3} />
```

## API 参考

<RuntimeMode>

### 工具定义

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `parameters` | Zod schema | `args` 的结构；使用一个携带项目数组的字段。 |
| `execute` | `(args) => TResult \| Promise<TResult>` | 调用解析后运行一次；其结果与渲染器显示的内容相互独立。 |
| `render` | `ToolCallMessagePartComponent<TArgs, TResult>` | 接收本次调用的 `args`、`status` 和 `result`；随着 `args` 的流式传输而重新运行。 |
| `display` | `"standalone" \| "inline"` | `"standalone"` 会将卡片显示在思维链轨迹之外。默认为 `"inline"`。 |

### 工具调用消息部分状态

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `part.status.type` | `"running" \| "complete" \| "incomplete" \| "requires-action"` | 支持渲染的调用生命周期。 |
| `useToolArgsStatus().propStatus` | `Partial<Record<keyof TArgs, "streaming" \| "complete">>` | 顶层参数的流式传输状态；从渲染器内部调用。 |

</RuntimeMode>

<StandaloneMode>

### TodoList

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `items` | `readonly TodoItem[]` | 必填 | 按顺序渲染的行。 |
| `revision` | `number` | | 设置后，会以 `· rev {revision}` 的形式追加到计数器。 |
| `className` | `string` | | 合并到根元素上。 |

### TodoItem

| 字段 | 类型 | 描述 |
|------|------|-------------|
| `id` | `string` | 行键；稳定的 id 可避免每次渲染时重复播放进入动画。 |
| `text` | `string` | 步骤的标签。 |
| `status` | `"pending" \| "active" \| "done"` | 控制图标和文本样式。 |

其他所有 `div` props 都会转发到根元素。

</StandaloneMode>
