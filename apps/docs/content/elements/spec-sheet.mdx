---
title: "规格表"
description: "继表格之后最常见的结构化答案：一个带标签的对象。"
---

单个带标签对象的结构化形态，也是大多数工具结果在表格之后紧接着采用的答案形式：一个标题、一个可选副标题，以及一列逐一显示的标签和值行。在运行时中，这些行来自工具结果；单独使用时，则直接传入这些行。

## 开始使用

<RuntimeMode>

此元素没有自己的 assistant-ui 原语，因此运行时接线使用的是工具渲染器，而不是原语组合。与模型可以自由编写的内容不同，规格表通常是真正的查询结果，因此这些行应放在工具的 `result` 上，而不是放在其流式传输的 `args` 上。

<Steps>
  <Step>

### 注册渲染函数

```tsx title="app/toolkit.tsx"
"use client";

import { defineToolkit } from "@assistant-ui/react";
import { SpecSheet } from "@/components/assistant-ui/elements/spec-sheet";

export const toolkit = defineToolkit({
  get_model_card: {
    type: "backend",
    render: ({ args, result }) => {
      if (!result) return <p>Looking up {args.modelId}…</p>;
      return (
        <SpecSheet
          title={result.title}
          subtitle={result.subtitle}
          rows={result.rows}
          visibleCount={result.rows.length}
        />
      );
    },
  },
});
```

由于整个规格表会作为一个结果一次性到达，而不是以流式步骤传入，因此 `visibleCount` 就是简单的 `result.rows.length`；不存在可用于确定其尺寸的部分状态。

  </Step>
  <Step>

### 让消息列表渲染它

```tsx title="app/MyRuntimeProvider.tsx"
import {
  AssistantRuntimeProvider,
  AuiConfig,
  Tools,
} from "@assistant-ui/react";
import { useChatRuntime } from "@assistant-ui/ai-sdk";
import { toolkit } from "./toolkit";

export function MyRuntimeProvider({
  children,
}: {
  children: React.ReactNode;
}) {
  const runtime = useChatRuntime();
  const config = AuiConfig({ tools: Tools({ toolkit }) });
  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

注册工具包后，`Thread` 以及任何基于 assistant-ui 消息部分原语（`MessagePrimitive.Parts` 或 `MessagePrimitive.GroupedParts`）构建的自定义消息列表，都会在消息中出现 `get_model_card` 调用的位置自动渲染已注册的 UI，因此无需手动放置任何内容。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

单独使用时，该元素是一个普通的展示组件：它不拥有自己的状态，因此最简单的用法是传入一组固定的行，并一次性全部显示。

<Steps>
  <Step>

### 直接传入行

```tsx title="app/model-card.tsx"
"use client";

import {
  SpecSheet,
  type SpecRow,
} from "@/components/assistant-ui/elements/spec-sheet";

const rows: readonly SpecRow[] = [
  { label: "context", value: "500,000 tokens" },
  { label: "input", value: "$15.00 / M" },
  { label: "best for", value: "Long agentic runs", emphasis: true },
];

export function ModelCard() {
  return (
    <SpecSheet
      title="Opus 5"
      subtitle="claude-opus-5"
      rows={rows}
      visibleCount={rows.length}
    />
  );
}
```

  </Step>
  <Step>

### 按自己的节奏显示行

```tsx
"use client";

import { useEffect, useState } from "react";

export function ModelCard() {
  const [visibleCount, setVisibleCount] = useState(0);

  useEffect(() => {
    if (visibleCount >= rows.length) return;
    const id = setTimeout(() => setVisibleCount((n) => n + 1), 260);
    return () => clearTimeout(id);
  }, [visibleCount]);

  return (
    <SpecSheet
      title="Opus 5"
      subtitle="claude-opus-5"
      rows={rows}
      visibleCount={visibleCount}
    />
  );
}
```

  </Step>
</Steps>

</StandaloneMode>

## 结构

```tsx
<div data-slot="spec-sheet">
  <div>
    <span>{/* title */}</span>
    <span>{/* optional subtitle */}</span>
  </div>

  <div>
    {/* one row per visible row, first row has no top border */}
    <span>{/* row.label, monospace */}</span>
    <span>{/* row.value, right aligned; emphasis bolds and brightens it */}</span>
  </div>
</div>
```

`title` 和 `subtitle` 始终会渲染，不受 `visibleCount` 影响；只有行列表会被截取。`visibleCount` 会向下取整，并以与数学元素中的 `visibleSteps` 相同的方式限制在 `0…rows.length` 范围内：NaN 或负数会映射为 0，超过数组长度的值会映射为数组长度。行使用 `row.label` 作为键，因此两个标签相同的行会在 React 协调过程中发生冲突；请确保同一个规格表中的标签唯一。第一行没有顶部边框；后续每一行都有。

## 示例

### 标记决定性行

`emphasis` 是行唯一的视觉变化：将其设置在应被视为答案而非辅助事实的行上，该行的值会比其他值显示得更粗、更亮。

```tsx
const rows: readonly SpecRow[] = [
  { label: "input", value: "$15.00 / M" },
  { label: "output", value: "$75.00 / M" },
  { label: "best for", value: "Long agentic runs", emphasis: true },
];
```

### 行的来源

<RuntimeMode>

后端条目只声明查询键。模型提供 `modelId`，服务器解析其余内容，而客户端渲染器看到的始终只有最终的结构。

```ts title="app/api/chat/route.ts"
get_model_card: tool({
  description: "Look up pricing and capability details for a model.",
  inputSchema: z.object({ modelId: z.string() }),
  execute: async ({ modelId }) => getModelCard(modelId),
}),
```

</RuntimeMode>

<StandaloneMode>

当这些行来自你自己的请求而不是固定常量时，请获取一次数据，并重置显示数量，使动画从头开始播放。

```tsx
async function loadModelCard(modelId: string) {
  const card = await fetchModelCard(modelId);
  setRows(card.rows);
  setVisibleCount(0);
}
```

</StandaloneMode>

### 重新设置规格表样式

两个区域都会在根元素上接收 `className`。行标签使用 `surfaces.tsx` 中共享的 `mono` 表面，因此重新设置该令牌的样式，会同步重新设置所有使用它的元素。

```tsx
<SpecSheet className="max-w-none gap-4" /* ... */ />
```

## API 参考

<RuntimeMode>

### 渲染属性

| 属性 | 类型 | 描述 |
|------|------|-------------|
| `args` | `{ modelId: string }` | 工具的参数，即模型提供的查询键。 |
| `result` | `{ title: string; subtitle?: string; rows: SpecRow[] } \| undefined` | 最终的规格表，在后端执行器解析完成前为 undefined。 |

### get_model_card 结果

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `title` | `string` | 规格表的标题。 |
| `subtitle` | `string` | 标题下方的可选说明文字。 |
| `rows[].label` | `string` | 行标签，以等宽字体显示。在结果中必须唯一。 |
| `rows[].value` | `string` | 行值，右对齐。 |
| `rows[].emphasis` | `boolean` | 为 true 时使值加粗并变亮。 |

</RuntimeMode>

<StandaloneMode>

### SpecSheet

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `title` | `string` | 必填 | 规格表的标题。 |
| `subtitle` | `string` | | 标题下方的可选说明文字。 |
| `rows` | `readonly SpecRow[]` | 必填 | 完整的行列表，仅渲染前 `visibleCount` 行。 |
| `visibleCount` | `number` | 必填 | 要显示的行数，向下取整并限制在 `0…rows.length` 范围内。 |
| `className` | `string` | | 合并到根元素上。 |

所有其他 `div` 属性都会转发到根元素。

### SpecRow

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `label` | `string` | 行标签，以等宽字体显示。用作 React 键，请确保其唯一。 |
| `value` | `string` | 行值，右对齐。 |
| `emphasis` | `boolean` | 可选；为 true 时使值加粗并变亮。 |

</StandaloneMode>
