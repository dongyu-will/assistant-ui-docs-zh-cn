---
title: "助手计划"
description: "助手逐步执行的检查清单，并显示一目了然的进度。"
---

一个带有标题计数、进度条的检查清单，其中每个步骤都会标记为已完成、进行中或尚未开始。在运行时中，计划来自模型驱动的工具调用；单独使用时，则由你自行维护步骤列表和当前步骤索引。

## 入门

<RuntimeMode>

这样的计划非常适合作为工具调用的结构：模型调用工具，传入完整的步骤列表以及当前所在步骤的索引。

<Steps>
  <Step>

### 渲染工具调用

注册一个 toolkit 条目，其 `render` 会将调用直接映射到 `AgentPlan`。这两个字段都来自 `args`，因此卡片无需额外信息，直接使用模型已发送的内容即可。

```tsx title="app/toolkit.tsx"
"use client";

import { defineToolkit } from "@assistant-ui/react";
import { AgentPlan } from "@/components/assistant-ui/elements/agent-plan";

export const toolkit = defineToolkit({
  update_plan: {
    type: "backend",
    render: ({ args }) => (
      <AgentPlan steps={args.steps} activeIndex={args.activeIndex} />
    ),
  },
});
```

模型每次完成一个步骤后都会再次调用 `update_plan`，因此计划会在消息记录中呈现为一组简短的卡片，而不是让同一张卡片原地变更。用于生成这些调用的 schema 和工具位于你的服务器上；此处仅展示渲染器。

  </Step>
  <Step>

### 注册 toolkit

```tsx title="app/MyRuntimeProvider.tsx"
import { AssistantRuntimeProvider, AuiConfig, Tools } from "@assistant-ui/react";
import { toolkit } from "./toolkit";

const config = AuiConfig({ tools: Tools({ toolkit }) });

export function MyRuntimeProvider({ children }: { children: React.ReactNode }) {
  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

现在，消息中出现的每个 `update_plan` 调用，都会在其所在位置渲染为 `AgentPlan` 卡片。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

单独使用时，该元素是一个受控显示组件：由你维护步骤列表，并在工作完成时推进 `activeIndex`。

<Steps>
  <Step>

### 保存计划状态

```tsx title="app/plan.tsx"
"use client";

import { useState } from "react";
import { AgentPlan } from "@/components/assistant-ui/elements/agent-plan";

const STEPS = [
  "Read existing composer state",
  "Design the draft store",
  "Wire runtime persistence",
  "Add regression tests",
  "Update the docs",
];

export function Plan() {
  const [activeIndex, setActiveIndex] = useState(0);
  return <AgentPlan steps={STEPS} activeIndex={activeIndex} />;
}
```

  </Step>
  <Step>

### 随工作完成推进计划

```tsx
function completeStep() {
  setActiveIndex((i) => i + 1);
}
```

当 `activeIndex` 达到 `steps.length` 后，所有步骤都会渲染为已完成，标题会显示 `n of n`。

  </Step>
</Steps>

</StandaloneMode>

## 组成

```tsx
<div data-slot="agent-plan">
  <div>
    <span>Plan</span>
    <span>{/* n of m */}</span>
  </div>
  <div>{/* progress bar */}</div>
  <ul>
    <li>
      <span>{/* check, spinner, or dot */}</span>
      <span>{/* step text */}</span>
    </li>
  </ul>
</div>
```

在从 `activeIndex` 绘制任何内容之前，它会先被限制在 `0…steps.length` 范围内，因此超出范围的值不会破坏布局：等于或超过 `steps.length` 的值会将所有步骤标记为已完成，而 `NaN` 会回退到 `0`。当某个步骤的索引小于限制后的当前步骤索引，或所有步骤都已完成时，该步骤为已完成；当其索引恰好等于当前步骤索引时，该步骤为进行中；否则仍为尚未开始。对于空的 `steps` 数组，标题会显示 `0 of 0`，进度条停留在 0%，列表不会渲染任何内容。

## 示例

### 重新设置计划样式

两条轨道的根元素都使用 `className`。计数器和图标列共享 `mono`，并使用来自 `surfaces.tsx` 的 `foreground` 透明度 token，因此只需修改一次调色板，就能应用到所有基于这些 token 构建的元素。

```tsx
<AgentPlan className="max-w-md gap-4" steps={steps} activeIndex={activeIndex} />
```

### 重启计划

<RuntimeMode>

需要重启的计划，只需再次调用 `update_plan`，并将 `activeIndex` 重置为 `0`。不存在单独的重置操作；下一次调用就是重置。

```tsx
render: ({ args }) => (
  <AgentPlan steps={args.steps} activeIndex={args.activeIndex} />
),
```

</RuntimeMode>

<StandaloneMode>

```tsx
function restart() {
  setActiveIndex(0);
}
```

</StandaloneMode>

## API 参考

<RuntimeMode>

### 渲染属性

| 属性 | 类型 | 描述 |
|------|------|-------------|
| `args.steps` | `string[]` | 按顺序排列的计划步骤。 |
| `args.activeIndex` | `number` | 当前正在进行的步骤索引。 |

</RuntimeMode>

<StandaloneMode>

### AgentPlan

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `steps` | `readonly string[]` | 必填 | 按顺序排列的计划步骤。 |
| `activeIndex` | `number` | 必填 | 正在进行的步骤索引。超出范围的值会被限制；`NaN` 会回退到 `0`。 |
| `className` | `string` | | 合并到根元素上。 |

所有其他 `div` 属性都会转发到根元素。

</StandaloneMode>
