## 入门

<RuntimeMode>

`reasoningEffort` 是 assistant-ui 模型上下文中的一个真实字段，其机制与输入框组件自身的模型选择器用来向模型传递力度设置的机制相同。选择一个级别和读取其消耗量是两个独立的问题：前者是注册，后者是适配器提供的使用数据。

<Steps>
  <Step>

### 注册所选的推理力度

```tsx title="components/assistant-ui/elements/reasoning-effort.tsx"
"use client";

import { useEffect, useState } from "react";
import { useAui } from "@assistant-ui/react";
import { ReasoningEffort, type EffortLevel } from "@/components/assistant-ui/elements/reasoning-effort";

const LEVELS: readonly EffortLevel[] = [
  { key: "low", label: "Low", budget: 2_000 },
  { key: "medium", label: "Medium", budget: 8_000 },
  { key: "high", label: "High", budget: 24_000 },
];

function useRegisteredEffort() {
  const [selectedKey, setSelectedKey] = useState("medium");
  const aui = useAui();

  useEffect(() => {
    return aui.modelContext.register({
      getModelContext: () => ({ config: { reasoningEffort: selectedKey } }),
    });
  }, [aui, selectedKey]);

  return { selectedKey, setSelectedKey };
}
```

`budget` 没有对应的运行时机制：它描述的是你自己的力度级别，因此无论如何都由应用定义。通过 `modelContext` 注册只会影响下一次运行，不会追溯性地修改已经进行中的运行。

  </Step>
  <Step>

### 显示运行的实际消耗

```tsx
import { useThreadTokenUsage } from "@assistant-ui/ai-sdk";

function AssistantEffort() {
  const { selectedKey, setSelectedKey } = useRegisteredEffort();
  const usage = useThreadTokenUsage();

  return (
    <ReasoningEffort
      levels={LEVELS}
      selectedKey={selectedKey}
      spent={usage?.reasoningTokens ?? 0}
      onSelect={setSelectedKey}
    />
  );
}
```

`useThreadTokenUsage` 由 `@assistant-ui/ai-sdk` 导出；如果使用其他适配器，`reasoningTokens` 则取决于该提供方使用数据的具体结构。

  </Step>
</Steps>

</RuntimeMode>

单独使用时，`levels`、`selectedKey` 和 `spent` 都只是由你管理的普通值；该元素只负责渲染它们并报告点击事件。

### 保存所选级别

```tsx title="app/effort.tsx"
"use client";

import { useState } from "react";
import { ReasoningEffort, type EffortLevel } from "@/components/assistant-ui/elements/reasoning-effort";

const LEVELS: readonly EffortLevel[] = [
  { key: "low", label: "Low", budget: 2_000 },
  { key: "high", label: "High", budget: 24_000 },
];

export function Effort() {
  const [selectedKey, setSelectedKey] = useState("low");
  return (
    <ReasoningEffort levels={LEVELS} selectedKey={selectedKey} spent={0} onSelect={setSelectedKey} />
  );
}
```

## 结构

```tsx
<div data-slot="reasoning-effort">
  <div>{/* "Thinking" label + "spent / budget" */}</div>
  <div>{/* one button per level, aria-pressed on the active one */}</div>
  <span>{/* progress fill, width = spent / budget as a percentage */}</span>
</div>
```

级别按照给定的顺序渲染，不会重新排序或分组。如果 `selectedKey` 与任何 `level.key` 都不匹配，预算将解析为 0，进度填充会保持折叠在 0%，而不会抛出错误。填充宽度是 `spent`，表示匹配级别的 `budget` 的占比，并限制在 0% 到 100% 之间，因此过大的 `spent` 值不会溢出进度条。

## 示例

### 读取模型自身的力度字段

输入框组件的模型选择器（`/elements/model-selector`）通过自身的力度控件写入同一个 `config.reasoningEffort` 字段。同时挂载两者会为同一字段注册两个提供方，因此在同一个应用中，应确保只有其中一个连接到模型上下文；assistant-ui 会根据优先级合并已注册的模型上下文，而不是根据实际渲染的组件进行选择。

### 重新设置控件样式

两个通道的根元素都接收 `className`，其初始值为 `flex w-full max-w-sm flex-col gap-2.5`。分段控件的轨道使用共享的 `field` 表面，计数使用 `mono` 令牌，两者都来自 `surfaces.tsx`。

```tsx
<ReasoningEffort className="max-w-none" /* ... */ />
```

## API 参考

<RuntimeMode>

### 模型上下文和使用情况

| 选择器 / 调用 | 类型 | 描述 |
|------|------|-------------|
| `aui.modelContext.register(provider)` | `(provider: ModelContextProvider) => Unsubscribe` | 为下一次运行注册 `config.reasoningEffort`；返回的函数会取消注册。 |
| `useThreadTokenUsage()`（`@assistant-ui/ai-sdk`） | `ThreadTokenUsage \| undefined` | `reasoningTokens` 是包含使用数据的最新消息在推理上消耗的令牌数。 |

</RuntimeMode>

<StandaloneMode>

### ReasoningEffort

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `levels` | `readonly EffortLevel[]` | 必填 | `{ key: string; label: string; budget: number }[]`，按照给定顺序渲染。 |
| `selectedKey` | `string` | 必填 | 活动级别的 `key`。不匹配的键会将预算解析为 0。 |
| `spent` | `number` | 必填 | 进度填充值，根据所选级别的 `budget` 读取。 |
| `onSelect` | `(key: string) => void` | 必填 | 按钮按下时，使用某个级别的 `key` 进行调用。 |
| `className` | `string` | | 合并到根元素上。 |

除 `children`、`levels`、`selectedKey`、`spent` 和 `onSelect` 外，所有其他 `div` 属性都会转发到根元素。

</StandaloneMode>
