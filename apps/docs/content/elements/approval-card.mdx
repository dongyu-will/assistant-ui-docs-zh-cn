title: "审批卡片"
description: "人在回路：助手在执行任何具有副作用的操作前会先征求同意。"
---

这是一张卡片，用于说明助手想要执行的操作、显示命令，并在切换为运行中、已完成或已拒绝的状态行之前等待用户决定。在运行时中，决定会通过工具调用自身的审批门传递；单独使用时，则由你维护状态并自行响应回调。

## 开始使用

<RuntimeMode>

类似这样的请求正是服务端工具审批门的用途：在用户作出回答之前，工具调用会携带一个 `approval` 对象，而 `respondToApproval` 会将回答发送回去。

<Steps>
  <Step>

### 渲染工具调用

```tsx title="app/toolkit.tsx"
"use client";

import { defineToolkit, type ToolApprovalResponse } from "@assistant-ui/react";
import { ApprovalCard } from "@/components/assistant-ui/elements/approval-card";

export const toolkit = defineToolkit({
  run_command: {
    type: "backend",
    render: ({ args, approval, respondToApproval, result }) => {
      // A refused response rejects and a precondition (an unknown option, an
      // answer the request does not take) throws, so `try`/`await` covers both
      // and the controls stay actionable.
      const answer = async (response: ToolApprovalResponse) => {
        try {
          await respondToApproval(response);
        } catch (failure) {
          console.error(failure);
        }
      };

      return (
        <ApprovalCard
          state={
            approval?.approved === false
              ? "denied"
              : approval?.approved === undefined
                ? "request"
                : result === undefined
                  ? "running"
                  : "done"
          }
          command={args.command}
          title={args.title}
          subtitle={args.subtitle}
          onAllowOnce={() => void answer({ optionId: "once" })}
          onAlwaysAllow={() => void answer({ optionId: "always" })}
          onDeny={() => void answer({ optionId: "deny" })}
        />
      );
    },
  },
});
```

在得到回答之前，`approval.approved` 始终是 `undefined`，因此只有在此期间调用 `respondToApproval` 才是合法的。发送 `optionId` 会记录主机三种选项中的具体选择，而不只是简单的“是”或“否”；请参阅[审批选项](/docs/tools/tool-ui#approval-options)，了解主机如何将 `"once"`、`"always"` 和 `"deny"` 声明为 `allow-once`、`allow-always` 和 `reject-once`。

  </Step>
  <Step>

### 注册工具包

```tsx title="app/MyRuntimeProvider.tsx"
import { AssistantRuntimeProvider, AuiConfig, Tools } from "@assistant-ui/react";
import { toolkit } from "./toolkit";

const config = AuiConfig({ tools: Tools({ toolkit }) });

export function MyRuntimeProvider({ children }: { children: React.ReactNode }) {
  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

审批门需要由能够发出审批请求的运行时提供；对于由 `toolApproval` 控制的工具，AI SDK v7 运行时可以提供此能力；对于你的 `ChatModelAdapter` 发出的审批门，`LocalRuntime` 可以提供此能力。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

单独使用时，该元素是一个受控显示组件：由你负责维护 `state`，并决定每个按钮的行为。

<Steps>
  <Step>

### 保存审批状态

```tsx title="app/approval.tsx"
"use client";

import { useState } from "react";
import {
  ApprovalCard,
  type ApprovalState,
} from "@/components/assistant-ui/elements/approval-card";

export function Approval() {
  const [state, setState] = useState<ApprovalState>("request");

  return (
    <ApprovalCard
      state={state}
      command="pnpm vitest run --changed"
      title="Run command"
      subtitle="The agent wants to run a shell command"
      onAllowOnce={() => setState("running")}
      onAlwaysAllow={() => setState("running")}
      onDeny={() => setState("denied")}
    />
  );
}
```

  </Step>
  <Step>

### 解析运行结果

```tsx
async function run() {
  const exitCode = await runCommand();
  setState("done");
}
```

这里没有用于设置退出代码的属性；在此版本中，`state: "done"` 始终显示为“以退出代码 0 完成”。

  </Step>
</Steps>

</StandaloneMode>

## 结构

```tsx
<div data-slot="approval-card">
  <div>
    <span>{/* terminal icon */}</span>
    <p>{/* title */}</p>
    <p>{/* subtitle */}</p>
  </div>
  <div>{/* command, monospace */}</div>
  <div>
    {/* state === "request": Deny, Always allow, Allow once */}
    {/* otherwise: a status line keyed on state, so it animates in */}
  </div>
</div>
```

页脚有两种形式：当 `state` 为 `"request"` 时显示三按钮栏，否则显示单行状态。状态行的图标和文本由状态固定决定（`"running"` 使用加载指示器，`"denied"` 使用 X，`"done"` 使用勾号），而不是由其他属性驱动。卡片自身不保存状态，也不会运行计时器；所有状态转换都来自你传入的 `state`，并且回调只会从请求行触发。

## 示例

### 重新设置卡片样式

两种模式都会在根元素上接收 `className`。命令块使用 `surfaces.tsx` 中的 `field` 表面，主按钮使用其中的 `inkButton`。

```tsx
<ApprovalCard className="max-w-md" /* ... */ />
```

### 拒绝并提供理由

<RuntimeMode>

`respondToApproval` 接受与决定一起传入的 `reason`，主机可以将其展示给模型：

```tsx
onDeny={() =>
  void answer({ optionId: "deny", reason: "not in this session" })
}
```

</RuntimeMode>

<StandaloneMode>

该元素没有理由字段；请在调用 `onDeny` 之前在自己的 UI 中收集理由，或者改为通过应用状态传递理由。

```tsx
onDeny={() => {
  logDenyReason("not in this session");
  setState("denied");
}}
```

</StandaloneMode>

## API 参考

<RuntimeMode>

### 渲染属性

| 来源 | 类型 | 描述 |
|--------|------|-------------|
| `args.command` / `args.title` / `args.subtitle` | `string` | 命令及其说明文案。 |
| `approval?.approved` | `boolean \| undefined` | `undefined` 映射到 `"request"`，`false` 映射到 `"denied"`，`true` 根据 `result` 映射到 `"running"` 或 `"done"`。 |
| `result` | `unknown` | 当 `approved` 为 `true` 后，其存在性会映射到 `"done"`。 |
| `respondToApproval(response)` | `(response: ToolApprovalResponse) => Promise<void>` | 发送决定。仅当 `approval.approved` 为 `undefined` 时才合法。当运行时无法记录响应时会拒绝。 |

</RuntimeMode>

<StandaloneMode>

### ApprovalCard

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `state` | `"request" \| "running" \| "done" \| "denied"` | 必填 | 要渲染的页脚。 |
| `command` | `string` | 必填 | 显示在等宽字体命令块中。 |
| `title` | `string` | 必填 | 标题。 |
| `subtitle` | `string` | 必填 | 副标题。 |
| `onAllowOnce` | `() => void` | | 由请求行的主按钮触发。 |
| `onAlwaysAllow` | `() => void` | | 由请求行的次按钮触发。 |
| `onDeny` | `() => void` | | 由请求行的“拒绝”按钮触发。 |
| `className` | `string` | | 合并到根元素上。 |

所有其他 `div` 属性都会转发到根元素。

</StandaloneMode>
