输入框操作栏中的一个小胶囊按钮会显示当前模型，并打开一个简短列表供你切换模型，无需离开正在编写的消息。在运行时中，该选择会注册到 assistant-ui 的模型上下文系统，因此确实会传递到下一次请求；在独立模式下，你只需将选择保存为状态。

## 快速开始

<RuntimeMode>

没有专门用于模型触发器的原语，因为“当前模型”并不像分支或附件那样属于线程或消息状态；它实际上是应用通过通用模型上下文系统注册的内容。读取已注册的名称即可显示它，注册新名称即可更改它。

<Steps>
  <Step>

### 读取当前模型

```tsx
import { useAuiState } from "@assistant-ui/react";

const modelName = useAuiState((s) => s.modelContext.modelName);
```

`s.modelContext.modelName` 来源于当前通过 `aui.modelContext.register(...)` 注册的所有 provider，并按优先级合并；如果没有注册任何 provider，则为 `undefined`。

  </Step>
  <Step>

### 注册变更

```tsx title="components/assistant-ui/elements/composer-model-trigger.tsx"
"use client";

import { useEffect, useState } from "react";
import { useAui, useAuiState } from "@assistant-ui/react";
import { ComposerModelTrigger, ComposerMenu, ComposerModelItem } from "@/components/assistant-ui/elements/composer";

const models = [
  { name: "Fast", meta: "$0.25/M" },
  { name: "Frontier", meta: "$3/M" },
];

export function ModelPicker() {
  const aui = useAui();
  const [selected, setSelected] = useState(models[0]);
  const [open, setOpen] = useState(false);

  useEffect(() => {
    return aui.modelContext.register({
      getModelContext: () => ({ config: { modelName: selected.name } }),
    });
  }, [aui, selected]);

  return (
    <div className="relative">
      <ComposerModelTrigger model={selected.name} open={open} onClick={() => setOpen((v) => !v)} />
      <ComposerMenu open={open}>
        {models.map((entry) => (
          <ComposerModelItem
            key={entry.name}
            entry={entry}
            selected={entry.name === selected.name}
            onClick={() => {
              setSelected(entry);
              setOpen(false);
            }}
          />
        ))}
      </ComposerMenu>
    </div>
  );
}
```

该 effect 会在 `selected` 每次变更时重新注册，并自动清理之前的注册，因为 `register` 会返回取消订阅函数。这与 [模型选择器](/elements/model-selector) kit 内部使用的模式相同；如果你还需要支持搜索、按 provider 分组以及推理力度控制的列表，可以直接安装该组件，而不必自行构建 effect。若要查看完整列表，而不是这个紧凑型触发器，请参阅[模型选择器设计](/elements/model-selector#the-model-picker-design)。

  </Step>
</Steps>

</RuntimeMode>

<StandaloneMode>

在独立模式下，触发器和菜单完全受控：你需要保存当前选中的模型以及菜单是否打开，这两个目录组件只负责渲染该状态。

<Steps>

### 保存选择

```tsx title="app/chat-box.tsx"
"use client";

import { useState } from "react";
import { ComposerModelTrigger, ComposerMenu, ComposerModelItem, type ComposerModel } from "@/components/assistant-ui/elements/composer";

const models: ComposerModel[] = [
  { name: "Fast", meta: "$0.25/M" },
  { name: "Frontier", meta: "$3/M" },
];

export function ModelPicker() {
  const [selected, setSelected] = useState(models[0]);
  const [open, setOpen] = useState(false);

  return (
    <div className="relative">
      <ComposerModelTrigger model={selected.name} open={open} onClick={() => setOpen((v) => !v)} />
      <ComposerMenu open={open} align="end">
        {models.map((entry) => (
          <ComposerModelItem
            key={entry.name}
            entry={entry}
            selected={entry.name === selected.name}
            onClick={() => {
              setSelected(entry);
              setOpen(false);
            }}
          />
        ))}
      </ComposerMenu>
    </div>
  );
}
```

  </Step>
  <Step>

### 自行关闭

`ComposerMenu` 和 `ComposerModelTrigger` 都不会监听外部点击或 Escape；`open` 只控制动画和 `pointer-events`。请在你决定的时机关闭菜单，通常是在点击外部时处理，或像上面那样在选择后关闭。

  </Step>
</Steps>

</StandaloneMode>

## 结构

```tsx
<div>
  <button aria-expanded={/* open */}>{/* model name */}<svg /* chevron */ /></button>
  <div data-slot="composer-menu" data-open={/* open */}>
    <button data-slot="composer-menu-item" data-active={/* selected */}>
      <span>{/* name */}</span>
      <span>{/* meta, tabular-nums */}</span>
      {/* a check mark fades and zooms in only on the selected row */}
    </button>
  </div>
</div>
```

触发器不会自动禁用自身，也不会管理自己的打开状态；无论在哪种模式下，这两者都由调用方负责。

## 示例

### 读取和写入是两个不同的调用

<RuntimeMode>

`s.modelContext.modelName` 只反映已注册的内容；设置它始终是一次 `register` 调用，而不是直接赋值。只显示名称的组件（例如页眉中的组件）只需要选择器；只有负责选择器 UI 的部分才需要调用 `register`。

```tsx
const modelName = useAuiState((s) => s.modelContext.modelName); // read
aui.modelContext.register({ getModelContext: () => ({ config: { modelName: "Frontier" } }) }); // write
```

</RuntimeMode>

### 重新设置触发器和菜单的样式

两种模式都与 [斜杠命令](/elements/composer-slash-commands) 和 [提及](/elements/composer-mentions) 共享 `ComposerMenu` 和 `ComposerModelItem`；在那里重新设置样式也会同时影响此菜单。触发器本身是一个独立的胶囊按钮，并使用自己的 `className`。

```tsx
<ComposerModelTrigger model={selected.name} open={open} className="text-foreground/80" />
```

## API 参考

<RuntimeMode>

### 模型上下文

| 选择器 | 类型 | 描述 |
|----------|------|-------------|
| `s.modelContext.modelName` | `string \| undefined` | 优先级最高的已注册 provider 的 `config.modelName`。 |
| `s.modelContext.toolNames` | `readonly string[]` | 从已注册 provider 合并而来的所有工具名称。 |
| `aui.modelContext.register(provider)` | `(provider: ModelContextProvider) => Unsubscribe` | 注册 `{ getModelContext: () => ({ config: { modelName } }) }`；调用返回的函数即可取消注册。 |

注册采用累加并按优先级排序：可以同时注册多个 provider（来自不同组件），当它们对 `modelName` 的定义不一致时，`priority` 最高的 provider 获胜。

</RuntimeMode>

<StandaloneMode>

### ComposerModel

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `name` | `string` | 显示为该行的标签。 |
| `meta` | `string` | 右对齐显示，例如价格。 |

### ComposerModelTrigger

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `model` | `string` | 必填 | 显示在箭头前的名称。 |
| `open` | `boolean` | 必填 | 设置 `aria-expanded`；不会自行控制任何菜单。 |
| `className` | `string` | | 合并到根元素上。 |

### ComposerModelItem

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `entry` | `ComposerModel` | 必填 | 要渲染的行。 |
| `selected` | `boolean` | 必填 | 显示动画复选标记。 |

</StandaloneMode>
