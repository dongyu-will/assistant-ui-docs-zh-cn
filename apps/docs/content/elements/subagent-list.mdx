由一组卡片组成，每个工作器对应一张卡片，显示完成或旋转图标、所用模型和进度条，末尾还可选择性添加一张用于综合处理的卡片。在运行时中，每个工作器对应一次独立的工具调用，列表由这些工具调用组装而成；单独使用时，则直接传入工作器列表及其进度。

## 快速开始

<RuntimeMode>

向多个子代理分发任务，本质上是在一次助手回复中发起多次工具调用，每个工作器对应一次调用。列表本身并不是任何单次调用的 UI，而是由所有调用组装而成。

<Steps>
  <Step>

### 隐藏渲染分发调用

使用一个返回空内容的 `render` 注册分发工具。其 schema 和执行逻辑位于你的服务器上；在这里，它只需要阻止默认工具卡片以内联方式再次显示，因为下方的聚合列表负责视觉呈现。

```tsx title="app/toolkit.tsx"
"use client";

import { defineToolkit } from "@assistant-ui/react";

export const toolkit = defineToolkit({
  dispatch_subagent: { type: "backend", render: () => null },
  summarize_findings: { type: "backend", render: () => null },
});
```

  </Step>
  <Step>

### 在消息下方聚合它们

读取当前消息的每个部分，保留 `dispatch_subagent` 调用，并将它们整合到 `SubagentList` 所需的 props 中。如果存在 `summarize_findings`，它会成为末尾的摘要卡片。

```tsx title="components/assistant-ui/elements/thread.aui.tsx"
import { MessagePrimitive, useAuiState } from "@assistant-ui/react";
import { SubagentList } from "@/components/assistant-ui/elements/subagent-list";

function SubagentProgress() {
  const parts = useAuiState((s) => s.message.parts);
  const calls = parts.filter(
    (p) => p.type === "tool-call" && p.toolName === "dispatch_subagent",
  );
  const summaryCall = parts.find(
    (p) => p.type === "tool-call" && p.toolName === "summarize_findings",
  );
  if (calls.length === 0) return null;

  return (
    <SubagentList
      agents={calls.map((c) => ({ name: c.args.name, model: c.args.model }))}
      completedCount={calls.filter((c) => c.status.type === "complete").length}
      progress={calls.map((c) => (c.status.type === "complete" ? 100 : 0))}
      showSummary={summaryCall !== undefined}
      summaryAgent={
        summaryCall
          ? { name: summaryCall.args.name, model: summaryCall.args.model }
          : { name: "", model: "" }
      }
    />
  );
}

function AssistantMessage() {
  return (
    <MessagePrimitive.Root>
      <MessagePrimitive.Parts />
      <SubagentProgress />
    </MessagePrimitive.Root>
  );
}
```

### 保存工作器列表及其进度

```tsx title="app/agents.tsx"
"use client";

import { useState } from "react";
import {
  SubagentList,
  type SubagentItem,
} from "@/components/assistant-ui/elements/subagent-list";

const AGENTS: readonly SubagentItem[] = [
  { name: "Explore the runtime", model: "haiku" },
  { name: "Fix composer types", model: "sonnet" },
  { name: "Write regression tests", model: "sonnet" },
];

export function Agents() {
  const [completedCount, setCompletedCount] = useState(0);
  const [progress, setProgress] = useState([0, 0, 0]);

  return (
    <SubagentList
      agents={AGENTS}
      completedCount={completedCount}
      progress={progress}
      showSummary={false}
      summaryAgent={{ name: "Summarize findings", model: "haiku" }}
    />
  );
}
```

  </Step>

### 报告进度和完成状态

```tsx
function onWorkerProgress(index: number, percent: number) {
  setProgress((prev) => prev.with(index, percent));
}

function onWorkerDone() {
  setCompletedCount((count) => count + 1);
}
```

`completedCount` 会从数组开头开始将代理标记为已完成，因此请按顺序完成它们，以便勾选标记显示在正确的卡片上。

## 结构

```tsx
<div data-slot="subagent-list">
  <div>
    <span>{/* check or spinner */}</span>
    <span>{/* agent name */}</span>
    <span>{/* model */}</span>
    <span role="progressbar">{/* progress bar, named from its agent */}</span>
  </div>
  {/* one card per agent, then the summary card when shown */}
</div>
```

当 `i < completedCount` 时，索引为 `i` 的代理即视为已完成；其进度条宽度和 progressbar 值来自 `progress[i]`，并限制在 `0…100` 范围内；缺失或 `NaN` 条目按 `0` 读取。每个 progressbar 都以其代理命名，并向辅助技术公开一个 `0…100` 值。当 `showSummary` 为 true 时，摘要卡片始终显示旋转状态和固定宽度的进度条，其 progressbar 不携带任何值：此版本无法将摘要本身标记为已完成，只能显示或隐藏摘要。根元素带有最小高度，因此随着代理完成以及摘要卡片淡入显示，布局不会发生跳动。

## 示例

### 重新设置工作器列表样式

两个区域都在根元素上使用 `className`。每张卡片都使用共享的 `paper` surface，并使用 `mono` token 显示模型标签，因此在 `surfaces.tsx` 中重新设置这些内容的主题后，这里的每张卡片以及所有基于它们构建的其他元素都会同步应用新样式。

```tsx
<SubagentList className="max-w-sm gap-3" /* ... */ />
```

### 进度从何而来

<RuntimeMode>

工具调用的 `status` 只能区分运行中和已完成，因此上面的映射只有两种状态：工作器的调用正在执行时为 `0`，结果返回后为 `100`。如果需要更平滑的实时百分比，就需要自行提供进度通道，例如使用以调用的 `toolCallId` 为键的应用级 store，由 websocket 或轮询更新填充，再以相同方式读取到 `progress` 中。

</RuntimeMode>

<StandaloneMode>

```tsx
async function runWorker(index: number) {
  for (let pct = 0; pct <= 100; pct += 20) {
    await tick();
    setProgress((prev) => prev.with(index, pct));
  }
  setCompletedCount((count) => count + 1);
}
```

## API 参考

<RuntimeMode>

### Render props

| Source | Type | Description |
|--------|------|-------------|
| `dispatch_subagent` call `args.name` / `args.model` | `string` | 每次调用对应一个工作器列表条目。 |
| `dispatch_subagent` call `status.type` | `"running" \| "requires-action" \| "incomplete" \| "complete"` | `"complete"` 会计入 `completedCount`，并读取为 `100` 进度；其他值均读取为 `0`。 |
| `summarize_findings` call | tool call 或 `undefined` | 仅凭存在性即可驱动 `showSummary`；其 `args` 会成为 `summaryAgent`。 |

</RuntimeMode>

<StandaloneMode>

### SubagentList

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `agents` | `readonly SubagentItem[]` | required | 按显示顺序排列的工作器列表。 |
| `completedCount` | `number` | required | 从 `agents` 开头开始计数，已完成的代理数量。 |
| `progress` | `readonly number[]` | required | 每个代理的进度条宽度和可访问进度值，与 `agents` 按索引对应。值会限制在 `0…100` 范围内；超出范围或 `NaN` 的条目按 `0` 读取。 |
| `showSummary` | `boolean` | required | 是否渲染末尾的摘要卡片。 |
| `summaryAgent` | `SubagentItem` | required | 摘要卡片的名称和模型。 |
| `className` | `string` | | 合并到根元素上的属性。 |

`SubagentItem` 是 `{ name: string; model: string }`。所有其他 `div` props 都会转发到根元素。

</StandaloneMode>
