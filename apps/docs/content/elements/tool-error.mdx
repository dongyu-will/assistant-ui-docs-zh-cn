失败的工具调用会显示为独立卡片，其中包含调用内容、错误信息、尝试次数，以及重试或跳过的方式。在运行时中，失败信息来自工具调用的状态；在独立使用时，则需要自行保存尝试次数和消息。

## 入门

<RuntimeMode>

状态最终确定为 `"incomplete"` 的调用即为失败调用。在显示工具正常结果的同一个渲染器中对它进行分支处理。

<Steps>
  <Step>

### 从工具包条目渲染失败状态

```tsx title="app/search-toolkit.tsx"
"use client";

import { useState } from "react";
import { useAui, type ToolCallMessagePartProps } from "@assistant-ui/react";
import { ToolError } from "@/components/assistant-ui/elements/tool-error";

function SearchTool({ toolName, args, status, result }: ToolCallMessagePartProps<{ query: string }, string>) {
  const [attempt, setAttempt] = useState(1);
  const aui = useAui();

  if (status?.type === "incomplete") {
    return (
      <ToolError
        name={toolName}
        target={args.query}
        message={typeof status.error === "string" ? status.error : JSON.stringify(status.error)}
        attempt={attempt}
        maxAttempts={3}
        retrying={false}
        onRetry={() => {
          setAttempt((a) => Math.min(a + 1, 3));
          aui.message.reload();
        }}
      />
    );
  }

  return <p>{result}</p>;
}
```

`status.error` 携带失败的 `execute` 抛出的内容或后端报告的内容；它是 `unknown`，因此在直接渲染前，请先处理字符串类型的情况。

  </Step>
  <Step>

### 重新生成线程以进行重试

```tsx title="app/providers.tsx"
import { AuiConfig, AuiProvider, Tools, defineToolkit, useAui } from "@assistant-ui/react";
import { z } from "zod";
import { SearchTool } from "./search-toolkit";

const toolkit = defineToolkit({
  search_web: {
    type: "frontend",
    description: "Search the web for a query.",
    parameters: z.object({ query: z.string() }),
    execute: async ({ query }) => runSearch(query),
    render: SearchTool,
  },
});

function Providers({ children }: { children: React.ReactNode }) {
  const aui = useAui();
  const config = AuiConfig({ tools: Tools({ toolkit }) });
  return (
    <AuiProvider extends={aui} config={config}>
      {children}
    </AuiProvider>
  );
}
```

assistant-ui 不会原地重试单个工具调用；`aui.message.reload()` 会重新发起整个线程，并以全新的尝试再次调用 `search_web`。

  </Step>
</Steps>

</RuntimeMode>

独立使用时，没有可重新开始的线程：`onRetry` 可以直接再次调用产生失败的内容，尝试次数则由你自行跟踪。

### 保存尝试次数

```tsx title="app/search-failure.tsx"
"use client";

import { useState } from "react";
import { ToolError } from "@/components/assistant-ui/elements/tool-error";

export function SearchFailure({ query }: { query: string }) {
  const [attempt, setAttempt] = useState(1);
  const [retrying, setRetrying] = useState(false);
  const [message, setMessage] = useState("The search API timed out.");

  return (
    <ToolError
      name="search_web"
      target={query}
      message={message}
      attempt={attempt}
      maxAttempts={3}
      retrying={retrying}
      onRetry={() => retry(query)}
    />
  );
}
```

  </Step>
  <Step>

### 不重新开始线程而进行重试

```tsx
async function retry(query: string) {
  setRetrying(true);
  try {
    const result = await runSearch(query);
    // success: replace this card with `result` in your own state
  } catch (err) {
    setAttempt((a) => a + 1);
    setMessage(err instanceof Error ? err.message : String(err));
  } finally {
    setRetrying(false);
  }
}
```

  </Step>
</Steps>

</StandaloneMode>

## 结构

```tsx
<div data-slot="tool-error">
  <div>{/* icon, name, target, "attempt/maxAttempts" */}</div>
  <div>{/* message, monospace */}</div>
  <div>
    <button>{/* Skip, disabled when onSkip is absent */}</button>
    <button>{/* Retry, disabled and spinning while retrying */}</button>
  </div>
</div>
```

跳过操作没有默认行为：不传入 `onSkip` 时，按钮仍会渲染但处于禁用状态，因此即使卡片只有重试路径，也仍会显示两个操作。`retrying` 为 true 时，重试按钮会自行禁用，并将图标替换为加载指示器；卡片中的其他内容不会响应 `retrying`。

## 示例

### 读取实际的失败原因

<RuntimeMode>

`status.type === "incomplete"` 不仅涵盖工具错误：`status.reason` 也可能是 `"cancelled"`、`"length"`、`"content-filter"` 或 `"other"`。仅针对 `"error"` 显示重试卡片，其余情况使用各自的消息：

```tsx
if (status?.type === "incomplete" && status.reason !== "error") {
  return <p>Cancelled before it finished.</p>;
}
```

</RuntimeMode>

### 重新设置卡片样式

两个区域的根元素都接收 `className`。根元素使用共享的 `paper` 表面样式，消息框使用 `field`，名称和尝试次数使用 `mono`，因此在 `surfaces.tsx` 中重新指定这些令牌后，这张卡片以及所有基于它们构建的内容都会同步更新样式。跳过和重试按钮使用各自的内联类，而不是共享令牌。

## API 参考

<RuntimeMode>

### 工具调用状态

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `status.type` | `"running" \| "complete" \| "incomplete" \| "requires-action"` | `"incomplete"` 表示失败（或已取消）状态。 |
| `status.reason` | `"cancelled" \| "length" \| "content-filter" \| "other" \| "error"` | 仅当 `status.type` 为 `"incomplete"` 时存在。 |
| `status.error` | `unknown` | 仅当 `status.type` 为 `"incomplete"` 时存在；表示抛出的值或后端报告的错误。 |
| `useToolCallElapsed()` | `number \| undefined` | 当前调用经过的时间；在调用完成且没有记录时长后为 `undefined`。 |
| `aui.message.reload()` | `() => void` | 重新发起当前助手线程，包括其中的工具调用。 |

</RuntimeMode>

<StandaloneMode>

### ToolError

| Prop | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `name` | `string` | 必填 | 工具名称。 |
| `target` | `string` | 必填 | 调用操作的对象。 |
| `message` | `string` | 必填 | 错误文本。 |
| `attempt` | `number` | 必填 | 当前尝试次数。 |
| `maxAttempts` | `number` | 必填 | 允许的尝试次数。 |
| `retrying` | `boolean` | 必填 | 为 true 时禁用重试按钮并显示加载状态。 |
| `onRetry` | `() => void` | | 从重试按钮调用。 |
| `onSkip` | `() => void` | | 从跳过按钮调用。不传入时，按钮保持禁用状态。 |
| `className` | `string` | | 合并到根元素上。 |

所有其他 `div` props 都会转发到根元素。

</StandaloneMode>
